# 关键页面高保真原型（rough take）

Type: prototype
Status: resolved
Blocked by: 04

## Question

服务对象定为双主线（工程风险管理员日常办公为主、甲方演示验收为辅），但「好看」「信息密度合适」「追溯能看明白」这些判断没法靠文字规格定下来，必须看到能点的东西。

**做出 5–8 个关键页面的粗粒度高保真原型，让用户能直接反应"这才是我想要的"或"不是这个"** —— 需要定下来。

具体要回答：

1. 选哪 5–8 个页面？候选至少覆盖：
   - 日常办公的入口首页（"本工程今日风险"之类）
   - 预警处置任务列表与详情（双主线都必需）
   - 标准化风险记录详情 —— 要能一眼看懂"风险为什么是这个等级"，即证据链与 P/C 计算口径在页面上怎么呈现
   - 识别 / 评估运行页（现状是 5s 轮询）
   - 复核决定页
   - Agent 停靠栏 / 全屏工作台
   - 一个甲方演示用的总览屏
2. 原型做到什么保真度？是可点击的 HTML/React rough prototype，还是静态图？验收标准是什么（"用户能说出下一步该点哪"这类可观察行为）？
3. 原型放哪、怎么和 `demo/v2` 现有 57 页原型共存？是替换、并存、还是从 v2 演进？
4. 每个原型的评审要收集什么反馈、以什么标准判定"通过"进入规格？
5. 原型里哪些东西是**故意做旧的**（避免被当成已定稿），如何在界面上标示？

产出是原型本身 + 逐页评审结论，作为资产链接回本票，不贴进票正文。

## 评审结论（用户 2026-10-18）

用户看过原型后同意结票。方向全部确认成立。

**采纳的方案**：
- 页面方向：B 纵向叙事（时间轴为主结构）
- 紧凑高密度（行高 28px 级）/ 弱化卡片（分隔线与对齐组织）/ 克制中性色（浅灰底白面，工程蓝只用于交互，风险色只表达等级）
- 桌面宽屏保留信息结构；左导航 152px／48px、右停靠区生产宽度 22rem。窗口变窄或缩放可由用户收起面板，正文折行、二维区域局部滚动，关键操作和焦点不得裁切；不增加移动端适配。
- ⌘K 为一级入口、全键盘可达
- Agent 主动在场：停靠区「助手工作」页签 + 页内 `AgentNote` + 处置闭环的 `AgentDelta`

**评审中提出的四处问题与修正**（全部已落地并验证）：
1. 侧栏用单个中文字当图标 → 改用 v2 既有 1.5px 描边线性图标集（`overview`/`project`/`identification`/`assessment`/`warnings`/`knowledge`）
2. 侧栏无展开/折叠 → 加 `⌘\` 切换，152px（展开带文字）↔ 48px（收起只留图标）。152px 是量出来的：最宽标签「预警与处置」61px，加图标/间距/序号/内边距实际需求 111px
3. 命令面板放在侧栏顶部语义不通 → 移到顶栏中间，成为长 340px 的搜索条「搜索风险、资料、任务，或输入命令…」+ `⌘K` 角标
4. 原型里看不到 Agent 在当前业务域的工作流程输出 → 停靠区加「助手工作」页签

**「助手工作」页签的设计**（本轮新增，回答"Agent 工作流输出在哪看"）：
- 本工程全部 Agent 任务，五类必经 Agent 任务全覆盖，按「进行中 / 非结束性知识编制 / 已结束」分组
- 展开单条可见：工具行动（白名单内工具与结果）→ 确定性校验逐项决定（操作类型、接受/拒绝、理由）→ 资源预算（Token/工具调用/候选用量条 + 墙钟）→ 正式结果（候选引用、校验引用、下游承载说明；失败则显示错误码、失败阶段、可否重试）
- **只展示结构化过程，不展示模型内部思维链**（AGENTS.md §2.1）
- 数据来自 `src/content/agent.ts` 真 fixture，五类任务、五类任务类型标签均已验证命中

**施工边界**：原型 fixture 不是后端能力证明；权限、记录正文与精确深链按票 06／09／10 的契约实施。风险徽章与图表共用受控等级配色，表单错误使用独立操作错误色；校准逐项展示的是确定性校验，人工决定仍针对整个建议。原型评审不能替代真实角色、历史版本、桌面缩放和正式命令验收。

**最终状态**：27 页（26 页 + 快捷键面板）全部渲染非空，禁用词扫描零命中，⌘K 过滤/Esc/g+数字/⌘\ 折叠全部验证通过，矩阵维度全部从配置派生无硬编码。

**资产去留**：原型代码在 `demo/v2/src/pages/prototype/`，一次性原型，按 prototype skill 不进生产、不提交主分支；方向已定，后续 change 施工时按本票结论在真实代码中重新实现（原型代码在原型约束下写成，无测试、最小错误处理，不得直接提升为生产代码）。
