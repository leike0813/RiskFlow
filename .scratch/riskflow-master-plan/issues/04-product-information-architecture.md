# 确定产品信息架构与界面设计系统

## Question

RiskFlow 应采用怎样的导航结构、核心页面、跨页面对象关系、工业风险驾驶舱视觉系统和 Agent 交互模式，才能让识别、评估、预警、处置和证据追溯形成一个清晰的产品，而不是技术模块菜单的堆叠？

## Answer

采用面向风险业务任务的八项一级导航：风险态势、工程项目、智能 Agent、风险识别、风险评估、预警处置、知识与规则、复核与审计。四层技术架构不直接暴露为用户菜单。

全局常驻工程、空间区段与工序阶段；标准化风险记录、风险评估记录、预警信息和处置建议通过领域标识贯穿页面。智能 Agent 使用“对话 + 任务执行 + 结构化结果 + 证据引用”工作台，不展示内部思维链，也不维护独立业务事实。视觉采用已确认的深蓝灰工业风险驾驶舱框架，风险色只表达等级与预警。

完整页面职责、对象闭环、视觉系统和五张汇报截图映射见：[RiskFlow 产品信息架构与界面设计系统](../prototypes/product-information-architecture.md)。

## Scope note

本票据只确定高层信息架构、导航、对象闭环和视觉方向。完整产品的角色差异、全部页面、交互、表单、异常状态、权限状态与验收行为由后续“设计完整产品界面与交互规格”票据决定。

> 修订记录：本票“智能 Agent 是独立一级工作台”的决策已被“设计完整产品界面与交互规格”票修订为“全局 Agent 停靠栏 + 全屏工作台模式”混合形态，一级导航相应从八项调整为七项业务导航；Agent 形态的唯一事实源以该票为准。
