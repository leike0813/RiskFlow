## ADDED Requirements

### Requirement: Worker统一携带可信任务执行依据

C08 MUST 通过精确任务引用及当前Worker租约窄读正式任务、不可变启动授权/父运行/冻结范围和策略及实际预算，不信任Agent自报信封。Worker MUST 在任务作用域携带该依据，模型、工件、工具及恢复读取在受保护行动前经同一C06当前授权接缝检查。原动作、工件、预算和信封身份保持，交互写入继续要求独立用户确认及新鲜人类授权。

#### Scenario: 同一任务各执行接缝共享当前授权检查

- **WHEN** Worker读取冻结输入、调用模型、执行工具或保存/恢复工件
- **THEN** 当前任务、租约、预算和权限均先验证，原短效启动上下文不会导致合法长任务固定在第5分钟失败

#### Scenario: 租约或任务状态失效

- **WHEN** 租约过期/被其它Worker领取、任务已取消/终止或预算不足
- **THEN** 后续受保护行动拒绝，不复活旧失败、清空台账或重发已完成动作

### Requirement: 行动按剩余额度执行并如实记录失败消耗

系统 MUST 将本行动预留的输入、输出及上下文token额度交给模型网关，在外部调用前按保守上界或真实tokenize核验。模型响应后解释或结算失败 MUST 保留实际usage、原响应和行动回执；预算失败终态可以记入已发生的超额消耗，但不得正常完成、重置台账或继续调用。新任务预算可在明确授权下重新定额并冻结新版本，运行中不得自动扩容。

#### Scenario: 剩余额度不足

- **WHEN** 渲染请求超过本行动剩余额度
- **THEN** 模型调用前预算拒绝，不发起外部推理，不通过重复领取绕过

#### Scenario: 已发生超额或解释失败

- **WHEN** 已获得模型响应但实际用量超额或后续解释/结算失败
- **THEN** 真实用量与精确回执被保存，预算超额任务正式失败，不丢用量或继续领取

### Requirement: 失败行动恢复必须有界收口

Worker MUST 正确区分输入、权限、工件和模型技术故障；不可重试失败必须终止并留证。可安全重试的已失败行动 MUST 复用原动作身份、冻结输入和累计预算；预算不足、恢复读拒绝或不确定效果不得通过重复claim空转，亦不得重置预算、丢失失败或覆盖原业务事实。

#### Scenario: 重复领取已失败行动

- **WHEN** Worker再次领取含已失败行动的任务
- **THEN** 按原失败类型与剩余预算安全恢复或正式终止，记录实际重试和结果
- **AND** 不在未推进动作或预算的情况下无限领取同一任务

#### Scenario: 恢复证据不可读

- **WHEN** 恢复所需工件被撤权、缺失、用途不符或完整性失败
- **THEN** 按对应结构化错误收口并阻止后续模型和工具行动，不把错误泛化为可无限重试的模型故障

#### Scenario: 恢复已完成工具读取进度

- **WHEN** Worker恢复同任务已完成的模型工具请求和工具观察
- **THEN** 从原精确行动证据重建有界成功调用记录，后续模型步保留已完成工具/输入/观察引用且不重复执行原动作
- **AND** 未完成或失败行动不入已读事实，原租约、取消、预算、权限与错误收口保持
