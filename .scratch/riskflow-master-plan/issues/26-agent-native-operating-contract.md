# 定义 Agent-native 横切运行与治理契约

## Question

RiskFlow 应怎样把“确定性产物 → Agent 审阅与受限工具行动 → 确定性校验 → 正式产物”的 Agent-native 模式贯穿资料接入、知识建模、风险识别、规则适配、评估预警、处置反馈、版本治理和用户交互；哪些阶段必须经过 Agent、Agent 可以读取和提议修改什么、工具权限与资源预算怎样限定、失败和暂停如何处理、怎样记录 Agent 对基线的增量与影响，并与人工复核、正式发布和确定性领域规则保持清晰边界？现有功能规格、界面规格、识别/评估契约和 MVP 范围需要据此作哪些修订？

## Comments

- 2026-08-28：已确认 Agent 审阅按任务性质而非按全流程阶段强制。只有需要语义判断、证据取舍或受限工具行动的环节才可设为必经 Agent；P/C 计算、风险矩阵映射、阈值判断、Schema 校验和业务入库等确定性阶段不以 Agent 可用性为前置，也不得由 Agent 改写结果。
- 2026-08-28：已确认系统内嵌 Agent 审阅与用户从停靠栏或全屏工作台发起的 Agent 操作共用统一“Agent 任务”契约。内嵌任务在已确认业务运行的预授权工具范围内自动执行；交互任务继承当前用户权限，产生业务事实或外部副作用前仍须用户确认；两者统一记录身份、工程、输入与策略版本、模型、工具、预算、增量和终态。
- 2026-08-28：已确认知识建模按来源决定 Agent 是否必经。从非结构化工程资料、规范或案例抽取或修订工序模型、风险机理条目、结构化评分规则和措施项时，必须经过 Agent 审阅并输出候选或相对冻结基线的增量，再由确定性校验收口；原样导入甲方已审核的版本化配置包时不强制 Agent 重新解释，只执行确定性契约校验。Agent 无权发布、停用或回滚知识版本，正式生效仍须人工确认。
- 2026-08-28：已确认风险识别不在 LLM 风险候选生成后追加第二次强制 Agent 审阅。每个工序工作项只在“确定性基线检索 → Agent 审阅与有界补搜 → 确定性上下文选择”中经过一次必经 Agent 任务；专用 LLM 节点生成候选后直接进入确定性校验，失败、冲突或低置信度转人工复核。当前未配置多模型、多角色，禁止让同一 Agent 对自身输出作形式化复审并充当独立制衡。
- 2026-08-28：已确认常规 `assessmentGraph` 与预警判定不设置必经内嵌 Agent 任务。指标实际值通过已发布映射从冻结资料和监测快照确定性取得，P/C、风险矩阵、四类预警触发和可靠入库全部由确定性模块完成；Agent 只在交互入口解释依据、诊断缺失输入和准备重新评估命令，不参与计算链，也不阻塞评估与预警。
- 2026-08-28：已确认处置建议生成采用必经内嵌 Agent 任务。确定性模块先从已发布措施库形成冻结候选集，Agent 仅在候选集内组合、排序并补全实施顺序、资源需求和目标指标，随后由确定性模块执行触发指标一致性、规范合规性和现场资源与工序约束可执行性三项校验；Agent 不得发明候选集外措施、批准执行或覆盖校验失败。
- 2026-08-28：已确认偏差超限后必须由 Agent 生成结构化校准建议候选。偏差记录由确定性模块先可靠入库；Agent 读取冻结的处置效果预测、实际反馈、偏差记录、所用规则/权重/阈值版本和证据，只能提出偏差原因与建议调整对象，不能直接修改数值或创建生效版本。候选通过结构与引用校验后进入人工复核，Agent 失败只暂停校准建议生成，不得丢失或回滚偏差事实。
- 2026-08-28：已确认 Agent 只能使用按任务类型配置并版本化的领域工具白名单。内嵌与交互任务的有效权限均取业务运行发起者权限、工程与资料权限、任务工具策略的交集；所有写入通过正式领域命令或候选工件接口完成，禁止 Agent 直接访问数据库、项目文件、Shell、任意网络或外部系统，MVP 不提供自由联网与通用执行能力。
- 2026-08-28：已确认每类 Agent 任务使用由系统强制执行的版本化硬预算，至少冻结最大模型调用、分类工具调用、输入上下文、输出、候选或处理对象规模、补搜轮次、墙钟时间、允许模型与并发数。Agent 可以提前结束，但不能自行扩容、切换模型或修改预算；后续调整只能发布新策略，不改变运行中或历史任务。
- 2026-08-28：已确认必经 Agent 任务失败、模型不可用或预算耗尽时不得跳过 Agent 或使用静默降级结果继续。系统只在冻结策略和剩余预算内重试；耗尽后保存确定性基线、Agent 增量、工具结果和失败原因，将对应工作项暂停或标为终止失败。恢复只能继续原任务，或由有权限用户使用新策略或新输入显式创建新任务；已可靠入库的上游事实不回滚。交互 Agent 不可用时直接显示阻断，不生成降级回答冒充正式结果。
- 2026-08-28：已确认独立确定性校验器拒绝 Agent 输出后，可将字段缺失、引用失效、候选越界、格式错误等结构化可修复问题反馈给同一 Agent，在原预算内生成新的不可变候选版本。权限不足、来源无资格、版本不兼容、规则冲突和处置建议业务约束失败不得通过循环尝试绕过；每轮保留候选及差异，次数耗尽后按阶段进入人工复核、暂停或终止失败。该机制属于外部确定性校验后的受限修正，不是同模型自审自批。
- 2026-08-28：已确认每次 Agent 任务同时保存可重建输入与原始模型输出。PostgreSQL 记录任务身份、冻结输入引用、模型/提示模板/工具策略/预算版本、步骤、工具参数与结果引用、校验结果、候选版本、终态和实际业务对象；实际渲染输入、原始响应及必要工具观察快照作为受权限保护的不可变内容工件保存，并由 PostgreSQL 记录哈希与引用。既有证据正文优先引用资料段或业务事实，不重复复制；不保存模型内部思维链。
- 2026-08-28：已确认 Agent 相对冻结基线的增量使用按任务类型定义的领域操作表达，不使用通用 JSON Patch 或只保存前后大对象。清洗、检索、知识编制、处置建议和校准建议分别拥有受限操作集合；确定性模块逐项记录接受、拒绝及原因，并引用最终候选或正式产物，禁止 Agent 通过通用补丁修改契约外字段。
- 2026-08-28：已确认不为所有 Agent 任务增加统一人工生效门槛。清洗结果通过硬约束后自动成为业务可用输入，检索增量经确定性选择器后自动影响本次推理上下文，处置建议候选通过三项约束后自动形成正式建议；知识候选不得自动发布，校准建议不得自动改变规则、权重或阈值，处置采纳与执行仍由人决定，交互 Agent 提交任何写命令前仍须用户确认。
- 2026-08-28：已确认 Agent 任务复用现有过程任务状态并仅增加“等待用户确认”：待运行、运行中、等待用户确认、可重试失败、终止失败、已完成、已取消；阶段、原因、剩余预算和恢复条件使用结构化字段表达。等待确认只用于交互任务；需要人工复核的候选生成后，Agent 任务结束并另建复核任务，由父业务运行等待复核。会话可长期存在，但每个 Agent 任务必须有界并进入终态。
- 2026-08-28：已确认权限治理按项目实际规模保持简单。Agent 任务创建时按当前用户、工程和资料权限校验一次，并将本次输入限制在任务上下文与工具白名单内；任务启动后按既定上下文运行到终态，不建设动态撤权、紧急取消、权限快照令牌或逐工具调用复验。Agent 提交正式领域命令时仅沿用该命令既有的普通权限校验，不新增 Agent 专用权限机制。
- 2026-08-28：已确认 MVP 必须真实跑通五类必经内嵌 Agent 任务：数据清洗与部分可用判断、非结构化知识编制、识别检索审阅与有界补搜、处置建议组合排序、偏差超限后的校准建议候选；同时保留交互 Agent 的查询、解释与命令准备入口。底层共用一个 Agent 任务运行模块，各业务阶段只提供任务策略、领域工具、资源预算、领域增量和确定性校验接口，不分别建设五套 Agent 框架。

## Answer

已形成 [Agent-native 横切运行与治理契约](../prototypes/agent-native-operating-contract.md)，并完成以下收口：

- 以一个深层 Agent 任务模块统一五类必经内嵌任务与交互式 Agent；各业务模块只提供任务策略、领域工具、硬预算、任务类型化增量和独立确定性校验。
- 数据清洗、非结构化知识编制、识别检索审阅、处置建议和偏差超限后的校准建议必须经过 Agent；甲方已审核配置原样导入、RI-S57 风险候选生成、普通 P/C/矩阵/预警及版本发布不经过必经 Agent。
- RI-S57 后不增加同一模型扮演的 Agent 自我审阅；检索 Agent 审阅的是确定性基线，风险候选随后直接进入确定性校验与人工复核路由。
- 工具按任务类型使用版本化白名单，MVP 不提供通用数据库、文件系统、Shell、自由网络或外部系统能力；任务创建时校验一次权限，正式领域命令仍走原权限校验。
- 每类任务冻结模型/工具调用、上下文、输出、候选、修复轮次、墙钟时间、模型和并发硬预算；必经任务失败不得跳过、换模型、扩预算或以基线冒充正式结果。
- Agent 只能提交任务类型化领域增量；确定性模块逐项记录接受、拒绝与原因。知识发布、校准生效、处置采纳与执行、人工复核及交互式写命令继续由人决定。
- 保存可重建输入、原始模型输出、工具行动、预算消耗、候选版本、增量、校验与正式结果引用，不保存模型内部思维链。

该契约已同步到项目约束、宏观架构、领域生命周期、MVP 定义、功能规格、接入规格、识别工作流、评估预警处置引擎、产品信息架构和完整界面规格。后续 OpenSpec 路线应先定义统一 Agent 任务能力，再由各业务 change 引用；本票没有拆出新的 Wayfinder 决策前置项。
