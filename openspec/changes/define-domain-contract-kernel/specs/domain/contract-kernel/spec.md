## Purpose

为 RiskFlow 全部生产模块提供唯一、可运行时校验且可派生静态类型的领域契约内核，保证识别、评估、预警与处置沿同一词汇、版本、证据和审计语义交换数据。

## ADDED Requirements

### Requirement: 固定领域词汇只有一个导出来源

系统 MUST 从共享契约包导出 RI/RA 固定领域枚举的只读值、运行时 Schema 和由该 Schema 派生的 TypeScript 类型。固定枚举 MUST 完整包含项目专利追踪中规定的中文值，调用方不得通过另一组 DTO 或散落字符串重定义这些值。（RI-S31～S34、RI-S41、RI-S43；RA-S1、RA-S2、RA-S6）

固定枚举包括：五项工序节点、八项装备部件、三项构件、八项状态参数描述、六项监测指标、六项风险机理类型、四项工序依赖关系类型、三项适用性元数据维度、两项风险评估指标类型、五项地下工程细分量化指标组、四项预警触发类型。

#### Scenario: 解析全部专利固定值
- **WHEN** 调用方逐项提交上述固定中文枚举值
- **THEN** 对应共享 Schema 全部接受
- **AND** 导出的只读值与 Schema 接受集合一致

#### Scenario: 拒绝契约外枚举值
- **WHEN** 调用方提交未列入固定枚举的近义词、英文别名或空值
- **THEN** 对应共享 Schema 拒绝该值
- **AND** 不自动改写为某个已知值

### Requirement: 通用契约保留身份、版本、双时间、证据与审计语义

共享契约 MUST 提供非空实体标识与项目标识、不可变版本引用、业务有效时间区间、系统记录时间、资料段证据定位信息和审计上下文。业务有效时间与系统记录时间 MUST 使用不同字段表达；版本引用 MUST 同时标识实体与精确版本，不能只引用可变的“当前版本”。资料段证据 MUST 通过 `sourceSegmentId` 指向 RI-S13 的资料段标识。（RI-S13、RI-S14、RI-S42、RI-S44、RI-S62、RI-S65；RA-S3～S7）

#### Scenario: 接受可重放的版本化事实
- **WHEN** 调用方提供非空实体/项目标识、精确版本标识、有效时间、记录时间、资料段标识和操作者
- **THEN** 共享契约接受该事实
- **AND** 下游能够区分事实何时有效与系统何时记录该事实

#### Scenario: 拒绝倒置的有效时间
- **WHEN** 业务有效时间同时提供起止时刻且结束时刻早于或等于开始时刻
- **THEN** 共享契约拒绝该时间区间

#### Scenario: 拒绝不可追溯的证据
- **WHEN** 证据定位缺少非空 `sourceSegmentId`
- **THEN** 共享契约拒绝该证据定位

### Requirement: 命令与错误使用稳定信封

共享契约 MUST 提供可参数化的命令信封和结构化错误信封。命令信封 MUST 携带命令标识、幂等键、项目标识、操作者、发起时间及类型化载荷；错误信封 MUST 携带稳定错误码、是否可重试和可选的结构化详情。错误的人类可读说明可以变化，不得作为调用方分支判断的唯一依据。

#### Scenario: 重放同一命令身份
- **WHEN** 调用方使用相同命令标识和幂等键重试同一类型化载荷
- **THEN** 命令信封保持相同的调用身份信息
- **AND** 下游无需从载荷内容推断幂等键

#### Scenario: 拒绝无调用身份的命令
- **WHEN** 命令缺少命令标识、幂等键、项目标识、操作者或发起时间中的任一项
- **THEN** 命令信封校验失败

#### Scenario: 调用方按错误码处理失败
- **WHEN** 下游收到结构化错误信封
- **THEN** 它能够从错误码和可重试标志决定终止、重试或转人工复核
- **AND** 不需要匹配完整错误说明文本

### Requirement: 识别输出与标准化风险记录保持唯一字段契约

模型输出结果 MUST 恰好包含 `riskSource`、`riskFactor`、`riskEvent`、`riskElementRelations`、`evidenceLocator`、`modelConfidence` 六项内容字段。标准化风险记录 MUST 在此基础上增加 `processNodeId`，并且恰好保留 §2.6 规定的七项内容字段；身份、版本、来源、机理条目、综合置信度和审计信息 MUST 位于独立记录信封中，不得扩张记录内容。（RI-S57、RI-S58、RI-S61～S65）

模型置信度和综合置信度 MUST 位于闭区间 `[0, 1]`。风险要素关系 MUST 明确给出来源要素、关系和目标要素。所有对象 MUST 拒绝未声明字段，使契约外模型字段能够进入后续人工复核路线，而不是静默丢弃。

#### Scenario: 接受符合 RI-S57 的模型结果
- **WHEN** 模型结果提供六项内容字段、可追溯证据、至少一条风险要素关系且置信度位于 `[0, 1]`
- **THEN** 模型输出结果 Schema 接受该对象

#### Scenario: 接受恰好七项内容的标准化风险记录
- **WHEN** 候选记录提供非空工序节点标识、六项模型结果内容且没有其它字段
- **THEN** 标准化风险记录 Schema 接受该对象

#### Scenario: 拒绝缺少入库必填项的记录
- **WHEN** 标准化风险记录缺少工序节点标识、风险事件、证据定位信息或模型置信度中的任一项
- **THEN** Schema 拒绝该记录
- **AND** 调用方可将失败结果路由至人工复核而不产生部分记录

#### Scenario: 拒绝扩张七字段内容
- **WHEN** 标准化风险记录在七项内容字段之外夹带版本、审计、综合置信度或任意模型自创字段
- **THEN** 标准化风险记录 Schema 拒绝该对象
- **AND** 对应信息只有放入独立记录信封才可通过校验

### Requirement: 适用性元数据与结构化评分规则可被确定性消费

适用性元数据 MUST 同时包含 `constructionMethod`、`stratumCondition`、`engineeringStage` 三个非空维度。结构化评分规则 MUST 包含 `ruleId`、`applicabilityConditions`、`indicatorItem`、`scoringThresholds`、`gradeIntervals`、`exceptionClauses`、`evidenceLocator`、`ruleVersion` 和 `reviewStatus`；评分阈值、分级区间及例外条款 MUST 是结构化集合，规则必须引用精确版本和条文证据。（RA-S1～S4）

#### Scenario: 接受完整适用性元数据
- **WHEN** 调用方同时提供施工工法数据、地层条件数据与工程阶段数据
- **THEN** 适用性元数据 Schema 接受该对象

#### Scenario: 拒绝缺少最小维度的元数据
- **WHEN** 适用性元数据缺少三个必含维度中的任一项
- **THEN** Schema 拒绝该对象
- **AND** 其它扩展元数据不能替代缺失维度

#### Scenario: 接受可追溯的结构化评分规则
- **WHEN** 评分规则含完整适用条件、至少一个阈值和分级区间、条文证据、精确版本与审核状态
- **THEN** 结构化评分规则 Schema 接受该对象

#### Scenario: 拒绝不可发布的规则形状
- **WHEN** 规则缺少适用性条件、指标项、评分结构、条文证据、精确版本或审核状态
- **THEN** Schema 拒绝该规则

### Requirement: 风险评估记录只引用一个风险事件来源

风险评估记录 MUST 通过可辨识联合类型表达风险输入：识别结果使用 `riskRecordId`，甲方外部风险事件使用 `externalRiskEventId`，二者必须二选一且仅一个。记录 MUST 保存适用性元数据快照、P/C 分值、风险等级、指标评分明细、触发指标、证据、适用规则集版本、权重版本、风险矩阵版本和审计信息；所有版本引用均为精确版本。（RA-S1、RA-S5）

#### Scenario: 接受识别结果作为评估输入
- **WHEN** 风险评估记录只提供 `riskRecordId` 并包含完整快照、计算结果、证据和版本引用
- **THEN** 风险评估记录 Schema 接受该对象

#### Scenario: 接受外部风险事件作为评估输入
- **WHEN** 风险评估记录只提供 `externalRiskEventId` 并包含完整快照、计算结果、证据和版本引用
- **THEN** 风险评估记录 Schema 接受该对象

#### Scenario: 拒绝含糊的风险输入
- **WHEN** 风险评估记录同时提供两个风险事件标识或两个都未提供
- **THEN** Schema 拒绝该对象
- **AND** 不通过空字符串约定选择输入来源

#### Scenario: 历史评估保持可重放
- **WHEN** 适用规则集、权重或风险矩阵后来发布新版本
- **THEN** 已校验的历史风险评估记录仍保留原精确版本引用和适用性元数据快照
- **AND** 共享契约不把引用改写为新版本

### Requirement: 预警、处置和偏差记录贯通同一证据链

预警信息 MUST 引用风险评估记录，并包含自身标识、预警等级、固定触发类型、触发指标、证据、建议处置方向、通知状态与审计信息。处置建议 MUST 引用预警信息，并包含自身标识、措施项、实施顺序、资源需求、目标指标、三项确定性校验结果、审核状态、版本和审计信息。偏差记录与校准建议 MUST 引用处置建议，并包含自身标识、预测/实际风险变化、偏差值、偏差阈值版本、证据、校准建议、审核状态、版本和审计信息。（RA-S6、RA-S7）

#### Scenario: 接受完整闭环记录
- **WHEN** 预警引用评估、处置引用预警、偏差记录引用处置，且每一环都提供其必含字段、证据、版本与审计信息
- **THEN** 三类记录 Schema 分别接受对应对象
- **AND** 调用方可沿标识重建评估到偏差/校准建议的追溯链

#### Scenario: 拒绝未知预警触发类型
- **WHEN** 预警信息使用四项固定触发类型之外的值
- **THEN** 预警信息 Schema 拒绝该对象

#### Scenario: 拒绝缺少处置约束结果的建议
- **WHEN** 处置建议缺少触发指标一致性、规范合规性或现场资源与工序约束可执行性校验结果中的任一项
- **THEN** 处置建议 Schema 拒绝该对象
- **AND** 不把未经三项校验的候选表示为正式建议

#### Scenario: 校准建议不伪装为已发布版本
- **WHEN** 偏差记录携带校准建议
- **THEN** 契约将它保持为带审核状态的建议内容
- **AND** 不提供直接覆盖规则、权重、阈值或分级区间当前生效版本的字段

### Requirement: 公共 Schema 与静态类型保持单一事实源

每个公共 DTO MUST 由对应 Zod Schema 使用类型推导产生 TypeScript 类型，且必须通过 `@riskflow/contracts` 的公开入口消费。共享契约包 MUST 不依赖 `core`、`adapters` 或任一应用，也不得导出评分、持久化、通知、Agent 或工作流实现。

#### Scenario: 调用方从公开入口复用契约
- **WHEN** 生产应用或其它共享包导入领域词汇、通用契约或记录契约
- **THEN** TypeScript 与 Node.js 均能从声明的公开入口解析同一实现
- **AND** 调用方无需复制字段定义

#### Scenario: 实现层不能反向进入契约包
- **WHEN** 依赖边界检查分析共享契约包
- **THEN** 契约包不存在对 `core`、`adapters` 或应用的反向依赖
