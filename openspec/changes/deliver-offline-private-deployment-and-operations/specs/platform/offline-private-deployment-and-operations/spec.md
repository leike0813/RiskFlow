## Purpose

为 RiskFlow 已归档能力提供可在甲方内网安装与运行的私有部署和运维边界，把软件、模型、配置、数据库、内容工件及恢复证据绑定到精确版本，使三 VM 离线交付、停止、同机逻辑副本、恢复和后续验收均能独立复核，明确单物理故障域的责任边界。

## ADDED Requirements

### Requirement: 跨虚拟机工件访问必须保持 C04 原契约

系统 MUST 在数据 VM 本地运行 C04 内容存储，通过仅限内网、双向 TLS 且有界的 put/open 流接口供应用 VM 使用。请求 MUST 使用原 C04 DTO 并复验当前工程、资料、空间和能力授权；传输身份不能替代业务授权。应用 VM 的 referenceGuard MUST 与原业务 PostgreSQL 事务共享上下文；维护接口 MUST 在数据 VM 本地运行。中断、截断、超额或读取 receipt 未完成 MUST 失败，不能将未核验字节登记为正式结果。

#### Scenario: 真实跨 VM 写入与读取

- **WHEN** 应用 VM 按原身份提交获授权工件并完整读取
- **THEN** 数据 VM 完成原耐久登记、审计与字节校验，应用事务按同一登记校验引用，不暴露宿主路径或全量缓冲正文

#### Scenario: 断流或传输身份越权

- **WHEN** put/open 截断、超限、超时，或服务身份合法但工程授权失效
- **THEN** 返回稳定失败且 verified 不成功；同身份重试遵守原幂等语义，不绕过权限或替换工件身份

### Requirement: 生产策略与窄读必须解析精确真实来源

系统 MUST 为全部必需组合根提供真实策略、授权和窄读来源；运行策略按不可变、已批准 catalog 的精确引用解析，业务定义按原正式依据集合与所属模块读取。C20 构建质量 MUST 经真实固定数据集和原验收门禁计算，不使用永真门禁；C24 路线和 C30 空间配对 MUST 从正式登记与工件证明。构造引用环只可在监听及后台消费前一次绑定真实委派，缺项或漂移 MUST 阻止就绪。HTTP 受理 MUST 用真实会话分别签发所需下游分支并耐久关联原上下文；后台跨能力调用 MUST 读取该目标分支已签发上下文再收窄和复验，不扩展原 parent 的能力或持久化会话令牌。

#### Scenario: 完整来源装配并保留质量查询授权

- **WHEN** 正式 catalog、数据集、依据集合和全部 provider 已就绪，API 同时接入普通 projection 与质量窄读
- **THEN** 所有声明能力使用原真实来源，质量查询仍执行两阶段资料授权，其它投影沿原端口执行

#### Scenario: 策略漂移或质量门禁失败

- **WHEN** 精确引用缺失、来源不匹配、环未绑定或检索验收失败
- **THEN** 服务或投影不进入就绪，不能从测试常量、其它版本、其它空间或默认策略补足

### Requirement: 部署运维状态与审计必须耐久且独立授权

系统 MUST 将部署作用域操作状态及其追加审计存于 PostgreSQL，阶段与审计同事务转换，精确输入、幂等键、修订与租约共同约束重试。宿主权限与 C06 全工程资料授权 MUST 分别核验；系统管理员不得因此获得正文权限。运行 API/Worker 不得持运维表写权或宿主控制凭据。宿主阶段记录只能用于诊断和恢复接续，数据库审计失败 MUST 阻止完成结论。

#### Scenario: 阶段重放与权限隔离

- **WHEN** 同操作身份重试或另一个主体试图同时维护实例
- **THEN** 原结果按修订复用或互斥拒绝，异载荷冲突；业务主体不能改写运维状态或审计

#### Scenario: 审计失败与授权缺项

- **WHEN** 阶段审计失败、工程枚举遗漏或资料授权不完整
- **THEN** 动作报告失败或待补审计，不能激活/完成，也不伪造工程引用或跳过无权工程

### Requirement: 部署必须遵循三台虚拟机的集中式边界

系统 MUST 在一台物理服务器内按推理、应用、数据三台 VM 部署：推理 VM 使用 GPU 直通承载 llama.cpp 与模型，应用 VM 承载 Web、API、Worker、HTTPS 入口与必要解析，数据 VM 承载 PostgreSQL、Qdrant 和不可变工件。普通客户端 MUST 只访问应用 HTTPS，内部服务与管理端口按职责隔离。部署不得以 Electron 客户端替代服务器能力，也不以 Docker Compose 为原产品决议前提。同机快照与副本 MUST 标明仅用于逻辑回退；MVP 不承诺独立备份、高可用、持续备份、周期演练、生产级 RPO/RTO 或长期代运维。

#### Scenario: 客户端只访问应用入口

- **WHEN** 桌面或浏览器客户端在批准内网连接完整部署
- **THEN** Web、API 与 SSE 经同一 HTTPS 入口工作，客户端不能直接访问数据库、索引、推理与管理端口

#### Scenario: 同机副本与宿主故障边界

- **WHEN** 部署报告说明 VM 隔离、快照与同机恢复能力
- **THEN** 报告区分逻辑恢复与物理故障，不把同机副本、三 VM 或一次恢复测试声明为独立备份、灾备或可用性承诺

### Requirement: 离线发布包必须完整且版本可核验

系统 MUST 提供不可变发布清单，固定代码版本、生产构建、工具链、桌面安装包、全部必要容器和系统依赖、模型及 OCR 制品、部署配置、许可证、SBOM 与操作手册的精确身份和完整性依据。离线安装 MUST 仅消费已批准并导入的制品，安装和运行不得隐式拉取镜像、包、字体、脚本或模型；制品缺失、身份不符、许可资料缺项或架构不匹配时 MUST 在启动业务服务前失败。测试替身、固定测试秘密、合成结果和开发服务器不得进入生产运行包。（横切 RI-S1～RI-S6；RA-S1～RA-S7）

#### Scenario: 断网环境完成安装

- **WHEN** 操作者使用完整发布介质在符合冻结宿主条件且不能访问公网的环境安装
- **THEN** 系统核验制品并从本地启动批准服务，留下发布身份与实际安装证据，不发生隐式下载

#### Scenario: 制品不完整或不匹配

- **WHEN** 必需镜像、模型、包、许可证缺失，或实际内容、版本、架构与清单不符
- **THEN** 安装返回稳定失败类别和安全定位，不启动部分业务实例、不换用其它版本

#### Scenario: 已验收界面尚未进入生产构建

- **WHEN** 发布范围声明包含某业务页面，但生产构建没有其真实路由及服务接缝
- **THEN** 对应发布验收失败，不能用参考原型、独立验收 harness 或静态截图证明页面已部署

### Requirement: 部署配置与秘密必须分离并保持原契约

系统 MUST 从受控部署输入冻结公开来源版本、模型能力和尺寸、OCR 管线与模型集合、检索兼容版本、工件限额、Agent/运行策略、网络及资源预算；每个业务模块只接受其既有严格契约，不得通过环境默认值补造规则或修改版本。密码、会话签名材料、数据库连接秘密与 TLS 私钥 MUST 由受限秘密文件提供，不进入发布清单、业务 DTO、日志、指标、命令参数或普通备份描述。配置缺项、精确引用漂移、过宽权限和资源配置矛盾 MUST 在副作用前失败。

#### Scenario: 同一配置可重放

- **WHEN** 同一发布和配置版本在兼容宿主重新装配
- **THEN** 各模块收到相同精确版本和有效预算，业务输入不能改写模型端点、权重路径或策略

#### Scenario: 配置非法或秘密不可用

- **WHEN** 配置缺少必需引用、尺寸或预算不一致，或秘密文件缺失、可被无关主体读取
- **THEN** 部署失败且不建立业务监听或后台执行，不输出秘密及宿主路径

#### Scenario: 秘密轮换保持历史可追溯

- **WHEN** 操作者按批准过程替换签名或数据库秘密并重启实例
- **THEN** 旧会话和连接按所属模块安全语义失效，历史主体、业务版本、审计及工件引用保持，不把旧秘密写进新发布包

### Requirement: 初始化必须幂等且运行主体使用最小权限

系统 MUST 将宿主初始化、数据库权限组、部署 LOGIN 主体、领域迁移、检查点准备和首次管理员引导作为显式部署动作。运行进程 MUST 使用按职责授予的非超级用户主体，不得持有迁移或宿主控制权限；首次管理员只可在账号库为空时按 C06 规则创建。重复初始化 MUST 保留已有事实和账号，迁移失败 MUST 阻止业务启动，不能重置数据库、凭据或历史审计。

#### Scenario: 空实例初始化成功

- **WHEN** 操作者在空数据库提交批准发布和秘密输入
- **THEN** 初始化建立所需权限与迁移、检查点和首次管理员，业务进程随后以最小权限启动

#### Scenario: 初始化重放或部分失败

- **WHEN** 同一初始化被重放，或某迁移/管理员引导步骤失败
- **THEN** 已成立事实保持，未完成项可按原身份重试；失败实例不进入就绪态，也不覆盖已有管理员

#### Scenario: 运行主体试图越权

- **WHEN** API 或 Worker 的数据库主体尝试 DDL、改写审计或获取部署控制权限
- **THEN** 请求被拒绝，运行主体不能借初始化连接或角色成员关系扩大权限

### Requirement: 服务生命周期必须使用真实公共接缝

系统 MUST 提供显式 API 与 Worker 进程入口，装配所声明业务能力所需的真实数据库、工件、授权、模型、OCR、检索、投影和工作流接口；必需依赖缺失时不得将实例声明为完整可用。领域事件和 Agent 任务 MUST 使用既有耐久 Outbox、幂等消费者、租约和硬预算执行，不能以进程内队列或新流程状态机替代。关闭和维护 MUST 停止接收新工作，有界收口在途任务、订阅和连接；技术重启只能复用原版本、原预算和原幂等身份，不重复已提交业务效果，也不自动采纳人工决定。

#### Scenario: 真实实例完成请求和后台消费

- **WHEN** 冻结实例收到合法业务请求并产生既有领域事件或 Agent 任务
- **THEN** 请求通过原公共端口执行，后台消费者使用耐久身份推进，正式结果、审计、事件与检查点可解析

#### Scenario: 缺少必需接线

- **WHEN** 发布声明的能力缺少真实端口、策略、事件消费者或模型部署
- **THEN** 启动/就绪检查明确失败，不能以空实现、测试替身、默认策略或部分端口冒充完整实例

#### Scenario: 进程重启与事件重投

- **WHEN** 进程在事实提交后、响应或事件确认前终止并按同一发布重启
- **THEN** 同身份重试复用已成立回执或结果，租约按原契约恢复，不重复审计、风险、评估、预警或人工决定

#### Scenario: 有界停止未能完成

- **WHEN** 关闭期限到达且仍有在途写入或未知执行状态
- **THEN** 运维动作记录未收口状态，不声明停写或安全备份，不扩大预算或抹去原任务状态

### Requirement: 内网访问与观测必须有界且最小披露

系统 MUST 以受控 HTTPS 同源边界提供 Web、API 和 SSE，保持 C09 安全 Cookie、来源验证、耐久游标和背压语义；数据库、索引、模型、OCR 及宿主控制接口不得直接作为普通客户端访问入口。存活/就绪观测 MUST 区分进程存在、依赖可用、业务完整接线和维护状态；C35 健康/模型查询仍由当前系统管理员授权且保持既有条目和时间边界。日志、资源与容量指标 MUST 只包含稳定状态、原因码、引用和计数，设置有限保留，不泄露正文、秘密、URL、宿主路径、模型原始响应或思维链。

#### Scenario: 安全同源访问和重连

- **WHEN** 用户通过内网 HTTPS 登录、查询并断线重连运行订阅
- **THEN** Cookie 属性与来源校验保持，静态深链刷新和 SSE 游标恢复可用，客户端只能访问获准公开接口

#### Scenario: 依赖失败或正在维护

- **WHEN** 必需依赖不可用、业务接线不完整或实例正在停止写入
- **THEN** 就绪检查失败，管理查询如实报告安全状态，不将存活或未配置解释为全部正常

#### Scenario: 慢探针或无权查询

- **WHEN** 管理探针超时、返回非法结果，或普通用户请求系统运维事实
- **THEN** 超时按既有安全原因码收口，拒权与未提供能力保持安全失败，不扩大读取范围或披露内部存在性

### Requirement: 模型与 OCR 必须离线预置并隔离资源

系统 MUST 以不可变部署身份绑定 llama.cpp 构建、聊天/Embedding 模型、启动参数、上下文窗口和维度，以及 OCR 构建、管线、全部模型与资源分配。OCR 与 llama.cpp MUST 使用独立实例、端点、并发和时间预算；CPU/内存及可用 GPU 资源分配须能在宿主核验。不能强制隔离的共享资源 MUST 在目标环境证据中暴露且阻止承诺未验证的隔离效果。服务启动不得下载模型，故障不得自动换模型、扩大预算或跳过必经 Agent。

#### Scenario: 预置服务身份与真实协议匹配

- **WHEN** 操作者以完整离线模型制品和冻结资源配置启动服务
- **THEN** 三项 llama.cpp 能力、OCR 三媒体及 Embedding 维度使用真实服务通过各自契约核验，并保存精确身份和证据

#### Scenario: OCR 饱和或崩溃

- **WHEN** OCR 队列饱和、超时、取消或服务崩溃，同时执行 llama.cpp 请求
- **THEN** 故障只沿 OCR 的任务与预算收口；llama.cpp 的版本、预算、进程和请求控制保持独立，实际资源影响进入实测报告

#### Scenario: 模型制品或资源证明缺失

- **WHEN** 权重、构建、许可证、窗口/维度或物理资源配置无法与声明身份对应
- **THEN** 部署/验收失败，不能用配置标签、协议替身或另一服务证明原部署可用

### Requirement: 同机逻辑副本必须绑定同一停写边界及全部耐久事实

系统 MUST 以固定备份身份、批准配置和宿主维护权限进入三 VM 协调的维护窗口，确认 API 写入口、Worker、模型/OCR 派生结果提交与工件维护均已停止；停写不成立时禁止继续。同机逻辑副本（下文备份）MUST 绑定同一数据库/文件快照业务引用、每个工程的完整授权哈希清单、数据库全部业务/身份/审计/Outbox/checkpoint 事实、耐久工件以及对应部署配置。备份包和秘密保管必须分离、受限；无完整授权工程不得被静默跳过。逻辑恢复点可用结论 MUST 以副本完整性、隔离恢复核验和 PostgreSQL 只追加运维审计为前提，宿主阶段记录仅用于执行恢复，任何阶段失败只能形成失败或待核验状态。相同身份和输入重试复用原批次，异载荷不得替换已成立备份。

#### Scenario: 完整停写备份成立

- **WHEN** 全部写入者和维护者已收口，操作者获得全部目标工程的恢复级授权并完成同边界数据库与工件副本
- **THEN** 备份记录固定快照业务引用、精确清单、版本、时间和计数；隔离核验通过后才发布可用恢复点

#### Scenario: 停写失败或工程授权不完整

- **WHEN** 仍有未知写入者/在途写入，或任一目标工程、资料和工件未获完整授权
- **THEN** 整批备份失败，不输出部分成功恢复点、不默认授予系统管理员工程正文权限

#### Scenario: 复制、空间或耐久记录失败

- **WHEN** 数据库导出、工件复制、空间检查或最终记录耐久提交失败
- **THEN** 保留安全失败记录与未完成批次，原实例和已有恢复点保持，未完成包不进入可用目录

#### Scenario: 同键重试与异载荷冲突

- **WHEN** 操作者以同一备份身份重试相同输入，或改变目标发布、工程集合与配置
- **THEN** 前者复用原阶段和已成立副本，后者在新副作用前返回不可重试冲突

### Requirement: 恢复必须先隔离核验再人工切换

系统 MUST 把恢复写入新的隔离数据库和工件根，使用备份绑定的兼容发布、配置及快照引用；不得在线覆盖原实例。恢复 MUST 核对数据库引用与哈希清单及文件副本，完整消费逐项结果和终态，并验证权限、审计、Outbox、检查点及检索代际；缺失、损坏、清单冲突、审计失败、版本不兼容或正文授权不完整均阻止通过。检索索引仅能从正式事实与原配置重建并通过就绪门，不能按物理文件补造领域事实。只有全部必要检查通过且操作者确认精确目标后才可切换，未确认时保持原实例；切换失败或重试不得销毁原实例或解除人工等待。

#### Scenario: 隔离恢复与原实例并存

- **WHEN** 完整恢复点被还原到新的隔离资源
- **THEN** 系统按精确快照核验全部工程、耐久引用和确定性重放，形成检查结果；确认前不对外服务或消费未决任务

#### Scenario: 缺失、损坏或快照不匹配

- **WHEN** 任一已提交引用缺少字节、摘要不符、数据库比文件副本更新，或恢复点/版本身份不匹配
- **THEN** 恢复失败并保存诊断引用，不静默补文件、替换模型、跳过工程或补造事实

#### Scenario: 索引重建与正式空结果

- **WHEN** 数据库与工件完整但 Qdrant/BM25 投影需重建，或正式运行结果为空
- **THEN** 索引从原发布、模型和策略重建并通过原就绪门；正式空结果按所属只读契约证明，不以记录缺席或空索引推断成功

#### Scenario: 人工切换、拒绝与重复操作

- **WHEN** 操作者确认核验通过的精确目标，拒绝确认，或重放同一切换操作
- **THEN** 确认后的切换保留原实例和证据；拒绝不切换；同身份重放复用原结果，目标变化须重新核验和确认

### Requirement: 发布回退与目标环境验收必须有真实证据

系统 MUST 提供兼容性检查、发布切换和回退手册，区分软件回退与数据恢复；数据库格式/迁移不兼容时不能只换旧镜像继续服务。目标硬件、资源预算、数据规模、并发、验收阈值 MUST 作为批准输入冻结，最低基线为 RTX 4090（24GB）与 128GB 主机内存；报告记录真实测量、命令、代码/配置/模型版本与失败证据。必需环境缺失、真实 smoke 未启用或关键场景被跳过时 MUST 明确失败或阻塞；合成样本标注待甲方复核，不宣称真实工程质量。完整 C37 运维验收必须包含断网安装、真实服务、重启幂等、权限拒绝、恢复破坏检测、索引重建、资源隔离、容量及性能基准。

工程检查与实机交付取证 MUST 分别记录。目标环境、模型/OCR、证书或批准输入缺失时，只阻塞对应交付验收，独立实现及工程审查继续；适用的真实本地接缝和正式运行输入校验仍须验证。全部交付证据齐全前 C37 总体结论 MUST 为 FAIL 或 BLOCKED，不得宣告交付通过或归档。

#### Scenario: 兼容版本回退
