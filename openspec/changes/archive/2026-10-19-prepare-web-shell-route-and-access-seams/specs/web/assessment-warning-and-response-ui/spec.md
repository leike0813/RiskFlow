## MODIFIED Requirements

### Requirement: C34 页面必须复用 v2 设计并只展示真实事实

系统 MUST 在 `apps/web` 生产应用保留 P-OV-01、P-RA-01～07、P-WR-01～04、P-RS-01～05 对应真实业务能力，以 `web/design-system` 为视觉事实源，并引用 `platform/web-shell-interaction-primitives` 的导航、区域组合、七态和分阶段切换契约，不以原型布局或固定页面数量限制新组合。当前工程公开 HTTP 是唯一业务取数入口；原型 fixture、角色镜像、注入状态与审阅覆盖层不得成为输入。工程或路由变化 MUST 清除旧结果、取消读取并忽略迟到响应；无工程、加载、空、异常、权限及不可用均有清晰可访问呈现。CH-6／CH-7 在新承载和历史精确深链验收前 MUST 保留现有评估发起、重评估、矩阵、处置详情及登记操作，不提前启用无目标的重定向。（RA-S1～RA-S7）

#### Scenario: 真实数据与页面可达
- **WHEN** 用户在获准工程访问原有合法业务页面
- **THEN** 页面显示服务端事实或明确引导/空/不可用态，详情支持领域标识和精确版本深链
- **AND** 不出现静态样例对象、假成功或审阅参数控制的业务权限

#### Scenario: 工程切换与失败
- **WHEN** 旧工程读取尚未结束时切换工程，或者新查询失败/被拒绝
- **THEN** 旧结果不能覆盖新工程，页面显示对应安全状态与可用重试
- **AND** 不泄露未获授权对象的存在性或正文

#### Scenario: UI-S02 原矩阵与处置历史继续可达
- **WHEN** CH-2 公共接缝上线而评估／处置的新承载未完成
- **THEN** 冻结矩阵只读页、原建议／执行／预测／反馈／校准精确地址仍按各自版本读取，合法独立执行不被强制挂到任务
