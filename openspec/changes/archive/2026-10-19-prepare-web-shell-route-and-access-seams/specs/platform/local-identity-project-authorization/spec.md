## ADDED Requirements

### Requirement: AC-R1 聚合入口授权必须独立于来源对象

系统 MUST 提供独立 `review-todo.read` 入口能力及闭合分支映射，沿新版本预设角色策略授予四个工程角色；仅系统管理员不新增该能力。入口授权不得隐式授予复核、预警、建议或 Agent 的读取／写入，不要求全部来源权交集，也不得为 reviewer 增授 Agent 能力。现有已交付读面的角色授予 MUST 按实际缺口修正：已有资料目录读取的 reviewer 与 business-viewer 可在原工程、空间、来源权限内读取原件，不扩大来源可见集合；不把原型全 denied 当作生产缺口。CH-2 不提供未实现聚合查询的成功响应或空结果；四来源聚合接口归 CH-9。（RI-S14；RA-S1～RA-S7）

#### Scenario: AC-S01 角色授予不扩大领域权限
- **WHEN** 复核人或现场处置人员取得待办入口权
- **THEN** 除明确补齐的原件读取分支外，原领域能力集合保持，复核人仍无 Agent 读取／启动权，现场处置人仍无经理的采纳／确认／配置写权；查看者仍无业务写权

#### Scenario: AC-S02 单工程角色与来源隔离
- **WHEN** 同账号在工程 A 有待办入口权而在工程 B 无该权，或有入口权但无某来源对象权
- **THEN** 两工程分别计算，入口权不使另一工程或无权来源可读、可枚举或可提交；多角色仍取既有能力并集

#### Scenario: AC-S03 未交付聚合不伪装可用
- **WHEN** CH-2 已登记入口能力但 CH-9 查询尚未交付
- **THEN** HTTP 不发布伪聚合操作，旧复核入口和真实命令保持；后续聚合必须重新执行来源授权

#### Scenario: AC-S07 新策略不使历史来源失效
- **WHEN** 新角色策略生效后有权用户读取引用旧策略快照的历史结果，或执行原允许的管理动作
- **THEN** 已登记历史快照和来源引用保持可解析，当前动作按当前权限检查；不改写旧授权、审计或业务行，也不因策略版本更新把合法历史误判为不存在

#### Scenario: AC-S08 原件读面保留来源限制
- **WHEN** 复核人或业务查看者从资料目录打开已有共享或指定可见资料的原件
- **THEN** 仅原工程、空间与来源授权交集内的精确版本可读；无来源权仍拒绝原件及下载，不借新分支绕过证据脱敏

### Requirement: AC-R2 导航能力呈现必须由当前工程服务端事实提供

系统 MUST 在有效 Cookie 会话下提供独立工程入口能力呈现，只返回当前账号在指定工程的角色策略能力、工程身份与策略版本，不返回资料权限、业务正文、会话 token 或可用于授权的上下文。工程成员、暂停、账号停用、首次改密及失效会话沿原规则检查；无工程访问资格同形拒绝。能力呈现只决定界面入口，不代替所属业务动作对工程、空间、资料及对象状态的当前授权。原会话元数据形状 MUST 不变，客户端不得以角色镜像或 URL 声明能力。（RI-S14）

#### Scenario: AC-S04 当前能力可传递到生产壳层
- **WHEN** 当前有效工程成员进入或切换工程
- **THEN** 壳层消费该工程服务端能力呈现，待办和助手独立判断，不沿用旧工程能力；仅系统管理员不因此获得工程业务入口权

#### Scenario: AC-S05 撤权和迟到响应不复活旧能力
- **WHEN** 工程成员被移除、账号停用、会话失效，或工程 A 的旧能力响应晚于切到 B
- **THEN** 后续入口读取按当前事实拒绝，客户端清除旧呈现且忽略迟到结果；原业务请求仍由服务端检查当前权限

#### Scenario: AC-S06 技术故障不被解释为无权
- **WHEN** 能力呈现读取发生技术故障
- **THEN** 界面显示可重试故障，不假造空能力或系统管理员身份；原合法深链仍由其所属服务端决定权限
