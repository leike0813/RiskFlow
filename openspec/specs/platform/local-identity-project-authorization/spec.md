# platform/local-identity-project-authorization Specification

## Purpose

为 RiskFlow 提供可在甲方内网独立运行的本地身份、服务端会话和工程级授权能力，使所有业务入口在形成事实或读取资料正文前都使用同一套可版本追溯、默认拒绝且可真实验收的访问决定。

## Requirements
### Requirement: 本地账号只能由受控管理动作建立和维护

系统 MUST 使用稳定账号身份与唯一规范化登录名维护 RiskFlow 本地账号，禁止自助注册。首次部署 MUST 只允许在账号库为空时通过受控部署动作创建一个初始系统管理员；此后只有当前有效的系统管理员可以创建账号、停用账号和重置密码。账号停用和密码重置 MUST 保留历史主体与审计，不得删除或改写其既有业务记录。（横切 RI-S14、RA-S1～S7；F-PJ-03）

#### Scenario: 首次受控引导创建系统管理员
- **WHEN** 部署者在账号库为空时提交合法初始管理员身份与密码
- **THEN** 系统原子创建一个要求首次改密的本地账号和系统管理员授予
- **AND** 密码、会话 token 和部署秘密不进入结果、日志或审计正文

#### Scenario: 已存在账号时拒绝再次引导
- **WHEN** 任一账号已经存在后再次调用初始管理员引导
- **THEN** 系统返回不可重试的终止错误
- **AND** 不创建、覆盖或提升任何账号

#### Scenario: 禁止自助注册和无权账号管理
- **WHEN** 未登录调用方、普通工程成员或无系统管理员授予的账号尝试创建、停用或重置账号
- **THEN** 系统在任何账号变更前拒绝请求并记录安全事件
- **AND** 响应不泄露目标账号是否存在或拥有哪些角色

#### Scenario: 停用账号保留历史身份
- **WHEN** 系统管理员停用一个已有业务记录的账号
- **THEN** 该账号不能建立新会话且其所有现有会话立即失效
- **AND** 历史业务事实、操作者引用和审计记录保持可追溯

### Requirement: 密码保存与校验遵守冻结安全策略

系统 MUST 仅保存带独立随机盐和参数版本的强密码派生值，不得保存、记录、导出或可逆加密明文密码。MVP 密码策略 MUST 接受 Unicode、空格和粘贴，不使用字符种类组合规则或静默截断；在未启用 MFA 时长度为 15～128 个 Unicode 字符且 UTF-8 编码不超过 512 字节。密码创建、重置和变更 MUST 使用冻结算法参数，并允许后续通过新凭据修订升级参数而不改写历史审计。

#### Scenario: 合法口令形成不可逆凭据
- **WHEN** 管理员创建账号或用户变更为满足长度边界的密码
- **THEN** 系统保存随机盐、派生值、算法与参数版本
- **AND** 数据库、命令收据、审计和返回值均不包含明文密码

#### Scenario: 拒绝过短、过长或超出字节上限的密码
- **WHEN** 密码少于 15 个 Unicode 字符、超过 128 个 Unicode 字符或 UTF-8 编码超过 512 字节
- **THEN** 服务端在执行高成本派生前返回结构化校验失败
- **AND** 不截断、归一化或改写用户提交的密码

#### Scenario: 未知账号与错误密码不可枚举
- **WHEN** 调用方以不存在、已停用、已锁定的登录名或错误密码尝试登录
- **THEN** 外部只观察到同一认证失败类别
- **AND** 系统执行等价的有界密码校验路径并在安全审计中保存内部原因码

#### Scenario: 连续失败触发有界节流
- **WHEN** 同一规范化登录名在滚动 15 分钟内累计 5 次失败
- **THEN** 后续尝试在 15 分钟内被服务端拒绝且仍返回不泄露账号状态的认证失败
- **AND** 成功登录或系统管理员重置密码后失败计数清零

### Requirement: 服务端会话具有不可预测 token 与完整失效语义

系统 MUST 在认证成功后创建服务端有状态会话，客户端只持有至少 128 位不可预测性的无业务含义 token；原始 token 不得明文持久化或记录。会话 MUST 同时执行 30 分钟空闲超时和 12 小时绝对超时，并支持显式注销。账号停用、密码重置、密码变更或会话密钥版本失效 MUST 使相关会话立即不可用；超时由服务端时间判断，客户端不能延长。（F-AG-01/02）

#### Scenario: 登录创建新会话而不接受外来会话标识
- **WHEN** 活跃账号提交正确密码且不处于节流期
- **THEN** 系统生成全新服务端会话和 opaque token
- **AND** 调用方提供的任意会话标识不会被接纳、续期或复用

#### Scenario: 空闲或绝对超时拒绝访问
- **WHEN** 会话距最后一次成功使用超过 30 分钟或距创建超过 12 小时
- **THEN** 服务端将会话判定为过期并拒绝后续认证
- **AND** 后续请求活动不能重新激活该会话

#### Scenario: 注销和凭据变化立即失效
- **WHEN** 用户注销，或账号被停用、重置密码、成功变更密码
- **THEN** 对应会话在同一提交后全部失效
- **AND** 旧 token 即使尚未达到时间上限也不能取得授权上下文

#### Scenario: 首次改密会话不能访问业务
- **WHEN** 使用初始或重置密码登录要求首次改密的账号
- **THEN** 系统只允许查询当前会话、变更密码和注销
- **AND** 在成功改密并签发全新会话前拒绝全部工程、资料、Agent 和业务能力

#### Scenario: 登录网络重放不产生多个会话
- **WHEN** 调用方以相同登录尝试标识和相同认证载荷重试已成功的登录
- **THEN** 系统返回同一逻辑会话与可重新生成的同一 opaque token
- **AND** 不重复创建会话或成功登录审计；同一尝试标识的不同载荷返回幂等冲突

### Requirement: 五个预设角色以闭合能力映射生效

系统 MUST 只提供系统管理员、工程风险管理员、复核人、现场处置人员和业务查看者五个预设角色；同一账号可以在不同工程拥有不同角色，并可在同一工程叠加多个工程角色。角色到 C02 `ModuleCapabilityV1` 的映射 MUST 具有不可变策略版本。系统管理员是系统级授予，不得仅因该角色获得任何工程业务能力、空间范围或资料正文权限。（F-PJ-01～03）

#### Scenario: 叠加工程角色取得能力并集
- **WHEN** 一个活跃工程成员在同一工程同时具有复核人和业务查看者角色
- **THEN** 服务端按冻结角色策略返回两个角色允许的业务能力并集
- **AND** 空间与资料权限仍分别收窄该能力集合

#### Scenario: 同一账号在不同工程权限不同
- **WHEN** 一个账号在工程 A 是工程风险管理员、在工程 B 是业务查看者
- **THEN** 对工程 A 和工程 B 的授权决定分别使用各自成员修订
- **AND** 工程 A 的写能力不能带入工程 B

#### Scenario: 系统管理员无业务特权
- **WHEN** 只有系统管理员授予、但不是目标工程成员的账号请求风险、资料、规则、复核、Agent 或投影业务能力
- **THEN** 系统返回不可重试的授权拒绝
- **AND** 不披露目标工程或资料是否存在

#### Scenario: 业务查看者不能写入或借 Agent 越权
- **WHEN** 业务查看者直接提交写命令或要求 Agent 代其提交写命令
- **THEN** 服务端在领域命令执行前拒绝
- **AND** 不创建业务事实、Agent 工具行动、领域事件或外部意图

### Requirement: 工程成员和空间授权范围使用版本化边界

系统 MUST 把工程作为业务授权顶层边界。系统管理员开通工程时 MUST 同时创建唯一根空间范围并指定至少一名工程风险管理员；开通动作不授予系统管理员本人业务访问。工程成员修订 MUST 固定角色集合和一个或多个空间范围，空间范围只属于一个工程并形成无环父子树；父范围授予覆盖其有效后代，子范围授予不得扩大到父范围或兄弟范围。移除成员和停用空间范围保留历史引用，新请求立即使用最新有效修订。（RA-S1；F-PJ-01～03）

#### Scenario: 开通工程建立最小访问边界
- **WHEN** 系统管理员以唯一工程身份和有效初始工程风险管理员开通工程
- **THEN** 系统原子建立工程访问壳、根空间范围和初始成员修订
- **AND** 系统管理员若未另行成为成员仍不能读取或修改工程业务

#### Scenario: 子范围授权不越界
- **WHEN** 成员只获授一个子空间范围并请求父范围、兄弟范围或另一工程的对象
- **THEN** 服务端拒绝该对象访问
- **AND** 返回信息不泄露越界对象的内容或存在性

#### Scenario: 拒绝非法空间层级
- **WHEN** 空间范围的父项属于另一工程、已停用、形成环或不存在
- **THEN** 系统在写入前返回结构化终止错误
- **AND** 原工程、空间和成员修订保持不变

#### Scenario: 移除成员即时阻断新请求
- **WHEN** 工程成员被移除后使用仍未超时的旧会话或旧授权上下文请求业务能力
- **THEN** 服务端重新读取当前成员修订并拒绝请求
- **AND** 旧业务记录继续引用原成员与授权版本

### Requirement: 资料权限只有工程内共享和指定可见两级

系统 MUST 将资料版本访问范围限制为“工程内共享”和“指定可见”两个值，不引入未定义的保密等级。新登记资料的默认值 MUST 是“指定可见”，且初始指定账号集合非空并包含登记人。资料段、OCR、JSON-LD、解析/清洗工件和由多个资料形成的派生工件 MUST 继承来源资料版本的授权，不得自行扩大；多来源派生工件取来源权限交集。资料正文/原件访问还 MUST 通过工程成员、空间范围和资料范围的交集。（RI-S14、RI-S42、RI-S61～S65；F-DA-01、F-AU-01/02）

#### Scenario: 工程内共享仍受成员和空间限制
- **WHEN** 活跃工程成员具备读取能力且其空间范围完整覆盖一份“工程内共享”资料的关联范围
- **THEN** 服务端允许读取该资料版本正文
- **AND** 另一工程成员或未覆盖全部关联范围的成员仍被拒绝

#### Scenario: 指定可见只允许明确账号
- **WHEN** 活跃工程成员请求“指定可见”资料且其账号不在该资料版本的当前允许集合中
- **THEN** 系统拒绝正文、原件和派生正文读取
- **AND** 工程业务权限或系统管理员角色不能绕过指定集合

#### Scenario: 结论和定位不等于正文权限
- **WHEN** 成员可查看风险结论及证据定位、但无对应资料正文权限
- **THEN** 查询只返回允许披露的定位与脱敏摘要
- **AND** 事件、错误、审计、Agent、检查点和导出均不得携带正文或可反推正文的诊断信息

#### Scenario: 派生工件不能扩大权限
- **WHEN** 工件由共享资料和指定可见资料共同派生，或由指定集合不同的多份资料共同派生
- **THEN** 工件正文只对同时满足全部来源授权的账号可见
- **AND** 任一来源权限收窄后，新请求立即按收窄后的交集判断

#### Scenario: 权限变更不追溯改写历史
- **WHEN** 资料访问范围或指定账号集合发布新修订
- **THEN** 新请求使用新修订，既有业务事实和审计仍保留当时的授权引用
- **AND** 历史记录不被重写为当前权限或当前操作者

### Requirement: 访问变更在并发和重试下原子且版本可追溯

系统 MUST 以单个 PostgreSQL 本地事务提交账号管理、工程开通、成员/空间/资料授权修订、命令收据和适用审计。已认证写命令 MUST 复用 C03 `(projectId, commandKind, idempotencyKey)` 唯一键与 strict payload 摘要；相同键和相同载荷返回原结果，相同键和不同载荷返回不可重试冲突。可变访问关系 MUST 使用预期版本或当前修订唯一约束收口并发，不得覆盖已发布修订。（RI-S14）

#### Scenario: 相同管理命令重试返回原结果
- **WHEN** 调用方以相同工程、命令类型、幂等键和有效载荷重试已完成访问管理命令
- **THEN** 系统返回首次产生的账号、工程、成员、空间或资料授权引用
- **AND** 不重复写修订、审计或命令收据

#### Scenario: 同键不同载荷冲突
- **WHEN** 调用方复用已完成命令的幂等键提交不同 strict payload
- **THEN** 系统返回 C02 `IDEMPOTENCY_CONFLICT` 语义并指向原命令
- **AND** 原访问事实和授权结果不变

#### Scenario: 并发成员修订只有一个获胜
- **WHEN** 两个调用方基于同一成员当前版本并发修改角色或空间范围
- **THEN** 至多一个修订成为新的当前版本
- **AND** 另一调用方收到不可重试的陈旧版本/并发冲突而不覆盖获胜结果

#### Scenario: 审计写入失败整体回滚
- **WHEN** 访问事实、命令收据或适用审计中的任一步写入失败
- **THEN** 同一命令的全部写入不可见
- **AND** 调用方可以沿用原命令身份安全重试

### Requirement: 安全审计、错误与敏感数据保持最小披露

系统 MUST 只追加记录登录、账号与权限变更、业务访问决定及拒绝；审计不可静默丢弃，权限变更和对应审计保持原子。资料访问按每次真实读取追加操作者、工程、对象、时间及结果，不作为业务写命令进行载荷去重。已通过工程入口检查的用户 MUST 能区分授权不足、目标不存在及读取异常；无工程访问资格的请求仍只返回权限拒绝。日志和公共错误不得含密码、token、秘密、正文、连接串或内部堆栈。

#### Scenario: 登录与越权形成最小安全事件

- **WHEN** 登录成功、登录失败或受保护请求被拒绝
- **THEN** 系统保存时间、结果码、主体/匿名尝试引用、工程/请求引用和策略版本等最小字段
- **AND** 不保存密码、token、目标正文或可用于枚举账号/工程/资料的细节

#### Scenario: 审计失败不静默放行

- **WHEN** 会话创建、授权成功或权限变更已准备完成但安全审计无法持久化
- **THEN** 相关事务回滚或授权决定失败
- **AND** 调用方不会观察到未留痕的成功会话、访问上下文或权限变化

#### Scenario: 应用角色不能改写安全审计

- **WHEN** 普通应用或 Worker 运行角色尝试更新或删除安全审计事件
- **THEN** PostgreSQL 拒绝操作
- **AND** 原记录保持不变

#### Scenario: 未授权与不存在目标不可区分

- **WHEN** 无工程访问资格的调用方请求存在或不存在对象
- **THEN** 统一返回权限拒绝；已获工程访问资格的业务对象读取按实际无权、不存在或技术故障分别呈现

#### Scenario: 读取故障明确呈现

- **WHEN** 有权用户读取资料或任务遇到系统异常
- **THEN** 返回读取失败及诊断引用，不伪装为权限拒绝或持续加载

#### Scenario: 重复查看留下真实访问记录

- **WHEN** 同一用户重复读取同一资料或不同资料，授权时间发生变化
- **THEN** 各次读取正常返回并分别记访问记录，不发生写命令幂等冲突

#### Scenario: 审计失败如实返回

- **WHEN** 访问记录无法持久化
- **THEN** 返回记录失败且不声明无记录的成功，不生成业务写命令完成回执

### Requirement: 身份与授权路径具有有界资源和独立性能验收

系统 MUST 限制登录名、密码、角色、空间和资料授权集合大小，并通过数据库唯一键、外键和面向当前修订的索引完成授权，不扫描其它工程或全部历史。密码校验资源成本 MUST 使用冻结参数并与普通授权性能分开验收；一次普通授权决定在预热的固定 PostgreSQL 测试环境中连续执行 200 次时 p95 MUST 不高于 100 ms，且结果必须包含相同策略/修订下的一致最小能力集合。

#### Scenario: 普通授权满足性能门槛
- **WHEN** 在固定 PostgreSQL 容器预热后对同一活跃成员、空间和资料组合连续执行 200 次授权
- **THEN** p95 延迟不高于 100 ms 且所有决定一致
- **AND** 测试不跳过、不使用内存授权表或预写结果

#### Scenario: 超大授权请求在查询前拒绝
- **WHEN** 请求携带超过冻结上限的角色、空间或资料引用集合
- **THEN** strict Schema 在数据库授权查询前拒绝该请求
- **AND** 系统不通过扩大内存、放宽超时或全库扫描继续执行

### Requirement: 当前会话元数据由服务端验证后提供

系统 MUST 提供当前会话元数据读取能力，使用既有服务端会话验证并返回会话、账号、到期时间和首次改密限制，不返回原始 token，不签发工程或系统管理授权上下文。成功读取 MUST 按既有会话使用规则更新空闲期限且不突破绝对期限；账号停用、密码与密钥版本变化、撤销或超时必须按会话失效语义拒绝。元数据不得由客户端 Cookie 内容、本地缓存或角色镜像推导。（F-AG-01/02）

#### Scenario: 有效会话可查询无 token 元数据
- **WHEN** 调用方提供有效服务端会话 token
- **THEN** 系统返回当前无 token 会话元数据，并按原空闲及绝对期限规则给出有效到期时间
- **AND** 不新增授权上下文或会话 token

#### Scenario: 首次改密会话仍可自省
- **WHEN** 有效会话所属账号必须首次改密
- **THEN** 系统返回受限及改密标志，允许继续既有改密与注销路径
- **AND** 业务授权限制保持生效

#### Scenario: 失效会话统一拒绝恢复
- **WHEN** 账号已停用、会话已撤销、密码或密钥版本不符，或者空闲/绝对期限已达到
- **THEN** 元数据读取以会话撤销或过期类别失败，不返回旧账号或授权元数据

#### Scenario: 自省不延长绝对期限
- **WHEN** 有效会话在绝对期限之前反复读取自身元数据
- **THEN** 空闲期限最多推进至原绝对期限，到达绝对期限后必须重新认证

### Requirement: C35 系统管理必须从当前会话取得独立管理授权

系统 MUST 提供当前会话系统管理身份、安全账号/工程/成员/空间目录及管理命令入口。每次请求由服务端验证 Cookie 会话、账号当前管理员授予、首次改密限制和安全修订；管理授权引用仅在服务端生成并传给 C06，客户端不得提交或覆盖。系统管理 MUST 不借用工程业务 branch 或空业务能力集合，不修改会话元数据的现有形状、不隐式授予工程业务能力。

#### Scenario: 当前管理员无工程身份
- **WHEN** 活跃且已完成首次改密的系统管理员请求目录或六项管理动作
- **THEN** 服务端独立证明管理员身份并调用原管理端口，不要求其先获得工程成员权限

#### Scenario: 旧管理授权与普通用户
- **WHEN** 用户不再是管理员、会话已失效、仍需改密或伪造管理引用
- **THEN** 在任何目录或命令前安全拒绝，不使用登录时的旧授权引用继续执行

### Requirement: C35 管理目录与六项写入必须保持版本和敏感数据边界

管理目录 MUST 有界，仅披露账号显示身份/状态/当前版本、工程访问壳、成员角色/范围与精确版本，不返回密码派生值、秘密、会话 token 或安全内部行。账号创建/停用/重置、工程开通/暂停、成员修订 MUST 复用 C06 的预期版本、幂等收据和原子安全审计；密码不得进入页面缓存、确认摘要、普通日志或收据。

#### Scenario: 管理命令重试与冲突
- **WHEN** 同一管理命令重放，或两个修订使用同一预期版本
- **THEN** 重放返回原引用，版本竞争至多一个胜出，不覆盖已发布修订

#### Scenario: 安全审计失败与密码处理
- **WHEN** 账号创建/重置含密码或安全审计无法持久化
- **THEN** 密码仅用于凭据计算且不进入回执/审计，审计失败回滚访问变更并不返回成功

### Requirement: 业务动作入口统一执行当前权限

系统 MUST 在用户业务入口或后台业务动作入口，依据当前账号、工程成员、角色、空间和资料范围检查权限，记录操作者、工程、目标及因果任务。每次新的资料读取或业务结果提交 MUST 应用当前权限；同一动作内的可信模块调用 MUST 复用该检查结果，不逐层签发短效上下文或比对调用编号。后台任务 MUST 保存发起者及冻结资源范围，不保存会话 token；注销和网页登录到期不取消任务，账号停用和权限收窄在下一动作生效。客户端与模型不得决定能力或扩大任务输入范围。

#### Scenario: 长任务独立于网页登录期限

- **WHEN** 原发起者仍有资料权限，后台任务运行超过网页登录或旧授权有效期
- **THEN** 任务在原预算内继续，不因短期凭据到期失败

#### Scenario: 撤权在下一业务动作生效

- **WHEN** 管理员收窄资料权限或停用账号
- **THEN** 下一次资料读取或结果提交由统一入口拒绝；已经提交的历史结果保留

#### Scenario: 可信内部调用复用入口决定

- **WHEN** 已获准业务动作通过多个模块完成同一读取或提交
- **THEN** 内部调用使用同一操作者和工程上下文，不因不同技术调用编号要求重新签发

#### Scenario: 保留不同账号可见范围

- **WHEN** 账号没有目标工程、空间或指定资料的读取资格
- **THEN** 入口拒绝资料披露，派生结果按全部来源的权限交集决定可见性
