# knowledge/assessment-configuration-and-measure-governance Specification

## Purpose
为 RiskFlow 提供经人工审核、边界精确且可确定性重放的评估配置与措施知识，使指标取值、风险分级、预警、处置候选和偏差校准始终引用同一组不可变依据。

## Requirements
### Requirement: 评估配置包具有严格类型与兼容身份

系统 MUST 以 C02 `KnowledgeDefinitionTypeV1` 中的 `indicator-system`、`indicator-field-mapping`、`weight-set`、`scoring-strategy`、`risk-matrix`、`risk-acceptance-threshold`、`monitoring-warning-threshold`、`joint-trigger-policy`、`measure-library`、`forecast-policy` 和 `deviation-policy` 表达 C18 配置。每个内容寻址配置包 MUST 只包含一个与治理命令一致的定义类型，并固定 schema 版本、精确工程修订、配置集合兼容身份和该类型的 strict 内容；未知字段、未知枚举、非有限数值、重复或未规范排序的身份集合、类型不符及超限内容 MUST 整体拒绝。配置正文 MUST 保留在 C04 工件中，不得复制为第二套可变事实。（RA-S2、RA-S5～RA-S7）

#### Scenario: 导入完整的甲方审核配置
- **WHEN** 获授权调用方以 C16 `submit-revision` 提交媒体类型、工程、定义类型、兼容身份和内容均匹配的精确配置工件
- **THEN** 系统完成确定性内容校验并创建一个 C16 不可变修订
- **AND** 不要求 Agent 重新解释或改写甲方审核内容

#### Scenario: 非法配置包整体拒绝
- **WHEN** 配置工件存在未知字段、定义类型错配、非法数值、重复身份、结构超限或与命令工程不一致
- **THEN** 系统返回闭合的业务或输入失败
- **AND** 不创建配置修订、审计成功、发布或评估配置集合事实

#### Scenario: 同一配置包重放保持幂等
- **WHEN** 调用方以相同命令身份和完全相同的内容工件重放导入
- **THEN** 系统返回首次创建的精确修订引用
- **AND** 同键异载荷仍由 C16 返回 `IDEMPOTENCY_CONFLICT`

### Requirement: 指标体系和字段映射显式连接冻结输入

指标体系 MUST 同时包含发生可能性与后果严重性指标，并使地下工程细分指标至少覆盖 C01 五类量化指标组中的两类。每个指标 MUST 固定指标身份、类型、分组、值种类、规范单位、适用条件和量化区间引用。字段映射 MUST 以闭合来源区分工程资料字段、监测规范值和 C14 的短期斜率、加速度、频域主峰、异常评分，显式给出目标指标、源字段段、源单位、目标单位及受控的 identity/affine 转换；不得使用自由 JSONPath、名称猜测或运行时单位推断。（RA-S1、RA-S2、RA-S5、RA-S6）

#### Scenario: 映射 C14 冻结监测特征
- **WHEN** 字段映射引用六项固定监测指标之一、精确监测字段种类、C14 特征种类和与目标指标一致的单位
- **THEN** 系统接受该映射并保留源字段、特征、单位转换与目标指标的精确关系
- **AND** 后续评估可以只依据冻结快照和该发布映射取值

#### Scenario: 拒绝猜测式字段或单位映射
- **WHEN** 映射使用自由路径表达式、未知监测指标/特征、未声明单位转换或不存在的目标指标
- **THEN** 系统拒绝该配置或兼容集合
- **AND** 不通过近义词、默认单位或“最新字段”补全

#### Scenario: 拒绝不完整指标覆盖
- **WHEN** 指标体系缺少 P/C 任一指标类型或五类量化指标组覆盖少于两类
- **THEN** 系统拒绝该指标体系修订

### Requirement: 权重与聚合策略使用闭合确定性模型

权重集 MUST 分别为发生可能性与后果严重性指标分配非负整数基点，每一侧权重之和精确等于 10000，并固定来源与兼容身份。聚合策略 MUST 分别从闭合的 `weighted-average` 或 `maximum` 中选择 P/C 算法及精确舍入规则；`weighted-average` 必须引用完整匹配的权重集，`maximum` 不得静默使用权重。系统 MUST NOT 接受公式字符串、表达式树、脚本、动态函数名或未版本化的聚合参数。（RA-S2、RA-S5）

#### Scenario: 精确权重集可以发布
- **WHEN** P/C 两侧权重分别完整覆盖其指标、无重复且各自基点合计 10000
- **THEN** 系统接受权重集并可用整数算术重放权重占比

#### Scenario: 聚合策略与权重不兼容时拒绝
- **WHEN** 加权平均缺少指标权重、权重指向错误轴，或最大值策略携带会影响结果的权重参数
- **THEN** 系统拒绝该兼容集合
- **AND** 不归一化、截断或补默认权重

#### Scenario: 任意公式 DSL 被拒绝
- **WHEN** 配置包尝试提交公式文本、嵌套表达式、脚本或闭合策略之外的运算符
- **THEN** strict Schema 拒绝输入

### Requirement: 风险矩阵使用无歧义十进制边界与穷尽单元

风险矩阵 MUST 独立定义有序、连续、互不重叠的 P 轴和 C 轴分段；边界 MUST 使用规范十进制字符串，分段采用固定的左闭右开规则且末段右端点闭合。矩阵 MUST 为两个轴的笛卡尔积各提供且仅提供一个单元，并将每个单元映射到有序风险等级；不得把 5×5 或 I～IV 级硬编码为固定形状。矩阵校验与映射 MUST 使用精确十进制比较，不得依赖二进制浮点近似或数组顺序猜测。（RA-S5）

#### Scenario: 非 5×5 矩阵通过完整校验
- **WHEN** 甲方配置的 P/C 分段数量不是 5，但分段连续且矩阵单元穷尽、唯一并引用合法风险等级
- **THEN** 系统接受该矩阵并保留其原始维度与等级顺序

#### Scenario: 共享边界只有一个归属
- **WHEN** P 或 C 分值精确等于两个相邻分段的共享边界
- **THEN** 系统按左闭右开规则只选择后一个分段
- **AND** 最终上界精确等于分值时归属末段

#### Scenario: 缺口、重叠或矩阵缺格整体拒绝
- **WHEN** 任一轴存在边界缺口、重叠、倒序或非规范十进制，或笛卡尔积存在缺失/重复单元
- **THEN** 系统整体拒绝风险矩阵
- **AND** 不插值、补格或选择邻近等级

### Requirement: 风险可接受阈值与监测预警阈值保持分离

风险可接受阈值 MUST 只按风险等级的有序身份表达允许上限或触发下限；监测预警阈值 MUST 只针对固定监测指标、规范值或 C14 特征、单位、比较运算符和规范十进制界限。两类阈值必须使用不同定义类型、内容结构、发布引用和审计链，任何一类都不得作为另一类的默认值或回退。（RA-S6）

#### Scenario: 风险等级越限只使用接受阈值
- **WHEN** 下游比较风险等级是否可接受
- **THEN** 配置集合只提供 `risk-acceptance-threshold` 的精确发布内容
- **AND** 不读取监测数值阈值推断风险接受性

#### Scenario: 监测值和趋势越限只使用监测阈值
- **WHEN** 下游比较监测规范值、斜率、加速度、频域主峰或异常评分
- **THEN** 配置集合只提供与指标、特征和单位匹配的 `monitoring-warning-threshold`
- **AND** 不读取风险等级阈值或执行单位猜测

#### Scenario: 混用两类阈值时拒绝
- **WHEN** 阈值内容携带另一阈值类型的字段、引用或语义
- **THEN** strict Schema 或兼容性校验拒绝该配置

### Requirement: 联合触发规则只能组合已发布监测阈值

联合触发规则 MUST 以扁平、无递归的 `all-of`、`any-of` 或 `at-least` 组合两个及以上唯一监测阈值身份；`at-least` 的计数必须位于 1 与成员数量之间。规则 MUST 固定适用条件、成员顺序和兼容身份，且所有成员必须属于同一兼容集合的监测预警阈值。系统 MUST NOT 接受嵌套规则、任意布尔表达式、脚本或风险接受阈值成员。（RA-S6）

#### Scenario: 合法多指标联合规则可重放
- **WHEN** 联合规则以闭合运算符引用同一配置集合中存在的多个监测阈值
- **THEN** 系统接受规则并以固定成员和计数语义保存

#### Scenario: 递归或越界联合规则被拒绝
- **WHEN** 联合规则包含嵌套表达式、重复/不存在成员、风险接受阈值或非法 `at-least` 计数
- **THEN** 系统整体拒绝该规则或兼容集合

### Requirement: 措施库限制候选并固定目标与适用性

措施库中的每项措施 MUST 固定措施身份、适用风险事件类别、适用性条件、对应触发类型、操作步骤、资源需求、目标指标、规范证据和禁忌条件。身份、步骤和目标必须非空、有界；身份与目标按规范身份排序，步骤按显式业务序号保序。目标指标必须存在于同一兼容集合的指标体系。后续 Agent 只能组合和排序由精确措施库发布形成的候选，不得新增、改写或绕过措施。（RA-S7）

#### Scenario: 按风险与适用性形成冻结候选
- **WHEN** 下游以风险事件、适用性元数据和精确措施库发布请求候选
- **THEN** 系统只返回同时满足适用条件与触发类型的措施身份和精确版本
- **AND** 候选形成后发布变化不改写该候选集

#### Scenario: 候选外措施不可进入正式建议
- **WHEN** Agent 增量引用精确候选集之外的措施或改写措施内容
- **THEN** 下游确定性校验必须拒绝该增量
- **AND** 措施库事实保持不变

### Requirement: 预测与偏差策略只声明可执行的版本化口径

预测策略 MUST 从 `historical-statistics`、`monitoring-trend` 或 `mechanism-model` 中选择方法，固定输入指标、目标指标、预测时域和所需模型/策略精确版本；偏差策略 MUST 从 `absolute`、`relative` 或 `risk-level-step` 中选择比较口径：absolute 使用规范十进制阈值，relative 使用规范十进制阈值与正的最小有效基线，risk-level-step 使用正整数等级步数，三者均固定证据要求。策略只能描述后续确定性或受控模型计算所需口径，不得执行公式、自动修改权重/阈值/区间，也不得在缺少预测时伪造偏差。（RA-S7）

#### Scenario: 预测和偏差使用同一冻结口径
- **WHEN** 下游在执行前冻结预测策略、目标指标和输入版本，并在反馈后使用匹配的偏差策略
- **THEN** 预测值、实际值和偏差可按同一指标、单位、时域和策略版本比较

#### Scenario: 无预测不得产生替代偏差
- **WHEN** 执行前没有符合冻结策略的预测结果
- **THEN** 偏差策略不允许以零值、历史均值或当前风险等级补造预测

#### Scenario: 偏差越限不直接改配置
- **WHEN** 偏差超过已冻结阈值
- **THEN** 该结果只能作为后续校准建议候选的输入
- **AND** 不覆盖已发布权重、阈值、区间、矩阵或策略

### Requirement: 发布集合固定完整兼容的精确配置

全流程配置解析 MUST 按工程、`requiredAt` 和 `asOfRecordedAt` 解析 11 类 C18 定义；按阶段解析 MUST 只要求该阶段所需成员：评分为指标体系、字段映射、权重、评分策略、矩阵、风险阈值、监测阈值及联合触发八类，处置增加措施库，预测使用预测策略，偏差使用偏差策略。各阶段物化自己的不可变配置集合，阶段之外的成员缺失不阻止本阶段。集合 MUST 固定工程修订、兼容身份，以及每个成员的定义类型、发布、修订、内容工件和规范内容摘要；所有本地与跨定义引用必须通过后才可返回。缺失、未生效、停用、跨工程、兼容身份不一致或引用失配 MUST 整体失败，不得回退历史版本、混用集合或返回部分配置。（RA-S2、RA-S5～RA-S7）

#### Scenario: 完整兼容发布形成精确集合

- **WHEN** 11 类配置在要求时刻均有同工程、同工程修订、同兼容身份且交叉引用有效的人工批准发布
- **THEN** 系统返回一个不可变评估配置发布集合引用
- **AND** 相同冻结输入重放得到相同成员、摘要和结果引用

#### Scenario: 发布变化不改写冻结集合

- **WHEN** 评估配置集合形成后任一成员发布新版本、停用或按历史修订重新发布
- **THEN** 原集合继续引用原精确成员并可重放
- **AND** 新运行必须显式解析并形成新集合

#### Scenario: 不完整或不兼容集合不降级

- **WHEN** 任一必需类型缺失、停用、未生效，或成员工程修订、兼容身份、指标/阈值/矩阵引用不一致
- **THEN** 系统返回结构化等待或业务阻塞
- **AND** 不使用未审核修订、历史发布、默认配置或其它工程内容继续

### Requirement: 配置治理复用人工发布、原子审计与最小披露

C18 配置 MUST 复用 C16 的送审、人工批准、发布、停用和 `rollback-by-new-release` 行为。内容校验事实 MUST 与配置修订原子成立；C18 配置发布或历史版本重新发布 MUST 与发布事实、审计、命令回执和既有 `knowledge.assessment-basis-published.v1` Outbox 事件原子提交，并关联配置包中的精确工程修订。所有命令 MUST 先执行 C06 工程与能力授权；Agent 不得发布、停用或回滚。失败、日志、事件和普通查询不得复制配置正文、来源正文或内部数据库错误。（RA-S2、RA-S7）

#### Scenario: 人工批准后发布配置
- **WHEN** 人工调用方以匹配目标修订的有效批准决定发布 C18 配置
- **THEN** 系统原子保存 C16 发布、C18 关联、审计、命令回执和评估依据发布事件
- **AND** 事件只携带精确发布与工程修订引用，不复制配置正文

#### Scenario: 回滚形成新的配置发布
- **WHEN** 人工调用方以历史 C18 发布、匹配批准决定和原因执行 `rollback-by-new-release`
- **THEN** 系统创建引用历史修订的新发布并原子记录审计与评估依据发布事件
- **AND** 原发布、停用决定、旧集合和历史运行保持不变

#### Scenario: Agent 或无权调用不能发布
- **WHEN** Agent、跨工程调用方或能力不足的调用方尝试发布、停用或回滚配置
- **THEN** 系统在泄露目标存在性或产生副作用前返回 `AUTHORIZATION_DENIED`
- **AND** 不产生配置、审计成功、事件或集合变化

#### Scenario: 任一原子写入失败整体回滚
- **WHEN** 配置关联、治理事实、审计、命令回执或 Outbox 任一步写入失败
- **THEN** 同一命令的全部写入均不可见
- **AND** 调用方可沿用原幂等身份安全重试
