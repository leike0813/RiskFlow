## ADDED Requirements

### Requirement: PJ-H-R1 工程工作区接缝必须闭合且正式装配

系统 MUST 为工程上下文修订/精确读取、工程访问维护和接入记录读取登记有限的版本化 HTTP 接缝，复用所属公共 Schema、Cookie 认证、当前授权、安全错误和既有确认/幂等语义。当前 actor、会话和授权只由服务端注入，路径工程必须匹配业务目标；不得公开部署脚本、任意工件读取、文件系统或自由命令入口。工程开通沿原系统管理入口，不要求伪造当前工程；工程访问维护不能借管理端口扩大系统管理员的业务权。新端口必须在正式部署和真实浏览器组合根接通，端口缺席不返回成功空结果；OpenAPI 必须与已激活路由一致。（RI-S14；RA-S1）

#### Scenario: PJ-H-S01 生产接缝与OpenAPI一致
- **WHEN** 同版 API、Web 和正式工程所有者已经装配
- **THEN** 有效 Cookie 可按严格公开载荷完成工程维护与读取，返回所属精确回执，OpenAPI 包含同一已激活操作；管理开通无需当前工程

#### Scenario: PJ-H-S02 非法输入与拒权不产生副作用
- **WHEN** 请求伪造主体/授权、提供任意路径/工件、未知分支/额外字段、跨工程引用或无当前权限
- **THEN** 按原契约或授权边界拒绝，不执行领域操作、不披露目标、不产生业务写入或成功回执

#### Scenario: PJ-H-S03 缺端口与技术异常
- **WHEN** 所需生产端口未接通或所属读取失败
- **THEN** 装配或请求明确失败，Web 显示安全不可用/故障并保留合法重试，不以空数组、静态结果或跳过关键验收计作通过
