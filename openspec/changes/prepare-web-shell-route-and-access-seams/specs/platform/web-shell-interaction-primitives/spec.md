## MODIFIED Requirements

### Requirement: Web shell 必须按承载就绪分阶段启用六导航

系统 MUST 以“风险总览、工程、识别、评估、预警与处置、治理”为最终六项一级业务导航，根地址依次为 `/overview`、`/projects`、`/identification`、`/assessment`、`/warnings`、`/knowledge`。公共接缝先行时 MUST 保留现有七项入口及原业务承载；各业务 change 在新承载通过当前权限、正文、历史精确深链和原命令验收后，才原子切换其地址、内部调用方并移除被替代页面实现。搜索、待办／助手及最终六导航由 CH-9 在 CH-3～CH-8 全部目标就绪后组合启用。未就绪不得删旧、发布指向无承载目标的导航或以隐藏入口冒充完成。Agent 和系统管理 MUST 为辅助入口；会话门禁 `/login`、`/change-password` 及 `/` 到 `/overview` 的语义不变。未知路径不得猜测目标或动态调用开放入口。

#### Scenario: SH-S01 公共接缝先行保全已有入口
- **WHEN** CH-2 已交付而新业务承载和组合验收尚未完成
- **THEN** 原七项导航、复核队列、历史矩阵及处置子记录入口继续可达，不发生尚未交付的业务重定向
- **AND** 未交付 contribution 仍呈现安全不可用态，不生成样例事实或假操作

#### Scenario: SH-S02 最终组合不得早于目标就绪
- **WHEN** 后续 change 请求启用六导航及新停靠组合
- **THEN** 只有目标承载、来源授权、精确历史链接及原命令已完成验收时才整体启用；不保留重复旧页面实现
- **AND** 未登记路径保持统一未找到，不泄露对象存在性

#### Scenario: 七项导航与路由一一对应
- **WHEN** 公共接缝已经交付但最终六导航组合尚未启用
- **THEN** 现有七项导航仍一一指向当前可用根路由；后续组合启用沿本要求的承载门槛执行
- **AND** Agent 与系统管理不占一级业务导航

#### Scenario: 未交付根页面不伪装业务能力
- **WHEN** 用户打开尚无 feature contribution 的合法业务根路由
- **THEN** shell 显示不含业务数据和写操作的不可用页状态
- **AND** 不生成风险数量、任务、图表、通知、示例事实或 Mock 操作入口

#### Scenario: 未登记路径安全失败
- **WHEN** 用户打开白名单外路径或尚未登记的业务详情路径
- **THEN** shell 显示不披露目标存在性的统一未找到页并保留当前发布阶段导航
- **AND** 不猜测相近路径、不动态加载任意模块或调用通用后端入口

### Requirement: 工程空间工序上下文必须原子切换

Web shell MUST 维护版本化界面上下文，至少包含当前工程标识、可选空间区段精确引用、可选工序节点标识和只增的上下文修订号。工程/空间/工序切换 MUST 停留在当前合法页面，原子替换上下文并重新加载当前页面；不得把旧工程对象状态带入新上下文，也不得由壳层推断工程层级、适用性元数据或工序事实。

#### Scenario: 切换工程清除旧内容
- **WHEN** 用户从一个工程切换到另一个获准工程
- **THEN** shell 在发起新查询前清除旧页面内容、空间区段和工序选择并增加上下文修订号
- **AND** 旧工程名称、对象、错误、证据或 Agent 自动上下文不在新工程加载期间闪现

#### Scenario: 切换空间或工序保持页面
- **WHEN** 用户在同一工程内切换获准空间区段或工序节点
- **THEN** 当前 pathname 保持不变并以新上下文重新加载页面 contribution
- **AND** 浏览器深链只表达经过共享 Schema 校验的标识/精确引用

#### Scenario: 无工程上下文时阻止业务页面读取
- **WHEN** 已认证用户尚未获得或选择可用工程
- **THEN** 当前发布阶段的导航可见但业务根页面显示工程上下文空态
- **AND** shell 不向 C09 构造空字符串、默认工程或跨工程查询

### Requirement: 页面区域组合必须共享有限视图状态

系统 MUST 允许页面声明有序区域块组合，覆盖列表、详情、表单、图表、时间线、矩阵、页签、运行、治理、复核、Agent 与动作区域；A 列表、B 详情、C 运行、D 治理、E 复核为单区域特例，不再限制页面只能选择一个骨架。每个页面及独立读取区域 MUST 复用 `idle`、`loading`、`ready`、`empty`、`error`、`forbidden`、`unavailable` 七态，状态变化不得保留与当前上下文不匹配的旧内容。组合只拥有呈现结构，不拥有领域 DTO、查询、命令或业务事实。

#### Scenario: SH-S03 真实页面承载复合区域
- **WHEN** 已有生产页同时展示列表及详情或图表
- **THEN** 有序区域均保留原当前工程、精确引用、分页与独立来源状态，不以一处成功掩盖另一处失败，也不引入第二份业务状态

#### Scenario: 加载不闪烁为空态
- **WHEN** 合法页面开始加载且结果尚未返回
- **THEN** 页面显示与区域组合相符的忙碌占位并向辅助技术标记加载中
- **AND** 不先显示空态、旧数据或虚构默认内容

#### Scenario: 空态只给真实下一步
- **WHEN** 获授权查询成功且返回业务定义的空结果
- **THEN** 页面显示空态及由 owning feature 提供的真实下一步
- **AND** 若没有已登记命令，空态不自行生成操作按钮

#### Scenario: 技术异常只显示安全摘要
- **WHEN** 页面收到 C09 安全错误信封或未分类传输失败
- **THEN** 页面只显示稳定错误代码、可重试性、请求关联标识和获准引用，并在可重试时提供重试
- **AND** 不显示堆栈、SQL、凭据、Cookie、原始 payload、证据正文、模型响应或内部文案

### Requirement: 右侧停靠区必须按独立权限组合所属贡献

Web shell MUST 提供可收起的停靠区。最终待办页签沿 `review-todo.read`、助手工作页签沿 `agent-task.read` 独立判断入口权；单页签被拒绝不得隐藏另一个有权页签，两者均被拒绝才收起新组合。技术不可用 MUST 保留已获准位置与原因，不解释为零事项。待办和新助手组合尚未交付时 MUST 保留既有上下文／Agent 承载及复核入口，不渲染空待办或假计数。证据、版本审计与关联对象仍由所属页面／证据贡献提供，不因旧上下文容器调整而丢失。停靠状态只保存开合及活动位置，不缓存正文或创建第二套 Agent 会话；聚合入口权不等于来源权限。

#### Scenario: SH-S04 两类入口权相互独立
- **WHEN** 用户仅有待办或仅有助手入口权
- **THEN** 壳层独立判定对应位置，不要求两能力交集；已接入的另一有权贡献不受影响
- **AND** 未交付待办时仍由旧复核入口承载，不伪装聚合已可调用

#### Scenario: 跨页面保持停靠状态
- **WHEN** 用户打开 Agent 面板后切换到另一合法业务根路由
- **THEN** 停靠区继续打开同一面板并更新当前页面上下文摘要
- **AND** 会话、任务和证据数据仍由 owning feature 的精确引用提供

#### Scenario: 无资料正文权限的证据脱敏
- **WHEN** 用户可见证据定位但没有来源资料正文权限
- **THEN** 所属证据区域只显示资料名称、章节路径、资料段标识等获准定位摘要和固定脱敏提示
- **AND** 不显示原文、监测正文、相邻片段或“加载失败”造成的歧义

#### Scenario: 未接入 Agent 功能
- **WHEN** 当前用户无 Agent 权限或 contribution 不可用
- **THEN** 不提供对话输入、任务启动或写命令；已授权但技术不可用的位置显示原因
- **AND** shell 不调用模型、不生成降级回答或维护本地伪会话

#### Scenario: Agent 只展示获准的可审计内容
- **WHEN** 所属能力注入当前用户可见的 Agent 会话或任务摘要
- **THEN** 面板只承载冻结上下文、策略/版本、工具、预算、类型化增量、确定性校验、证据和领域结果引用
- **AND** 不提供模型内部思维链、原始模型正文或第二套领域结果字段

### Requirement: 写命令必须经过统一确认原语

任何会产生业务事实或外部副作用的 UI 操作 MUST 复用唯一确认控制器和对话框，在提交前显示作用域（工程或真实管理上下文）、目标、精确输入版本、预计事实、外部副作用及所需权限。高影响命令 MUST 额外显式确认；取消、Escape、关闭、路由离开、工程或认证上下文变化不得提交旧确认。控制器 MUST 冻结完整请求信封及载荷，提交中阻止重复提交；可重试失败只重发同一身份和载荷，编辑输入须重新确认并取得新身份。交互 Agent 只绑定 C08 提案并经 `agent-task.confirm-command`；普通命令和系统管理继续使用原所属端口和回执。确认层不得生成业务幂等规则、伪造工程或维护第二套领域状态。（RI-S6／RI-S14；RA-S1～RA-S7）

#### Scenario: 普通命令确认后提交一次
- **WHEN** 有权用户检查确认摘要并确认普通命令
- **THEN** 原语调用 owning feature 提供的单一提交处理器并在进行中阻止重复点击
- **AND** 网络重试继续使用调用方提供的原命令标识、幂等键、工程和精确版本

#### Scenario: 高影响命令要求显式二次确认
- **WHEN** 发布、回滚、作废或批量复核等高影响命令进入确认
- **THEN** 默认焦点位于取消操作，完成额外确认前提交按钮保持禁用
- **AND** Escape、取消、路由离开或关闭对话框均不产生业务事实

#### Scenario: 无权限确认卡不可提交
- **WHEN** 确认摘要可见但当前权限态不允许命令
- **THEN** 确认按钮置灰并以可访问方式说明所需权限
- **AND** 不能通过 Enter、快捷键或 Agent 面板绕过服务端常规权限校验

#### Scenario: 陈旧版本确认失败
- **WHEN** 用户确认期间目标精确版本已被替代
- **THEN** C09 的陈旧版本错误按结构化异常呈现并要求刷新摘要
- **AND** shell 不自动改写目标版本、不复用确认结果提交新版本

#### Scenario: 无工程的系统管理确认
- **WHEN** 当前真实系统管理员在未选择工程时确认既有账号或工程管理命令
- **THEN** 原语以真实管理上下文呈现作用域并提交原冻结请求，复用既有管理回执；不伪造工程、不获得资料权限，注销或管理上下文变化令确认失效

#### Scenario: SH-S05 编辑或上下文变化使旧确认失效
- **WHEN** 弹窗打开或提交失败后用户改变输入、工程、路由或认证上下文
- **THEN** 旧确认不能再次发请求；已送达的事实不被伪装取消，迟到结果不能覆盖新页面
- **AND** 新载荷须重新检查、生成命令身份并再次确认

### Requirement: 键盘和焦点行为必须可预测

shell、导航、停靠区、页面区域与确认对话框 MUST 使用语义化 landmark 和原生交互元素，支持键盘、可见焦点、跳过导航、标题播报和焦点恢复。左栏 MUST 可由用户在 152px 与 48px 间切换，右栏宽 22rem 且可收起，尺寸消费生产令牌。桌面三种窗口 1280×720、1440×900、1920×1080 在 100%／200% 缩放下 MUST 保持关键操作可到达且不遮挡焦点；正文折行、二维区域局部滚动，不自动把停靠区下沉或禁用浏览器缩放。减少动态效果时禁用非必要动画，不引入自绘标题栏或移动端承诺。

#### Scenario: 键盘完成导航
- **WHEN** 用户仅使用 Tab、Shift+Tab、Enter 和浏览器前进后退
- **THEN** 可到达跳过导航、当前阶段全部导航、页面主标题和可用操作，当前路由以文字和程序状态同时标识
- **AND** 路由变化后焦点移动到主标题并由礼貌 live region 播报

#### Scenario: 停靠区键盘操作
- **WHEN** 焦点位于已交付的右侧停靠区标签
- **THEN** 左右方向键、Home、End 切换当前获准标签，Escape 收起并把焦点返回开启按钮
- **AND** 收起内容不可聚焦且不被辅助技术重复读取

#### Scenario: 确认对话框焦点收口
- **WHEN** 命令确认对话框打开
- **THEN** 背景区域不可交互，Tab 焦点留在对话框内，关闭后返回原触发控件或其已卸载时的合法页面焦点
- **AND** 焦点不会因异步状态变化落到被卸载或禁用的提交按钮

#### Scenario: SH-S06 原生桌面缩放下可完成交互
- **WHEN** 用户在三种桌面窗口的两种缩放下收起左右栏、浏览二维内容并操作已有确认
- **THEN** 导航、页签、表单、错误、确认和取消均可达，溢出可实际滚动且焦点不被固定层遮挡

## ADDED Requirements

### Requirement: SH-R1 精确路由匹配和已知别名必须保全身份

系统 MUST 完整逐段匹配已登记路径，仅对实际同时匹配的模板按首个静态／参数差异段的静态段优先。静态形状相同、仅参数名不同的相交模板 MUST 在注册时拒绝，不依赖注册顺序或字典序选择对象。旧别名 MUST 仅匹配已知完整模板和段边界；未知旧路径不得被广义前缀替换为另一个合法对象。简单别名保留查询串；涉及对象／版本重映射的业务地址必须由所属域授权解析，保全工程、修订、评估来源、动作上下文与各对象独立精确版本；不得把子记录版本当任务版本，不得扫描目录首页或以任意最新对象替代。CH-2 只落实公共匹配与已有简单别名，业务转换随所属承载就绪后启用。

#### Scenario: SH-S07 真正相交模板静态前缀优先
- **WHEN** 同时注册 `/warnings/:warningId/actions` 与 `/warnings/tasks/:taskId`
- **THEN** `/warnings/abc/actions` 只匹配 warning 动作，`/warnings/tasks/actions` 匹配 taskId=actions；调换注册顺序结果相同

#### Scenario: SH-S08 相同静态形状禁止歧义注册
- **WHEN** 两个模板只有同位置参数名称不同而可匹配同一完整路径
- **THEN** 注册失败，不静默任选目标；合法 base contribution 的同 ID 同路径替换仍可用

#### Scenario: SH-S09 已知别名保全查询且未知模板拒绝
- **WHEN** 用户打开已知 `/project`、`/review` 或质量别名及其已登记详情模板，携带精确版本与工程选择器
- **THEN** 只到当前阶段已交付的规范承载且查询语义不丢失；未知中段或未登记后缀仍未找到，不意外重定向到另一个对象

#### Scenario: SH-S10 后续业务转换保全双引用
- **WHEN** 后续业务 change 启用旧子记录到任务页签的精确解析
- **THEN** 任务与子记录分别授权和定位版本，矛盾引用同形拒绝；合法独立行动保留共享独立形态，不强制创建任务
