## Purpose

为 RiskFlow 在正式处置建议之后提供可追溯的人工决定、现场执行、处置效果预测、执行后反馈与确定性偏差事实，使后续校准只消费不可变、可重放且权属清晰的正式输入。（RA-S7）

## ADDED Requirements

### Requirement: 人工决定与预测工作流保持独立所有权

系统 MUST 只对精确、不可变且三项校验均通过的正式处置建议记录人工采纳或拒绝决定，并保存决定、原因、操作者、业务时间、审计以及调用方提供的真实路由决定与预测运行引用。采纳决定不得等同于现场执行；拒绝决定不得形成效果预测。预测运行、路由和检查点仍由工作流模块拥有，C28 不得生成、伪造或持久化第二套工作流运行。（RA-S7）

#### Scenario: 采纳正式建议并交给独立预测运行
- **WHEN** 获授权调用方采纳一个同工程、同空间且仍有效的正式建议，并提供工作流模块已创建的精确路由决定与预测运行引用
- **THEN** 系统保存不可变采纳决定及其精确引用，允许该独立运行继续冻结预测输入
- **AND** 此时不存在现场执行或反馈事实

#### Scenario: 拒绝建议不形成预测或执行
- **WHEN** 获授权调用方拒绝正式建议并提供拒绝原因
- **THEN** 系统保存拒绝决定和审计，但不形成效果预测、执行、反馈或偏差事实

#### Scenario: 虚假或错配运行引用不能进入决定
- **WHEN** 路由决定或预测运行引用缺失、跨工程、与建议不匹配或不是工作流模块提供的精确引用
- **THEN** 系统返回类型化失败且不保存决定
- **AND** 不以本地随机标识、占位运行或自建状态机补足

### Requirement: 效果预测冻结建议、监测和评估依据

系统 MUST 以已采纳建议、采纳决定、执行前 C14 监测快照、建议所追溯的 C25 评估输入快照以及该快照固定的 C18 预测策略形成不可变预测输入。预测策略 MUST 与建议目标指标、单位、时域和精确 `requiredRef` 相容；所有输入、策略、授权和证据均按精确版本保存，后续监测、评估或配置发布不得改写旧预测。（RA-S7）

#### Scenario: 冻结完整预测输入
- **WHEN** 已经采纳的建议目标指标可由同工程执行前监测快照和冻结评估依据支持，且预测策略引用的执行方法版本可用
- **THEN** 系统保存不可变预测输入及其精确建议、决定、监测、评估、策略和执行方法引用
- **AND** 重放只读取这些冻结版本

#### Scenario: 预测依据不完整时显式不可用
- **WHEN** 建议未采纳，目标指标或单位不匹配，监测快照不可用，策略版本缺失，或者 `requiredRef` 指向的方法不可执行
- **THEN** 系统保存或返回稳定的预测不可用原因且不创建效果预测
- **AND** 不使用零值、历史均值、最新配置、其它工程模型或 Agent 输出补齐

### Requirement: 三类预测方法必须按版本化执行器产生可重放结果

系统 MUST 仅按冻结预测策略选择 `historical-statistics`、`monitoring-trend` 或 `mechanism-model`，并调用与 `requiredRef` 完全一致的版本化执行器。正式效果预测 MUST 固定目标指标的预测值、单位、时域、预测后风险状态、方法版本、输入摘要和证据；相同冻结输入必须得到相同业务结果。预测计算不得创建必经 Agent 任务，也不得允许执行器改写建议、监测、评估或配置事实。（RA-S7）

#### Scenario: 版本化方法形成正式预测
- **WHEN** 冻结策略的方法、`requiredRef`、输入指标、目标指标、单位和时域均由对应执行器支持
- **THEN** 系统产生可按精确版本读取的效果预测，并可从冻结输入独立复算其结果

#### Scenario: 方法版本或结果不合法时失败闭合
- **WHEN** 执行器版本不匹配、输入不足、结果含非有限值、单位或目标指标不符、证据缺失或输出风险状态无效
- **THEN** 系统返回类型化不可用或失败且不保存正式预测
- **AND** 不切换方法、版本、模型或扩大资源预算

### Requirement: 现场执行区分已采纳建议与独立行动

系统 MUST 将每次现场执行保存为不可变事实，并以闭合来源区分已采纳建议和现场独立行动。已采纳建议执行 MUST 引用仍有效的采纳决定及正式建议；独立行动 MUST 引用精确措施发布，不得伪造建议、采纳或预测。执行事实 MUST 保存实际执行者、受权录入者、发生时间、工程与空间、措施身份和非空证据，且不得关闭预警任务或宣称风险解除。（RA-S7）

#### Scenario: 记录已采纳建议的现场执行
- **WHEN** 获授权现场人员执行一个已采纳且未被拒绝或取代的建议，并提供完整证据
- **THEN** 系统保存单一不可变执行事实并贯通建议、预警和评估引用
- **AND** 采纳与执行保持两个可分别审计的事实

#### Scenario: 记录独立现场行动
- **WHEN** 获授权现场人员执行未来源于系统建议的行动并引用同工程已发布措施及证据
- **THEN** 系统保存 `independent-action` 执行事实
- **AND** 不生成采纳决定、建议引用或效果预测

#### Scenario: 伪造执行者或来源时拒绝
- **WHEN** 录入主体冒充执行者、建议未采纳、措施发布跨工程或无权、发生时间不合法，或者证据不完整
- **THEN** 系统在披露目标或产生业务副作用前拒绝

### Requirement: 反馈只消费执行后冻结事实与实际评估

系统 MUST 仅在执行事实成立后记录反馈，并固定执行后 C14 监测快照、受权反馈工件、由 C25 依据该快照形成的实际风险评估记录、发生时间、来源证据及授权。监测快照必须晚于或覆盖执行发生时点，实际评估必须与执行所追溯的风险输入、空间和冻结评估依据相容。反馈不得直接修改执行、建议、预测、预警或评估历史。（RA-S7）

#### Scenario: 执行后反馈形成完整事实
- **WHEN** 获授权调用方提交同工程执行记录、执行后监测快照、反馈工件和按同一风险输入形成的实际评估记录
- **THEN** 系统保存不可变反馈及其精确执行、监测、工件、实际评估和证据引用
- **AND** 既有 `warning.feedback-recorded.v1` 只在反馈、审计、回执和待发布事件原子成立后产生

#### Scenario: 时间或评估链不匹配时拒绝反馈
- **WHEN** 监测快照早于执行、实际评估来自其它风险输入或空间、反馈工件不可读，或者任一引用跨工程或越权
- **THEN** 系统返回不可枚举的类型化失败且不保存部分反馈或事件

### Requirement: 偏差事实按冻结策略确定性计算

系统 MUST 只在正式效果预测和相容反馈均存在时，按原评估输入快照固定的精确 C18 偏差策略比较同一目标指标、单位、时域和风险等级序。`absolute` MUST 计算实际值与预测值之差的绝对值；`relative` MUST 以预测值绝对值和正最小基线中的较大者为分母计算绝对相对偏差；`risk-level-step` MUST 按冻结风险矩阵等级序计算预测与实际风险等级的绝对步数。结果 MUST 保存稳定偏差事实标识、处置建议与执行引用、预测/实际值和风险状态、偏差值、阈值版本、是否越限、方向、证据及版本。（RA-S7）

#### Scenario: 三类策略精确判定阈值边界
- **WHEN** 预测和反馈完整相容，且计算结果恰好等于或越过冻结阈值
- **THEN** 系统按该策略的规范十进制或整数等级步数得到唯一偏差值与 `thresholdExceeded` 判定
- **AND** 相同冻结输入重放得到相同偏差事实

#### Scenario: 无预测或比较口径不一致时不造偏差
- **WHEN** 执行没有合法预测，预测与反馈的目标指标、单位、时域或评估依据不一致，或偏差策略缺失/不相容
- **THEN** 系统返回显式不可用或类型化失败且不保存偏差事实
- **AND** 不用零值、历史均值、当前风险等级或其它策略替代

#### Scenario: C28 不伪造公共偏差记录
- **WHEN** C28 保存未越限或已越限的确定性偏差事实
- **THEN** 系统不创建公共 `DeviationRecord`，也不填充 `calibrationRecommendation` 或 `reviewStatus`
- **AND** 不创建校准 Agent 任务、校准建议或配置发布事实

### Requirement: C29 可按稳定引用组合公共偏差与校准结果

C28 偏差事实 MUST 只追加且可按稳定身份和精确版本读取，并完整提供 C29 形成公共偏差记录所需的处置建议标识、预测与实际风险状态、偏差值、偏差阈值版本和证据引用。C29 后续 MAY 将该事实与真实校准建议及审核状态组合为公共 `DeviationRecord`；任何后续建议、审核、发布或回滚不得修改 C28 原事实。（RA-S7）

#### Scenario: C29 精确读取偏差事实
- **WHEN** C29 以同工程、获授权的稳定偏差事实引用读取一个精确版本
- **THEN** 系统返回完整且不可变的组合输入，不解析 latest 或重新计算旧偏差

#### Scenario: 后续校准不改写偏差事实
- **WHEN** C29 创建、审核、拒绝、修订或发布校准建议
- **THEN** C28 偏差事实及其预测、反馈、阈值和证据引用保持不变

### Requirement: 权限、幂等、事务与审计先于业务成功

系统 MUST 在读取建议、监测、评估、配置、措施或反馈工件前复验当前 C06 工程、空间、来源和精确分支授权，且下游预测执行权限不得超过发起运行。每个决定、预测、执行、反馈和偏差写入 MUST 使用 C03 业务幂等键与 PostgreSQL 事务；相同键同载荷重试返回原逻辑结果，同键异载荷拒绝，并发提交不得产生重复事实。业务事实、命令回执、C07 审计及该分支声明的 Outbox 事件必须原子成立。（RA-S7）

#### Scenario: 无权或跨工程调用不可枚举
- **WHEN** 调用方无权访问任一输入、工程或空间，或者下游授权比上游更宽
- **THEN** 系统在读取目标正文或产生成功副作用前返回不可枚举的授权拒绝

#### Scenario: 同键重试和并发只产生一份事实
- **WHEN** 相同载荷以同一幂等键重试或多个命令并发竞争同一业务身份
- **THEN** 系统返回同一逻辑结果或类型化冲突
- **AND** 不重复保存事实、审计、回执或反馈事件

#### Scenario: 任一原子成员失败整体回滚
- **WHEN** 业务事实、审计、命令回执或 Outbox 任一写入失败
- **THEN** 本次命令的全部写入不可见并可沿原幂等身份安全重试
