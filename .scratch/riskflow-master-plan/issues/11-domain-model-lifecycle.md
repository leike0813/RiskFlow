# 建立统一领域模型与业务对象生命周期

## Question

从工程、区段、资料段、工序模型、机理条目、标准化风险记录、适用规则集、风险评估记录、预警、处置、反馈、复核到审计，哪些对象拥有独立身份与版本，彼此如何关联，各自允许哪些状态转换，怎样避免识别事实、评估事实和界面投影互相复制或改写？

## 已确认决策

### 风险闭环的稳定身份

- 以标准化风险记录（Standardized Risk Record）作为风险闭环的唯一稳定身份，不新增持久化的 `RiskCase` 或同义业务事实。
- `riskRecordId` 在同一风险的生命周期中保持稳定；识别补充资料、多来源合并或人工修正时形成不可变的新版本，不覆盖历史版本。
- 风险评估记录必须引用当次评估使用的标准化风险记录精确版本；预警信息、处置建议、反馈与偏差继续逐级引用其直接上游事实。
- 甲方直接提供的外部风险事件保持独立身份，继续通过 `riskRecordId` / `externalRiskEventId` 二选一契约进入评估。
- 界面中的统一风险详情是由标准化风险记录及其下游事实组合得到的查询投影，不拥有独立风险身份，也不得回写领域事实。

### 五类统一生命周期

所有领域对象必须归入以下五类之一，不得为相似对象重复发明版本和状态语义：

1. **工程上下文主数据**：工程是权限、数据归属和业务运行的顶层边界；空间区段隶属于单一工程，可按里程或施工分区形成层级。工程与区段采用“筹备 → 生效 → 结束 → 归档”；名称、里程边界、工法、地层条件等关键变化形成新修订，已产生事实继续引用原修订或快照。工程结束后禁止新增业务事实，但保留查询、审计与导出。
2. **受治理定义**：站隧一体化施工工序模型、风险机理条目、指标体系、量化标准、结构化评分规则、权重、风险矩阵、阈值与措施库。统一采用“草稿 → 待审核 → 已发布 → 已停用”；提交审核后版本冻结，修改必须创建新版本，回滚通过重新启用历史版本实现。
3. **不可变业务事实**：资料版本及资料段、监测快照、标准化风险记录版本、风险评估记录、预警信息、处置建议、反馈和偏差记录。事实入库后只追加；修正通过新版本、新记录、取代关系或作废关系表达，不原地改写。
4. **过程任务**：接入任务、LangGraph 运行、复核任务、处置执行任务和通知任务。任务拥有稳定身份与显式状态转换，并保留每次转换的历史事件。
5. **查询投影**：风险态势、统一风险详情、待办列表和图谱视图。投影由前四类对象组合生成，不拥有业务事实，不能直接回写领域对象。

### 工程资料与证据身份

- 工程资料项表示用户认知中的同一份资料，具有稳定身份并归属于一个工程。
- 每次上传新内容或使用新的解析规则重新处理，都创建不可变的工程资料版本；每个版本分配新的 `资料ID`，旧版本不得覆盖。
- 资料段只属于一个确定的工程资料版本，资料段标识严格保持 `资料ID-章节ID-资料段ID`。证据定位无需在该格式之外再拼接隐藏版本号。
- 工程资料与空间区段通过关联关系表达；一份资料可以覆盖多个区段，不能将资料强制归属于单一区段。
- 连续监测数据采用“监测序列 → 不可变数据批次或时间窗口”；每个批次按相同规则登记为可追溯的工程资料版本。

### 知识与规则的版本粒度

- 工序节点、风险机理条目、规范条文、结构化评分规则、指标项和措施项等对象具有稳定身份与独立修订版本。
- 正式业务运行不读取零散条目的“最新版”，只引用已发布集合，例如站隧一体化施工工序模型版本、风险机理库发布版、指标体系版本和措施库版本。
- 发布集合只保存成员的精确版本引用，不复制条目内容；任一成员调整后，需要创建新的集合版本才能对后续运行生效。
- 适用规则集是根据工程适用性元数据快照与已发布规则集合生成的项目级不可变版本，审核发布后才能用于风险评估。
- 风险评估记录冻结适用规则集、权重、风险矩阵、阈值和适用性元数据的精确版本引用，不在运行期间追随“当前最新版”。

### 模型候选结果与正式风险事实

- LLM 模型输出结果只是一次 LangGraph 运行产生的不可变候选工件，不能直接作为标准化风险记录使用。
- 候选结果通过 Schema、证据、规则和完整性校验后，才写入标准化风险记录的新版本；低置信度、重大风险或校验失败时必须先完成人工复核。
- 自动通过和人工通过都必须形成验收决定，记录决定方式、依据、责任主体和时间。
- 标准化风险记录的新版本成立后触发新的风险评估；既有风险评估记录、预警信息和处置记录保持不变。
- 后续发现误判时追加作废决定及理由，由查询投影据此排除该版本的当前效力；历史事实不得物理删除。

### 评估、预警与处置的事实和任务

- 每次 RA-S5 计算生成一条不可变的风险评估记录；重新评估始终新增记录，通过触发原因与因果关系关联历史记录。
- 每次 RA-S6 触发生成不可变的预警信息，冻结当时使用的风险评估记录、触发指标与证据。
- 预警处置任务是独立过程对象。相同风险与触发范围持续越限时，新的预警信息关联到尚未关闭的任务；风险升级通过追加升级事件表达，避免重复生成无意义待办。
- 处置建议是不可变的建议版本；审核、接受、执行、完成和取消等进度由预警处置任务承担，不回写建议内容。
- 现场反馈和偏差记录只追加，并引用具体的预警处置任务、处置建议版本及处置前后的监测快照。

### 人工复核与审计

- 使用统一的复核任务过程对象承接工序模型、标准化风险记录、规则冲突、重大预警、处置建议和校准建议等审核场景。
- 复核任务只保存目标对象及其精确版本、触发原因、所需权限、期限和当前状态；具体审核意见与决定由对应领域的类型化 Schema 定义。
- 复核任务采用“待领取 → 复核中 → 已决定 / 已取消”。要求修改时结束当前任务，由提交方创建新版本和新的复核任务；审核过程中不得直接修改原对象。
- LangGraph 只在图状态中保存 `reviewTaskId` 并暂停；复核决定形成后，通过正式领域命令生成新事实或发布版本，再恢复原运行。
- 审计日志是不可变事件流，记录操作者、动作、目标版本、时间、原因和运行关联；业务对象仍是事实源，首期不采用完整事件溯源重建全部业务状态。

### 共享知识与项目版本

- 风险机理、规范条文、类比工程案例、指标定义和措施项默认属于共享知识库并携带适用条件；项目专有内容使用项目作用域保存，不复制整套知识库。
- 站隧一体化施工工序模型分为可复用基线和项目版本。项目可以从基线初始化，但识别运行只使用已审核发布的项目工序模型版本。
- 项目工序节点拥有自己的 `processNodeId`；标准化风险记录引用项目节点及其精确工序模型版本，不能只引用通用模板节点。
- 适用规则集、权重选择、风险矩阵选择和阈值组合均为项目级发布版本。
- 共享知识更新不会自动改变已发布项目版本；项目必须显式生成差异，完成审核并发布新版本后才对后续运行生效。

### 双时间语义

- 不可变事实同时记录业务发生时间与系统记录时间；受治理定义另外记录生效区间和发布时间。
- 补录的历史监测数据可以触发注明“历史补算”的新评估记录，不得伪装成当前实时数据。
- 当前风险由有效版本、业务时间及作废/取代关系计算，不能简单选择最后更新的数据库记录。
- 历史查询支持按指定业务时点与系统记录时点重建当时可见的风险、规则和预警状态。
