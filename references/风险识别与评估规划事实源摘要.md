# RiskFlow 规划事实源摘要

## 1. 用途与事实源边界

本文供 OpenSpec 规划 Agent 使用，综合以下五份材料：识别专利、评估专利、详细研究方案、2026 年度阶段汇报、合同研究内容与技术路线。它替代逐份读取原文；原始 Office 文件不进入 Agent 上下文。

事实采用以下优先级：

1. 识别专利规定风险识别方法与系统的算法主线。
2. 评估专利规定风险评估、预警和处置闭环的算法主线；其中批注属于审阅意见，不是已定字段契约。
3. 详细研究方案规定乙方实施蓝图和整体架构。
4. 阶段汇报用于核对对外术语、当前进展和近期验证重点。
5. 合同研究内容与技术路线规定甲乙双方边界和交付范围。

规划时还须以当前代码、已归档 OpenSpec 主规格和当前 change 为实现事实源。若它们与本文冲突，记录 drift 或 Open Question，不自行改写既有公共契约。

## 2. 项目目标、责任与交付

RiskFlow 面向变径盾构站隧一体化这一新装备、新工法。在缺少同类历史数据和成熟规则的条件下，系统要把多源工程资料、施工工序、工程机理、规范规则和监测数据组织成可追溯链路，完成风险识别、量化评估、动态预警与处置反馈。

甲方提供或审核：

- 风险源、风险因素、风险事件及其逻辑关系；
- 风险评估指标体系、量化标准、权重、风险分级准则、风险矩阵和接受准则；
- 规范与企业规则、措施知识，以及真实脱敏的设计、地勘、方案、日志和监测样本；
- 专家复核、仿真或试验结果。

乙方负责：

- 将业务输入实现为版本化配置、领域模型、知识库、算法和软件；
- 建设多源资料处理、知识图谱、检索增强、LLM 推理、确定性评分、预警处置和审计追溯能力；
- 交付数据标准、知识库/知识图谱原型、风险识别模型、评估平台、源代码和测试报告。

计划分三阶段推进：数据管线与知识图谱原型；识别模型与验证；评估、前后端和平台集成。阶段汇报显示当前已形成四层框架和对象链路，近期重点是样例资料接入、最小闭环联调及现场准确性、可解释性、可追溯性验证。

## 3. 一体化架构与主链路

四层架构固定为：

1. **数据接入层**：文件、数据库、API、OCR、富文本、CAD 标注、监测预处理、语义分块、风险事件接入和适用性元数据绑定。
2. **知识建模层**：站隧一体化施工工序模型（Process Model）、风险机理库（Risk-Mechanism KB）、检索证据库、风险评估标准库、指标体系、量化标准和措施库。
3. **智能推理层**：识别侧的混合检索、关系检索、机理驱动推理与规则/仿真约束；评估侧的规则适配、P/C 确定性计算、风险矩阵和处置建议约束校验。
4. **应用输出层**：标准化风险记录、工序风险关联图谱、风险评估记录、预警、处置与反馈、人工复核、证据追溯和风险管理系统接口。

固定端到端链路：

`资料段标识 → 工序节点 → 风险机理条目 → 标准化风险记录 → 风险评估记录 → 预警信息 → 处置建议 → 偏差记录 / 校准建议`

界面按业务闭环组织，至少覆盖风险态势总览、资料与监测接入、智能识别、工序风险关联图谱、风险评估、预警处置、证据追溯与人工复核、规则与指标版本管理。

## 4. 风险识别主线（RI-S1—RI-S6）

代码、测试和 OpenSpec 使用 `RI-S1`—`RI-S6`，面向甲方时使用专利原编号 S1—S6。

### RI-S1 工程资料接入与处理

- 接入施工设计、施工组织、地勘、施工步骤、装备设计、专项方案、日志、监测和风险评估资料；支持文件上传、数据库直连和 API。
- 元数据至少可记录类型、形成时间、工点位置、区间里程、来源单位和版本号。
- 按资料类型，再按章节、表格或监测时间段登记；资料段标识格式为 `资料ID-章节ID-资料段ID`。
- 权限登记记录操作者、时间戳和变更日志，结果必须能回到原始资料版本。

### RI-S2 格式化转换与合规校验

- 按文件类型分别执行 OCR、富文本解析、CAD 标注提取、监测预处理和语义分块，并保留章节、页码、表格结构、图注等结构信息。
- 监测预处理执行时间对齐、异常值和缺失值处理，计算短期斜率、加速度、频域主峰并生成监测摘要。
- 语义块不超过 512 字符，相邻块保留前后指针。
- 输出为 JSON-LD，至少含元数据、文本块、证据片段，可含表格、监测和工法步骤字段。
- 按字段、实体、关系和资料段逐项校验；失败记录原因并回到资料段标识重处理。

### RI-S3 站隧一体化施工工序模型

- 工序节点包含节点标识、输入描述和输出描述；最小工序集为：扩径准备、变径空间扩挖、刀盘扩径、盾体扩径、缩径转换。
- 装备节点最小集：小盾构、扩径模块、扩挖机构、拼装机械臂、伸缩帽檐、反力系统、推进系统、焊接装配单元。
- 构件节点最小集：钢管片、锚杆、尾盾。
- 状态参数最小分类：盾体直径、刀盘直径、主驱动伸出量、土仓/泥水压力、注浆参数、支护状态、反力体系状态、焊接/拼装状态。
- 工序间建立时间先后、资源依赖、受力依赖；工序与装备/构件建立作用关系。
- 校验节点状态和依赖关系；不能可靠收口时进入人工复核。模型保留资料段证据定位。

### RI-S4 风险机理库

- 机理条目来自工程机理知识、规范条文和工程资料中的风险描述。
- 条目字段至少覆盖风险机理类型、适用工序、地质水文适用条件、触发条件、监测征兆、风险事件和证据需求。
- 风险机理类型最小集：掌子面稳定性失效、支护结构失效、渗流突涌、过挖与地表沉降、施工装备故障、装配连接失效。
- 机理条目关联工序节点、状态参数和监测指标；证据定位指向 RI-S1 的资料段标识。
- 监测指标最小集：地表沉降、支护结构变形、地下水位、泥水压力、注浆压力、盾构姿态参数。
- 机理库记录来源、审核状态、版本和更新日志；校验触发条件、证据需求和关键工序覆盖。

### RI-S5 RAG + LLM 启发式推理

- 检索证据库（Retrieval Evidence Base）=`风险机理库 ∪ 规范标准库 ∪ 类比工程案例库`；案例至少覆盖盾构、顶管、暗挖、扩挖和地下工程风险。
- 同一证据库建立独立的向量相似度索引与 BM25 倒排索引；融合策略、权重和 Top-K 为配置，不写死在调用点。
- 关系检索取当前工序的机理条目、前后工序和依赖关系。
- 模型上下文必须包含工序节点描述、状态参数描述、受力依赖关系、风险机理条目和检索证据。
- 提示模板明确当前工序、上述五类依据和统一输出字段。
- 模型输出包含风险源、风险因素、风险事件、风险要素关系、证据定位信息和模型置信度；经结构化、字段统一和完整性校验后形成标准化风险记录。
- 不合格记录进入人工复核。规则一致性与仿真/试验约束可修正置信度。
- LoRA 微调是可选能力，只使用专家复核结果或合成样本；原始与微调权重同时可加载、可回退。

### RI-S6 入库与追溯

- 入库前检查工序节点标识、风险事件、证据定位信息、模型置信度；任一缺失即人工复核。
- 工序风险关联图谱节点包括工序节点、机理条目、风险源、风险因素、风险事件；至少保存工序↔风险事件、风险因素↔风险事件两类边。
- 结果存储写入标准化风险记录、资料来源、风险机理条目标识、版本、审计日志、综合置信度及其依据。
- 同一风险在多个工序节点或多个资料来源出现时，按工序一致性、事件表达相似性和证据定位相似性合并；无重复时显式跳过。
- 综合置信度由模型置信度、规则一致性、仿真约束和多来源合并共同形成，公式和权重配置化。

## 5. 风险评估、预警与处置主线（RA-S1—RA-S7）

代码、测试和 OpenSpec 使用 `RA-S1`—`RA-S7`，面向甲方时使用专利原编号 S1—S7。

### RA-S1 数据与适用性元数据

- 获取工程资料、风险事件和监测量测数据；首选上游是通过 RI-S6 完整性检查的标准化风险记录。
- 适用性元数据（Applicability Metadata）最小维度：施工工法数据、地层条件数据、工程阶段数据；可扩展形成时间、工点位置和空间区段。
- 风险事件标准化保留事件类别、发生时间、涉及构件和触发迹象。
- 监测数据执行时间对齐、异常值和缺失值处理，计算短期斜率、加速度、异常评分并生成摘要。
- 每次评估保存适用性元数据快照，不只引用可变项目主数据。

### RA-S2 指标体系与量化标准

- 至少包含发生可能性评估指标和后果严重性评估指标。
- 地下工程细分指标至少覆盖以下五组中的两组：地质与围岩、地下水与渗透、开挖与支护、施工工艺与设备、监测量测与周边环境。
- 每个指标配置适用条件、权重、分级区间、分值和阈值来源；权重记录来源和版本。
- 建立“资料字段/监测摘要字段 → 指标项”显式映射，评分时不临时猜测。
- 指标、量化标准、分级准则和矩阵由甲方提供或审核，并按不可变版本管理。

### RA-S3 标准条文结构化

- 风险评估标准库覆盖国家规范、行业标准和企业规程，保留来源、版本和条文证据定位。
- LLM 将条文转换为结构化评分规则：适用条件、指标项、评分阈值、分级区间、例外条款。
- 规则适用条件显式抽取施工工法、地层条件和工程阶段；定性描述映射到可度量指标或区间。
- 无法可靠结构化的规则进入人工复核。

### RA-S4 一致性与适用性校验

- 先检测相互冲突或覆盖重叠的规则，输出冲突说明并交专家复核。
- 再严格匹配项目元数据与规则适用条件，筛除不适用规则，形成适用规则集（Applicable Rule Set）。
- 适用规则集记录生成时间、审核状态、版本和项目元数据快照，支持差异比较与回滚。
- 规则适配由结构化、一致性校验、适用性校验和审核共同完成，不能由 LLM 自行选规则。

### RA-S5 风险评分与分级

- 从工程资料和监测摘要取得指标实际值，经已发布适用规则集映射单指标分值。
- 结合版本化权重分别计算发生可能性分值 P 和后果严重性分值 C，再通过甲方版本化风险矩阵确定等级。
- P/C 聚合、矩阵映射和最终等级是确定性、可重放的领域逻辑，LLM 不直接给最终分值或等级。
- 专利中的“5×5”“I—IV 级”是实施示例，不得替代甲方发布的矩阵和等级配置。

### RA-S6 动态预警

- 触发类型：风险等级超过风险可接受阈值、监测指标越限、趋势/加速度/异常评分越限、多指标联合规则命中。
- 风险可接受阈值与监测预警阈值分别配置、分别追溯。
- 越限指标形成触发指标（Trigger Indicator）；预警保留等级、触发类型、触发指标、证据和建议处置方向。
- 通知策略与责任人由配置驱动；预警先可靠入库，再发送外部通知。

### RA-S7 处置、反馈与校准

- 从版本化措施库按风险事件和适用性元数据形成候选集；LLM 只组合和排序候选措施。
- 处置建议（Response Recommendation）包含措施、顺序、资源需求和目标指标，依次通过触发指标一致性、规范合规性、现场资源与工序可执行性校验。
- 依据历史统计、监测趋势或机理模型预测处置后的风险变化；实施后采集监测和现场反馈，形成偏差记录（Deviation Record）。
- 偏差越限只生成校准建议。权重、阈值和区间不得自动覆盖生效版本，必须经人工审核生成新版本并支持回滚。

## 6. 关键记录契约

规划不得另起字段体系；以 OpenSpec 主规格中的版本化 Schema 为最终 SSOT。以下是来源材料要求的最小语义集合。

### 6.1 识别记录

标准化风险记录（Standardized Risk Record）：

- `processNodeId` 工序节点标识；
- `riskSource` 风险源；
- `riskFactor` 风险因素；
- `riskEvent` 风险事件；
- `riskElementRelations` 风险要素关系；
- `evidenceLocator` 证据定位信息；
- `modelConfidence` 模型置信度。

完整性检查必含：`processNodeId`、`riskEvent`、`evidenceLocator`、`modelConfidence`。

### 6.2 评估记录

- 结构化评分规则（Structured Scoring Rule）：规则标识、适用条件、指标项、评分阈值、分级区间、例外条款、条文证据定位、规则版本、审核状态。
- 风险评估记录（Risk Assessment Record）：记录标识；`riskRecordId` / `externalRiskEventId` 二选一且仅一个；适用性元数据快照；P、C、风险等级；指标明细、触发指标、证据；适用规则集与风险矩阵版本；审计信息。
- 预警信息：风险评估记录标识、预警等级、触发类型、触发指标、证据、建议处置方向、通知状态、审计信息。
- 处置建议：预警标识、措施、顺序、资源、目标指标、三项校验结果、审核状态、版本和审计信息。
- 偏差记录与校准建议：处置建议标识、预测与实际风险变化、偏差值、偏差阈值版本、证据、校准建议、审核状态、版本和审计信息。

识别与评估共享同一个风险事件事实。评估通过 `riskRecordId` 引用识别结果，不复制或改写；甲方外部事件使用 `externalRiskEventId` 并建立独立证据链。

## 7. 编排与确定性边界

- 顶层 `riskFlowGraph` 组合可独立运行和测试的 `identificationGraph`、`assessmentGraph`；预警和处置只能作为评估子图的受控分支。
- LangGraph 负责编排、状态转换、检查点、重试、暂停/恢复和人工复核路由；Schema、评分、矩阵、阈值、版本发布和持久化规则由独立领域模块负责。
- 图状态只传递版本化 DTO，优先保存实体标识、版本和结果引用；节点不跨层读取或修改内部存储。
- LLM 可用于工程文本抽取、机理推理、条文结构化和候选措施组合；P/C、矩阵、阈值、规则一致性和 Schema 校验必须确定性执行。
- 节点幂等；外部写入使用运行标识和业务幂等键。检查点与业务入库分别保留并可关联。
- 规则冲突、字段不完整、低置信度、处置校验失败和校准发布均为显式人工复核状态。
- 监测摘要、适用性元数据、适用规则集版本或风险矩阵版本变化时追加新的评估记录，历史记录不覆盖。
- 每次运行记录图/节点版本、输入及版本、输出实体、路由、模型/提示版本、规则/矩阵版本、操作者和时间戳。

## 8. 规划完成检查

每个 change 的 proposal、specs、design、implementation-plan 和 tasks 至少回答：

- 涉及 RI-S1—RI-S6 或 RA-S1—RA-S7 的哪些步骤，是否保留可追踪对应物；
- 输入、输出、Schema、版本、权限、事务、幂等、审计和人工复核边界是什么；
- 是否维持四层边界和识别→评估的单一风险事件事实；
- 业务规则是否来自甲方审核的版本化配置，是否避免写入业务代码；
- LLM 与确定性逻辑的边界是否清楚；
- 每条结果能否沿端到端链路回放并解释；
- 数据或业务定义尚未由甲方提供时，是否明确标注合成样本、占位配置和待审核状态。
