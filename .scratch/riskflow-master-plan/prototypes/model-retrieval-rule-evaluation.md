# RiskFlow 模型、检索与规则质量评测策略——待复核推荐记录

> 状态：Wayfinder 已确认的规划基线；本文不替代后续 OpenSpec 正式规格。

## 1. 评测要回答什么

### 问题 1：是否用一个综合分判断 MVP 质量？

可选方向：

- 把解析、检索、生成、规则和处置质量加权成一个总分；
- 按能力分别设门槛，任一硬门槛失败即不通过；
- 只做专家主观验收，不设机器指标。

**推荐默认：按能力分别设门槛，不计算综合总分。**

暂定结论：评测结果只使用“通过 / 不通过 / 无法评测”三种状态。结构、权限、证据、确定性计算和安全约束属于硬门槛；语义质量采用指标门槛与专家判断共同判定。任何切片的关键错误不得被其它高分抵消。“无法评测”不能当作通过。

### 问题 2：开发验证、技术就绪和 MVP 验收是否共用一套数据？

可选方向：

- 所有阶段反复使用同一批样例；
- 开发集、冻结评测包、甲方验收包分开；
- 只等甲方资料到位后一次性验收。

**推荐默认：采用三层数据用途。**

暂定结论：

1. **开发集**用于调试、提示模板迭代、错误分析和自动化测试，可以包含合成数据；
2. **冻结评测包**用于模型、检索、Agent 和规则质量门禁，冻结后不得继续参与调参；
3. **甲方验收包**由甲方提供或书面认可，独立于前两者，只用于最终 MVP 验收。

合成数据可以覆盖边界和故障，但只能证明技术就绪。没有甲方验收包时，最高状态仍是“技术就绪”。

### 问题 3：数据如何切分，才能避免同一资料泄漏到训练与评测？

可选方向：

- 随机切分资料段或问答；
- 按原始资料、工程、规范条文族和风险事件族整体切分；
- 不做隔离，只在报告里声明复用情况。

**推荐默认：按来源家族整体隔离，禁止按资料段随机切分。**

暂定结论：同一工程资料版本的相邻资料段、同一规范条文及其改写、同一风险事件的近义表达、同一合成模板的派生样本必须落在同一用途集合。LoRA 训练数据与冻结评测包、甲方验收包之间按内容哈希、资料身份、条文身份和语义近重复四层查重。发现泄漏后，该次结果作废并重新建立冻结评测包。

## 2. 评测包与金标准

### 问题 4：冻结评测包最少覆盖哪些业务切片？

可选方向：

- 只覆盖汇报主线“变径空间扩挖—地表沉降”；
- 覆盖 MVP 实际路径及专利最小集合；
- 一开始覆盖完整产品的全部格式、指标和外部系统。

**推荐默认：覆盖 MVP 实际路径及专利最小集合，不扩张到完整产品。**

暂定结论：冻结评测包至少覆盖：

- 五个必含工序节点和六类风险机理类型；
- 风险机理库、规范标准库、类比工程案例库三类检索来源；
- DOCX、文本型 PDF、扫描型 PDF/图片、XLSX/CSV 四组业务可用输入；
- 至少一条地表沉降监测序列及短期斜率、加速度、频域主峰、异常评分；
- 施工工法数据、地层条件数据、工程阶段数据三个适用性维度；
- 四类预警触发、处置建议三项校验及五类必经内嵌 Agent 任务；
- 正例、负例、证据不足、规则冲突、适用性未知、字段缺失、越界候选和应暂停场景。

每个关键切片至少应有 5 个正例和 5 个负例；总样本少于 30 的指标必须同时报告原始成功/失败数，不单独依赖百分比。资料不足导致某切片无法达到最低覆盖时，该切片记为“无法评测”，不得用其它切片代替。

### 问题 5：语义任务的金标准由谁、以什么形式确认？

可选方向：

- 由当前模型生成答案，再由另一轮模型校对；
- 一名编制者标注，领域复核人逐项审核关键语义与证据；
- 只保存自由文本专家意见。

**推荐默认：一人编制、一名领域复核人审核，使用结构化金标准。**

暂定结论：标准化风险记录、知识条目、检索相关性、结构化评分规则和处置建议的金标准必须绑定资料段证据。风险事件采用规范化身份、可接受同义表达和关系集合比较，不精确比对整句文字。争议项在裁定前标记为“不确定”，不进入分母；不得让被测模型裁定自己的答案。

确定性金标准直接来自已审核版本化配置：指标映射、权重、评分策略、风险矩阵、两类阈值和措施约束。甲方规则尚未到位时，只能使用明确标注的同形合成版本，报告不得把它描述为甲方业务正确性。

### 问题 6：评测结果按什么粒度聚合？

可选方向：

- 只给全量平均值；
- 同时给总体值、关键切片值和逐例错误清单；
- 只展示逐例结果，不做指标。

**推荐默认：总体、切片、逐例三层并存。**

暂定结论：报告至少按输入格式、工序节点、风险机理类型、证据来源、规则适用性场景、预警触发类型和 Agent 任务类型切片。总体达标但任一关键切片触发硬失败时，能力仍判为不通过。所有指标必须显示分子、分母和评测包版本。

## 3. 数据接入与知识编制质量

### 问题 7：资料解析与监测清洗的质量门槛是什么？

可选方向：

- 只要程序没有报错就算成功；
- 结构与关键业务值设硬门槛，普通文本设质量目标；
- 对所有字符、空白和版式做完全一致比较。

**推荐默认：结构与下游使用值设硬门槛，普通文本采用规范化准确率。**

暂定门槛：

| 能力 | 指标与门槛 |
|---|---|
| 合法样例处理 | 处理流程完成率 100%；非法或不支持样例必须形成结构化失败，不得产生空成功结果 |
| JSON-LD 与资料段 | Schema、资料段标识唯一性、前后指针、来源版本和证据可达性 100% 正确 |
| DOCX / 文本型 PDF | 规范化字符准确率 ≥ 99.5%；被标注为必需的章节、表格、页码和图注结构召回率 100% |
| 扫描件 / OCR | 规范化字符准确率 ≥ 97%；会被识别或评估使用的关键工程字段召回率 100%，否则该资料段不得判为业务可用 |
| XLSX / CSV / 监测 | 下游使用的单元格、采样值、时间、单位和对象映射 100% 正确；单位换算和衍生特征在版本化数值容差内 100% 一致 |
| 不可变与审计 | raw 未被改写、排除范围明确、处理版本与前后差异可重建，均为 100% |

数据清洗 Agent 的有用性另按“被确定性模块接受的正确增量 / 全部接受增量”计算，目标 ≥ 95%；任何关键数值的有害修改、越权处理或无证据判定均为硬失败。业务可用性判断在关键继续/暂停场景上必须 100% 与金标准一致，总体一致率目标 ≥ 90%。

### 问题 8：工序模型、风险机理和结构化知识候选如何计分？

可选方向：

- 对整段生成文本做相似度；
- 对字段、实体、关系、证据和覆盖分别计分；
- 只看最终人工是否发布。

**推荐默认：以结构化对象和证据为评测单元。**

暂定门槛：候选 Schema 通过率和引用可达率在进入人工审核前必须达到 100%；字段、实体和关系的 micro-F1 ≥ 0.90，任何关键切片不得低于 0.80；证据支持精确率 ≥ 0.95；五个必含工序节点覆盖率 100%。无可靠证据、无法结构化或存在冲突的候选应正确进入复核，静默补造知识属于硬失败。人工审核后的发布版本仍须满足 Schema、证据和专利最小覆盖 100%。

## 4. 混合检索与检索 Agent

### 问题 9：混合检索用什么基线和指标？

可选方向：

- 只评完整链路，不保存单路结果；
- 同时评 BM25、向量、RRF 融合，并保留无检索提示基线；
- 只由专家浏览若干 Top-K。

**推荐默认：BM25、向量和融合三路独立计量，以冻结相关性标注为金标准。**

暂定门槛：

| 指标 | MVP 冻结评测包门槛 |
|---|---|
| Recall@10 | 总体 ≥ 0.90；各关键切片 ≥ 0.80；标记为关键证据的查询为 1.00 |
| Precision@10 | 总体 ≥ 0.70，且无权限、未发布或明确不适用证据不得进入结果 |
| NDCG@10 | ≥ 0.80 |
| MRR | ≥ 0.75 |
| 零结果率 | ≤ 2%；存在标注相关证据的关键查询不得零结果 |
| 本地单查询延迟 | 冻结 MVP 语料、单查询条件下 p95 ≤ 2 秒，不含 Agent 和主推理模型时间 |

融合结果的 Recall@10 与 NDCG@10 不得低于两条单路中的较优结果，关键查询不得因融合丢失相关证据。检索综合得分只用于同一查询内排序，不与模型置信度或综合置信度混用。

索引 `ready` 的硬门槛继续是成员、双索引、版本、内容哈希、回查、权限和过滤字段 100% 对账。构建时间、峰值内存和索引体积必须记录；它们的部署容量门槛由“确定 MVP 测试、验收与交付证据”结合最终语料规模和虚拟机资源确定，不能在质量票中用脱离规模的绝对数值冒充结论。

### 问题 10：检索 Agent 的增量价值如何判断？

可选方向：

- 只要 Agent 调用了工具就算完成；
- 比较同一冻结基线在 Agent 前后的质量、安全、成本和延迟；
- 只由模型自评是否更好。

**推荐默认：做成同一工作项上的成对对比。**

暂定门槛：Agent 后的 Recall@10 和 NDCG@10 总体不得下降，关键证据召回不得下降；无依据补充、越权候选、错误版本引用和硬冲突证据的静默删除均为 0 容忍；错误提升或降级率 ≤ 5%。同时报告新增相关证据数、误降级数、无依据补充数、工具调用、模型调用、预算消耗和端到端耗时。只改善排名但增加关键错误的 Agent 不通过。

## 5. 风险识别模型质量

### 问题 11：标准化风险记录按文本相似度还是风险事实计分？

可选方向：

- 逐字比较完整输出；
- 按风险事件身份、字段、关系和证据支持计分；
- 只检查 Schema。

**推荐默认：按结构化风险事实计分，文本只做归一化辅助匹配。**

暂定门槛：

| 指标 | 门槛 |
|---|---|
| 首次结构化输出 Schema 通过率 | ≥ 95%，用于发现提示模板和模型问题 |
| 有界修复后可自动验收记录 | Schema、必填字段、枚举、权限和证据可达性 100% |
| 风险事件级支持精确率 | ≥ 0.90 |
| 风险事件级召回率 | ≥ 0.85；关键风险召回率 1.00 |
| 证据支持正确率 | ≥ 0.95；自动验收记录不得引用不存在、越权或无关证据 |
| 无依据风险记录率 | ≤ 5%；关键风险或自动验收切片中为 0 |

比较基线包括：无检索提示、确定性基线检索但无 Agent 审阅、完整“混合检索 + Agent 审阅 + 五项上下文”三种配置。完整配置必须提高或保持支持精确率与关键风险召回，不能用增加无依据输出换取表面召回。

### 问题 12：`modelConfidence` 和综合置信度能否直接当作准确率？

可选方向：

- 直接以模型自报置信度排序并设阈值；
- 只把置信度当作一个待校准信号，用冻结评测包选择自动验收阈值；
- 完全不评置信度。

**推荐默认：置信度只作待校准信号。**

暂定结论：自动验收阈值应在冻结评测包上选择，使自动验收切片的风险事件支持精确率 ≥ 95%、关键错误为 0；未达到时扩大人工复核范围。样本达到 100 条以上时报告 Brier Score 和 Expected Calibration Error；MVP 小样本不足时只报告分桶准确率、覆盖率和原始计数，不把不稳定的校准统计作为硬门槛。人工修正不回写 `modelConfidence`。

## 6. 规则适配、确定性评估与预警

### 问题 13：结构化评分规则和适用规则集如何分开评？

可选方向：

- 把规则抽取和适用性筛选混成一个端到端正确率；
- 分别评价 LLM/Agent 候选质量与确定性规则适配；
- 只检查最终 P/C 是否正确。

**推荐默认：候选质量与确定性适配分开。**

暂定门槛：

- 结构化评分规则候选的关键字段 micro-F1 ≥ 0.95，规范条文证据正确率 100%，不得编造数值阈值；无法可靠映射和例外歧义的复核召回率 100%；
- 一致性校验对人工植入的冲突与重叠召回率 100%，非冲突规则误报率 ≤ 5%；
- 对已审核规则执行确定性适用性校验时，入选精确率和召回率均为 100%，并完整记录每条入选或筛除原因；
- 任何明确不适用规则进入适用规则集均为硬失败，检索排名或 LLM 判断不得覆盖适用性校验。

### 问题 14：P/C、风险矩阵与四类预警使用统计指标还是精确一致？

可选方向：

- 用总体准确率，允许少量误差；
- 对所有金标准、阈值边界和矩阵单元要求精确一致；
- 抽几个示例人工核对。

**推荐默认：确定性领域逻辑必须精确一致。**

暂定门槛：资料字段/监测摘要到指标项映射、单位换算、单指标分值、P/C 聚合、舍入、矩阵映射、风险可接受阈值、监测预警阈值和四类触发在全部金标准案例上 100% 一致。风险矩阵的每个生效单元、每个阈值的低于/等于/高于边界、缺失和单位不兼容分支都必须覆盖。数值容差只能由版本化公式明确声明；不能事后放宽测试容差。

## 7. 处置、反馈与五类 Agent 任务

### 问题 15：处置建议怎样兼顾安全约束与专家可用性？

可选方向：

- 只让专家给整体印象分；
- 先做硬约束，再评价组合、顺序和完整性；
- 只要三项校验通过就认为质量足够。

**推荐默认：硬约束先行，专家评价只覆盖工程可用性。**

暂定门槛：候选措施必须 100% 来自冻结候选集，触发指标一致性、规范合规性和现场资源与工序约束可执行性三项校验不得被绕过；候选集外措施、禁止性冲突和越权批准为 0 容忍。通过硬约束的建议，其措施项、实施顺序、资源需求和目标指标完整率 ≥ 95%，领域专家判为“可直接采用或仅需非实质编辑”的比例 ≥ 90%；任何可能造成安全危害的建议直接判该切片失败。

处置效果预测按冻结策略与金标准数值容差验证；偏差记录必须 100% 使用预测时的同口径版本。校准建议候选必须 100% 引用偏差、预测、反馈和原规则版本，直接修改权重、阈值、区间或创建生效版本的行为为 0 容忍。

### 问题 16：五类必经 Agent 是否共用一个笼统成功率？

可选方向：

- 共用“任务完成率”；
- 共用治理硬门槛，各任务另有业务质量指标；
- 每类完全独立，不做横向治理检查。

**推荐默认：共用治理硬门槛，业务价值按任务类型分别评价。**

暂定硬门槛：工具白名单违规、权限扩大、预算越限、静默换模型/策略、跳过必经任务、修改已发布定义、改变 P/C/矩阵/阈值、缺失关键审计工件均为 0 容忍；任务输入、原始响应、工具行动、Agent 增量、确定性接受/拒绝及正式结果引用的审计完整率为 100%。

业务质量分别使用：清洗的正确增量和有害修改、知识编制的字段/关系/证据、检索审阅的成对收益、处置建议的约束与专家可用性、校准建议的引用完整性与建议对象合理性。共用“任务完成率”只作运行指标，不代表质量。

## 8. 人工抽样、重复运行与基线治理

### 问题 17：哪些结果必须人工复核，剩余结果怎样抽样？

可选方向：

- 全部结果人工逐条复核；
- 只随机抽 5%；
- 高风险与异常全检，其余分层抽样。

**推荐默认：冻结金标准由人工全量审核；系统输出采用风险分层抽样。**

暂定抽样规则：

- 甲方验收包中的语义输出 100% 人工复核；
- 冻结评测包的金标准在发布前 100% 经领域复核人审核；
- 运行评测时，全检关键风险、规则冲突、低置信度、系统与金标准不一致、Agent 产生实质增量、应暂停/复核的场景；
- 对其余自动验收结果，在每个关键切片中抽取 `min(该切片全部结果, max(30, 向上取整(20% × 该切片结果数)))`；
- 抽样发现关键错误时，该切片判为失败并扩展为 100% 复核；普通错误超过门槛时同样扩检，不得只替换出错样本后重新计算。

### 问题 18：LLM 和 Agent 的非确定性怎样进入评测？

可选方向：

- 只运行一次；
- 每个冻结配置运行三次，确定性节点另做精确重放；
- 运行很多次取最好结果。

**推荐默认：语义链路三次独立运行，报告均值、最差值和逐例波动。**

暂定结论：模型 GGUF 哈希、llama.cpp 构建、量化配置、采样参数、随机种子、提示模板、检索索引代际、Agent 策略、工具、预算和评测包版本必须冻结。硬安全门槛三次都要通过；语义指标以三次平均值达标且最差一次不低于门槛 2 个百分点为通过。不得挑最好一次作为正式结果。确定性模块在同输入同版本下必须精确重放，业务事实引用和计算结果 100% 一致。

### 问题 19：质量门槛可否在看到评测结果后调整？

可选方向：

- 随项目进度灵活修改；
- 门槛先版本化冻结，变更只能创建新版本并保留旧结果；
- 永远固定首版门槛。

**推荐默认：门槛版本化冻结，可提高或基于正式依据修改，但不得静默降低。**

暂定结论：每次报告引用数据集、标注、评测器、门槛和候选系统版本。若门槛或标注发生实质变化，必须生成新评测版本并同时保留旧报告。使用同一冻结评测包反复调参后，该包降级为开发集，必须准备新的未见评测包。甲方正式指标到位后可以替换同形合成规则，但历史结果仍保留并明确不可作为甲方验收结论。

## 9. LoRA 准入与退出

### 问题 20：什么情况下才启动 LoRA？

可选方向：

- 因合同或研究方案提到 LoRA，MVP 默认实施；
- 只在基础模型经提示、检索和 Schema 收口后仍稳定失败时实施；
- 永不实施微调。

**推荐默认：LoRA 是由评测触发的后续能力，不是 MVP 默认依赖。**

暂定准入条件必须同时满足：

1. Qwen3.8-27B 基线已完成提示模板、五项上下文、混合检索、Agent 检索审阅和有界结构修复，仍在冻结评测包上未达到至少一个语义质量门槛；
2. 失败集中在可由参数适配学习的稳定任务，不属于资料缺失、错误规则、检索漏召回、上下文超窗、Schema 缺陷或确定性逻辑错误；
3. 已有独立、去重、证据可靠的训练集，且冻结评测包和甲方验收包没有泄漏；
4. 训练、量化、加载、回退和审计能够在私有部署约束内完成，原始权重与 LoRA 权重可以同时加载和回退。

LoRA 候选与原模型必须在完全相同的检索、提示、量化和评测配置下比较。候选需使触发准入的主指标提高至少 5 个百分点，或在样本较小时把该类关键错误数降低至少 30%；不得出现任何硬门槛回归、关键切片回归或无依据输出增加，其余语义指标最差回归不超过 2 个百分点，推理 p95 增幅不超过 25%。不满足即不进入 MVP 基线，保留原模型。

## 10. 评测模块与交付接口

### 问题 21：评测能力应散落在各业务模块还是形成统一接口？

可选方向：

- 每个业务模块自己写脚本和报表；
- 一个评测编排模块管理数据集、运行、指标和报告，各领域模块提供少量任务适配器；
- 直接把生产 LangGraph 当作测试框架。

**推荐默认：建立一个深层“质量评测”模块，不另造业务流程。**

暂定结论：质量评测模块的外部接口只需要“登记冻结评测包、对指定候选版本运行评测、读取版本化报告”三类能力。解析、知识、识别、评估、预警处置和 Agent 模块各自提供受控评测适配器，复用生产接口与 Schema；评测模块不复制 P/C、矩阵、阈值、检索或领域校验实现。生产 LangGraph 可以作为端到端被测对象，但不承担数据集管理和指标计算。

每份报告至少包含：评测包及来源资格、候选与全部策略版本、总体/切片/逐例结果、基线差异、三次运行波动、硬失败、人工复核记录、资源消耗、原始工件引用和最终状态。

### 问题 22：本票与后续验收票、OpenSpec 路线如何分工？

可选方向：

- 本票直接拆成编码任务；
- 本票固定质量策略，后续票定义系统级验收和交付证据，最终路线再切 OpenSpec changes；
- 把所有细节继续留给后续票。

**推荐默认：本票固定质量策略和门槛，后续票负责整体验收编排。**

暂定结论：“确定 MVP 测试、验收与交付证据”应引用本文，补充功能、权限、安全、恢复、部署、系统性能、离线安装和交付证据模板，并把甲方确认项与实机基准项分开。最终 OpenSpec 路线至少要让评测数据契约与报告 Schema 先于模型/检索调优落地；P/C、矩阵和预警的金标准仍由各自领域模块拥有，质量评测模块只调用，不建立第二套事实源。

## 11. 当前推荐结论摘要

- 不设综合总分；硬约束、确定性计算和高风险安全条件一票否决。
- 使用开发集、冻结评测包、甲方验收包，按来源家族隔离，防止训练和评测泄漏。
- 评测包覆盖专利最小集合、MVP 输入、三类证据、四类触发、三项处置校验与五类 Agent。
- 解析、知识、检索、标准化风险记录、规则候选、适用性、P/C、预警、处置和 Agent 分别使用稳定可观察指标。
- P/C、矩阵、阈值、权限、证据可达性与 Agent 治理使用 100% 硬门槛；语义能力按冻结切片计量。
- 甲方验收包语义输出全检；其它输出采用高风险全检和分层抽样，发现关键错误即扩检。
- 语义链路运行三次，不挑最好结果；确定性模块必须精确重放。
- LoRA 只在完整基线仍稳定失败、失败可学习且数据隔离充分时准入，并须证明实质收益和可回退。
- 质量评测形成一个深层模块，复用各领域正式接口，不复制业务逻辑或另建评分事实源。

## 12. 复核方式

复核时可以只指出需要改动的“问题 N”和你的替代选择；未提出异议的项目将按上述推荐默认项确认。若某一改动会推翻后续依赖结论，应从该问题起重新展开受影响分支，再正式关闭前沿票。
