## Purpose

为 RiskFlow 提供可独立验收的 PostgreSQL 业务事实、审计、事务 Outbox、幂等消费与 LangGraph 检查点基础，使后续领域模块在最小权限和至少一次执行条件下仍能原子、可追溯且可恢复地形成事实。

## ADDED Requirements

### Requirement: PostgreSQL schema 与角色保持事实和权限边界

系统 MUST 在同一 PostgreSQL 实例中隔离业务事实、只追加审计、Outbox 与 LangGraph 检查点，并为迁移、业务运行、Outbox Worker 和 checkpointer 提供不同的最小权限角色。业务运行角色不得更新或删除审计，不得管理 checkpointer 内部表；checkpointer 角色不得读取或写入业务、审计或 Outbox；PUBLIC 不得在这些 schema 中创建对象。部署秘密、LOGIN 主体及角色成员关系不属于本能力保存的业务数据。（RI-S14、RI-S44、RI-S62～RI-S65；RA-S4～RA-S7）

#### Scenario: 各运行角色只访问自己的数据面
- **WHEN** 业务、Outbox Worker 与 checkpointer 分别使用其运行角色访问 PostgreSQL
- **THEN** 每个角色只能执行已授予的数据操作
- **AND** 跨边界读取、DDL、审计修改或 checkpointer 访问被 PostgreSQL 拒绝

#### Scenario: 审计修改权限被拒绝
- **WHEN** 普通业务或 Worker 角色尝试更新或删除已保存审计
- **THEN** PostgreSQL 拒绝操作
- **AND** 原审计记录保持不变

#### Scenario: 敏感正文不进入基础设施记录
- **WHEN** 原子提交保存审计、命令收据或待发布事件
- **THEN** 基础设施表只保存 C01/C02 已声明的身份、版本、时间、授权、因果、结果和事实引用
- **AND** 不保存资料正文、证据正文、模型响应、凭据、连接串或思维链

### Requirement: 模块迁移按领域目录和 change 标识自动发现

系统 MUST 从版本化领域目录与 change 标识目录发现迁移贡献，校验全局序号、路径、导出形状和重复项，并按全局序号确定执行顺序。新增模块迁移 MUST 只增加所属目录文件，不修改中央迁移索引；迁移执行 MUST 使用专用迁移身份、互斥锁与受控部署入口，应用或 Worker 启动不得隐式执行迁移或 checkpointer setup。

#### Scenario: 新模块迁移无需中央注册
- **WHEN** 一个已归档依赖的 change 在自己的领域/change 目录增加合法且未冲突的迁移文件
- **THEN** 迁移提供器自动发现并按全局序号返回该迁移
- **AND** 无需修改中央数组、barrel 或注册表

#### Scenario: 非法或重复迁移在执行前失败
- **WHEN** 发现非法领域目录、非法 change 标识、非法文件名、缺失迁移导出或重复全局序号
- **THEN** 迁移入口返回结构化终止错误
- **AND** 不执行任何待处理迁移

#### Scenario: 并发迁移串行化
- **WHEN** 两个部署执行者同时尝试运行同一迁移集合
- **THEN** PostgreSQL/Kysely 迁移锁保证迁移只执行一次并形成一致历史
- **AND** 未获取执行权的一方不会重复创建 schema 或表

#### Scenario: 启动路径不改变数据库结构
- **WHEN** API、Worker 或 checkpointer 运行时工厂启动
- **THEN** 它们不自动运行领域迁移或 checkpointer setup
- **AND** 未完成部署迁移时以结构化技术错误失败，不临时建表继续运行

### Requirement: 业务事实、审计、命令结果与待发布事件原子提交

系统 MUST 以单个 PostgreSQL 本地事务执行一个模块命令的事实写入、只追加审计、命令幂等结果和零个或多个 C02 `DomainEventV1` Outbox 行。所有事件 MUST 先通过 C02 strict Schema，并与命令的工程、生产命令、业务幂等键和审计引用一致；任一步失败 MUST 回滚全部写入。事务作用域不得向跨模块调用方暴露 SQL、Kysely、表行、任意仓储或通用查询器。（RI-S14、RI-S44、RI-S62～RI-S65；RA-S4～RA-S7）

#### Scenario: 原子提交成功
- **WHEN** 模块事实写入、审计和全部待发布事件均合法且数据库操作成功
- **THEN** 它们与命令结果在一次事务提交后同时可见
- **AND** 每条事实、审计和事件保留工程、版本、业务发生时间、系统记录时间、命令、授权与因果引用

#### Scenario: 审计或 Outbox 写入失败时整体回滚
- **WHEN** 事实写入后审计或任一 Outbox 行因约束、权限或连接故障失败
- **THEN** 事实、审计、命令结果和全部 Outbox 行均不可见
- **AND** 重试仍可使用原命令与业务幂等键重新执行

#### Scenario: 事件引用与命令不一致时拒绝提交
- **WHEN** 待发布事件的工程、生产命令、幂等键或审计引用与当前原子提交不一致
- **THEN** 事务单元在写入前返回结构化终止错误
- **AND** 不向 Outbox 保存契约外或跨工程事件

### Requirement: 命令幂等在并发与重试下保持单一结果

系统 MUST 以 C02 固定的 `(projectId, commandKind, idempotencyKey)` 作为命令唯一键，并比较规范化 strict payload 的确定性摘要。相同键和相同 payload 的串行或并发重试 MUST 返回首次完成的同一结果引用，不再次执行事实写入、审计或事件入队；相同键和不同 payload MUST 返回 C02 `IDEMPOTENCY_CONFLICT` 语义且保留原结果。

#### Scenario: 相同命令重试返回原结果
- **WHEN** 已完成命令以相同工程、命令类型、幂等键和有效载荷再次提交
- **THEN** 系统返回首次提交的结果、审计和事件引用
- **AND** 事实、审计和 Outbox 数量不增加

#### Scenario: 并发相同命令只执行一次
- **WHEN** 两个执行者并发提交相同幂等身份与相同有效载荷
- **THEN** 唯一约束和事务锁使业务回调只形成一个已提交结果
- **AND** 两个调用方观察到同一逻辑结果引用

#### Scenario: 同键不同载荷冲突
- **WHEN** 调用方复用已存在的幂等键提交不同的 strict payload
- **THEN** 系统返回不可重试的幂等冲突并指向原命令
- **AND** 原事实、审计、命令结果和事件保持不变

### Requirement: Outbox 以租约和至少一次语义可靠投递

系统 MUST 从已提交 Outbox 表批量领取到期事件，使用有期限租约和锁所有者防止同一时刻重复处理，并只在投递成功后确认发布。投递失败 MUST 按冻结策略记录尝试次数、结构化错误、下次重试时间；进程在发布后、确认前崩溃时，租约到期后 MUST 允许重投。达到冻结最大尝试次数的事件 MUST 保留为终止失败，不得删除、伪装已发布或阻塞其它可投递事件。

#### Scenario: 正常领取并确认发布
- **WHEN** Worker 领取一批到期事件、投递成功并以同一租约确认
- **THEN** 每条事件变为已发布并记录确认时间
- **AND** 后续扫描不再领取这些事件

#### Scenario: 发布后确认前崩溃导致重投
- **WHEN** 投递回调成功后 Worker 在确认前终止
- **THEN** 事件在租约到期后重新变为可领取
- **AND** 系统按至少一次语义再次投递同一 `eventId`

#### Scenario: 旧租约不能确认新领取
- **WHEN** 旧 Worker 在租约过期且事件已被新 Worker 领取后提交确认或失败结果
- **THEN** 系统返回可重试的租约丢失错误
- **AND** 不覆盖当前租约、投递状态或尝试记录

#### Scenario: 并发批量领取不重复占有事件
- **WHEN** 多个 Worker 同时扫描同一批到期事件
- **THEN** 每条事件在该租约期内最多由一个 Worker 获得
- **AND** 已锁定事件不会阻塞其它未锁定事件被领取

### Requirement: 每个消费者对重复领域事件幂等收口

系统 MUST 以 `(consumerName, eventId)` 保存消费者收件箱记录，并校验同一事件身份对应的规范化事件摘要。消费者业务写入与完成收据 MUST 使用同一 PostgreSQL 事务；成功重投返回原处理结果，不再次产生业务事实。处理失败或进程终止 MUST 回滚未完成业务写入，并允许按策略重试；同一 `eventId` 的不同事件内容 MUST 终止为冲突。

#### Scenario: 重复事件返回原消费者结果
- **WHEN** 同一消费者再次收到已完成的相同领域事件
- **THEN** 系统返回首次消费的结果引用
- **AND** 不再次调用产生业务事实的处理逻辑

#### Scenario: 消费处理失败不留下部分事实
- **WHEN** 消费者处理逻辑在写入一个下游事实后失败
- **THEN** 下游事实和完成收据均回滚
- **AND** 后续重试可重新处理原事件

#### Scenario: 并发重复消费只形成一个事实
- **WHEN** 同一消费者并发处理同一 `eventId`
- **THEN** 唯一约束和行锁使一个执行者形成结果，另一执行者返回同一结果
- **AND** 下游事实只出现一次

#### Scenario: 相同事件身份的内容冲突
- **WHEN** 消费者收到与既有 `eventId` 相同但 strict 事件内容不同的消息
- **THEN** 系统返回不可重试的幂等冲突
- **AND** 不调用消费者业务处理逻辑

### Requirement: LangGraph checkpointer 与业务事实完全隔离

系统 MUST 使用官方 PostgreSQL checkpointer 的独立 schema、连接角色和受控 setup 入口保存小型图状态，并以 C02 的 `runId/threadId/commandId/eventId` 引用关联业务运行。checkpointer 写入、清理、失败和恢复 MUST 与业务事务分离；检查点不得作为业务查询或业务记录来源，不能补造缺失的标准化风险记录、评估记录、预警、处置、复核决定或审计。（RI-S61～RI-S65；RA-S5～RA-S7）

#### Scenario: 检查点可以独立保存和恢复
- **WHEN** 工作流以稳定 `threadId` 写入多个检查点并重新创建运行进程
- **THEN** checkpointer 能读取线程最新状态与历史
- **AND** 保存的图状态只包含 C02 允许的小型版本化引用和路由结果

#### Scenario: 检查点不能补造业务事实
- **WHEN** 检查点引用一个不存在或已回滚的业务提交
- **THEN** 恢复方得到结构化不一致错误
- **AND** 不从检查点内容创建业务事实、审计或 Outbox 行

#### Scenario: 检查点失败不回滚已入库事实
- **WHEN** 业务事务已提交而后续 checkpointer 写入失败
- **THEN** 已提交事实、审计和事件保持有效
- **AND** 恢复流程使用原业务幂等键核对既有提交后继续或终止

#### Scenario: 清理检查点不删除业务记录
- **WHEN** 获授权运维动作清理一个线程的检查点或重建 checkpointer schema
- **THEN** 业务事实、审计、命令收据、Outbox 和消费者收据保持不变
- **AND** checkpointer 角色仍无法直接读取这些记录

### Requirement: 基础设施失败、时间与审计保持结构化可追溯

系统 MUST 将迁移、连接、事务、幂等、租约、投递、消费和 checkpointer 失败表示为闭合错误类别，标明可重试性、阶段、发生时间和受保护诊断引用，并由上层映射到 C02 `ModuleErrorV1`；不得要求调用方匹配完整文案。所有持久化时间 MUST 使用带时区时间，区分业务发生时间、事件系统记录时间、数据库持久化时间、租约时间和重试时间；重试不得改写首次业务时间、事件版本、审计或结果引用。

#### Scenario: 可重试基础设施故障保留原身份
- **WHEN** 连接中断、锁超时或投递临时失败被分类为可重试
- **THEN** 错误包含稳定类别、阶段、发生时间和诊断引用
- **AND** 重试沿用原命令、事件、消费者、运行和冻结策略身份

#### Scenario: 非法迁移或幂等冲突不可重试
- **WHEN** 系统发现迁移结构非法、全局序号冲突或同键不同载荷
- **THEN** 错误被分类为不可重试终止失败
- **AND** 不通过循环重试、换策略或修改既有记录绕过冲突

#### Scenario: 重试不改写历史时间与版本
- **WHEN** Outbox 或消费者在稍后时间成功重试
- **THEN** 原事件的业务发生时间、系统记录时间、事件版本和审计引用不变
- **AND** 另行记录尝试、租约、失败与完成时间
