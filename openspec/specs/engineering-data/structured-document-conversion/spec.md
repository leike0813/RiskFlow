# engineering-data/structured-document-conversion Specification

## Purpose
把获授权的工程资料确定性转换为结构统一、坐标可追溯且可由后续清洗和识别流程消费的 JSON-LD 工件与资料段集合，并以结构化诊断保留转换失败的资料段和原因。

## Requirements
### Requirement: 统一转换契约只传递精确引用

系统 MUST 通过独立于既有工程数据端口的闭合转换端口接收转换命令和查询。命令 MUST 固定工程、资料版本、输入内容工件、转换策略、授权上下文与幂等身份；输入类型 MUST 是 DOCX、文本型 PDF、XLSX、CSV 与 OCR 版面结果的可辨识联合。结果 MUST 只返回转换记录、JSON-LD 工件、资料段集合或诊断工件的精确引用，不得内联资料正文、完整 JSON-LD、通用对象袋、文件或 URL；PDF、扫描 PDF、PNG/JPEG 与 DOCX MUST 通过已配置 MinerU 通道处理，XLSX/CSV MUST 通过原生确定性解析；两者 MUST 共用同一规范化、JSON-LD、权限、事务和资料段登记。

#### Scenario: 结构化文档转换成功
- **WHEN** 调用方提交受支持的 DOCX、文本型 PDF、XLSX 或 CSV 精确资料版本及有效授权
- **THEN** 系统返回成功转换记录、JSON-LD 工件和资料段集合的精确引用
- **AND** 返回值不包含原始资料或完整转换内容

#### Scenario: OCR 消费共享契约
- **WHEN** C13 提交符合共享 Schema 的 OCR 版面结果
- **THEN** 同一转换端口接受该输入分支并应用统一规范化与合规规则
- **AND** C12 不把扫描图片自行识别为文字

#### Scenario: 未声明输入被拒绝
- **WHEN** 调用方提交 CAD、任意文件类型或契约外字段
- **THEN** strict Schema 在读取内容前拒绝输入
- **AND** 不产生转换记录或输出工件

### Requirement: 转换保留源文件可证明的结构与坐标

系统 MUST 按文件类型保留可从源文件稳定取得的结构信息。DOCX MUST 保留标题层级、段落和表格顺序、表格结构、图注以及源文件显式提供的分页信息；文本型 PDF MUST 保留页码、文本顺序和文本坐标；XLSX MUST 保留工作表、单元格坐标、合并区域、公式及源文件缓存值；UTF-8 CSV MUST 保留行列坐标和符合 CSV 语义的字段值。PDF 页面尺寸与坐标 MUST 声明点单位，图片 MUST 声明像素单位；归一化坐标 MUST 按真实页面尺寸缩放。DOCX MUST 使用源文件可证明的结构顺序与显式分页，服务渲染页不得当成源 DOCX 页码。系统不得推测源文件未提供的页码、重新计算公式或把解析失败伪装成空结构。

#### Scenario: DOCX 结构可追溯
- **WHEN** DOCX 含多级标题、表格、图注和显式分页标记
- **THEN** JSON-LD 中的结构顺序和资料段定位保留这些可验证信息

#### Scenario: 表格坐标可追溯
- **WHEN** XLSX 或 CSV 含表头、空值、引用字符或多行字段
- **THEN** 转换结果保留解析后的值及对应工作表或行列坐标
- **AND** XLSX 公式与缓存值保持可区分

#### Scenario: 无可靠文本层的 PDF 使用 MinerU
- **WHEN** PDF 没有可靠文本层
- **THEN** 系统通过同一受控 MinerU 通道转换并执行结构与质量校验
- **AND** 缺页或空输出形成类型化失败，不产生空成功

#### Scenario: 无可靠文本层的 PDF 失败
- **WHEN** PDF 没有可靠文本层且 MinerU 未提供通过质量校验的文字与定位
- **THEN** 系统返回指向诊断工件的类型化失败
- **AND** 不生成空的成功 JSON-LD 工件或资料段集合

### Requirement: JSON-LD 使用受控结构语义

系统 MUST 生成可运行时校验的 JSON-LD，至少包含资料元数据、文本块列表和证据片段列表，并在源文件存在相应结构时包含表格字段或工法步骤字段。JSON-LD MUST 使用本地版本化受控上下文，结构实体和关系 MUST 来自闭合集合，证据定位 MUST 指向有效资料段标识；转换过程不得解析远程上下文或把风险知识语义推断为源资料事实。（RI-S21～RI-S23）

#### Scenario: 有效 JSON-LD 通过合规校验
- **WHEN** 规范化结果具有完整元数据、结构实体、关系、文本块、证据片段与资料段引用
- **THEN** 系统生成使用受控上下文的 JSON-LD 工件
- **AND** 每个证据定位都可回溯到同一资料版本的资料段

#### Scenario: 非法结构关系被拒绝
- **WHEN** 规范化结果含未知实体类型、未知关系类型、悬空引用或远程上下文
- **THEN** 合规校验返回类型化失败和诊断工件引用
- **AND** 不登记部分有效结构

### Requirement: 文本块不超过 512 个 Unicode 码点并具有双向指针

系统 MUST 按规范化文档顺序对文本分块，每块正文长度不得超过 512 个 Unicode 码点。分块 MUST 优先服从结构边界和稳定文本边界，仅在单一片段仍超限时硬切分；相邻块 MUST 建立前后指针，首块没有前指针、末块没有后指针，全部文本不得重复或丢失。（RI-S21）

#### Scenario: 超长段落确定性分块
- **WHEN** 一个规范化段落超过 512 个 Unicode 码点
- **THEN** 系统按相同策略和版本生成相同的有序文本块
- **AND** 每块不超过 512 个 Unicode 码点且拼接后与原规范化正文一致

#### Scenario: 相邻块指针闭合
- **WHEN** 一份资料产生多个文本块
- **THEN** 任意非首块的前指针指向前一块，任意非末块的后指针指向后一块
- **AND** 不存在跨资料版本或悬空指针

### Requirement: 合规校验按失败资料段原子收口

系统 MUST 在登记资料段前按字段、结构实体、关系和资料段执行合规校验。任一检查失败时，系统 MUST 形成稳定错误代码、失败阶段、可重试性、失败原因与可确定的资料段标识，并将详细信息写入诊断工件；一次转换的资料段集合 MUST 整体登记或完全不登记，不得以删除失败段的方式返回部分成功。（RI-S23）

#### Scenario: 单个资料段不合规
- **WHEN** 一份转换结果中任一资料段存在缺失字段、非法关系或无效定位
- **THEN** 整次转换以失败终态保存诊断引用和可确定的失败资料段标识
- **AND** C11 不登记该转换的任何资料段

#### Scenario: 解析前无法确定资料段
- **WHEN** 输入容器损坏到无法建立资料段标识
- **THEN** 诊断记录资料版本、解析阶段和失败原因
- **AND** 不虚构资料段标识

### Requirement: 权限、版本与幂等性在内容读取前生效

转换 MUST 在业务入口检查目标工程、资料范围和已登记输入版本，按受控存储引用读取原件；日常读取不要求额外全文哈希收据。转换保持原件、结构坐标、转换版本及来源关系，相同转换写命令复用结果，不同输入生成新版本。

#### Scenario: 无正文权限的转换被拒绝

- **WHEN** 调用主体能看到资料定位但没有读取正文和执行转换的权限
- **THEN** 系统在打开输入工件前返回不可重试权限错误
- **AND** 错误和审计不泄露正文

#### Scenario: 相同命令幂等重试

- **WHEN** 调用方以相同幂等身份和相同有效载荷重试已终结转换
- **THEN** 系统返回原转换结果引用
- **AND** 不重复写工件、资料段、转换记录或审计

#### Scenario: 同键不同载荷冲突

- **WHEN** 调用方复用同一幂等键提交不同的资料版本、工件或策略
- **THEN** 系统返回不可重试的幂等冲突
- **AND** 原结果保持不变

#### Scenario: 登记原件直接转换

- **WHEN** 已登记且可读的原件进入转换
- **THEN** 读取该原件并按文件类型解析，不额外回读全文验真

#### Scenario: 转换与清洗职责区分

- **WHEN** 完整转换包含后续可排除的页眉或非关键资料段
- **THEN** 转换保留结构，后续清洗决定可用范围，不在转换中隐藏失败段

### Requirement: 不可信文档在版本化资源边界内处理

系统 MUST 把输入资料视为不可信内容，并按版本化转换策略限制输入字节、压缩包条目与解压总量、压缩比、XML 规模、PDF 页数和文本项、工作表与单元格、CSV 记录与字段以及输出块数。加密、损坏、格式伪装、外部实体、压缩炸弹、超过资源限制或非 UTF-8 CSV MUST 返回结构化诊断；原生解析与结果规范化不得自由访问网络、执行宏、脚本、公式或嵌入对象；MinerU 通道只能按冻结端点上传受权字节及下载受限产物。XLSX 合法包内绝对关系 Target MUST 正确解析，外部关系、包外路径和不存在的目标 MUST 被拒绝。

#### Scenario: 恶意压缩包被拒绝
- **WHEN** DOCX 或 XLSX 超过压缩条目、解压总量或压缩比限制，或 XML 声明外部实体
- **THEN** 系统终止解析并保存安全诊断引用
- **AND** 不继续展开内容或产生部分输出

#### Scenario: CSV 编码不受支持
- **WHEN** CSV 不能按 UTF-8 可靠解码
- **THEN** 系统返回含稳定格式错误代码的诊断引用
- **AND** 不以替换字符静默改写原值


#### Scenario: 合法 XLSX 包内绝对关系
- **WHEN** XLSX 使用以 /xl/ 开头的合法包内工作表关系
- **THEN** 系统正确解析工作表并保留公式与缓存值
- **AND** 外部 URL 或越界关系仍整体拒绝

### Requirement: 转换结果具备可重放审计

每次转换终态 MUST 记录转换记录版本、工程与资料版本、输入和输出工件引用、资料段集合引用、解析器集合版本、转换策略版本、授权策略版本、命令与因果运行、状态、统计、操作者和时间戳；失败终态还 MUST 记录诊断引用。转换记录 MUST 只追加且可由相同输入与冻结版本重放；C12 不得在尚未完成 C15 数据准备时发布资料输入已就绪事件。

#### Scenario: 成功转换可重放
- **WHEN** 审计方查询一个成功转换记录
- **THEN** 系统返回足以定位精确输入、冻结版本、输出和资料段集合的引用与统计
- **AND** 不依赖可变的当前资料或解析器配置解释历史结果

#### Scenario: 转换完成不提前发布准备事件
- **WHEN** C12 成功保存 JSON-LD 与资料段集合
- **THEN** 系统仅保存转换事实和审计
- **AND** 不发布代表清洗与部分可用判断已完成的资料输入已就绪事件
