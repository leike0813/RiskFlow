## Purpose

为 RiskFlow 提供受统一 Agent 运行时约束的数据清洗与业务可用性收口，使结构化/OCR 文档和监测快照在不改写原始事实与关键数值的前提下形成可追溯、可部分使用且可由识别流程冻结消费的输入。（RI-S13、RI-S14、RI-S21～RI-S23；RA-S1）

## ADDED Requirements

### Requirement: 清洗准备冻结精确文档与监测输入

系统 MUST 为一次数据清洗准备固定工程修订、空间范围、资料版本、每份资料对应的成功转换记录、JSON-LD 工件和资料段集合、可选监测快照、数据处理策略、父运行、授权上下文与业务幂等身份。文档输入 MUST 接受 DOCX、文本型 PDF、XLSX、CSV 以及通过同一转换契约形成的 OCR 版面结果；监测输入 MUST 只引用 C14 已冻结的精确快照，不得读取持续变化的“最新值”。同一准备中的资料版本与资料段集合 MUST 一一对应。（RI-S13、RI-S14、RI-S21；RA-S1）

#### Scenario: 四类结构化文档与地表沉降快照进入同一准备

- **WHEN** 获授权调用方提交四个分别具有成功 DOCX、文本型 PDF、XLSX、CSV 转换结果的精确资料版本，并按冻结数据处理策略提供地表沉降监测截止点
- **THEN** 系统形成只含精确转换、JSON-LD、资料段集合和监测快照引用的不可变清洗准备
- **AND** 不把资料正文、完整 JSON-LD 或监测样本值复制进任务信封

#### Scenario: OCR 结果复用同一清洗契约

- **WHEN** C13 通过统一转换接口形成成功 OCR 版面结果、JSON-LD 工件和资料段集合
- **THEN** 系统按与其它文档相同的清洗输入处理该结果，并保留页码、版面、置信度和表格定位证据
- **AND** 不读取 PaddleX 私有响应来建立第二套文档事实

#### Scenario: 输入版本不完整或不一致时拒绝准备

- **WHEN** 任一资料没有成功且版本匹配的转换与资料段集合、资料与集合不能一一对应、监测快照不属于请求工程/空间/截止点，或数据处理策略版本不匹配
- **THEN** 系统在创建 Agent 任务前返回结构化业务阻断、版本或授权失败
- **AND** 不猜测“最新版”、不省略失败输入、不创建可运行任务

### Requirement: data-cleaning 任务只使用版本化只读领域工具

系统 MUST 通过 C08 `AgentTaskPortV1` 创建 `embedded`、`data-cleaning` 任务，并注册严格的任务动作、候选、增量、确定性校验器和结果收口器。该任务的领域工具白名单 MUST 仅允许在冻结输入和授权范围内有界读取文档资料段切片或监测快照切片；工具 MUST 复验任务类型、策略版本、工程、空间、资料授权、输入版本、对象上限和当前授权撤销。工具不得提供 SQL、Shell、文件系统、自由联网、任意对象查询或业务写入。（RI-S14、RI-S21）

#### Scenario: 读取获准的文档资料段切片

- **WHEN** Agent 请求冻结 JSON-LD 中存在、属于获准资料版本且数量不超过工具策略上限的资料段
- **THEN** 工具返回受保护的不可变观察工件引用，其中仅含所请求的结构、正文片段、定位、置信度和数值保护标记
- **AND** 读取及观察工件继承原资料权限并计入 C08 工具、对象、上下文和墙钟预算

#### Scenario: 读取获准的监测快照切片

- **WHEN** Agent 请求冻结监测快照中存在且数量不超过上限的成员、对齐点或特征
- **THEN** 工具返回受保护观察工件引用，并保持原样本值、规范值、特征值、单位、状态和证据不变
- **AND** 工具不重新对齐、插值、外推或计算新特征

#### Scenario: 越权或越界工具请求被拒绝

- **WHEN** 动作请求冻结集合外对象、其它工程/资料、未列入白名单的工具、超过对象预算，或当前资料授权已撤销
- **THEN** C08 返回稳定的工具、预算或授权错误并记录失败证据
- **AND** 不打开目标正文、不调用其它处理器、不扩大任务输入或工具集合

### Requirement: Agent 增量只能排除既有引用

系统 MUST 将清洗候选表示为任务类型化增量，且每项操作只能按精确资料段标识或监测样本版本引用提出排除，并携带策略允许的原因码和现有证据引用。增量不得包含正文替换、通用 JSON Patch、整对象覆盖、数值、单位、时间戳、公式缓存值、坐标、置信度、C14 特征或已发布事实的新值。原始转换工件、资料段集合、监测批次、样本和快照始终不变。（RI-S21～RI-S23；RA-S1）

#### Scenario: 合法引用级排除进入确定性校验

- **WHEN** Agent 对冻结集合内的重复/噪声资料段或异常监测样本提交允许原因码、目标引用和证据
- **THEN** 系统逐项校验并记录 `accepted | rejected`、稳定原因码及证据引用
- **AND** Agent 输出本身不修改任何资料段、样本、快照或下游事实

#### Scenario: 正文或数值修改整体拒绝

- **WHEN** 候选包含替换文字、修正数值/单位/时间、重算公式/特征、路径式补丁、未知字段或整对象内容
- **THEN** strict Schema 或确定性校验拒绝该候选
- **AND** 不把非法内容转换为排除操作或正式清洗结果

#### Scenario: 受保护关键数值不能通过排除消失

- **WHEN** 候选试图排除数据处理策略或冻结输入标记为关键数值证据的资料段，或试图把受保护监测样本从可用集合移除
- **THEN** 确定性校验以不可修正规则拒绝记录该项及证据
- **AND** 不允许通过改写原因码、拆分操作或修正循环绕过保护

### Requirement: 业务可用性由确定性策略收口

系统 MUST 依据冻结数据处理策略，从原输入可计算性、被接受的排除项、保留资料段/监测样本覆盖率、必需结构和关键数值保护状态确定每份文档、监测输入及整体的 `available | partial | unavailable`。Agent 可以提出排除和简短质量观察，但不得直接指定、提升或覆盖最终可用性。C14 的 `available | partial | unavailable` 仅作为监测算法可计算性基线，C15 不得把它自动等同于业务可用性，也不得把 `unavailable` 提升为可用。（RI-S21～RI-S23；RA-S1）

#### Scenario: 保留子集达到部分可用门槛

- **WHEN** 一份输入存在被接受的排除项，但保留集合仍达到冻结策略的最低覆盖、必需结构和关键数值要求
- **THEN** 系统将该输入确定为 `partial`，保存精确保留/排除范围及逐项原因
- **AND** 下游只能消费保留引用，同时仍可追溯全部原始输入和排除证据

#### Scenario: 无排除且全部门槛通过

- **WHEN** 输入基线可用、没有被接受的排除项且全部确定性质量门通过
- **THEN** 系统将该输入确定为 `available`
- **AND** 结果引用原输入，不重写或复制其正文和数值

#### Scenario: 低于最低门槛时不可用

- **WHEN** 保留集合低于最低覆盖、必需结构缺失、C14 快照不可计算，或关键数值保护无法满足
- **THEN** 系统将对应输入确定为 `unavailable` 并保存稳定原因与证据
- **AND** 不用零值、空内容、未审核候选或其它输入替代

### Requirement: 清洗结果经确定性收口自动生效并完整留痕

系统 MUST 在候选通过确定性校验后形成不可变清洗结果工件，并以工程数据模块的正式清洗事实记录任务、冻结输入、策略、模型、提示、工具、预算、候选、逐项校验、保留/排除范围、可用性、证据、权限和审计引用。清洗结果不需要人工发布或确认；只有 C08 任务达到 `completed` 且其正式结果引用与清洗事实一致时，结果才可被识别准备消费。系统不得保存或展示模型内部思维链。（RI-S14、RI-S21～RI-S23）

#### Scenario: 合格候选自动形成正式清洗结果

- **WHEN** `data-cleaning` 候选全部通过确定性校验且结果工件、正式清洗事实和审计均成功保存
- **THEN** C08 任务完成后该结果自动成为对应冻结输入和策略的可消费结果
- **AND** 不创建人工发布、批准或二次 Agent 自审前置

#### Scenario: 工件或业务收口失败不成立结果

- **WHEN** 结果工件、正式清洗事实、逐项决定、命令收据或审计任一步失败
- **THEN** 系统返回结构化工件、持久化或任务失败并保留已可靠成立的诊断证据
- **AND** 下游不得把内存候选、孤儿工件或未完成任务当作正式结果

### Requirement: 必经 Agent 失败不得静默跳过

系统 MUST 把模型不可用、工具失败、预算耗尽、租约恢复失败、确定性拒绝和任务终止分别保存为可审计失败。识别准备 MUST 验证对应 `data-cleaning` 任务已完成并消费其精确结果；任务未运行、运行中、失败、取消或结果版本不匹配时 MUST 阻断，不得直接使用 C12/C13 转换结果、C14 快照、缓存候选、默认可用结论或替代模型继续。（RI-S21～RI-S23）

#### Scenario: 预算耗尽阻断准备

- **WHEN** 必经清洗任务耗尽模型、工具、上下文、候选、对象、修正、并发或墙钟预算且没有合格结果
- **THEN** 任务进入显式失败终态，识别准备返回对应失败/阻断引用
- **AND** 不扩容、换模型、减少审计或把未清洗输入标记为可用

#### Scenario: 任务仍在运行时不冻结输入

- **WHEN** 调用方在清洗任务完成前请求识别准备快照
- **THEN** 系统返回结构化业务阻断并指向同一任务
- **AND** 不创建准备快照、输入就绪事件或下游运行

#### Scenario: 失败重试沿用冻结任务

- **WHEN** 可安全重试的技术故障在 C08 冻结重试预算内恢复
- **THEN** 系统沿用原任务、输入、策略、模型、工具、动作幂等键和累计预算
- **AND** 不重复工具副作用、正式清洗事实、排除决定或审计

### Requirement: 识别准备只冻结已收口的可用输入

系统 MUST 实现既有 `identification-preparation` 冻结语义，并消费前置契约演进后的复数 `includedSourceSegmentSetRefs[]`。每个 `sourceVersionRef` MUST 按相同顺序对应一个精确资料段集合；排除决定 MUST 指向这些集合内的资料段。至少一份文档达到 `available` 或 `partial` 且整体策略门通过时，系统 MUST 保存不可变识别准备快照；不可用文档的全部段保持显式排除，部分可用文档只排除已接受范围。监测结果可用或部分可用时保存精确快照引用，不可用时在覆盖决定中保留原因而不把监测快照作为可消费输入。（RI-S1、RI-S2、RI-S13、RI-S21～RI-S23）

#### Scenario: 多资料部分可用准备成功

- **WHEN** 四份资料的清洗任务完成，其中至少一份为部分可用，所有资料版本与资料段集合一一对应且整体覆盖达到策略门槛
- **THEN** 系统返回一个识别准备快照，保留全部资料版本/集合引用、精确排除决定、整体覆盖决定和清洗版本引用
- **AND** 下游可以仅从未排除资料段继续，同时重放每项排除和质量结论

#### Scenario: 全部文档不可用时阻断

- **WHEN** 所有请求文档的清洗结论均为 `unavailable`，或整体覆盖低于冻结策略下限
- **THEN** 系统返回业务阻断并保留清洗结果与原因引用
- **AND** 不创建空准备快照或发布输入就绪事件

#### Scenario: 前置复数契约未就绪时禁止实现

- **WHEN** `evolve-identification-preparation-segment-set-refs` 尚未归档，或运行时仍只接受单数资料段集合字段
- **THEN** C15 实现/启动检查失败并报告契约版本不兼容
- **AND** 不在 C15 内修改公共 Schema、压缩多资料为一个集合或只取第一份资料

### Requirement: 准备快照、审计和输入就绪事件原子提交

系统 MUST 在一个 C03 事务中提交识别准备快照、覆盖决定、排除决定引用、命令收据、一条事实审计和 `engineering.inputs-ready.v1` Outbox 事件。事件 MUST 只携带精确识别准备快照引用，不得复制资料正文、清洗候选、监测值或 Agent 响应。任何事务步骤失败 MUST 整体回滚；C12、C13、C14 或单项清洗结果完成时不得提前发布该事件。（RI-S14、RI-S23）

#### Scenario: 完整准备可靠发布输入就绪事件

- **WHEN** 全部必经清洗任务完成、确定性收口通过且准备快照事务提交成功
- **THEN** 系统原子保存准备、审计、回执和一条引用该准备的输入就绪事件
- **AND** 至少一次事件投递由消费者按事件身份和业务幂等键去重

#### Scenario: 审计或 Outbox 失败整体回滚

- **WHEN** 准备快照、覆盖决定、命令收据、审计或 Outbox 任一步写入失败
- **THEN** 整个准备提交失败且不返回业务成功
- **AND** 已完成清洗结果保持不变，可用原命令身份安全重试准备收口

### Requirement: 版本、幂等与权限支持精确重放

系统 MUST 使清洗准备、任务、结果、排除决定和识别准备快照只追加且可由精确资料版本、转换记录、监测快照、数据处理/模型/提示/工具/预算/校验策略、授权与命令身份重放。相同作用域、幂等键和规范化载荷 MUST 返回原逻辑结果；同键不同载荷 MUST 返回不可重试冲突。输入或策略变化 MUST 创建新任务与新结果，不得覆盖历史。每次工具读取、最终收口和准备冻结 MUST 重新校验当前工程、空间和资料权限，未授权与不存在采用不可枚举失败。（RI-S14、RI-S21～RI-S23）

#### Scenario: 相同准备重放不重复副作用

- **WHEN** 调用方以相同工程、幂等身份、输入和全部冻结版本重试清洗准备或识别准备冻结
- **THEN** 系统返回原任务、清洗结果和准备快照引用
- **AND** 不重复模型/工具调用、结果事实、排除决定、审计或 Outbox 事件

#### Scenario: 输入或策略变化形成新版本

- **WHEN** 任一资料版本、转换记录、监测快照、数据处理策略、模型、提示、工具、预算或校验策略发生变化
- **THEN** 系统创建新的冻结准备、Agent 任务和清洗结果
- **AND** 旧结果及引用它的识别准备快照保持不变

#### Scenario: 当前资料权限撤销后拒绝消费

- **WHEN** 任务创建后、工具读取或识别准备冻结前，任一资料正文授权已撤销或请求范围扩大
- **THEN** 系统返回统一授权失败并记录安全审计
- **AND** 不泄露目标存在性、资料正文、监测值或旧观察工件内容
