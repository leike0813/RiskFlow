# domain/calibration-suggestion-and-governance-loop Specification

## Purpose
为 RiskFlow 把 C28 已越限的不可变偏差事实转化为受约束的校准建议、人工复核结果和可继续治理但尚未发布的配置修订草案，闭合 RA-S7 且不让 Agent 或复核决定越权改写正式配置。

## Requirements

### Requirement: 校准入口只接受精确且已越限的偏差事实

系统 MUST 通过 C28 公共只读接缝按工程、稳定身份和精确版本读取私有偏差事实，并在启动校准任务前验证当前 C06 授权、`thresholdExceeded=true`、处置建议、冻结评估输入、目标指标、阈值策略和证据链均闭合。系统 MUST 由该不可变事实确定性派生公共 `DeviationRecord` 的标识和首版本；相同事实不得派生不同身份，未越限、错工程、越权、缺失或不完整事实不得启动任务或创建公开记录。（RA-S7）

#### Scenario: 已越限事实进入校准
- **WHEN** 获授权调用方提交同工程、精确版本、证据完整且 `thresholdExceeded=true` 的偏差事实引用
- **THEN** 系统形成稳定的公共偏差记录引用并冻结校准输入
- **AND** 重试读取相同事实得到同一公共记录身份

#### Scenario: 冻结评估输入与目标依据精确匹配
- **WHEN** C28 偏差事实引用的 C25 精确输入快照属于同一工程和空间，且调用方提交的依据集合、目标发布和内容摘要均与 C25 窄读投影一致
- **THEN** 系统才可冻结校准输入并继续读取目标正文
- **AND** 相同命令重放复用同一冻结工件和公共记录身份

#### Scenario: 其它有效依据不能替代冻结依据
- **WHEN** 调用方提交同工程另一份有效依据集合或目标发布，或者快照缺失、版本陈旧、跨工程或跨空间
- **THEN** 系统拒绝且不创建冻结工件、Agent 任务、校准建议或公开记录
- **AND** 不仅凭调用方提供的 release set 引用组装校准快照

#### Scenario: 未越限事实不进入校准
- **WHEN** 精确偏差事实的 `thresholdExceeded=false`
- **THEN** 系统返回稳定的不适用结果且不创建 Agent 任务、校准建议、公开偏差记录或复核任务

#### Scenario: 无权或错配事实不可枚举
- **WHEN** 授权过期、被撤销、分支或工程不匹配，或者偏差事实不存在、版本错误或证据不完整
- **THEN** 系统在披露事实正文或产生业务副作用前失败关闭
- **AND** 不改读 latest、其它工程事实或重新计算偏差来补足

### Requirement: 校准 Agent 只产生受冻结依据约束的类型化操作

系统 MUST 为每个合格偏差创建 `calibration-suggestion` 有界 Agent 任务，并固定发起者、工程、真实父工作流运行、偏差事实、公用偏差记录引用、目标定义与基准发布的精确版本、完整基准文档、模型与提示模板、工具策略和硬预算。Agent 增量 MUST 是面向权重、阈值或区间的闭合类型化领域操作以及非空理由和证据引用，不得使用通用 JSON Patch、整对象覆盖、自由路径或发布命令。确定性模块 MUST 验证操作目标仍属于冻结评估依据、字段与数值边界合法、证据可读，并把操作应用于精确基准后以 C18/C19 严格 Schema 验证完整候选文档。（RA-S7）

#### Scenario: 合格候选通过确定性收口
- **WHEN** Agent 结果精确绑定原任务、偏差事实、目标发布和基准摘要，且每项类型化操作、证据与完整候选文档均通过确定性校验
- **THEN** 系统接受候选并保存逐项校验结果
- **AND** Agent 结果本身不修改任何配置、发布状态或人工决定

#### Scenario: 可修复格式错误在原预算内重试
- **WHEN** 候选仅存在字段、格式、引用或候选边界等可修复错误，且原任务仍有预算
- **THEN** 系统可把结构化拒绝原因反馈给同一任务生成新候选
- **AND** 不换模型、扩预算、改变冻结输入或创建平行任务

#### Scenario: 规则与版本冲突失败关闭
- **WHEN** 候选目标越出冻结依据、基准版本不匹配、权限或来源资格失败、操作违反配置规则，或者预算耗尽
- **THEN** 系统拒绝该候选且不创建正式校准建议
- **AND** 不以循环重试、默认值、基线复制或整对象覆盖绕过

### Requirement: 校准建议与公共偏差记录以真实引用原子成立

系统 MUST 复用既有 `create-calibration-suggestion` 命令并提交确定性派生的 `DeviationRecordRefV1`、已收口的 Agent 结果引用和精确校验策略引用。校准建议、首版公共 `DeviationRecord`、复核任务关联、命令回执、审计和既有 `warning.calibration-suggestion-created.v1` 待发布事件 MUST 按 C03 事务边界原子成立；公共记录的 `calibrationRecommendation` MUST 指向本次真实建议标识，`reviewStatus` MUST 为 `pending`，不得使用占位建议或空引用。（RA-S7）

#### Scenario: 创建待复核校准建议
- **WHEN** 合格 Agent 结果、派生偏差记录引用和校验策略精确匹配，且 C07 已接受针对该建议精确版本的复核任务
- **THEN** 系统原子保存不可变建议、`pending` 公共偏差记录、复核关联、审计、回执和校准建议创建事件
- **AND** 事件只携带既有契约声明的精确引用
- **AND** 复核等待运行使用源 Agent 任务的真实父运行引用，不生成占位运行

#### Scenario: 相同命令幂等重放
- **WHEN** 相同工程、业务幂等键和相同载荷重试或并发竞争
- **THEN** 系统返回首次成功的同一逻辑建议、偏差记录和复核任务引用
- **AND** 不重复保存建议、公开记录、审计、回执或事件

#### Scenario: 原子成员失败不留下部分正式事实
- **WHEN** 建议、公开记录、复核关联、审计、回执或 Outbox 任一写入失败
- **THEN** C29 事务内全部写入不可见，并可沿原幂等身份安全重试
- **AND** 不把 C07 已创建但尚未关联的任务冒充成功结果

### Requirement: 人工复核决定只推进对应建议版本

系统 MUST 让 C07 针对校准建议精确版本接收 `approve-draft-creation`、`reject` 或 `return-for-revision` 决定，并通过精确决定证明核对调用方声明。`reject` MUST 形成 `reviewStatus=rejected` 的新公共偏差记录版本且不创建草案；`return-for-revision` MUST 在同一事务内追加绑定退回决定、前驱建议版本和预分配后继建议引用的血缘事实，并追加指向该真实预留引用的下一 `pending` 公共偏差记录版本，不得插入候选占位。后续新的有界任务只能消费一次该预留引用，保存完整后继建议和新的复核任务；任何决定都不得转移到后继建议或修改历史事实。（RA-S7）

#### Scenario: 拒绝建议形成被拒绝版本
- **WHEN** C07 对当前精确建议记录合法 `reject` 决定
- **THEN** 系统追加 `reviewStatus=rejected` 的公共偏差记录版本并保存精确决定关联
- **AND** 不创建配置工件、修订草案或发布事实

#### Scenario: 退回建议创建独立后继任务
- **WHEN** C07 对当前精确建议记录合法 `return-for-revision` 决定
- **THEN** 原建议和决定保持不可变，系统恰好追加一项绑定决定与前驱版本的后继引用预留及下一 `pending` 公共记录版本
- **AND** 新任务形成完整候选后消费该预留，保存对应建议版本并创建只绑定该后继版本的新复核任务
- **AND** 后继任务仍受原偏差事实、冻结基准、权限和剩余治理规则约束

#### Scenario: 退回与后继创建保持幂等
- **WHEN** 同一精确退回决定在后继预留消费前重放，或同一后继创建命令重放
- **THEN** 系统分别复用同一预留和同一完整后继建议，不追加第二项血缘、建议、公共记录或复核任务
- **AND** 预留已消费后再次以原建议和决定请求退回，或其它命令尝试重复消费时，系统拒绝且不写入新事实

#### Scenario: 无效后继消费失败关闭
- **WHEN** 后继创建缺少预留，预留的工程、偏差、前驱、决定或版本不匹配，或者预留已被其它命令消费
- **THEN** 系统拒绝创建建议并保持建议、血缘、公共记录、审计、回执和事件不变
- **AND** 不用调用方派生的新引用、占位候选或 latest 记录替代预留

#### Scenario: 陈旧决定不推进新建议
- **WHEN** 决定目标不是待推进建议的精确版本，或任务保存的决定引用与查询决定不一致
- **THEN** 系统返回类型化冲突或完整性失败
- **AND** 不更新公开偏差状态或创建草案

#### Scenario: 调用方声明与真实决定类型不一致
- **WHEN** 调用方把真实 `return-for-revision` 决定声明为 `reject`，或把真实 `reject` 决定声明为退回
- **THEN** 系统依据 C07 精确决定证明拒绝请求
- **AND** 不追加公共偏差记录、血缘、审计、回执或草案

### Requirement: 只有精确批准证明可以创建未发布配置草案

系统 MUST 在创建草案前通过 C07 专用公共只读端口取得与同工程校准建议、复核任务和 `approve-draft-creation` 决定精确绑定的批准证明，并重新校验当前调用者的配置治理权限、目标定义、基准发布、候选摘要和全部证据。证明和校验均成立时，系统 MUST 确定性应用已批准的类型化操作，验证完整 C18/C19 候选文档，保存内容工件并复用 C16 `submit-revision` 创建一项未发布修订；随后才可追加 `reviewStatus=approved` 的公共偏差记录版本及草案关联。（RA-S7）

#### Scenario: 批准建议创建单一草案
- **WHEN** 精确批准证明、当前治理授权、基准发布、候选文档和证据均有效
- **THEN** 系统创建一项绑定原定义和精确基准发布的 C16 未发布修订，并追加 `approved` 公共偏差记录版本
- **AND** 修订可追溯到偏差事实、Agent 任务、建议、复核任务、决定和候选工件

#### Scenario: 无证明拒绝创建草案
- **WHEN** 决定不存在、不是批准、目标错配、任务与决定不一致，或者调用方未提供可验证的精确批准证明
- **THEN** 系统拒绝草案创建且不写入候选工件、知识修订或 `approved` 公共偏差记录版本
- **AND** 不直接读取 C07 表、复制其事实或把复核完成等同于批准

#### Scenario: 基准漂移拒绝套用建议
- **WHEN** 已批准建议引用的基准发布已不再满足 C16 提交前置，或目标内容摘要与冻结基准不一致
- **THEN** 系统返回类型化版本冲突且不把操作套用到 latest 或其它发布
- **AND** 人工批准不会被转移到重建的新候选

#### Scenario: 草案创建重试不产生重复修订
- **WHEN** 同一批准建议沿同一业务幂等身份重试或并发提交
- **THEN** 系统返回同一逻辑 C16 修订与 `approved` 公共偏差记录版本，或返回类型化冲突
- **AND** 不重复保存工件、修订、审计或关联

### Requirement: 校准草案继续受既有知识治理约束

C29 创建的修订 MUST 保持未发布状态，并继续接受 C16 的知识修订校验、独立复核、发布、停用和回滚规则。C29、校准 Agent 和校准建议复核人 MUST NOT 直接发布、覆盖或回滚 C18/C19 正式定义，也不得修改历史评估、P/C、矩阵结果、偏差事实或人工决定；任何后续生效必须由具备当前权限的人通过既有知识治理命令显式完成。（RA-S7）

#### Scenario: 批准校准不等于发布配置
- **WHEN** 校准建议获得 `approve-draft-creation` 且草案创建成功
- **THEN** 新修订保持未发布，现行配置和历史评估结果不变
- **AND** 发布仍需既有知识修订人工批准证明和显式发布命令

#### Scenario: 后续发布不改写校准历史
- **WHEN** 草案随后被发布、拒绝、停用或回滚
- **THEN** 原偏差事实、建议、逐项校验、校准复核决定和公开偏差记录版本保持不可变
- **AND** 追溯链保留后续知识治理结果的精确引用

### Requirement: 校准闭环保持权限、审计和重放边界

系统 MUST 在每次读取偏差、任务结果、复核证明、基准配置或内容工件前复验当前工程、空间、来源和精确分支授权，下游权限不得超过发起任务。每个任务、候选、建议、复核关联、公开偏差记录版本、草案关联和失败 MUST 保存可重建输入、原始模型响应引用、工具行动、确定性校验、预算消耗、授权与审计；不得保存或展示模型内部思维链。相同冻结输入和已批准操作 MUST 可重建相同完整候选文档。（RA-S7）

#### Scenario: 授权收窄阻断后续阶段
- **WHEN** 调用者或下游任务的授权过期、被撤销、跨工程、跨空间或比上游更宽
- **THEN** 系统在读取目标正文或产生成功副作用前拒绝
- **AND** 不因先前阶段曾获授权而沿用旧权限

#### Scenario: 第三方按精确引用重放校准
- **WHEN** 审计者持有获准的偏差事实、冻结基准、任务结果、类型化操作、校验策略和人工决定引用
- **THEN** 审计者可重建候选文档并核对建议、公开记录和草案关联
- **AND** 重放不依赖 latest、模型思维链、自由文本匹配或 C07/C16 私有表

### Requirement: 校准公开治理入口必须使用单分支授权和精确决定

系统 MUST 提供校准复核结果收口与未发布草案创建两个独立公开命令。结果收口只接受精确建议、真实复核决定及 reject/return-for-revision，草案创建只接受精确建议、真实 approve-draft-creation 决定。命令入口 MUST 按自身分支复验单能力授权，下游复核证明、知识读取和修订提交 MUST 分别取得当前主体、工程、空间和来源范围内的用途授权，不要求调用方伪造多能力上下文。全部操作 MUST 复用既有 C29/C07/C16 用例、幂等身份和事务语义，不直接发布配置。（RA-S7）

结果收口的公开成功 outcome MUST 仅为 rejected 或 returned；草案结果 MUST 使用独立草案形状。请求与结果均按各自命令分支校验，不能因内部用例支持批准而放宽公开收口结果。

#### Scenario: 单能力上下文下形成未发布草案
- **WHEN** 经理以真实会话确认精确批准决定，且复核证明、知识读取和治理分支均获准
- **THEN** 系统返回原用例形成的草案工件、知识修订和公共偏差版本
- **AND** 当前配置保持不变，重试返回同一修订

#### Scenario: 拒绝退回与错误决定分离
- **WHEN** 用户提交真实拒绝/退回决定，或者把批准决定声明为拒绝/退回
- **THEN** 前者只收口对应精确建议，后者被拒绝
- **AND** 不转移决定、不创建占位后继或绕过独立复核

#### Scenario: 收口成功不能返回草案批准
- **WHEN** 结果收口分支返回批准 outcome 或草案创建结果形状
- **THEN** 公共结果边界拒绝该响应
- **AND** 不将其呈现为合法拒绝或退回成功

#### Scenario: 下游撤权或尾事务失败
- **WHEN** 下游治理/证明授权被撤销，或知识修订成功后校准尾事务失败
- **THEN** 撤权在读取/副作用前失败，尾事务可沿原命令身份重试收敛到单一草案
- **AND** 不扩大原授权、不重复修订、不将部分成功标为完工
