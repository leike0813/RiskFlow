# 设计完整产品界面与交互规格

## Question

在完整角色、用例、功能与工作流已经确定后，八项一级导航下需要哪些完整页面、对象详情、创建与审核表单、异常/空/加载状态、跨页面跳转、Agent 交互、证据抽屉与权限差异，才能形成可直接实施和验收的完整产品界面规格，而不只覆盖五张汇报画面？

## Comments

- 已确认规格按七项业务导航逐页组织；先定义五类全局页面骨架（列表、对象详情、运行监控、治理与版本、复核工作台）统一空/加载/异常/权限降级行为，各页面只写业务差异；逐页标注 MVP 与完整产品差异；创建/审核表单引用 §2.6/§2.7 与领域 schema 的 SSOT，只写界面特有交互，不复制字段定义。
- 已确认无权限的命令与入口在界面上置灰并提示所需权限（而非不渲染）；因业务状态暂不可用的操作同样置灰但提示原因。
- 已确认复核详情采用“通用决定表单 + 识别复核专属一站式修正并通过页（P-RV-03）”的组合，与识别工作流契约对齐。
- 已确认 Agent 采用“全局停靠栏 + 全屏工作台模式”的混合形态，**修订 04 号票**“智能 Agent 是独立一级工作台”的决策：停靠栏位于右侧停靠区，跨页面保持会话与任务状态并自动携带当前页面对象上下文；全屏工作台承载多步骤任务监控、结构化结果审阅与复杂命令确认；两种模式共享同一会话与任务状态。一级导航相应从八项调整为七项业务导航，Agent 入口移至顶栏。
- 2026-08-28：本票的界面规格决策保持已解决；依据该规格正在进行的 Demo 实现另由[完成完整产品界面 Demo 供汇报截图派生](25-full-product-ui-demo.md)记录。汇报截图派生必须等待 Demo 完成后再从真实页面取景。

## Answer

完整产品界面规格采用“五类全局骨架 + 七项业务导航逐页差异 + 全局 Agent 停靠栏”的组织方式，共约 45 个页面：风险态势 1、工程项目 10、智能 Agent 3（停靠栏/全屏工作台/任务详情）、风险识别 7、风险评估 7、预警处置 9、知识与规则 8、复核与审计 7，另有系统管理区 5 页（系统管理员专用，不进业务导航）。

证据抽屉统一于右侧停靠区“上下文”面板，资料段标识穿透到原文，无权限时只显示定位摘要；高影响命令执行前展示工程、对象、精确版本、预计结果与外部副作用；无权命令置灰并提示所需权限；运行监控页完整呈现统一过程任务状态、阶段进度、错误重试与业务阻断入口。规格同时给出跨页面跳转矩阵、五角色 × 界面差异矩阵、RI-S1～S6/RA-S1～S7 专利追踪表和十条验收要点，并明确五张汇报截图的正式页面派生来源（Agent 截图改为“业务页 + 停靠栏组合视图”），逐像素校准留给“设计汇报截图”票。

完整规格见：[RiskFlow 完整产品界面与交互规格](../prototypes/full-product-ui-spec.md)。
