## ADDED Requirements

### Requirement: 报告预览保留所属分页游标契约

报告预览 MUST 接受所属C31分页端口生成的完整游标，复用其Schema并保持查询、排序键、授权范围绑定；不得因另设更小字符串上限而拒绝合法分页。历史查询登记及导出资源预算保持。

#### Scenario: 真实长引用生成续页游标

- **WHEN** 合法查询/运行引用使所属分页游标超过512字符
- **THEN** 预览响应通过HTTP Schema且原游标可在所属分页端口续页，错查询或错范围仍拒绝

### Requirement: 部署复验按原上下文范围计算当前权限

部署普通verify及工件/模型verifyDeploymentContext复用审计上下文时，空资源请求 MUST 沿C06既有语义使用该精确上下文持久来源的空间及来源版本，不能丢失grant或使用环境更宽范围。新authorize的显式空资源集合、复验的显式非空请求 MUST 保持原语义。当前权限、主体/工程/能力、任务冻结及租约仍由原C06/C08检查，未知上下文不得回退环境来源或复制旧grant。

#### Scenario: 精确小范围上下文在较宽环境中复验

- **WHEN** 复验目标上下文仅含环境来源的子集，且当前仍有权
- **THEN** 复验返回该子集的当前决定，报告分页和C04/C03可消费，既不清空也不扩大范围

#### Scenario: 明确资源请求、未知上下文及撤权

- **WHEN** 新授权明确请求空集合、复验明确请求非空集合、上下文未知或当前撤权
- **THEN** 前两者保留实际请求语义，后两者拒绝且不产生受保护业务写入

### Requirement: 部署人员入口按当前会话和当前业务权限处理重放

部署人员请求 MUST 从真实当前会话确定主体并使用既有当前业务动作授权通路，原命令调用编号仅关联日志和业务幂等，不以历史五分钟上下文是否到期决定权限。不得修改旧授权或延长TTL，当前会话失效、账号/工程/资料拒权继续阻止业务动作。

#### Scenario: 原命令授权历史记录已过期

- **WHEN** 当前会话和当前业务权限有效，重放已提交反馈的原命令但历史调用授权已到期
- **THEN** 按当前权限消费原已提交事实和稳定幂等，不返回历史上下文到期或重新登记反馈

#### Scenario: 当前会话或业务权限失效

- **WHEN** 当前会话失效或当前业务权限拒绝
- **THEN** 在业务推进前拒绝，不因原命令曾成功而放行

### Requirement: 当前有权运行读取保留跨恢复历史阶段

运行读面 MUST 在当前工程权限、精确C04状态及完整父子链边核验后，按精确运行有界读取已登记阶段和结果引用；合法恢复导致的历史授权摘要变化 MUST NOT 拆散同一运行。原摘要保留用于审计，不要求关系、阶段和最新状态的历史摘要相同。

#### Scenario: 同一运行恢复时授权上下文发生合法变化

- **WHEN** 当前有权用户读取已完成运行，精确父子关系成立但阶段、关系与状态的历史摘要不同
- **THEN** 返回同一运行的完整已登记阶段和结果，保留精确引用及分页边界

#### Scenario: 缺失关系或当前拒权

- **WHEN** 父子链边缺失、引用版本不符或当前状态工件不可读取
- **THEN** 拒绝读取，不猜测父子关系或补写历史

### Requirement: 人工采纳门禁使用当前等待

C30 MUST 仅在当前状态为waiting且lastWaitingRef为human-decision时阻断其它恢复原因。正式采纳证明及路由已经成立后，历史人工等待行 MUST 保留且不得阻断后续配置或Agent等待的精确恢复；首次采纳的唯一等待、C41证明、版本及当前权限检查保持。

#### Scenario: 已采纳运行继续配置等待

- **WHEN** 原预测已正式采纳并转入评估配置等待，当前精确准备已完成
- **THEN** 恢复原子运行，不重新采纳或创建第二子运行，历史人工等待及审计保持

### Requirement: 内嵌任务恢复观察原正式任务

C27/C29内嵌任务ensure MUST 在现有当前权限检查后按唯一agentTaskRefFor身份精确读取已登记任务，以同一校验验证原工程、主体、命令、父运行、冻结输入及模型/策略引用。已有任务 MUST 按真实状态返回，不再次startTask；缺任务才沿原启动路径。失败或取消不得重开，当前拒权和身份错配不得返回候选。

#### Scenario: 完成通知携带当前授权

- **WHEN** 原任务已完成且本次当前合法恢复授权与历史启动授权不同
- **THEN** 读取并核验原任务后返回其正式结果，不重提原启动命令、不新增模型或改变历史任务

### Requirement: 独立子运行使用自己的检查点边界

识别和评估独立子运行 MUST 在父节点内外使用同一自身线程、根命名空间和所属saver，执行及回读均清除继承父checkpoint_id、checkpoint_map及scratchpad。既有原检查点不得删除或修改，不得因独立回读缺失而重跑已完成评估或创建替代Agent。当前权限、检查点Schema、引用和持久化校验保持。

#### Scenario: 父节点内等待后独立回读和恢复

- **WHEN** 父StateGraph节点启动或恢复独立评估子运行并进入等待
- **THEN** 子检查点属于自身线程根命名空间及所属saver，独立回读命中同一状态，后续恢复不消耗父检查点

#### Scenario: 原检查点落在父任务命名空间

- **WHEN** 已登记等待的原子检查点可经唯一已观察精确命名空间、当前权限及正式登记证明
- **THEN** 仅可在保留原记录、核验完整原状态及禁止业务和模型写入的受控恢复中，按同一线程登记其根等待检查点；不得猜测其它命名空间或重跑业务

### Requirement: 公开Agent完成通知转交原评估等待

C30 MUST 将公开agent-task-completed的完整结果引用转交给等待同一精确Agent任务的原评估子运行，按原冻结输入核验子身份并使用当前子状态版本与当前恢复权限。恢复后 MUST 回读子运行正式状态再聚合父结果；错任务通知拒绝，其它兄弟与终态不得推进或重开。不新增评估、任务或模型额度，C25继续核验原任务真实完成结果。

#### Scenario: 原评估Agent已完成

- **WHEN** 有权主体用当前父版本通知原评估等待的同一Agent完成
- **THEN** 原完整结果及恢复上下文交给同一子运行，父按恢复后的正式状态继续聚合

#### Scenario: 其它任务或终态子运行

- **WHEN** 完成通知不是当前评估等待任务，或者其它子运行已经终态
- **THEN** 错任务通知拒绝，终态及未匹配兄弟不恢复，不新增模型调用

### Requirement: 评估入口恢复按当前权限读取原A0引用

readAssessmentEntrySnapshot MUST 从同工程同运行的唯一A0入口行读取原inputSnapshotRef，并通过该行精确C04正文的当前权限与正文工程/运行归属检查，不要求当前授权增量与历史完整摘要相等。缺正文、损坏、撤权、错目标、非A0或多义 MUST 拒绝，不重建指针或重跑已完成任务。

#### Scenario: 已完成Agent后的等待恢复

- **WHEN** 原评估等待任务已完成，当前合法授权来源增量变化
- **THEN** 原入口快照仍可按当前权限读取，继续原运行与任务结果，不新增评估、模型或放宽来源权限

### Requirement: 评估追溯分别核对运行入口与冻结准备

C30 MUST 使用已登记入口方式、冻结引用及重评入口事实，沿唯一workflowEntryIdentityFor验证运行入口身份；A0入口行存在inputSnapshotRef时，其entryIdentity MUST 与该快照引用一致。运行入口摘要与准备引用不得被当作同一种标识比较。工程、运行、状态版本、入口方式、评估结果归属、前驱和原因检查保持。

#### Scenario: 原运行引用独立准备并在A0冻结因果准备

- **WHEN** 运行入口摘要由原冻结输入确定，A0登记另一个带本次因果的准备引用
- **THEN** 两种身份分别核验成功，原评估可追溯，无需重跑或修改历史记录

#### Scenario: 运行入口或准备身份错配

- **WHEN** 运行入口摘要与登记输入不符，或A0准备身份与其快照引用不符
- **THEN** 入口元数据读取明确失败，不返回部分追溯

### Requirement: 评估入口绑定精确独立准备

公开assess启动载荷 MUST 支持可选assessmentPreparationSnapshotRef，并将其纳入冻结引用及入口身份。A0 MUST 经C11当前受权窄读，精确匹配工程修订、风险、空间、适用性、assess入口、发起人与完整监测集合；只接受未绑定旧父因果的独立准备。匹配后 MUST 经原C11路径幂等冻结原资料字段/证据/监测及本次运行因果，原独立准备保持不可变；缺省沿既有冻结路径。

#### Scenario: 当前有权主体使用匹配准备

- **WHEN** 显式准备与全部入口引用及主体一致，资料与空间当前可读
- **THEN** A0保存本次绑定准备，后续阶段只消费原精确值和本次因果，原独立准备可经根入口追溯，准备引用改变时形成不同入口身份

#### Scenario: 错绑定拒绝且无下游效果

- **WHEN** 准备错修订、风险、空间、适用性、监测集合、主体或入口，已有旧父因果，或者当前无权
- **THEN** A0拒绝，不冻结新准备、不创建依据或评估记录，历史准备保持

### Requirement: 确定性评估按真实输入权限执行

C25评估 MUST 按真实准备空间和来源复验当前工程/主体/分支/调用权限，并由风险、监测、依据和工件所属入口逐项核验实际消费范围。身份检查与范围检查返回不同资料增量时，不得要求二者完整集合包含或相等；redacted或实际输入当前无权仍 MUST 拒绝。输入快照、提交前复验、审计及原子事务保持，终态任务和失败不复活。

#### Scenario: 身份检查与准备范围增量不同

- **WHEN** 当前身份读取不携资料增量而准备范围读取合法返回真实来源，实际风险/监测/依据均有权且版本正确
- **THEN** 评估继续原确定性流程，不因两份授权增量集合不同阻断

#### Scenario: 实际消费范围被撤权

- **WHEN** 任一真实输入或父工件当前无权、脱敏或版本不符
- **THEN** 读取或提交前拒绝，不产生正式评估记录或成功事件

### Requirement: 父事件证明使用当前权限及正式运行事实

C30父事件证明 MUST 按当前工程/主体/调用权限、精确父子链边、正式运行绑定与同版本C04状态和消费事实核验，不得要求本次事件与历史登记的完整授权摘要相同。当前空间 MUST 覆盖该运行唯一精确入口冻结的空间集合；根入口缺失、多义、错空间、撤权、错父子或不可证明消费均拒绝。证明为有界只读，来源资格仍由实际消费资料的所属入口验证，原事件投递台账不得重置。

#### Scenario: 合法业务事件未携带整批历史资料授权

- **WHEN** 已提交风险记录事件的当前权限覆盖原父运行空间，主体/父子/运行与消费事实均成立，但资料授权集合与启动时不同
- **THEN** 可读取原父并核验真实消费，不因历史授权摘要不同拒绝，也不扩充本次资料权限

#### Scenario: 当前空间不能覆盖原运行

- **WHEN** 当前事件授权缺少根入口的任一冻结空间或当前撤权
- **THEN** 父事件证明拒绝且不推进图、模型或消费回执

### Requirement: 原识别等待支持精确Agent失败通知

workflow.resume-run MUST 支持strict原因agent-task-failed，仅携带retrieval-review且embedded的精确agentTaskRef。C30 MUST 按当前恢复权限、状态版本及原识别等待转交C24，不构造完成或失败结果引用；父可重试技术失败后仍 MUST 保留原通知并按冻结重试策略恢复原阶段。不得更换任务、重开批次或增加模型额度。

#### Scenario: 公开通知原等待任务失败

- **WHEN** 原有权主体以当前父版本通知同一识别等待任务终态失败
- **THEN** 原任务引用交给原C24子运行核验并收口失败项，原成功事实及预算保留

#### Scenario: 通知载荷越界

- **WHEN** 失败通知携带非检索审阅/非内嵌任务、结果正文或其它额外字段
- **THEN** 公开Schema拒绝，不启动或推进任务

### Requirement: 父图按子运行稳定错误分类

C30 MUST 在没有顶层稳定code时读取子运行异常的一层.error，沿既有错误分类规则保留详情和不可重试边界。不得按异常文案或递归cause猜测分类，不得把权限、冲突和检查点错误折为未知可重试失败。

#### Scenario: 子运行稳定异常进入父恢复

- **WHEN** C24恢复抛出携带稳定错误的运行异常
- **THEN** 父按该稳定错误分类并记录当前父阶段，保持原预算及已成立事实

### Requirement: 显式识别执行批次

identify-and-assess公开启动载荷 MUST 支持可选executionBatchId，按既有IdentifierSchema校验，并经唯一workflowEntryIdentityFor纳入入口摘要。批次不同 MUST 形成独立运行和线程；同批次重投 MUST 保持原运行及幂等约束。缺省时 MUST 保持原身份，不把批次混入业务frozenRefs或改变准备匹配、权限和预算。

#### Scenario: 同输入启动独立批次

- **WHEN** 同一工程、图与业务冻结引用使用两个不同executionBatchId启动
- **THEN** 形成不同运行和线程，分别固定各自输入时刻；旧运行和历史结果保持

#### Scenario: 批次重投与同键冲突

- **WHEN** 同批次同载荷重投，或在同幂等键下更换批次
- **THEN** 前者返回原运行且无重复业务效果，后者按异载荷拒绝

### Requirement: 父运行通过显式命令绑定匹配识别准备

系统 MUST 在workflow.resume-run中支持strict原因identification-preparation-ready，仅接收精确identificationPreparationSnapshotRef。C30 MUST 复验当前恢复权限、原主体、预期状态版本及识别准备等待，经C15/C04核验正式准备和完成结果，匹配原工程修订、完整空间/来源集合及已有监测范围。绑定 MUST 是本次命令的新审计事实，原独立清洗因果、冻结图版本、预算和结果保持不可变；父运行只可绑定一个准备引用，沿既有事务、入口快照和LangGraph恢复。

#### Scenario: 当前有权用户绑定匹配独立准备

- **WHEN** 当前有权的原主体提交匹配冻结输入的正式准备和有效等待点版本
- **THEN** 记录本次命令和精确准备绑定，沿原父运行继续识别，不重新清洗或伪造父任务事件

#### Scenario: 错范围或无效等待拒绝

- **WHEN** reader缺失、准备不存在/未完成/损坏/错主体/工程修订/空间/来源，或当前撤权、游标过期、运行取消/终态及不在识别准备等待
- **THEN** 拒绝绑定和业务推进，不创建识别子运行，不用其它资料集合替代

#### Scenario: 并发及回执重投保持唯一绑定

- **WHEN** 不同准备竞争同一父运行，或恢复命令重投
- **THEN** 原事务及幂等身份只允许一个准备绑定，异准备冲突；同引用沿当前权限和原状态版本规则处理，不覆盖历史或重复创建识别子运行

#### Scenario: 父恢复控制写引用具有正式证明

- **WHEN** LangGraph恢复控制写先于识别节点携带准备引用
- **THEN** 已核验准备先登记为同一父运行入口快照，恢复方据该精确登记事实继续，检查点只保存进度，不仅凭恢复载荷或其它运行的准备放行

### Requirement: 父图检查点保持同运行冻结图版本

系统 MUST 从已登记运行状态的graphVersion构造父图检查点；该可选值缺失时只使用同运行上下文的graphVersion。不得以入口摘要或当前部署最新图替换，原图版本及阶段结果保持有效，检查点不递归验证正文。

#### Scenario: 节点推进及恢复保持图版本

- **WHEN** 父图完成准备、进入等待或从已登记状态恢复
- **THEN** 检查点图版本保持启动时冻结的精确版本，入口摘要与图版本不同不导致合法运行被拒绝

#### Scenario: 已提交事实领先检查点后按原身份恢复

- **WHEN** 业务阶段已提交、检查点写入失败，当前业务入口有权且存在该运行已提交阶段结果
- **THEN** 按既有阶段到节点映射恢复原运行，保留检查点的历史启动授权引用，当前授权独立复验并记入本次业务审计
- **AND** 复用原运行与已完成结果，历史启动授权仅用于追溯
