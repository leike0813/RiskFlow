# 监测验收输入修正方案

必要修正沿用户持续授权推进；本方案不把原静态包认定为已可直接导入。已核对的问题及出处见monitoring-registration-entry-gap-2026-10-16.md。

1. 原CSV是对应监测行的资料事实源，保留其指标、数值、单位和原采样时刻。monitoring.json存在的派生时间差异保留，不回写原件，也不以它覆盖CSV。按明确case资料段建立独立的合成情景监测对象；对象标签说明属于合成情景，不推断真实物理测点、空间坐标或case之间的时间关系。
2. 每次评估只绑定与目标工序/适用性及所选case一致的精确监测快照，采用当前正式工程/空间引用和实际C11资料段。指标映射继续按indicator+parameterCode+metric解析，不将多个case的同刻值混入一个序列。
3. 原件不足以覆盖时序、预警变化、更正/补录和预测的正路径，另建明确标注“合成样本、待甲方复核”的纵向监测补充资料。它是独立来源/新版本，显式保存对象、规则化采样时间、数值、单位和生成规则，绝不冒充原CSV的测量历史；原来源、数值、旧结果及失败保持。先闭合具体输入清单，再正式导入。
4. 新资料沿C04 put、C11登记及原生CSV转换取得真实原件/JSON-LD/资料段引用，按C15原清洗及部分可用规则收口，再用D-89受控provision登记序列/显式可用性策略；批次和快照仍走既有正式入口。不直写表，不以文档或配置自检替代正式回执。
5. 可用性策略明确窗口、间隔、插值界限、各特征最小点数、覆盖率和原算法版本；预算、指标阈值、权重、矩阵及质量门槛保持。单点原始输入只能证明相应可用项，不能伪造斜率、频谱或预测结果。时序不足或清洗拒绝如实保留为非PASS。
6. 正式取证核对重复交付不增事实、更正/补录只追加、旧快照稳定、撤权/错序列拒绝；随后取得评估/预警、建议、人工决定、执行反馈与校准链。新输入和正式报告按同次精确引用绑定。

当前仅完成事实核对和方案，未生成纵向资料、未登记监测事实、未改变原包或系统判断。具体补充数据仍须在实施前写入当前design/IP范围；不得把本方案当作功能通过。
