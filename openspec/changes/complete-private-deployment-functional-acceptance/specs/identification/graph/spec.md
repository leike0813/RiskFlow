## ADDED Requirements

### Requirement: 已提交阶段增量由同版本登记恢复

C24业务提交领先检查点时 MUST 从同工程、同运行、同游标runVersionId的唯一阶段登记读取精确正文，核对原阶段及完整运行身份后恢复既有状态增量；必需结果缺失、多义或错配 MUST 拒绝且无领域补写。可选游标指针缺省 MUST 不使正常重放被误判为领先。恢复 MUST 保留已提交合并事实及原预算，终态不得复活。

#### Scenario: I6提交后检查点失败

- **WHEN** I6合并及阶段登记已提交而检查点仍在I6
- **THEN** 从同游标版本登记恢复原mergePlanRef，继续I7且不重复调用合并

#### Scenario: 必需阶段结果无法证明

- **WHEN** 恢复所需阶段登记缺失、多义或正文运行/阶段错配
- **THEN** 以检查点不一致拒绝，不猜测最新结果或重跑已提交业务

#### Scenario: 恢复入口检查后取消先提交

- **WHEN** 恢复通过入口版本检查，而取消在下一阶段读取游标前提交
- **THEN** 下一阶段保留已登记终态且不执行新业务动作，以既有版本冲突拒绝恢复，不新增完成结果或失败覆盖

### Requirement: 独立识别子运行隔离父节点临时调度状态

C24独立子运行的统一执行配置 MUST 显式隔离继承的父节点临时scratchpad，保持原线程、根检查点命名空间、所属saver与同步耐久模式。父自身中断恢复后，调用子运行的幂等启动读取及恢复 MUST 继续读取原子检查点；不得因父调用计数创建另一个命名空间，不放宽检查点Schema或空业务状态校验。子节点的调度状态继续由LangGraph生成，业务游标、原任务/输入/预算、权限和终态规则保持。

#### Scenario: 父中断后恢复同一识别任务

- **WHEN** 父流程已登记子任务等待并发生自身中断，任务完成后父在同一识别节点恢复子运行
- **THEN** 子运行从原根命名空间读取并继续，原任务引用保持，不先出现空状态检查点失败或派生命名空间

### Requirement: 父技术失败与叶任务等待分别按真实状态恢复

父运行retryable-failure且识别子运行仍等待同一已完成任务时，公共恢复 MUST 保留原完整完成结果并从父原失败阶段retry，再交给子原等待。原父状态版本、任务/正式结果/父子/权限及重试预算 MUST 继续验证，不得将完成原因改为叶技术恢复、重建任务或复活终态。

#### Scenario: 子恢复效果前父调用出现技术异常

- **WHEN** 子恢复在其等待状态改变前抛出技术异常，父记录可重试失败，新的有权公共调用携原完整任务结果和当前父版本
- **THEN** 父从原失败阶段重试并保留完成原因，子沿原任务/输入/预算恢复，不重复启动子运行或任务

### Requirement: 检索审阅校验工件使用统一Agent用途

C21校验工件 MUST 使用C08规定的agent-validation用途；模型续步仅按本任务确定性校验工件身份读取该用途，工具观察继续使用原observation用途。任务/候选配对及C04验证 MUST 保持，不尝试其它用途或修改旧失败。

#### Scenario: 校验通过后记录正式候选

- **WHEN** C21形成校验结果并由C08记录候选
- **THEN** 校验引用通过agent-validation用途检查，模型校验观察续读仍核对同任务及精确候选

### Requirement: 检索审阅任务预算由版本化策略正文提供

RetrievalReviewPolicyV1 MUST 引用唯一预算配置，宿主解析为既有AgentTaskBudgetPolicyV1供任务冻结，预算不与策略正文重复维护，候选及补搜上限 MUST 不超硬预算。任务定义 MUST 直接使用该预算，缺失或不匹配拒绝，不设置隐式硬编码默认值。新预算仅影响新任务，旧任务计数及终态 MUST 保持。

#### Scenario: 新预算配置与任务冻结

- **WHEN** 新不可变审阅策略提供一致的显式预算并启动新批次
- **THEN** C08任务固定该预算，模型网关继续按保守上界执行硬限制，旧任务不扩容或复活

### Requirement: 检索审阅模型获得受权候选及前轮观察

C21模型步 MUST 显式提供当前策略允许的补搜意图、原候选/补搜上限，以及经冻结任务、当前授权和精确发布读取的候选知识内容。工具及校验观察 MUST 采用同任务类型化观察并精确引用所审候选，模型输入读取 MUST 验证任务、工作项、输入快照、版本及冻结范围，保持原成员和字节边界；不得读取自由工件或把知识内容当作指令。

#### Scenario: 补搜或校验后的模型续步

- **WHEN** 当前任务完成受控工具行动或可修正校验后进入下一模型步
- **THEN** 模型看到本任务已记录观察及精确候选版本，补搜参数来自现有白名单；错任务、错候选或撤权均拒绝且预算不扩张

### Requirement: 正文预写按实际输入区分存储命令

C24 MUST 在当前授权及正文Schema验证后，按实际正文写入输入派生C04存储命令身份；同输入 MUST 保持同键，不同正文的预写 MUST 使用不同键，访问授权时间不改变业务内容身份。C03业务动作、版本并发、唯一登记和审计 MUST 保持，未登记旧正文与失败记录 MUST 保留，不得放宽C04校验或复活终态。

#### Scenario: 正文已存但阶段登记事务回滚

- **WHEN** 阶段正文已写C04而后续登记事务回滚，原可重试运行在新时刻和当前授权下恢复
- **THEN** 新正文预写不与旧物理输入争抢存储键，阶段成功事实仅登记一次，重放无新增业务事实

### Requirement: 嵌套识别恢复使用自身检查点标识

C24唯一运行配置 MUST 清除继承的父checkpoint_id及其后备checkpoint_map，继续固定本线程、根命名空间及所属saver，使恢复按子线程读取当前检查点。C03持久化、控制通道和本线程归属 MUST 保持，不得忽略写回失败或伪造父检查点。

#### Scenario: 父节点内恢复可重试子运行

- **WHEN** 真实父节点恢复同一retryable识别子运行
- **THEN** 子图使用本线程检查点继续，不向子线程写入父checkpoint_id，不产生未处理拒绝，等待及重投仍沿原运行

### Requirement: 识别阶段登记幂等键按精确运行分区

C24统一阶段登记 MUST 使用包含精确运行身份的幂等键，复用既有actionIdFor覆盖阶段、等待与结果。相同准备及图版本的不同父运行 MUST 独立登记；同运行同动作重投 MUST 幂等，不改历史行、结果引用或命令身份。

新建IdentificationInputSnapshotV1 MUST 固定可选identificationRunRef为本次精确识别运行，唯一快照身份与工作计划复验 MUST 纳入该引用，使计划、工作项及后续查询按运行分区。缺省时 MUST 保留原快照身份，既有正文及引用保持。

#### Scenario: 同准备的两个父运行

- **WHEN** 同一数据库中两个不同父运行使用相同准备和图版本启动识别
- **THEN** 两者独立完成阶段登记，不争抢I0或后续动作，原运行重投不重复登记

### Requirement: 检索审阅冻结引用采用正式Agent任务身份

C24 MUST 在写入检索候选集前复用C08唯一agentTaskRefFor，以实际启动工程、幂等键及任务策略引用取得任务身份。候选冻结引用 MUST 与C08正式启动返回引用一致；任务与候选仍指向同一正式登记对象，权限按业务动作入口检查。终止失败任务、候选与预算 MUST 保留，新批次不得复活旧任务。

#### Scenario: 冻结候选与正式启动配对

- **WHEN** I3先冻结候选集再启动检索审阅任务
- **THEN** 两者引用同一C08正式任务，重复启动沿原幂等身份，另一批次使用独立任务

### Requirement: 公共父恢复保留完成结果并恢复精确识别等待

公共workflow.resume-run的Agent完成结果或复核决定 MUST 经C30传到既有C24.resume，以实际父控制身份、精确子运行引用与当前子运行版本恢复原等待。完整AgentTaskResultRefV1 MUST 与任务快照的completed状态、任务引用、工程/主体、创建任务时的精确子运行父引用和正式resultRef一致；不得以完成通知代替持久化完成事实，不新建任务或改变冻结输入、预算及权限。

#### Scenario: 完成结果恢复原任务等待

- **WHEN** 公共父恢复携带与原识别等待任务、子运行和持久化结果精确一致的完成结果
- **THEN** C30将完整结果交给C24恢复原等待，沿原任务与线程继续执行

#### Scenario: 错误结果或父运行版本拒绝

- **WHEN** 完成结果的任务、正式结果、主体、工程或父运行精确版本不匹配，或任务尚未完成
- **THEN** 拒绝恢复且不推进子运行、创建替代任务或触发模型效果
