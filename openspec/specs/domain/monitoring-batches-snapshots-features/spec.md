# domain/monitoring-batches-snapshots-features Specification

## Purpose
为 RiskFlow 提供可追溯、只追加且可确定性重放的监测序列、批次、快照与时序特征，使识别、评估、预警和处置反馈只消费精确冻结的监测事实，而不直接读取持续变化的外部数据。

## Requirements

### Requirement: 监测序列使用稳定身份和不可变修订

系统 MUST 以同一工程、空间区段、监测对象和监测参数的稳定身份归集监测序列，并以不可变修订固定工程修订、空间区段修订、监测指标、参数码、规范单位、允许的单位换算和有效时间。监测指标 MUST 引用 C01 的六项固定监测指标枚举；新修订不得覆盖旧修订或改变既有批次和快照引用。（RI-S21、RI-S43；RA-S1）

#### Scenario: 登记地表沉降序列修订
- **WHEN** 获授权调用方提交同一工程和空间区段内的监测对象、`地表沉降` 指标、参数码、规范单位、单位换算和有效时间
- **THEN** 系统创建监测序列的不可变修订并返回精确 `MonitoringSeriesRefV1`
- **AND** 后续批次只能引用该精确修订声明的指标、范围和单位规则

#### Scenario: 序列配置变化创建新修订
- **WHEN** 规范单位、单位换算、监测参数或所属工程上下文发生变化
- **THEN** 系统创建同一稳定序列的新修订
- **AND** 既有批次和快照继续引用原精确修订

#### Scenario: 拒绝散落监测指标名称
- **WHEN** 调用方提交六项固定监测指标之外的近义词、英文别名或空值
- **THEN** strict Schema 拒绝该序列修订

### Requirement: 样本工件在批次登记前完成有界严格校验

系统 MUST 通过 C04 内容工件接收 UTF-8、逐行 strict Schema 的监测样本；每个样本至少固定来源样本键、采样时间、有限数值和单位。系统 MUST 校验工件完整性、工程与空间授权、来源证据、样本顺序、批次时间窗、序列单位规则和结构上限；任一项失败时 MUST 整批拒绝，不得保存部分样本。原始工件和来源证据 MUST 保持可追溯。（RI-S13、RI-S14、RI-S21、RI-S23；RA-S1）

#### Scenario: 登记合法样本工件
- **WHEN** `register-monitoring-batch` 引用一个已耐久、证据非空、属于目标工程与空间范围且全部样本落入命令时间窗的合法工件
- **THEN** 系统把数值按精确序列修订的换算规则转换为规范单位并登记不可变批次
- **AND** 返回既有 `register-monitoring-batch` 成功结果和精确 `MonitoringBatchRefV1`

#### Scenario: 非法样本使整批失败
- **WHEN** 样本工件含未知字段、无效 UTF-8、非有限数值、乱序或重复时间、范围外时间、未知单位、缺失来源证据或超过结构上限
- **THEN** 系统返回闭合失败结果
- **AND** 不产生批次、样本、审计成功记录或下游事件

#### Scenario: 无权工件不可枚举
- **WHEN** 调用方无权访问目标序列、空间范围、资料授权或样本工件中的任一项
- **THEN** 系统返回 `AUTHORIZATION_DENIED`
- **AND** 错误不泄露目标是否存在、样本值、来源位置或其它工程信息

### Requirement: 监测批次和样本更正保持只追加

系统 MUST 将每次交付保存为不可变监测批次，并以闭合关系区分 `original`、`correction` 和 `supplement`。更正批次 MUST 指向同序列的先前批次，只为已存在采样时间追加新值；补录批次 MUST 指向同序列的先前批次，只为当时缺失的历史采样时间追加值。任何关系均不得更新或删除先前批次和样本。（RI-S21；RA-S1、RA-S7）

#### Scenario: 同一采样时间追加更正
- **WHEN** 已登记采样时间收到不同规范值且新批次以 `correction` 指向包含原值的同序列先前批次
- **THEN** 系统追加更正批次和新样本版本并保留明确前序关系
- **AND** 原始批次、原始值及引用它的快照保持不变

#### Scenario: 迟到样本作为历史补录
- **WHEN** 新到样本早于序列已登记的最新采样时间、目标时间当时没有有效值且批次以 `supplement` 指向同序列先前批次
- **THEN** 系统追加历史补录批次并保留迟到标记与来源证据
- **AND** 不覆盖其它时间点或已冻结快照

#### Scenario: 关系语义不符时拒绝
- **WHEN** 更正引用其它序列、补录与已有有效时间冲突、原始批次试图写入不同值的既有采样时间，或前序批次不存在
- **THEN** 系统返回不可重试的业务阻塞或陈旧版本错误
- **AND** 不产生部分关系或样本

### Requirement: 完全重复交付和并发登记保持幂等

系统 MUST 复用 C03 的命令幂等语义，并以规范化样本集合、序列修订、时间窗、批次关系、精确来源引用和证据形成交付指纹。相同工程、命令分支和幂等键的同载荷重试 MUST 返回原批次；同键不同载荷 MUST 返回 `IDEMPOTENCY_CONFLICT`。来源与证据相同的完全重复交付不得因新命令或并发重试生成第二份样本事实；数值相同但来源或证据不同的交付 MUST 保留独立可追溯事实。（RI-S21；RA-S1）

#### Scenario: 相同命令重放返回原批次
- **WHEN** 调用方使用相同幂等键重试完全相同的批次登记
- **THEN** 系统返回原 `MonitoringBatchRefV1`
- **AND** 不重复写批次、样本或审计

#### Scenario: 不同命令提交完全重复交付
- **WHEN** 同一序列、时间窗、关系、规范化样本集合、精确来源引用和证据已由另一成功命令登记
- **THEN** 系统返回既有批次引用
- **AND** 不创建语义重复的批次或样本

#### Scenario: 相同数值来自不同证据
- **WHEN** 新交付与既有批次包含相同时间和值，但精确来源引用或证据不同
- **THEN** 系统保留新的批次及其独立证据链
- **AND** 不把多来源交付错误折叠为一次重复重试

#### Scenario: 同键不同载荷发生冲突
- **WHEN** 调用方复用一个已完成幂等键提交不同序列、工件、时间窗或关系
- **THEN** 系统返回 `IDEMPOTENCY_CONFLICT`
- **AND** 原批次保持不变

### Requirement: 监测快照同时冻结业务时间和系统记录时间

系统 MUST 通过既有 `EngineeringDataPortV1.freeze(monitoring-snapshot)`，按精确序列修订、截止点和不可变可用性策略创建 `MonitoringSnapshotRefV1`。快照 MUST 固定由策略确定的时间窗、冻结时的系统记录时点、实际采用的批次及样本版本、规范单位、策略版本、算法版本、对齐结果、特征、可用性原因、证据和审计；选择样本时只能使用采样时间不晚于截止点且在系统记录时点已登记的事实。（RI-S21；RA-S1、RA-S5～RA-S7）

#### Scenario: 冻结包含当时有效更正的快照
- **WHEN** 截止点前的采样已有一条在冻结记录时点可见的有效更正
- **THEN** 快照固定更正后的样本版本和完整前序证据链
- **AND** 同一时间点只出现一个当时有效值

#### Scenario: 后续数据不改变旧快照
- **WHEN** 快照创建后又登记迟到样本、更正批次或序列新修订
- **THEN** 旧快照的样本成员、特征、可用性、证据和版本引用逐字节保持不变
- **AND** 新业务运行必须显式创建新快照才能使用新增事实

#### Scenario: 无可用样本仍形成可解释快照
- **WHEN** 冻结时间窗内没有满足业务时间和系统记录时间条件的有效样本
- **THEN** 系统创建状态为不可用的不可变快照并记录稳定原因码
- **AND** 不伪造零值、插值、特征或“最新值”

### Requirement: 时间对齐和单位换算是版本化确定性计算

系统 MUST 先按序列修订执行显式仿射单位换算，再按可用性策略给出的窗口、间隔和最大插值跨度生成以截止点为锚的等间隔时间网格。精确时间点优先使用有效样本；仅在同一序列前后样本均存在且跨度不超过策略上限时执行线性插值；系统不得外推或用零值填补缺失。相同冻结输入和版本必须产生相同对齐结果。（RI-S21；RA-S1）

#### Scenario: 在允许跨度内线性插值
- **WHEN** 一个网格点两侧都有有效规范值且样本跨度未超过策略上限
- **THEN** 系统使用线性插值生成该网格值并标记两个来源样本

#### Scenario: 缺少边界时保留缺失
- **WHEN** 网格点缺少任一侧样本或样本跨度超过策略上限
- **THEN** 系统将该网格点记录为缺失并给出稳定原因码
- **AND** 不执行外推、最近值填充或零填充

#### Scenario: 未声明单位换算时拒绝批次
- **WHEN** 样本单位既不是序列规范单位，也没有在精确序列修订中声明换算
- **THEN** 系统拒绝登记该批次
- **AND** 不猜测单位或比例

### Requirement: 快照生成四项确定性时序特征

系统 MUST 从冻结后的等间隔有效值计算短期斜率、加速度、频域主峰和异常评分，并保存每项特征的值、单位、窗口、实际输入数量、算法版本和可计算性。短期斜率 MUST 使用冻结策略窗口内的普通最小二乘直线斜率；加速度 MUST 使用相邻斜率序列的普通最小二乘斜率；频域主峰 MUST 对连续等间隔窗口去均值、应用 Hann 窗后，在排除直流分量的正频率中选择功率最大且并列时频率最低的频点；异常评分 MUST 使用当前值相对前序基线的带尺度下限有符号 median/MAD 分数。系统不得由 LLM 给出或修改这些值。（RI-S21；RA-S1、RA-S5、RA-S6）

#### Scenario: 地表沉降样例得到可交叉验证特征
- **WHEN** 地表沉降快照具有策略要求的连续、等间隔规范值
- **THEN** 系统按冻结公式产生可由独立参考计算交叉验证的斜率、加速度、频域主峰和异常评分
- **AND** 重放相同输入与版本得到相同数值和特征可计算性

#### Scenario: 缺样时单项特征不可计算
- **WHEN** 某项特征缺少策略要求的连续样本数量或频域输入超过结构上限
- **THEN** 系统只将该项标记为不可计算并记录稳定原因码
- **AND** 不以零、NaN、Infinity 或其它特征代替

#### Scenario: 异常评分不清洗原值
- **WHEN** 当前值相对基线得到较高异常评分
- **THEN** 快照同时保留原规范值和异常评分
- **AND** 是否排除、修正或判定业务可用由 C15 的清洗 Agent 与确定性收口决定

### Requirement: 快照可用性区分算法可计算性和后续业务判断

系统 MUST 依据精确可用性策略记录覆盖率、缺失率、连续窗口和四项特征各自的 `available | unavailable` 状态及稳定原因码，并据此形成 `available | partial | unavailable` 的确定性快照可用性。该事实只表达 C14 输入和算法是否可计算，不得代替 C15 的 Agent 清洗结果、排除范围或业务部分可用决定。（RI-S21；RA-S1）

#### Scenario: 部分特征可计算
- **WHEN** 对齐结果足以计算短期斜率和异常评分，但不足以计算加速度或频域主峰
- **THEN** 快照状态为 `partial` 并逐项记录可计算状态与原因
- **AND** 已算出的稳定特征保持可消费

#### Scenario: 策略版本变化不改旧结论
- **WHEN** 可用性策略后来发布新版本
- **THEN** 旧快照继续引用原策略并保留原可用性结论
- **AND** 使用新策略必须创建新快照

### Requirement: 快照查询遵守授权并返回精确只读结果

系统 MUST 实现既有 `EngineeringDataPortV1.read(monitoring-snapshot)`，在读取前重新执行当前 C06 工程、空间和资料权限校验；成功结果 MUST 返回只指向该精确快照的 `QueryResultRefV1`，查询投影不得修改领域事实。无权、跨工程与不存在必须采用不可枚举失败语义。（RI-S14；RA-S1）

#### Scenario: 获授权读取精确快照
- **WHEN** 调用方拥有目标工程、空间和全部来源资料的当前读取权限
- **THEN** 系统返回只关联请求 `MonitoringSnapshotRefV1` 的查询结果引用
- **AND** 该结果只展示冻结样本、特征、可用性、版本和获准证据定位

#### Scenario: 权限撤销后不能读取旧快照正文
- **WHEN** 快照创建后调用方的工程、空间或来源资料权限已撤销
- **THEN** 后续读取返回 `AUTHORIZATION_DENIED`
- **AND** 既有快照事实和历史审计不被删除或改写

### Requirement: 批次与快照提交原子记录审计且不伪造下游事件

系统 MUST 复用 C03 在单个 PostgreSQL 事务中提交批次或快照领域事实、命令收据和 C07 审计；任何写入失败 MUST 整体回滚。审计 MUST 关联操作者、授权上下文、命令与幂等身份、精确序列/批次/快照引用、业务时间、记录时间、来源证据和更正/补录原因。C14 不得为普通批次登记发布重评估事件，也不得在无法比较前后业务快照时伪造 `engineering.assessment-input-changed.v1`。（RI-S14、RI-S21；RA-S1、RA-S7）

#### Scenario: 审计失败使批次登记回滚
- **WHEN** 批次、命令收据或审计中的任一写入失败
- **THEN** 整个事务回滚并返回结构化技术错误
- **AND** 不留下可见批次、样本或成功收据

#### Scenario: 普通批次不发布重评估事件
- **WHEN** 原始、更正或补录批次成功登记但尚未由所属流程形成并比较新旧监测快照
- **THEN** C14 只保存批次事实和审计
- **AND** 不发布 `engineering.assessment-input-changed.v1`

#### Scenario: 敏感值不进入错误与日志
- **WHEN** 批次或快照处理失败
- **THEN** 普通错误与日志只包含稳定错误码、阶段和获准引用
- **AND** 样本值、工件正文、来源正文及未授权存在性只写入受保护诊断或审计路径

### Requirement: 精确监测序列修订可按当前授权狭窄读取

系统 MUST 提供 C14 所有的狭窄只读能力，以精确 `MonitoringSeriesRefV1`、工程、调用身份、读取身份、请求时间和 C06 授权上下文读取一个监测序列修订。系统 MUST 在返回前重新校验当前 `engineering-data.read` 工程和空间权限；成功结果 MUST 只包含 `monitoringSeriesRef`、`seriesId`、`projectId`、`projectRevisionRef`、`spatialScopeRef`、`monitoringObject`、`monitoringIndicator`、`parameterCode`、`canonicalUnit`、显式 `unitConversions`、`effectivePeriod`、`recordedAt`、可选 `previousRevisionRef` 和 `current | superseded` 修订状态。结果 MUST 使用 strict Schema，不得包含原始或规范监测值、批次、样本、快照对齐点、特征、来源正文、自由字段或列表查询能力。每次成功读取 MUST 通过既有原子幂等语义只追加命令收据和审计，不得复制或修改序列注册事实。（RI-S14、RI-S21、RI-S43；RA-S1、RA-S5、RA-S6）

#### Scenario: 获授权读取精确序列修订元数据
- **WHEN** 调用方提交属于目标工程的精确序列修订引用，并持有覆盖该序列空间区段的当前 C06 读取授权
- **THEN** 系统返回该精确修订的身份、指标、参数码、规范单位、显式换算、版本引用、有效期和 `current | superseded` 状态
- **AND** 调用方可用 `monitoringIndicator + parameterCode` 和单位字段核对 C18 的监测字段映射

#### Scenario: 序列元数据读取不泄露监测数据
- **WHEN** 获授权调用方读取一个精确序列修订
- **THEN** strict 结果不含原始或规范监测值、批次、样本、对齐点、快照特征、来源正文或未声明字段
- **AND** 监测值和特征仍只能通过既有获授权快照查询路径读取

#### Scenario: 目标或授权异常不可枚举
- **WHEN** 精确序列修订在请求工程中缺失、不存在、版本不匹配或属于其它工程，或者调用方的工程或空间授权已撤销
- **THEN** 系统统一返回 `AUTHORIZATION_DENIED`
- **AND** 错误不泄露序列是否存在、所属工程、当前版本、指标、单位或其它修订信息

#### Scenario: 重复读取只记录一次审计
- **WHEN** 调用方以相同读取身份重试完全相同的精确序列修订读取
- **THEN** 系统返回同一精确修订的有界结果并复用既有成功收据
- **AND** 不重复追加审计或任何序列事实

#### Scenario: 相同读取身份不能改换目标
- **WHEN** 调用方复用已完成的读取身份但改变工程、序列修订引用、调用身份、请求时间或授权上下文
- **THEN** 系统返回 `IDEMPOTENCY_CONFLICT`
- **AND** 原收据、审计和序列事实保持不变
