## MODIFIED Requirements

### Requirement: 反馈命令必须由真实执行后输入和实际评估组成

系统 MUST 接受获授权用户针对精确执行事实提交执行后监测快照、反馈工件和反馈发生时间；服务端 MUST 只从同一风险输入的已成立 C25 评估结果及受权冻结依据创建不可变反馈输入快照，再交给 C28 记录反馈。缺少其中任一事实时不得以基线评估、预测值、占位引用或客户端自称结果代替。正式反馈成立后，独立反馈分段才可读取该精确引用继续偏差与校准流程。（RA-S7）

确认「实际评估已完成」时，服务端 MUST 用按精确评估记录引用发出的运行完成证明，而不是任何自述或最新值；该证明 MUST 以调用方授权范围**覆盖**该运行已登记事实的范围为准，不要求调用方上下文与写入运行时的上下文逐字相同。调用方为读取而签发的上下文范围 MUST 仍由调用方按任务需要收窄，本要求不放宽任何调用方自身的授权。

#### Scenario: 执行后反馈形成正式事实
- **WHEN** 获授权用户提交同工程执行、执行后监测、受权工件和合法时间，且同风险输入的实际评估已完成
- **THEN** 系统保存包含精确执行、监测、工件、实际评估及证据引用的不可变反馈，返回正式反馈引用
- **AND** 后续工作流只读取该反馈引用，不重做人工录入

#### Scenario: 实际评估缺失或链不符时失败
- **WHEN** 实际评估尚未形成、监测早于执行、评估风险输入或空间不符，或工件不可读
- **THEN** 系统返回稳定、不可枚举的失败且不保存部分反馈、成功审计或反馈事件
- **AND** 保留原命令身份供满足前置条件后安全重试

#### Scenario: 以按任务收窄的读取上下文确认实际评估
- **WHEN** 获授权用户按单个空间收窄签发读取上下文，而该评估由更宽范围启动的运行产生
- **THEN** 运行完成证明按覆盖判定承认该运行的事实，正式反馈照常成立
- **AND** 读取上下文本身不被扩大，仍只承载本次任务所需的空间与来源范围
