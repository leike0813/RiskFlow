## 主线：按工程业务闭环讲，用专利覆盖点收尾

演示沿**典范追溯链**走一圈，每站同时点出对应专利步骤——甲方听得懂业务，专利覆盖自然带出，而不是先讲专利再找页面。

```
资料 DOC2026001 ─ 资料段 DOC2026001-S32-SEG007 ─ 工序节点 PN-VDS-04 ─ 机理条目 MEC-VDS-017
   ↓ 识别
风险记录 RISK-2026-001
   ↓ 评估
评估记录 ASSESS-2026-001  ← ★ 现场可解释性主落点
   ↓ 预警

   ↓ 偏差
```

## ★ 现场可解释性：单页闭环

甲方当场问「这个风险为什么是这个等级」时，**从评估记录详情同页给出全部依据，不离开当前对象**。首屏给出推导摘要，逐指标明细可折叠、分页或滚动读完；不要求最多 512 项指标在一个物理屏幕内同时显示：

```
逐指标取值与基础分  →  权重后得分合计  →  P / C 分值  →  矩阵落点  →  风险等级
                                                    ↑ 当前记录高亮
逐项附：适用规则集版本 · 权重版本 · 矩阵版本 · 适用性元数据快照 · 取值证据段
```

这条路径是票 05 原型 `AssessmentRecordDetailPage` 已验证形态（「等级是怎么来的」六步推导表 + 落点矩阵 + P 侧/C 侧逐指标表 + 适用规则与版本），演示前按真实配置复跑一遍即可。

## 数据说法脚本

**开场统一说一次，之后不再重复**：

> 目前系统内的指标、风险矩阵与阈值口径**尚未经甲方审核**，接入贵方正式配置后数值会随之调整。

普通业务演示开场不使用「合成」「模拟」「演示数据」作装饰性说明；这项取舍只约束普通业务页面和讲解脚本，不适用于质量页面、试运行报告、验收记录及其导出或截图证据。

**质量与验收材料必须标注“合成样本，待甲方复核”并保留来源、适用范围及候选资格**，不能因截图文案规则而删除。开场说明只补充业务语境，不替代这些材料中的标注，也不构成甲方最终业务验收通过的证据。

**五张汇报图先不重出**，演示用真页面不用静态截图。代价是汇报材料里仍是旧设计系统的图，规格中已标注需按新设计系统重出。

## 演示中的红线（`screenshot-content-inventory.md:247-256`）

业务演示截图和讲解不得使用开发状态词包装尚未交付的能力；以下约束同时适用，但不得据此删除质量或验收材料必需的合成标记：

- 不把 Demo、Mock、占位、测试环境、开发中或敬请期待的内容呈现为已交付业务事实；
- 未获得来源的国家标准号、规范条款号、真实工程里程、真实人员姓名
- 「准确率 99%」「秒级完成」「自动消除风险」等未经验证的宣传语
- LLM 内部思维链、系统提示词、原始模型响应
- 将模型置信度与综合置信度混为同一指标
- 将风险可接受阈值与监测预警阈值合并
- 将校准建议展示成已自动修改权重或规则
- 不同屏幕使用不同项目、时点、风险编号、P/C、等级或监测当前值

最后一条对演示尤其要紧：六个站必须用同一条典范追溯链的数据，不能第一站用一个风险、第二站换成另一个。

**「助手工作」页签的展示边界**：展示工具行动、逐项确定性校验、资源预算、正式结果（票 05 已定），**不展示原始模型响应与思维链**——前者正是上述红线之一。

## 遗留风险

1. **开场口径仍可能被误解为甲方提供的数据。** 普通业务页面沿用已决定的呈现取舍；质量与验收材料必须保留来源、合成标记和待复核资格。正式配置导入后产生新版本、重跑受影响验收，不原地改写历史结果或以本演示宣称最终业务验收通过。
2. **汇报图与真页面风格不一致**：五张图仍是旧设计系统，演示用真页面。若甲方同时看材料与演示，会感到两种风格。建议在真页面稳定后重出，且派生点跟着新结构调整（总览 / 助手工作 / 识别任务 / 评估与预警 / 处置与追溯）。
3. **原型来源标签未完成生产核对**：`GB 50299` 所在指标必须按真实来源、版本和定位核对，不能仅换标准号或去掉来源列，见 §规范引用白名单。
4. **「等级是怎么来的」依赖 B-1 之外的数据完整性**：评估记录详情要展示逐指标取值与得分，前提是评估记录返回足够字段——票 06 的 `AssessmentRecordViewV1`（`packages/contracts/src/ports/index.ts:4823`）已含 `indicators≤512` / `axes` / `matrixPlot` / `configurationRefs` 七项，应能支撑，需在 CH-6 验收时确认。
