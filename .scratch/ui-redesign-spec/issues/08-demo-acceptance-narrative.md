# 甲方演示 / 验收叙事线

Type: grilling
Status: resolved
Blocked by: 05

## Question

新导航树与页面归位已定（见票 02 的映射表），哪些页面承担演示节点已经清楚。但**演示时按什么顺序讲、每站讲什么、甲方要看的是哪个业务闭环**仍未定。

服务对象是双主线（工程风险管理员日常办公为主、甲方演示验收为辅），演示线要独立于日常动线设计——日常动线是「上传资料 → 启动识别 → 评估 → 预警 → 处置任务」，而验收要证明的是**系统覆盖识别专利 RI-S1–RI-S6 与评估专利 RA-S1–RA-S7 全步骤**，且能解释每个 P/C 分值、风险等级和预警触发所用的指标、规则、权重、矩阵版本与适用性元数据（`AGENTS.md` §7 交付物对齐）。

具体要回答：

1. **演示叙事顺序**：从哪一站开始、经过哪几站、以什么收尾？是按专利步骤（RI-S1→RI-S6、RA-S1→RA-S7）走，还是按工程业务闭环走？
2. **每站演示什么**：哪些页面必须出现（甲方验收要看能力清单），哪些可以跳过。是否需要一个专门的「演示模式」把 8 页待建中已具备的部分串起来？
3. **「能解释」如何在界面上当场演示**：追溯链已从 `/review-audit/trace` 独立页降为各详情页内能力（票 02 原则 4）。甲方要求当场回答"这个风险为什么是这个等级"时，演示者从哪个页面、点几下能走到完整解释？
4. **合成数据的说法**：已定界面不标注合成状态（票 01），但演示时必须口头说明（`synthetic-v1` 当前是 3×2 矩阵、四级无名称）。演示者需要一份**说法脚本**——怎么解释这些数字、怎么交代真实配置到位后的变化。
5. **演示屏**：`full-product-ui-spec.md:258-266` §18 已规划五张汇报截图派生点，`demo/screenshots/` 有 v1 五张定稿，`demo/v2/screenshots/` 有 v2 五张。这些截图在新设计系统（票 04）下要不要重出？重出的时机与归属。
6. 演示线与日常主路径不一致的地方（比如日常不展示的追溯页，演示要用），是设一个演示专用视图还是临时深链？

产出是演示叙事脚本（分站、每站讲的点、说法脚本），作为资产链接回本票。

## Answer

产出资产：[甲方演示 / 验收叙事线](../../riskflow-master-plan/prototypes/demo-acceptance-narrative.md)。

**主线**：按工程业务闭环讲，用专利覆盖点收尾。沿典范追溯链 `DOC2026001 → … → CAL-2026-001` 走六站（资料接入 / 识别 / 评估 / 预警 / 处置 / 偏差与校准），每站同时点出对应专利步骤（RI-S1～S6、RA-S1～S7），甲方听得懂业务而不用先听专利。

**★ 现场可解释性同页闭环**：评估记录详情首屏给出「指标得分 → 权重 → P/C → 矩阵落点 → 等级」摘要，同页展开逐项依据和精确配置版本。明细可折叠、分页或滚动，不要求最多 512 项指标同屏显示，不离开当前对象。

**数据说法脚本**：普通业务演示开场沿用「指标、风险矩阵与阈值尚未经甲方审核，正式配置接入后会调整」，普通业务页面不额外标合成状态。但质量页面、试运行报告、验收记录及导出或截图证据必须保留“合成样本，待甲方复核”、来源、适用范围和候选资格；口头说明不能替代材料标注。

**规范来源核对**：MANIFEST A1–A7 只是已取得的来源候选，不自动证明某个指标或阈值有依据。每项须核对实际来源、版本、条款／资料段、适用性和数值性质。原型误引 `GB 50299` 的指标必须据真实输入修正，不得仅换成白名单标准号或隐藏来源列。必要依据缺失时如实不可用；合成值在质量／验收材料中保留合成资格。

**演示方式**：不设演示模式，用真实导航与快捷键——所演即所得。配合票 05 已定的 ⌘K 直达任意对象、`g`+数字切一级导航、`⌘\` 折叠侧栏，演示者全程键盘操作，顺带展示桌面端范式与全键盘可达。**五张汇报图先不重出**，演示用真页面。

**红线已抄录进资产**（`screenshot-content-inventory.md:247-256`），其中两条对本次演示尤其要紧：不得将校准建议展示成已自动修改权重或规则；**六个站必须用同一条典范追溯链的数据**，不能第一站用一个风险、第二站换另一个。另注：「助手工作」页签展示工具行动、逐项校验、资源预算、正式结果，**不展示原始模型响应与思维链**——前者正是红线之一。

**遗留风险**：

1. 普通业务页面不标合成状态仍存在来源误解风险，质量与验收材料的显式标注不能省略，技术演示不等于甲方最终业务验收。
2. 汇报图仍是旧设计系统，与真页面风格不一致，真页面稳定后须重出，派生点跟着新结构调整。
3. 原型 `GB 50299` 标签尚未完成真实来源核对；由 CH-6／CH-8 按来源、版本、定位和适用性修正，不能只改文案。
4. 「等级是怎么来的」依赖 `AssessmentRecordViewV1`（`packages/contracts/src/ports/index.ts:4823`）返回足够字段（`indicators≤512` / `axes` / `matrixPlot` / `configurationRefs` 七项），应能支撑，需在 CH-6 验收时确认。
