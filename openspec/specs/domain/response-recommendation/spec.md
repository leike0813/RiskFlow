# domain/response-recommendation Specification

## Purpose
为 RiskFlow 在已入库预警和处置任务之上，以甲方审核的精确措施发布生成有界候选，借助受限 Agent 组合排序，并经确定性约束校验形成可追溯的正式处置建议，保持人工采纳与现场执行的独立边界。（RA-S7）

## Requirements
### Requirement: 措施候选只来自冻结的已发布依据

处置阶段 MUST 根据已成立预警、评估及适用性，从选定运行清单解析措施库、生成和校验策略、Agent 与现场上下文并冻结。风险类别由处置策略显式绑定；候选来自已批准措施，匹配目标、适用条件及触发事实。后续策略变化不修改已冻结候选，也不要求评估阶段预先具备这些策略。

#### Scenario: 多预警冻结同一任务的候选

- **WHEN** 同一处置任务关联多条正式预警并在本阶段获得已批准措施、生成与校验策略
- **THEN** 冻结一套针对这些预警的候选和处置上下文，不要求原评分快照预先保存后续策略

#### Scenario: 不合格来源不能进入候选

- **WHEN** 精确风险输入没有经已审核策略绑定的类别，或措施属于其它工程、未获批准的发布、不同兼容集合、不满足该任务的类别、适用性和触发类型
- **THEN** 系统不将其纳入候选；若没有合格措施，则返回结构化阻塞
- **AND** 不以宽松匹配或静态兜底措施补齐

#### Scenario: 进入处置再准备配置

- **WHEN** 已有正式评估预警，处置配置此时齐备
- **THEN** 形成处置输入和候选，追溯原评估，无需重评分

#### Scenario: 处置配置待准备

- **WHEN** 措施或现场上下文尚不齐备
- **THEN** 该阶段显示待准备，评估和预警结果保持可用

### Requirement: 处置 Agent 只能组合和排序冻结候选

系统 MUST 为 `response-recommendation` 使用 C08 版本化有界任务，冻结任务发起者、工程、输入版本、模型/提示/工具策略、预算和候选集。Agent 增量 MUST 只表达候选措施的选择、组合和实施顺序，不得创建或改写措施、规范、触发事实、资源事实或人工决定。每版候选、原始响应、工具行动、增量逐项接受/拒绝原因及预算消耗 MUST 留下可重建引用；任务失败或预算耗尽 MUST 保留失败证据并阻止正式建议。（RA-S7）

#### Scenario: 合法组合成为建议候选
- **WHEN** Agent 在冻结候选集内给出非空、无重复且有序的措施组合
- **THEN** 系统以类型化增量校验并保存不可变建议候选版本及其任务结果引用
- **AND** Agent 不直接写入正式建议或采纳决定

#### Scenario: 越界增量被拒绝
- **WHEN** Agent 引用候选集之外的措施、重写措施内容，或任务在预算耗尽、工具失败后仍无合格增量
- **THEN** 系统记录逐项拒绝或任务失败及证据，且不创建正式处置建议
- **AND** 仅字段、格式和候选集引用等可修复错误可在原任务剩余预算内重试；来源资格、权限和三项约束失败不得通过修正循环绕过

### Requirement: 候选与命令引用必须精确对应

既有 `create-candidate` 分支 MUST 只接受同一工程、同一冻结处置任务和措施候选集的已完成 `AgentTaskResultRefV1`，校验任务类型、结果族、候选版本及生成策略精确引用后返回正式候选引用。`validate-and-record` MUST 只按候选精确版本读取冻结依据及其验证策略和现场上下文，不得从当前可变任务、最新措施或当前现场值重新组装旧候选。重放同一命令与载荷 MUST 返回原结果；同一幂等键载荷变化 MUST 拒绝。（RA-S7）

#### Scenario: 结果与冻结依据一致
- **WHEN** 完成的处置 Agent 任务、措施候选查询结果和处置任务版本具有相同工程、冻结输入与精确策略引用
- **THEN** `create-candidate` 返回可按精确版本读取的建议候选引用
- **AND** 相同命令重试不产生第二份候选或审计事实

#### Scenario: 结果错配或过期
- **WHEN** Agent 任务失败、结果族不是建议候选、查询结果来自其它任务，或候选/验证策略/现场上下文引用不匹配
- **THEN** 系统返回类型化拒绝，不创建正式建议、成功审计或隐式替代候选

### Requirement: 三项处置约束由确定性模块逐项校验

系统 MUST 对冻结候选依次执行触发指标一致性、规范合规性与现场可执行性校验，并为每项保存通过与否、原因和证据引用：触发依据预警触发类型、触发事实与措施目标指标，规范依据措施库规范证据与禁忌，现场依据精确现场资源、工序与空间上下文。缺失依据视为失败；任一项失败 MUST 保留候选和校验快照、进入适用的 C07 复核路径，不得生成正式建议或允许人工直接强制通过。（RA-S7）

监测原始值越限、特征越限与联合规则 MUST 通过同版监测预警阈值、字段映射及联合规则成员展开为唯一评估指标身份，所选对应措施的目标指标 MUST 覆盖这些指标并由冻结审核策略提供目标值。

风险等级超过风险可接受阈值的触发项 MUST 按风险可接受阈值身份解释，不得当作监测阈值或评估指标身份。

同一任务中的每条预警 MUST 按自身类型完成校验，任一失败都不得形成部分正式建议；校验 MUST 使用候选已冻结的依据，历史缺失依据 MUST 显式失败。

#### Scenario: 三项均通过

- **WHEN** 候选措施目标满足关联预警各自类型的触发一致性规则，规范依据和禁忌核对通过，现场资源及工序条件满足
- **THEN** 系统保存三项独立的通过结果与引用，允许将该候选转换为正式建议

#### Scenario: 任一项失败或依据缺失

- **WHEN** 候选目标与触发事实不一致、规范禁忌命中，或现场资源及工序依据不足
- **THEN** 系统逐项记录失败原因和证据，返回待复核候选引用
- **AND** 人工只能提交修订候选后重新接受全部三项校验，不能把失败候选直接批准为正式建议

#### Scenario: 单独风险等级预警可形成正式建议

- **WHEN** 任务只有风险等级阈值预警，冻结依据证明严格越限，至少一项对应措施的目标属于关联评估的有效指标且有审核目标值，其余两项约束通过
- **THEN** 系统允许正式建议入库，并保存阈值、矩阵、评估和措施目标的校验证据
- **AND** 阈值身份不进入监测映射或措施目标，未选作措施目标的评分指标无需全部覆盖，入库不自动产生采纳、预测、执行或风险解除事实

#### Scenario: 风险等级分支的阈值身份与对应措施核对

- **WHEN** 任务含风险等级超过风险可接受阈值的触发项
- **THEN** 系统 MUST 核对关联评估、输入及适用性快照与冻结的风险可接受阈值、矩阵版本属于相同工程及相容集合，触发项对应唯一适用阈值，实际等级在冻结矩阵中的有序位置严格超过允许上限，并保存可重建的精确依据
- **AND** 所选措施中 MUST 至少有一项同时匹配该预警的风险类别、适用性和触发类型；这些对应措施的每个目标 MUST 属于该关联评估的有效指标集合，并有冻结审核策略提供的目标值
- **AND** 该分支不要求措施覆盖全部评分指标，亦不以阈值身份冒充目标指标；建议入库不承诺处置效果已经达到可接受等级，效果由后续独立预测与反馈表达

#### Scenario: 混合触发逐条校验且不部分通过

- **WHEN** 同一任务同时含风险等级、监测原始值、特征及联合规则预警
- **THEN** 每条预警使用对应冻结依据，全部满足且其余两项约束通过才生成一份正式建议
- **AND** 任一监测映射缺失、指标未覆盖或风险等级依据失败均阻止正式建议，不能由其它类型的通过结果替代

#### Scenario: 风险等级依据或对应措施不足时失败

- **WHEN** 阈值缺失或不唯一、矩阵或评估版本错配、等级不在矩阵中或未严格越限、没有选中对应措施、目标不属于关联评估或缺少审核目标值
- **THEN** 系统记录类型化失败及可用的精确引用，不写正式建议；已形成的候选校验失败进入复核
- **AND** 不清空失败项、按触发类型直接判通过、读取最新配置或由 Agent 重新解释阈值

#### Scenario: 冻结依据不随发布变化且历史缺失不补造

- **WHEN** 候选冻结后配置发布变化，或历史风险等级候选没有保存必要校验依据
- **THEN** 前者在当前仍获准读取的前提下按原冻结版本校验并保持原命令重放结果，后者显式失败且只能由合法的新任务或风险输入版本形成新冻结候选集
- **AND** 不覆盖旧候选、旧校验或旧建议，同键异载荷和撤权仍按既有契约拒绝

### Requirement: 正式建议不可变且贯通评估到措施

正式建议 MUST 在三项处置约束通过后保存目标、措施、顺序、资源、校验结论及原评估来源。后续采纳、执行及恢复读取该权威结果，不要求建议正文、校验表和文件三份记录反复互证。历史内容不可变，人工采纳和执行仍为独立动作。

#### Scenario: 合格建议入库并可重放

- **WHEN** 候选三项校验均通过，且所有精确来源引用仍可按冻结版本验证
- **THEN** 系统返回 `ResponseRecommendationRefV1`，可沿建议 → 预警 → 评估重建措施与校验依据
- **AND** 相同冻结输入和命令重试返回相同正式结果

#### Scenario: 不完整或失败结果不可冒充正式建议

- **WHEN** 候选缺少必需措施/顺序/资源/目标字段，或三项校验有任一未通过
- **THEN** 公共 Schema 或领域校验拒绝正式建议入库
- **AND** 不以空记录、占位结果或待审核状态绕过校验

#### Scenario: 正式结果直接供采纳

- **WHEN** 建议已通过三项校验并保存
- **THEN** 用户可查看并明确采纳该版本，不重复执行原校验或读取多副本证明

#### Scenario: 失败候选不可采纳

- **WHEN** 候选任一专业约束失败
- **THEN** 继续显示失败原因，修订后重新校验

### Requirement: 权限、事务和审计在业务事实前收口

系统 MUST 在目标读取、资料披露和写入前复验当前 C06 工程、空间、来源与精确分支授权；跨工程、越界和无权目标不得泄露存在性。候选、校验快照或正式建议的每条成功命令 MUST 通过 C03 命令回执和同一 PostgreSQL 事务保存对应业务事实及 C07 只追加审计；任何一步失败 MUST 整体回滚。候选冲突、并发验证和失败重试 MUST 不生成重复正式建议、审计或任务结果。（RA-S7）

#### Scenario: 无权或跨工程请求
- **WHEN** 调用方无权访问处置任务、其任一来源或现场上下文
- **THEN** 系统在读取目标内容或产生成功副作用前返回不可枚举的授权拒绝

#### Scenario: 审计写入失败
- **WHEN** 正式建议、命令回执或审计任一步写入失败
- **THEN** 同一命令的全部业务写入不可见，可按原幂等身份安全重试

### Requirement: 建议生成与人工采纳分离

正式建议通过校验后 MAY 成为可供人工决定的建议，但系统 MUST NOT 将生成、入库或预警确认解释为采纳、现场执行、风险解除、处置任务关闭、反馈或校准。采纳和执行 MUST 经既有 `record` 分支及其独立授权、人工决定和审计边界处理；C27 不提前形成这些后续事实。（RA-S7）

#### Scenario: 入库后尚未采纳
- **WHEN** 三项校验通过并保存正式建议
- **THEN** 预警、任务和建议保持各自事实，且不存在由建议入库自动产生的采纳、执行、反馈或任务关闭事实
