## ADDED Requirements

### Requirement: 系统必须提供校准建议草案创建批准证明只读接缝

系统 MUST 由 C07 通过专用公共决定证明端口接收工程、精确 `CalibrationSuggestionRefV1`、`ReviewDecisionRefV1` 和 C06 授权上下文，并以闭合结果证明该建议的精确决定类型。只有同一工程中状态为 `decided` 的 `calibration-suggestion` 复核任务，其精确目标等于所查询建议且任务保存的精确决定引用匹配时，系统才可按决定正文返回 `approved-for-draft`、`rejected` 或 `returned-for-revision`；决定不存在或目标不匹配时返回对应未匹配原因。证明只包含决定类型、精确建议、复核任务、复核决定和决定时间，不得返回原因正文、证据正文或数据库行；任务与决定事实违反既有状态约束时 MUST 作为技术完整性失败关闭，不得生成决定证明。（RA-S7）

#### Scenario: 精确校准建议获得草案创建批准证明
- **WHEN** 获授权调用方提交同一工程中指向精确校准建议的 `approve-draft-creation` 决定引用，且关联复核任务保持有效决定状态
- **THEN** 系统返回闭合的已批准结果及精确建议、复核任务、复核决定和决定时间
- **AND** 调用方无需读取 C07 表、追溯投影或解析活动文案即可执行确定性草案创建校验

#### Scenario: 拒绝或退回决定形成精确类型证明
- **WHEN** 所查询决定为 `reject` 或 `return-for-revision`
- **THEN** 系统分别返回 `rejected` 或 `returned-for-revision`，并绑定精确建议、任务、决定和时间
- **AND** C29 必须以该类型核对调用方声明，不得把退回伪装成拒绝或把拒绝伪装成退回

#### Scenario: 错目标决定不能形成批准证明
- **WHEN** 决定指向另一校准建议或另一精确版本
- **THEN** 系统返回 `target-mismatch` 未批准原因
- **AND** 不把决定转移到调用方提交的建议版本

#### Scenario: 任务决定事实不一致时失败关闭
- **WHEN** 决定关联的任务并非 `decided`，或任务保存的决定引用与查询决定不一致
- **THEN** 系统返回技术完整性失败且不生成批准证明
- **AND** 不增加正常状态机无法产生的未批准原因

#### Scenario: 决定不存在时稳定阻断
- **WHEN** 当前工程内不存在所查询的精确决定引用
- **THEN** 系统返回 `decision-not-found` 未批准原因
- **AND** C29 稳定阻断草案创建且不匹配错误文案

### Requirement: 校准批准证明查询必须遵守既有只读授权

校准批准证明查询 MUST 复用映射到 `review-audit.read` 的专用复核审计查询分支，并在读取任务、决定或目标存在性之前通过 C06 校验调用者、工程和版本化授权上下文。查询 MUST 先以工程和精确决定引用约束 C07 自有事实；其它工程中存在的同名引用与完全不存在 MUST 对调用方不可区分。查询 MUST NOT 创建或修改复核任务、决定、拒绝审计、业务审计、命令回执或 Outbox 事件，且不得改变既有知识修订批准证明和复核命令签名。

#### Scenario: 获授权下游读取校准批准证明
- **WHEN** 调用方持有当前工程和专用证明查询分支的有效 C06 授权上下文
- **THEN** C07 可以只读验证决定与建议关系并返回闭合证明结果
- **AND** 查询不产生 C07 业务写入、领域事件或配置草案

#### Scenario: 无权查询不读取决定事实
- **WHEN** 授权上下文过期、被撤销、能力不足、分支不匹配或工程不匹配
- **THEN** 系统在读取任何复核任务或决定前返回 `AUTHORIZATION_DENIED`
- **AND** 响应不泄露决定、任务或建议是否存在

#### Scenario: 跨工程决定不可枚举
- **WHEN** 获授权调用方在当前工程查询只存在于其它工程的精确决定引用
- **THEN** 系统返回与当前工程内决定不存在相同的 `decision-not-found` 结果
- **AND** 查询不通过无工程约束的回退读取辨认该决定的真实归属
