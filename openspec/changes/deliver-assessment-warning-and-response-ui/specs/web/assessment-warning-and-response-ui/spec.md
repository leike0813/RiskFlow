## Purpose

在 RiskFlow 既有真实接入应用中交付风险评估、预警与人工处置的完整页面路径，复用 v2 设计原型的布局和交互，使用户能够解释历史评分、完成受权人工登记，并沿精确版本追溯预测、反馈、偏差与校准。

## ADDED Requirements

### Requirement: C34 页面必须复用 v2 设计并只展示真实事实

系统 MUST 在既有应用提供 v2 的 P-OV-01、P-RA-01～07、P-WR-01～04、P-RS-01～05 共 17 页，复用其页面分区、卡片、列表、运行阶段、版本引用与版本化矩阵设计；只从当前工程的公开 HTTP 接口取得事实。原型 fixture、角色镜像、注入状态和审阅覆盖层 MUST 不成为业务输入。工程或路由变化 MUST 清除旧结果、取消读取并忽略迟到响应；无工程、加载、空、异常、权限及不可用状态 MUST 有清晰且可访问的呈现。（RA-S1～RA-S7）

#### Scenario: 真实数据与页面可达
- **WHEN** 用户在获准工程访问 17 个合法页面
- **THEN** 页面显示服务端事实或明确的引导/空/不可用态，详情支持领域标识和精确版本深链
- **AND** 不出现静态样例对象、假成功或审阅参数控制的业务权限

#### Scenario: 工程切换与失败
- **WHEN** 旧工程读取尚未结束时切换工程，或者新查询失败/被拒绝
- **THEN** 旧结果不能覆盖新工程，页面显示对应安全状态与可用重试
- **AND** 不泄露未获授权对象的存在性或正文

### Requirement: 评估候选与启动向导必须提交有限工作流

待评估页 MUST 有界呈现当前获准候选及其服务端判断状态；启动向导 MUST 支持初评、重评，风险输入遵循标准化风险记录与已登记外部事件二选一。向导 MUST 固定工程、空间、风险输入、适用性快照、可选监测、入口所需依据及工作流策略的精确引用，展示缺失前置；确认后仅经既有工作流启动命令提交。缺失配置或输入 MUST 阻止提交，客户端不得硬编码策略或创建外部事件占位。（RA-S1～RA-S5）

#### Scenario: 确认后启动初评或重评
- **WHEN** 有权用户选定初评或重评的完整输入并确认
- **THEN** 系统以唯一命令身份启动对应有限运行并返回真实运行深链
- **AND** 重评包含前驱、原因和变化引用，历史记录保持不变

#### Scenario: 缺失前置或响应丢失
- **WHEN** 输入/运行策略缺失，或已提交命令响应丢失
- **THEN** 前者不提交，后者以原身份与原载荷重试并取得同一运行
- **AND** 不切换版本、模型或预算

### Requirement: 运行与重评历史必须保持已成立事实

评估运行页 MUST 通过既有运行投影有界呈现状态、A0～A9 阶段、等待/失败原因及正式结果引用；重评历史 MUST 显示前驱、入口、原因、冻结输入和后继结果。活动运行 MUST 单一轮询且终态停止，失败不清除已入库结果，不提供跳过 Agent、扩预算或自动恢复入口。（RA-S5～RA-S7）

#### Scenario: 运行等待或失败仍可追溯
- **WHEN** 运行在建议阶段等待复核或失败，评估与预警已经成立
- **THEN** 页面保留正式引用并显示阶段与结构化失败原因
- **AND** 终态停止刷新，重评不会覆盖前驱

#### Scenario: 重评历史保留显式入口事实
- **WHEN** 用户查看已恢复重评运行的历史解释
- **THEN** 页面展示原前驱、显式原因与变化引用，而不是完整冻结输入的变化猜测
- **AND** 原入口事实不可读时展示安全失败，不补默认原因或空变化列表冒充完整解释

### Requirement: 评估记录与矩阵必须解释冻结评分依据

记录列表/详情和矩阵页 MUST 展示真实风险输入引用、逐指标实际值/规则/权重、P/C 分值、等级、触发及冻结版本。P/C 贡献和矩阵落点 MUST 来自保存的决策工件，矩阵网格与等级标签 MUST 来自该记录固定的发布版本；页面不得重算分带或使用当前矩阵解释历史。多矩阵版本 MUST 分组或明确选择版本，不混画；无记录时可展示所选获准矩阵空网格，未获准矩阵不展示。（RA-S3～RA-S6）

#### Scenario: 历史记录按原矩阵解释
- **WHEN** 当前矩阵已更新而用户读取历史记录
- **THEN** P/C、轴贡献、落点与等级仍与其冻结工件及原发布一致
- **AND** 初评/重评入口来自准备事实，记录的风险输入 kind 不被当作入口类别

#### Scenario: 缺失解释不补造
- **WHEN** 决策工件或精确矩阵不可读、错配或超出读取边界
- **THEN** 对应解释区失败闭合且不显示完整解释成功
- **AND** 不使用原型坐标、当前阈值或零值替代

### Requirement: 预警与任务必须区分确认和闭环

预警中心/详情与任务列表/详情 MUST 有界显示真实预警、触发单值与指标、开立时阈值/版本、任务 open/closed、确认事实及站内通知事实。统计 MUST 明示当前页范围。确认 MUST 经既有精确预警与任务引用命令，确认不关闭任务。采纳、执行、反馈和校准 MUST 作为独立关联事实呈现，不合成原型六步状态机；尚未投递的意图不标成已送达。（RA-S6～RA-S7）

#### Scenario: 确认只形成确认事实
- **WHEN** 用户确认一条有效预警并安全重试同一命令
- **THEN** 页面显示同一确认事实及操作者，任务仍保持领域状态
- **AND** 不重复写入、自动采纳或宣称风险解除

#### Scenario: 触发与通知忠实于冻结事实
- **WHEN** 用户查看多类触发及仅登记意图的预警
- **THEN** 各预警保留单值触发类别，阈值从冻结解释取得，通知按真实投递事实呈现
- **AND** 不伪造 SMS/邮件渠道、当前阈值或收件角色

### Requirement: 正式建议必须经过人工采纳或拒绝

建议详情 MUST 展示措施顺序、资源、目标指标与三项校验；只有正式建议可以采纳/拒绝，失败候选只能沿运行/复核引用追溯。采纳与拒绝 MUST 经既有人工命令，采纳后展示真实决定及预测运行，拒绝终止该建议的人工路径；排序理由仅在保存的公开结果包含时展示，不编造理由。（RA-S7）

#### Scenario: 采纳与拒绝分离
- **WHEN** 用户确认采纳或拒绝精确建议版本
- **THEN** 页面展示服务端终局决定；采纳可进入真实预测运行，拒绝不产生预测
- **AND** 两者均不登记现场执行

#### Scenario: 候选失败或目标陈旧
- **WHEN** 建议尚非正式、三项校验失败或确认目标已陈旧
- **THEN** 系统拒绝采纳并展示结构化原因
- **AND** 不把人工决定转移到新版本

### Requirement: 执行与反馈表单必须登记人工事实

执行登记 MUST 支持已采纳建议与已发布措施独立行动的闭合来源，固定执行者、录入者、发生时刻、精确引用和非空证据。反馈登记 MUST 固定执行、执行后监测、已登记反馈工件、实际评估及发生时刻，并经既有公开命令提交。服务端保持身份、时间与风险链校验；页面不得生成采纳、反馈、工件或评估占位。反馈表单作为执行登记页中的独立区段，成功后进入反馈详情。（RA-S7）

#### Scenario: 两种来源登记与正式反馈
- **WHEN** 现场用户确认合法执行，随后提交完整执行后反馈
- **THEN** 系统分别返回正式执行与反馈引用，独立行动不生成建议或预测
- **AND** 采纳、执行和反馈可分别审计

#### Scenario: 实际评估或证据缺失
- **WHEN** 用户缺少实际评估、已登记工件、证据或合法时刻，或者冒充其它执行者
- **THEN** 命令失败闭合且不留下部分反馈或成功展示
- **AND** 同一载荷可按原身份安全重试，修改载荷须重新确认

### Requirement: 预测偏差与校准必须按真实结果只读解释

预测详情 MUST 显示冻结依据、策略、预测可用性、真实预测值和风险状态；无预测必须显式不可用。反馈偏差页 MUST 展示真实执行后输入与实际评估、保存的偏差值/阈值/方向/越限判断，未越限不得伪造公共偏差或校准建议。校准详情 MUST 展示类型化操作、逐项确定性校验、目标基准、Agent 策略引用、复核与草案关联；复核决定沿既有复核页完成。获授权经理 MUST 能确认后以精确决定收口拒绝/退回或创建未发布草案，后续配置发布沿既有治理页完成。（RA-S7）

#### Scenario: 无预测或未越限
- **WHEN** 独立行动无预测，或者已有偏差未越限
- **THEN** 页面分别显示预测/偏差不可用或真实未越限事实
- **AND** 不生成零预测、公共校准占位或自算偏差

#### Scenario: 校准批准只生成草案
- **WHEN** 建议取得真实批准并有未发布草案关联
- **THEN** 页面展示批准与草案精确引用及知识治理入口
- **AND** 不把批准标为已发布，也不提供自动发布操作

### Requirement: 所有写入必须确认并保持授权幂等

启动、确认、采纳/拒绝、执行、反馈、校准结果收口/草案创建 MUST 复用统一确认，包含工程、对象、精确输入版本、预计事实、外部副作用和权限；取消不提交。服务端 MUST 每次复验会话、工程、空间与来源授权；原命令重试固定完整信封与载荷，改变载荷须新身份及再次确认。页面深链与证据 MUST 保持 C32/C33 的精确引用和定位脱敏边界。（RA-S1～RA-S7；RI-S6）

#### Scenario: 取消无副作用且重试幂等
- **WHEN** 用户取消确认，或确认后发生响应丢失并重试
- **THEN** 取消不发命令，重试返回原事实且无重复审计/事件
- **AND** 同键异载荷冲突不会覆盖原事实

#### Scenario: 权限撤销与证据脱敏
- **WHEN** 确认期间权限被撤销或用户无资料正文权限
- **THEN** 写入失败且证据只显示获准定位摘要
- **AND** 不通过 URL、错误、关联卡或另一接口披露正文

### Requirement: C34 必须以真实浏览器验收业务接缝

系统 MUST 复用既有 Chromium、真实 PostgreSQL 迁移/会话/HTTP harness 验收 17 页、初评/重评入口、预警确认、采纳拒绝、两类执行、正式反馈、历史评分解释、校准治理与跨页精确追溯。测试数据可为合成样本但 MUST 明确待甲方复核并固定版本；不得以 Mock 浏览器、假后端、关键 skip 或静态成功页替代。失败必须保留 trace，服务不可用须非零退出。（RA-S1～RA-S7）

#### Scenario: 真实闭环与失败边界验收
- **WHEN** 在真实浏览器执行 C34 验收
- **THEN** 正式命令结果与持久事实一致，权限/陈旧版本/重试/缺失前置均得到预期结果
- **AND** 测试验证可观察事实与引用，不锁定完整文案、CSS、DOM 排序或截图

### Requirement: 风险态势必须按有界所属摘要呈现

风险态势页 MUST 组合评估记录与预警任务拥有方的当前授权摘要，并保留既有风险总览投影的一页精确运行与追溯引用；各区明确统计范围、时点和口径，投影仅由用户请求续页。图表只使用摘要或当前有界页。任一来源失败 MUST 单独显示不可用，不把另一来源冒充完整总量。页面 MUST 不遍历全库或将部分页计数声称为全工程总量，不改原历史投影与报告重放输入，报告导出不属于本页写能力。（RA-S5～RA-S7）

#### Scenario: 摘要失败与范围切换
- **WHEN** 用户切换空间范围或预警摘要来源失败
- **THEN** 页面清除旧范围摘要并分别呈现新范围结果与失败区域
- **AND** 不显示旧总量、静态趋势、假报告导出或跨权限计数

#### Scenario: 原投影引用按页追溯

- **WHEN** 用户从态势页读取运行引用并请求下一页
- **THEN** 系统沿原查询结果和授权范围取得有界页，链接保留精确版本与证据引用
- **AND** 当前摘要不改写查询时点的历史结果，也不触发全量翻页
