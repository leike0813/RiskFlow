# web/design-system Specification

## Purpose

为 RiskFlow 生产 Web 界面提供一致且可验证的视觉、基础交互与风险图表呈现契约，使业务页面复用同一组语义令牌和受控组件，同时保持工程权限、历史版本、人工决定及端到端追溯事实不变。本能力不取代现有壳层和各业务域的行为规格。

## Requirements

### Requirement: DS-R1 生产视觉必须由单一语义令牌体系提供

生产共享设计层及本 change 迁移的消费者 MUST 从生产令牌唯一取得字体与配对行高、间距、表面、边框、交互强调、焦点和动效值，不以截图或一次性原型作为运行依赖。普通交互 MUST 使用工程蓝；错误、成功、待复核及风险等级 MUST 保持各自语义。目标导航展开/收起宽度为 152px／48px，目标右停靠区为 22rem；本 change 只提供这些令牌，不提前启用后续导航、面板或路由变更。

#### Scenario: DS-S01 已有生产页面消费统一主题
- **WHEN** 用户在正式 Web 页面查看列表与其可用操作
- **THEN** 页面共享表面、文字、焦点、字号行高和交互强调体系，不出现额外默认主题蓝或依赖原型资源的显示
- **AND** 原页面的当前工程、查询范围、排序、对象引用与命令行为不变

#### Scenario: DS-S02 令牌迁移不提前改变业务入口
- **WHEN** 设计系统 change 完成而后续导航 change 尚未启用
- **THEN** 现有业务入口、七项导航、停靠内容与合法深链继续可达，不因新增尺寸令牌被隐藏或重定向

### Requirement: DS-R2 风险与操作错误必须使用不同语义

风险徽章、图例与图表 MUST 根据同一份受控等级呈现规则使用颜色和文字，依据已授权结果的等级标识、顺序及显示名，不从标识字符串、格子位置或固定矩阵档数推断风险。操作失败和表单校验 MUST 使用独立错误语义，不借用任一风险等级。缺少等级名称或无法支持的颜色映射时 MUST 保留实际标识与可读说明，不伪造名称、等级或完整解释。（RA-S3～RA-S6）

#### Scenario: DS-S03 非约定名称的等级仍正确显示
- **WHEN** 合法配置使用不同于 level-1 等原型字面量的等级标识并给出顺序和可用显示名
- **THEN** 徽章、矩阵和图例对同一等级给出一致呈现；有名称用该名称，无名称保留实际标识，不按字符串猜测等级

#### Scenario: DS-S04 普通操作失败不成为风险等级
- **WHEN** 用户遇到提交失败或必填项校验失败
- **THEN** 错误位置提供可读且可访问的错误反馈，不显示风险等级徽章，也不将失败映射为最高风险

#### Scenario: DS-S05 不可映射等级不被悄悄改写
- **WHEN** 读面返回当前呈现规则不能映射的等级或不完整的等级元数据
- **THEN** 界面保留获准原始标识与安全说明，不夹取为最近等级、不以默认等级冒充正式结果

### Requirement: DS-R3 矩阵及图表必须忠实呈现所选精确配置

矩阵 MUST 使用所选记录冻结版本的轴档、单元格和等级集合定位，支持不同轴长度及非连续档位标识；P/C、落点与等级只消费保存的公开解释，不在界面重新计算分带或改用当前配置。图表 MUST 只消费已有有界读结果，延续原图表的就绪、空和不可用语义；缺少必需矩阵或解释时不得以零、静态原型坐标或另一版本补齐。（RA-S3～RA-S6）

#### Scenario: DS-S06 不同维度及非连续轴标识可呈现
- **WHEN** 已授权精确矩阵分别具有 3×2 与 5×5 形态，轴标识不等于连续整数
- **THEN** 展示的轴档、单元格、图例与高亮仅对应各自配置，不多画固定行列，不按标识数值反算位置

#### Scenario: DS-S07 历史矩阵不随当前发布变化
- **WHEN** 当前矩阵已更新但用户打开历史评估的精确版本
- **THEN** 网格、落点、等级及引用仍来自该记录冻结的矩阵，其他版本不混入，未取得解释时明确不可用

#### Scenario: DS-S08 空与不可用不会冒充正常图表
- **WHEN** 图表的正式有界结果为空，或来源读取失败、无权或缺少必需配置
- **THEN** 分别按原有空/不可用及权限边界呈现，不生成示例点、不泄露无权对象，也不遍历全库补数据

### Requirement: DS-R4 基础组件迁移必须保全原有用户行为

基础组件替换 MUST 保留行身份、输入含义、当前页范围、链接目标、显式操作及分页所有权；不得启用另一套默认分页、排序、筛选或自动提交来改变原业务语义。七态与证据定位/脱敏语义 MUST 保留；写命令保留原确认及所属域提交，样式层不拥有业务请求、幂等身份、权限或领域状态。（RI-S6；RA-S1～RA-S7）

#### Scenario: DS-S09 数据表格不改变查询与翻页所有权
- **WHEN** 用户浏览原有服务端分页列表并操作某一行的链接或按钮
- **THEN** 所有当前页条目与原行身份保持一致，组件不再切出第二套客户端分页，链接和操作指向原精确对象，下一页仍由原查询负责

#### Scenario: DS-S10 确认和证据边界不随组件更换改变
- **WHEN** 用户取消或关闭写操作确认，或者查看无资料正文权限的证据
- **THEN** 前者不提交，后者只披露原先获准定位和脱敏说明；重试继续使用原冻结请求，组件迁移不改变权限或对象版本

### Requirement: DS-R5 键盘缩放及动态偏好必须在真实页面可用

正式页面的基础交互 MUST 支持键盘、可见焦点、可访问名称、错误说明和焦点恢复；使用者偏好减少动态效果时禁用非必要动画。表格等二维区域可局部滚动，正文与表单应能折行；在桌面窗口 1280×720、1440×900、1920×1080 的 100%／200% 缩放下，操作控件、错误信息与聚焦项不得被裁掉或遮挡。CH-1 验证其迁移的共享组件及现有页面，目标新壳层布局的正式启用仍归后续 change，不增加移动端或暗色切换。

#### Scenario: DS-S11 缩放后仍能操作并返回焦点
- **WHEN** 用户在受支持桌面窗口以 200% 缩放通过键盘访问已迁移列表和已有确认入口
- **THEN** 正文可读、二维内容可滚动、可用操作能聚焦和执行，关闭确认后焦点回到合法触发点，不因固定层遮挡而不可操作

#### Scenario: DS-S12 减弱动态效果不影响状态表达
- **WHEN** 用户启用减少动态效果并触发加载或错误状态
- **THEN** 非必要动画停止，加载/错误仍有可读状态和可用下一步，不依赖动画结束事件完成业务动作

### Requirement: DS-R6 生产消费与验收必须保持可追溯且不依赖原型

设计系统 MUST 在现有生产入口和至少一处真实共享消费面上使用，不以无人消费的组件目录、独立演示路由或原型 fixture 宣称交付。验收 MUST 覆盖正式构建、真实浏览器与既有 HTTP/权限接缝，记录所用命令、版本、失败证据及未执行事项；依赖必须按精确版本和治理记录可重放、可离线取得。缺少环境或行为证据不得计为通过，质量/验收材料保留合成来源与待甲方复核资格。

#### Scenario: DS-S13 正式页面独立于原型运行
- **WHEN** 从正式构建打开已接通业务页面并检查主题与基础组件
- **THEN** 所需样式和交互来自生产资源，未请求原型目录或外部 CDN；页面继续使用原正式读写和当前授权，不增加假后端

#### Scenario: DS-S14 验收环境缺失不转为静态通过
- **WHEN** 必需浏览器、HTTP 服务、数据库或依赖离线材料不可用
- **THEN** 对应验收明确失败或阻塞，保留可复核原因，不以单测、非空截图、跳过关键分支或原型表现替代真实验收
