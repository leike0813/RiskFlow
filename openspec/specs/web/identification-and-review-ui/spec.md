# web/identification-and-review-ui Specification

## Purpose

本能力在既有 demo 应用（riskflow-demo）上交付"风险识别"与"复核"两块业务导航的真实数据界面：八个既有页面改由 apps/api 既有 HTTP 命令/查询与只读面驱动，复核决定经既有 `review-audit.decide-review` 命令真实提交，统一空/加载/异常/权限骨架、证据抽屉脱敏两态与领域标识深链，并扩展真实浏览器验收链路覆盖上述行为。

## Requirements

### Requirement: 识别与复核页面必须只经既有 HTTP 面取得业务事实

本 change 全部页面 MUST 只经闭合路由清单中的 query branch 与既有查询取得业务事实，不得 import `demo/src/content/` 静态内容模型作为业务事实来源，不得渲染与当前工程无关的写死样例。页面 MUST 由 `apps/web` 的生产构建交付，数据接入 MUST 集中在其唯一 API 接入层：查询/命令提交、传输信封组装、错误脱敏映射与取消语义唯一实现，页面不得各自拼装 HTTP 细节。除复核队列的"原样通过/拒绝"经既有 `review-audit.decide-review` 命令提交外，本 change MUST NOT 提供任何其它会产生业务事实的操作入口；既有静态原型中的假写操作按钮（启动识别、审计重放、确认处置方案、发起复核等）MUST 移除，不以占位或禁用态冒充已接线能力。（RI-S1～RI-S6）

#### Scenario: 页面渲染当前工程的真实事实

- **WHEN** 获授权用户打开识别或复核任一页面
- **THEN** 页面内容由当前工程上下文的真实查询结果驱动，刷新后按服务端当前事实重建，不出现静态样例残留

#### Scenario: 假写入口不存在

- **WHEN** 审查八个页面的可点击操作
- **THEN** 除复核决定外不存在任何提交业务命令的入口；原静态原型的假确认按钮已移除而非改头换面
### Requirement: 空、加载、异常、权限四类骨架行为必须逐页一致

各页面 MUST 遵循对应骨架（列表 A / 详情 B / 运行监控 C / 复核工作台 E）的状态约定：加载时骨架占位不闪烁切换空态；空态说明当前筛选下无数据并给出最可能的下一步入口；异常显示结构化错误摘要与重试，不显示技术堆栈；权限不足显示权限骨架并提示所需能力，不披露目标存在性。`NOT_FOUND` 与 `AUTHENTICATION_REQUIRED` MUST 映射为权限/会话语义而非普通错误。（RI-S61～RI-S65）

#### Scenario: 无权访问识别页面

- **WHEN** 不具备识别读能力的角色打开识别运行列表页
- **THEN** 呈现权限骨架与所需能力提示，页面不显示任何运行数量或标识线索

#### Scenario: 查询失败可重试

- **WHEN** 只读查询因瞬时故障失败
- **THEN** 页面显示结构化错误摘要与重试入口，重试重新发起同一查询，不显示堆栈或内部标识

### Requirement: 识别运行列表与详情必须呈现真实运行事实

识别运行列表页 MUST 经 `risk-identification.run-list` 有界分页呈现运行条目（运行引用、状态、阶段、启动者、启动时间、验收/待复核/拒收计数；触发原因列仅在服务端返回登记事实时呈现，缺省显示"—"），行点击进入运行详情。识别运行详情页 MUST 经 `risk-identification.run-read` 呈现：运行头部（标识、状态、阶段、触发原因、操作者、启动时间、幂等键）、I0–I9 阶段进度、工序工作项覆盖核对、合并组与验收路由摘要、关联 Agent 与复核任务引用、结果汇总（验收/待复核/拒收引用集合）。运行状态词汇 MUST 使用固定枚举（待运行/运行中/等待复核/可重试失败/终止失败/已完成/已取消）；运行中的页面 MUST 定间隔轮询并在终态停止；Agent 可重试失败 MUST 完整呈现错误码与可重试性，MUST NOT 提供跳过、换模型或扩预算入口。已入库事实计数不因运行暂停或失败而回退。（RI-S5～RI-S6）

#### Scenario: 列表分页与详情联动

- **WHEN** 用户翻阅运行列表并点击某行
- **THEN** 列表按游标分页返回有界条目，详情页呈现该精确运行的阶段进度与结果汇总

#### Scenario: 等待复核如实呈现

- **WHEN** 运行因候选待人工复核而暂停
- **THEN** 详情页呈现"等待复核"状态与复核任务引用，不把暂停伪装为完成或失败

#### Scenario: Agent 失败无跳过入口

- **WHEN** 运行内必经 Agent 任务以可重试失败终止
- **THEN** 页面呈现失败阶段、错误码与可重试性，不存在跳过/换模型/扩预算按钮

### Requirement: 风险记录列表与详情必须呈现识别侧记录事实

风险记录列表页 MUST 经 `risk-identification.record-catalog` 有界分页呈现记录条目（记录引用、工序节点、风险事件摘要、综合置信度、验收方式、当前效力），支持按工序节点与验收方式筛选，行点击进入记录详情。风险记录详情页 MUST 经 `risk-identification.record-read` 呈现识别侧事实：七字段正文（工序节点标识、风险源、风险因素、风险事件、风险要素关系、证据定位信息、模型置信度）、记录信封（版本、机理条目引用、资料来源、识别运行引用、综合置信度及其形成依据、验收决定）、证据链入口与取代/作废关系。`modelConfidence` MUST 只读呈现；人工修正通过的记录 MUST 并列呈现原模型置信度与人工修正标记。页面 MUST NOT 呈现评估等级、P/C、预警或处置建议内容（属后续 change 域），也不得以静态样例冒充。（RI-S5～RI-S6）

#### Scenario: 记录详情呈现精确版本正文

- **WHEN** 用户打开任一风险记录详情
- **THEN** 正文来自该精确记录版本引用，刷新后按同一版本重建，不混入其它版本内容

#### Scenario: 评估域内容缺席不编造

- **WHEN** 审查记录详情页的区块
- **THEN** 不存在风险等级徽章、P/C 分值、预警或处置建议区块；静态原型中的此类内容已移除

### Requirement: 关联图页必须只呈现可证明的投影边

关联图页 MUST 经既有 `projection.query`（`association-graph`）与 `projection.result-read` 呈现工序节点 × 风险机理条目 × 风险源/因素/事件的关联边，支持按节点聚焦与沿边下钻到风险记录与机理条目深链。图数据 MUST 全部来自投影返回的可证明链边：主体不可证明可见、边集合越界或来源资格不能证明时 MUST 呈现结构化失败/空态原因，MUST NOT 降级为裁切后的伪完整图或编造边；图加载失败时 MUST 提供按工序分组的记录列表作为降级视图（数据来自记录目录查询，不受影响）。本 change MUST NOT 为补全图而新增链边写入。（RI-S6）

#### Scenario: 可证明关联正常呈现

- **WHEN** 主体存在可证明链边
- **THEN** 图视图呈现投影返回的边与节点分类图例，沿边可下钻到记录详情

#### Scenario: 不可证明时失败闭合

- **WHEN** 主体无可证明链边、投影查询越界或授权不足
- **THEN** 页面呈现结构化原因与空态/权限骨架，不呈现裁切图或编造节点

### Requirement: 证据追溯页必须呈现固定追溯链并可穿透

证据追溯页 MUST 以 URL 深链参数中的领域标识为查询主体，经既有 `projection.query`（`trace-chain`）与 `projection.result-read` 呈现固定追溯链：资料段标识 → 工序节点 → 风险机理条目 → 标准化风险记录 →（已成立时的）风险评估记录 → 预警信息 → 处置建议 → 偏差/校准；任一节点 MUST 可跳对应详情页。链中资料段节点 MUST 提供证据抽屉入口；无资料权限的节点 MUST 只显定位摘要与固定脱敏提示。无查询主体时呈现引导空态；链尾缺席按投影返回的缺席事实呈现，不补造。（RI-S6；RA-S5～RA-S7）

#### Scenario: 沿链穿透到详情

- **WHEN** 用户从风险记录详情打开追溯链并点击机理条目节点
- **THEN** 追溯链按该记录引用查询呈现，机理条目节点跳到对应治理条目详情

#### Scenario: 无权限节点只显定位摘要

- **WHEN** 链中资料段对当前用户无访问授权
- **THEN** 该节点只显示资料段标识与章节路径等定位摘要及固定脱敏提示，不发起替代取数

### Requirement: 复核队列必须呈现真实任务并支持原样通过与拒绝

复核队列页 MUST 经 `review-audit.queue-read` 有界分页呈现复核任务（完整任务引用、复核类型、由目标引用确定性渲染的复核对象标签、提交时间、状态；触发原因列仅在服务端返回登记事实时呈现），支持按类型与状态筛选与多选。目标版本已被取代的任务 MUST 标记过期并禁止对其提交决定，提示重新领取。行内与批量"原样通过/拒绝" MUST 经既有 `review-audit.decide-review` 命令提交：提交前确认对话框 MUST 列明工程、对象、精确版本、预计结果与外部副作用；命令 MUST 携带幂等键，重复提交同一决定不重复生效；目标版本陈旧、无权或命令失败时 MUST 失败闭合并呈现结构化原因。页面 MUST NOT 提供"修正并通过"编辑表单（属后续页面范围），不直接编辑被审对象本体。（RI-S6）

#### Scenario: 队列呈现真实任务

- **WHEN** 获授权复核人打开复核队列
- **THEN** 队列条目来自真实复核任务登记，按类型/状态筛选有界分页，过期任务有明确标记且其决定按钮禁用

#### Scenario: 决定提交带确认与幂等

- **WHEN** 复核人对选中任务确认"原样通过"
- **THEN** 确认摘要列明工程/对象/精确版本/预计结果/副作用，提交经既有决定命令携带幂等键；同一决定重复提交不产生第二条决定事实

#### Scenario: 陈旧版本决定被拒

- **WHEN** 任务目标版本在提交前已被取代
- **THEN** 命令以结构化原因失败闭合，页面提示重新领取，不产生决定事实

### Requirement: 运行记录页必须聚合两类有界只读运行事实

运行记录页 MUST 聚合呈现两类运行：识别运行（经 `risk-identification.run-list`）与评估/riskflow 链运行（经既有 `projection.query` 的 `risk-overview` 与 `projection.result-read` 的 `run-summary` 条目），条目呈现运行标识、类型、状态、启动时间与操作者，识别运行可跳识别运行详情。页面只读：MUST NOT 提供恢复运行、重试或审计重放入口（属运行运维域）；任一来源失败时对应分组呈现结构化失败原因，不以另一来源结果冒充完整。（RI-S5～RI-S6；RA-S5～RA-S7）

#### Scenario: 两类运行分源聚合

- **WHEN** 获授权用户打开运行记录页
- **THEN** 识别运行与链运行分别来自其有界只读查询，类型列区分来源，识别运行行可跳详情

#### Scenario: 单一来源失败不冒充完整

- **WHEN** 投影读取失败而识别运行读取成功
- **THEN** 链运行分组呈现结构化失败原因与重试，识别运行分组不受影响，页面不声称展示全部运行

### Requirement: 证据抽屉在识别与复核页面必须保持脱敏两态

本 change 各页面中的证据入口 MUST 经既有 `engineering-data.evidence-access` 查询与结果再读取打开证据抽屉：呈现资料段标识（资料ID-章节ID-资料段ID）、章节路径等定位摘要与引用该证据的业务对象；任何授权状态下 MUST NOT 呈现段正文原文。无资料访问授权时 MUST 只显示定位摘要与固定脱敏提示，不得呈现"加载失败"歧义，不得经其它路径绕取原文。（RI-S1～RI-S2、RI-S6）

#### Scenario: 无授权时固定脱敏

- **WHEN** 用户在风险记录详情打开无授权资料段的证据入口
- **THEN** 抽屉只显示定位摘要与固定脱敏提示，不发起任何替代取数

### Requirement: 跨页深链必须使用领域标识

页面间跳转 MUST 使用领域标识深链：运行列表 → 运行详情；记录列表/关联图/追溯链 → 记录详情；记录详情 → 工序模型（节点锚点）、机理条目、证据抽屉、追溯链；复核队列决定提交后可跳对应运行详情。路由 MUST 参数化（`/identification/runs/:runId`、`/identification/records/:recordId`），不得硬编码单一对象标识，不得用页面私有状态搬运业务事实。（RI-S6）

#### Scenario: 参数化深链可直达

- **WHEN** 用户直接打开携带精确运行引用的详情 URL
- **THEN** 页面按该引用查询并呈现对应运行事实；引用无权或不存在时呈现权限/空态骨架

### Requirement: 浏览器验收必须使用真实浏览器与正式接缝

系统 MUST 提供可运行的真实 Chromium 验收命令，在 `apps/web` 生产构建与真实 HTTP/授权/投影接缝（真实 PostgreSQL、真实迁移、真实会话登录）上验证：登录、识别与复核导航八页可达、四态骨架、权限降级、证据脱敏两态、复核决定真实提交与幂等、跨页深链。验收记录 MUST 包含浏览器版本、命令与失败 trace；浏览器或必需服务不可用时 MUST 明确失败，不以 Mock 浏览器、Mock 后端或跳过关键断言代替通过结论。（RI-S61～RI-S65）

#### Scenario: 真实浏览器完成识别与复核链路

- **WHEN** 固定测试环境具备真实 Chromium、PostgreSQL 与已登记识别/复核夹具事实
- **THEN** 验收从登录走到运行列表/详情、记录列表/详情、关联图、证据追溯、复核队列与运行记录，核对真实事实渲染、决定提交、无权脱敏与深链跳转

#### Scenario: 环境不可用明确失败

- **WHEN** 浏览器二进制、数据库容器或 API 服务不可用
- **THEN** 命令以非零状态退出并保留失败证据，不把跳过场景计作通过
