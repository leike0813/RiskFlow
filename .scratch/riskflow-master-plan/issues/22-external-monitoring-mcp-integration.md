# 确定外部系统、实时监测与 MCP 集成契约

## Question

甲方风险管理系统、实时监测数据源、文件/数据库/API 接入与通知渠道应通过哪些版本化命令、查询、事件和适配器接入；MCP 在“实时多源监测数据 → 指标实际取值”通路中的职责、失败处理、权限、审计和离线替代方案是什么？

## Answer

### 接入边界与事实归属

- MVP 只保证通过统一数据接入模块导入 XLSX/CSV 等批次数据并完成应用内通知；甲方风险管理系统、数据库、HTTP API、实时监测流和 MCP 连接不作为 MVP 的运行依赖，也不建设没有真实对象支撑的空连接器。
- 完整产品可以在具体系统和样例明确后扩展数据库、HTTP API、实时监测流、外部风险管理系统和通知渠道。
- RiskFlow 是内部风险、评估、预警、处置和审计事实的唯一来源。外部系统只能提供受控输入或接收已成立结果，不共享业务数据库，也不能直接覆盖 RiskFlow 事实。
- 外部风险事件保留 `externalRiskEventId`、来源类型、事件类别、发生时间、涉及构件、触发迹象、适用性元数据和独立证据链；评估记录只能二选一引用 `riskRecordId` 或 `externalRiskEventId`。更正、撤回和补充均追加新版本并审计。

### 统一接入与跨系统消息

- 文件、数据库、HTTP API 和实时流均通过同一数据接入模块和提供方无关的适配器接口。适配器只登记来源、获取或接收来源交付并携带来源元数据与幂等标识；解析、清洗、资料段登记、指标映射和业务事实写入由 RiskFlow 内部模块完成。
- 跨系统交互分为版本化命令、查询和事件。命令表达来源交付、监测时间窗请求、结果发布和通知等明确动作；查询只读取来源状态、已登记版本、已冻结监测快照和同步状态；事件表达来源版本接收、监测批次接收、快照可用、接入失败以及结果同步成功或失败。
- 消息至少关联契约版本、来源交付标识、幂等键、运行标识、业务发生时间、系统记录时间和实体版本引用；事件按至少一次投递处理，消费者必须幂等。适配器、LangGraph 和外部系统均不得绕过版本、权限、审计和业务命令。
- 向甲方系统默认同步已成立的标准化风险记录、风险评估记录、预警信息、处置反馈事实及追溯引用，不默认发送原始资料或 Agent 过程。具体字段映射在连接对象确定后另行形成 OpenSpec change。

### 实时监测、冻结与故障

- 实时来源可持续交付观测事件或小批次，在线接收不等待完整时间窗。进入识别、评估、预警或处置效果比较时，按业务运行的监测截止点对已接收数据形成冻结监测快照，不读取外部可变的“最新值”。
- 新鲜度、覆盖率和质量按“来源 × 指标 × 业务用途”配置并版本化。快照逐指标保留可用、降级可用或不可用状态；只有关键指标不可用时才暂停对应运行，非关键指标保留原因后继续。插值、迟到容忍度和最大允许陈旧时间由已发布配置决定。
- 超时、断流、认证失败或交付质量不足时执行有限重试并记录结构化失败。已接收数据不删除；没有合格快照时不以旧快照冒充实时结果，既有事实不回滚。来源恢复后形成新的批次、快照和运行；旧快照可展示，但必须标明新鲜度状态。
- 离线文件或人工导出只能作为显式替代或历史补录，沿用统一接入模块，形成独立批次和快照并记录来源模式、业务发生时间、接收时间及与原来源或故障的关系，不得自动伪装为实时数据。

### MCP 与治理边界

- 本票不规定 MCP 协议的能力边界，也不预先选择 MCP Server、工具、读写范围或固定业务用途。MCP 只保留为可选、可扩展的外部能力接入位置；实时监测是既有规划中的候选场景，不构成本票对协议的永久限定。
- 具体 MCP 连接对象明确后，再由独立集成契约和 OpenSpec change 确定其适配器、消息、权限、失败恢复、审计、数据固化和验收方式；采用 MCP 本身不改变 RiskFlow 的事实归属。
- 所有外部接入和同步使用“工程权限 + 来源授权 + 集成策略”的交集；审计记录发起主体、工程与来源、契约版本、请求或时间窗口、输入输出版本、幂等键、结果、失败原因和重试关系。连接凭据不扩大用户或 Agent 的权限。
- 预警必须可靠入库后才创建通知投递任务。MVP 保证应用内通知，完整产品按配置增加外部渠道；投递失败只保留重试和失败状态，不回滚预警，送达不等于预警确认或处置完成。
