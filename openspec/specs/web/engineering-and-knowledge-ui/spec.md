# web/engineering-and-knowledge-ui Specification

## Purpose

本能力在既有 demo 应用（riskflow-demo）上交付"工程项目"与"知识与规则"两块业务导航的只读界面：九个既有页面改由 apps/api 真实只读面驱动，新增检索结果查看页，统一证据抽屉脱敏两态与空/加载/异常/权限骨架行为，并提供真实浏览器验收链路。

## Requirements

### Requirement: 页面必须只经既有 HTTP 只读面取得业务事实

全部页面 MUST 只经闭合 HTTP 接缝取得当前工程的正式事实，由 `apps/web` 生产构建交付，数据接入集中在唯一 API 层；不得消费原型静态内容或由页面拼装传输授权。工程工作区 MAY 提供本能力明确规定且已接通所属领域端口的工程上下文、空间、成员及资料访问操作，写入 MUST 使用公共壳层唯一确认和所属领域的预期版本、幂等及审计。知识治理和工序模型的原有只读行为不因工程改造而扩展，不得以假按钮、原型样例或部署脚本冒充可用 Web 命令。（RI-S1～RI-S6；RA-S1～RA-S7）

#### Scenario: 页面渲染当前工程的真实事实

- **WHEN** 获授权用户打开任一业务页面
- **THEN** 页面按当前工程和精确引用读取服务端事实，刷新重建，不显示静态样例或另一工程内容

#### Scenario: PJ-S01 真实命令与只读边界

- **WHEN** 用户查看工程维护入口或未改造的知识页面
- **THEN** 仅本 change 已登记的工程操作可以在确认后提交原所属命令，知识页面仍只读；不存在假上传、假解析、假清洗或通用写入入口

#### Scenario: 写操作入口不存在

- **WHEN** 用户查看本 change 未改造的知识治理或工序模型只读页面
- **THEN** 不存在新增的业务写入口，原静态假确认按钮不重新接入；工程维护动作仅按 PJ-S01 和本能力新增要求提供
### Requirement: 会话与工程上下文必须显式且可切换

界面 MUST 提供登录页，经既有 `session/login` 建立会话；未认证或会话失效时跳转登录页，不把认证失败呈现为普通业务错误。工程上下文 MUST 以 URL 查询参数选择（工程与工程修订），切换工程只改变后续查询上下文并停留在当前页面重新加载；服务端返回的会话元数据不得被页面扩展为工程列表之外的含义。无工程上下文时页面呈现引导空态而非报错。（RI-S14、RI-S61～RI-S65）

#### Scenario: 未登录访问业务页

- **WHEN** 浏览器无有效会话直接打开业务页面
- **THEN** 跳转登录页，登录成功后回到原目标页面

#### Scenario: 切换工程重新加载

- **WHEN** 用户在资料目录页切换工程
- **THEN** 页面停留原地并按新工程重新查询，旧工程内容立即清除，不短暂残留

### Requirement: 空、加载、异常、权限四类骨架行为必须逐页一致

各页面 MUST 引用 `platform/web-shell-interaction-primitives` 的区域组合与七态契约，列表 A、详情 B、治理 D 作为单区域特例，不再限制为单值骨架。加载时占位不得闪烁为空态；空态只给已登记真实下一步；异常显示结构化安全摘要与可用重试；无权限不得泄露对象数量或名称。`NOT_FOUND` 与 `AUTHENTICATION_REQUIRED` MUST 保留原目标可见性及会话语义，不映射为普通错误。（RI-S61～RI-S65）

#### Scenario: 无权访问知识页面

- **WHEN** 不具备知识读能力的角色打开机理库页
- **THEN** 呈现权限骨架与所需能力提示，页面不显示任何条目数量或名称线索

#### Scenario: 查询失败可重试

- **WHEN** 只读查询因瞬时故障失败
- **THEN** 页面显示结构化错误摘要与重试入口，重试重新发起同一查询，不显示堆栈或内部标识

### Requirement: 证据抽屉必须经 evidence-access 呈现脱敏两态

证据抽屉 MUST 经 `engineering-data.evidence-access` 查询与结果再读取打开：呈现资料段标识（资料ID-章节ID-资料段ID）、章节路径等定位摘要，以及引用该证据的业务对象；段正文原文无 HTTP 通路，抽屉在任何授权状态下都 MUST NOT 呈现段正文原文。无资料访问授权时 MUST 只显示定位摘要（资料名称、章节路径、资料段标识）并给出固定脱敏提示，不得呈现"加载失败"歧义，不得经其它路径绕取原文。抽屉内 MUST 可跳转资料详情页并携带资料段锚点。（RI-S1～RI-S2、RI-S6）

#### Scenario: 有授权时呈现定位与引用

- **WHEN** 用户对证据来源版本具备访问授权并打开证据入口
- **THEN** 抽屉显示段标识、章节路径等定位摘要与引用该证据的业务对象清单，不显示段正文原文

#### Scenario: 无授权时固定脱敏

- **WHEN** 用户无该来源版本访问授权
- **THEN** 抽屉只显示定位摘要与固定脱敏提示，不发起任何替代取数

### Requirement: 工程概览页必须呈现当前上下文与发布集合

工程概览页 MUST 以工程业务身份、适用性三维度、空间区段和接入概况组织工作区，以业务名称为主，精确标识和版本置于可复制的辅助信息。上下文、知识版本、资料目录及监测目录 MUST 独立读取和呈现状态；缺知识治理或其它域权限不得使已有工程上下文及合法资料/监测入口不可用，不得把当前页条目数当总数。缺失适用性维度逐项标出，不用默认值补齐。工程内提供资料与监测、工程上下文、成员及开通的可达二级入口，接入任务从资料与监测进入；开通入口按系统管理身份决定，不要求当前工程。既有五条工程规范地址及其精确对象查询保持可达，不提前启用全站六导航。（RI-S1；RA-S1）

#### Scenario: 上下文完整时呈现概览

- **WHEN** 当前工程上下文已生效且三维适用性齐备
- **THEN** 呈现工程名称、三维度、空间树和获准接入概况，知识版本独立显示，不要求额外域权限才能查看工程事实

#### Scenario: 适用性维度缺失逐项标出

- **WHEN** 工程尚无业务修订或任一必含维度缺失
- **THEN** 如实显示准备状态与缺项，有权者可进入真实上下文维护，不生成默认版本

#### Scenario: PJ-S02 来源失败相互隔离

- **WHEN** 知识版本、资料目录或监测目录之一拒权或失败
- **THEN** 该区域分别显示拒权或可重试故障，其余成功区域及入口保持可用，不显示假零或假完整统计

### Requirement: 资料目录与资料详情必须呈现登记、解析与清洗事实

资料目录 MUST 按服务端游标呈现真实资料名称、类型、形成时间、来源单位、精确版本、解析和清洗可用性；统计明确工程总量或当前页范围，客户端不得再分页或遍历全库。详情 MUST 直接按资料精确版本读取，不依赖目录首页，原件作为默认内容，资料分段、解析清洗与权限分别组织；证据入口沿原脱敏契约。处理记录只引用实际登记的转换、段集合、清洗准备和任务，不从解析状态猜测任务或正式结果。重复内容沿既有版本关联呈现，不伪造新资料或覆盖旧版本。（RI-S1～RI-S2）

#### Scenario: 目录分页与详情联动

- **WHEN** 用户续页后打开资料，或直接打开不在首页的历史资料版本
- **THEN** 按该精确版本呈现原件信息与资料分段，刷新不改读当前版本，续页只消费有界服务端页

#### Scenario: 清洗可用性如实呈现

- **WHEN** 资料已有正式清洗结果、只有清洗任务或未取得可读取的处理关系
- **THEN** 分别展示正式可用性与排除范围、获准任务的真实状态或尚未登记可读取结果，不因目录摘要缺席而断言未清洗，不把任务完成等同于业务可用

### Requirement: 监测序列详情必须呈现快照与越限事实

监测入口 MUST 通过有界目录选择序列，精确详情 MUST 直接读取所给序列版本，不依赖目录首页。批次、补录、更正关系及冻结数据范围沿既有登记事实呈现；快照选择 MUST 保留精确引用，明确所选时间窗、样本量、特征可用性和原因。快照正文与当前知识阈值独立，不得用当前阈值冒充历史冻结判定依据，不在客户端重新判定或造曲线；未取得有效解释的越限判断显示不可用。没有快照时保持真实空态。（RI-S1～RI-S2；RA-S1、RA-S6）

#### Scenario: 快照统计与阈值同屏

- **WHEN** 用户选择一个有权读取的精确冻结快照
- **THEN** 呈现该快照真实统计、特征及已保存依据；另有当前阈值时明确区分，不能将当前版本标成历史快照的冻结依据

#### Scenario: 无快照空态

- **WHEN** 所选序列尚无冻结快照
- **THEN** 呈现原因和合法下一步，不插值、生成样例点或读任意其它序列

#### Scenario: PJ-S03 目录页外监测精确直达

- **WHEN** 用户直达不在当前目录页的序列或选择非最新历史快照
- **THEN** 直接读取该版本；目录、知识或其它序列失败不改写目标，错版与拒权不回落首页首项

### Requirement: 工序模型页必须呈现已发布模型与证据定位

工序模型页 MUST 经 `knowledge-modeling.governance-read` 读取当前发布的工序模型版本，呈现工序节点（含输入/输出描述与状态参数）、装备部件、构件与三类依赖关系（时间先后、资源依赖、受力依赖），节点提供证据定位入口；五个必含工序节点 MUST 有覆盖核对呈现。模型未发布时 MUST 显示治理空态而非样例模型。（RI-S3）

#### Scenario: 已发布模型完整呈现

- **WHEN** 当前工程存在已发布工序模型版本
- **THEN** 页面呈现节点、装备、构件、三类关系与版本徽章，必含五节点覆盖核对全部标出

#### Scenario: 未发布时治理空态

- **WHEN** 当前工程无已发布工序模型
- **THEN** 页面呈现治理空态与"未发布"说明，不渲染任何样例节点

### Requirement: 知识治理四页必须呈现列表、详情与版本事实

机理库、规则集、风险矩阵、措施库四页 MUST 经 `knowledge-modeling.governance-read` 呈现：对象列表（审核状态筛选：草稿/待审核/已发布/已停用）、条目详情（当前精确版本的正文与证据定位）、版本徽章。机理条目呈现机理类型枚举、适用工序、地质水文适用、触发条件/监测征兆/风险事件表达与证据需求；规则集页呈现结构化评分规则与适用规则集成员版本及适用性元数据快照；风险矩阵页呈现矩阵版本网格与分级区间；措施库页呈现措施项适用条件（风险事件/工法/地层/阶段）与资源约束。四页只读，不提供修订、送审、发布、停用或回滚入口。（RI-S4；RA-S2～RA-S4、RA-S7）

#### Scenario: 按审核状态筛选列表

- **WHEN** 用户在机理库页按"已发布"筛选
- **THEN** 列表只呈现该状态条目，条目含版本徽章与审核状态标记

#### Scenario: 详情呈现精确版本正文

- **WHEN** 用户打开任一治理条目详情
- **THEN** 正文来自该精确修订/发布引用，刷新后按同一版本重建，不混入其它修订内容

### Requirement: 检索结果查看页必须只呈现已登记检索事实

检索结果查看页 MUST 作为深链目标，按 URL 中的精确 `knowledgeQueryResultRef` 经 `knowledge-modeling.retrieval-result` 呈现：混合检索的命中列表（条目引用、融合得分、证据定位入口）或关系上下文的邻接节点、依赖边与机理条目入选/筛除及原因。页面 MUST NOT 提供自由文本检索或脱离识别运行的临时检索入口；引用无效或无权时呈现权限/空态骨架。（RI-S5；RA-S3）

#### Scenario: 深链打开混合检索结果

- **WHEN** 用户经深链打开混合检索结果引用
- **THEN** 页面呈现命中列表与策略版本引用，命中证据可打开证据抽屉

#### Scenario: 无临时检索入口

- **WHEN** 审查检索结果查看页的交互元素
- **THEN** 不存在查询输入框或"发起检索"操作，页面只呈现已登记结果

### Requirement: 跨页深链与版本追溯必须使用领域标识

页面间跳转 MUST 使用领域标识深链：资料详情可跳到引用它的业务对象，治理条目详情可经 `trace-chain` 投影查询与结果读取呈现关联对象（如机理条目被引用的风险记录、规则/矩阵版本被引用的评估记录），证据入口就地出现在每个结论与版本旁。跨页跳转不得用页面私有状态搬运业务事实；关联对象区在投影不可用时呈现结构化原因，不降级为编造链接。（RI-S6；RA-S5～RA-S7）

#### Scenario: 治理条目关联对象可点透

- **WHEN** 机理条目详情存在引用它的风险记录
- **THEN** 关联对象区经投影读取呈现记录引用，点击沿深链跳转；无引用时显式呈现空态

#### Scenario: 关联读取失败不编造

- **WHEN** 投影查询或结果读取失败
- **THEN** 关联对象区呈现结构化失败原因与重试，页面主体事实不受影响

### Requirement: 浏览器验收必须使用真实浏览器与正式接缝

系统 MUST 在 `apps/web` 生产构建与真实 HTTP、授权、投影、PostgreSQL 迁移和会话上提供真实 Chromium 验收。导航及骨架引用 `platform/web-shell-interaction-primitives` 当前发布阶段，不重复固定导航数量；仍须验证本能力页面可达、工程切换、权限降级、证据脱敏两态与跨页深链。记录 MUST 包含浏览器版本、命令和失败 trace，关键环境不可用不得以 Mock 或 skip 计作通过。（RI-S61～RI-S65）

#### Scenario: 真实浏览器完成只读链路

- **WHEN** 固定测试环境具备真实 Chromium、PostgreSQL 与已登记夹具事实
- **THEN** 验收从登录走到工程概览、资料详情、监测详情与知识治理页，核对真实事实渲染、无权脱敏与深链跳转

#### Scenario: 环境不可用明确失败

- **WHEN** 浏览器二进制、数据库容器或 API 服务不可用
- **THEN** 命令以非零状态退出并保留失败证据，不把跳过场景计作通过

### Requirement: 资料详情必须以原件为默认内容

系统 MUST 从资料目录的真实名称进入精确版本原件视图，呈现文件信息、预览/下载及独立解析清洗页签。PDF显示实际页面，位图显示原图，TXT/CSV显示原文本；Office与不支持预览格式允许下载完整原件并明确本机查看方式。不得以MinerU或清洗结果冒充原件，不能把转换块编号当原件页码。目录/预览必须有界并取消旧工程在途读取。

#### Scenario: 五格式原件可核对

- **WHEN** 用户从当前目录打开已登记的PDF、扫描PDF、图片、文本或Office资料
- **THEN** 支持格式呈现真实原件，不支持网页预览的格式可保存字节一致的原文件，解析失败不阻止原件查看

#### Scenario: 版本及权限变化

- **WHEN** 用户打开历史版本或切工程/注销/撤权
- **THEN** 历史原件保持精确版本，旧预览被清除，新请求按当前授权拒绝或读取

### Requirement: PJ-R1 工程上下文维护必须追加原领域修订

系统 MUST 提供真实工程业务上下文与空间区段维护，使用所属端口的完整字段、当前预期版本和三维适用性，空间身份来自现有授权树，不复制树或用自由输入标识制造引用。每条命令独立确认、提交与回执，不假装工程开通、空间授权和业务修订是跨模块原子事务；阶段失败保留已成功事实并可从该阶段继续。历史精确修订只读，不因切换当前工程而改写。已结束/归档、陈旧版本、非法里程或越界空间由原领域拒绝，不自动换版重提。（RA-S1；RI-S14）

#### Scenario: PJ-S04 首次业务上下文及区段

- **WHEN** 工程已开通且获授权管理员填写三维适用性与从已登记空间选择的区段资料
- **THEN** 分别确认并追加工程/区段业务修订，成功后显示服务端精确回执；前一步成功后后一步失败不谎报全部回滚或重复创建前一步

#### Scenario: PJ-S05 历史并发与输入校验

- **WHEN** 用户查看历史修订，或另一操作者先更新当前版本，或填写越界里程/空间
- **THEN** 历史保持只读；陈旧或非法命令显示类型化失败，无新事实，刷新后重新确认，不自动替换输入或预期版本

#### Scenario: PJ-S06 取消及上下文失效

- **WHEN** 确认被取消，或输入、路由、工程、认证上下文在确认中变化
- **THEN** 未提交命令零请求，原确认失效；可重试失败只重发原冻结身份和载荷，迟到回执不覆盖新工程

### Requirement: PJ-R2 工程开通及成员资料访问必须沿当前授权

工程开通 MUST 与既有系统管理使用同一表单及六项管理命令，不新增系统管理员业务特权。成员、空间及资料访问维护 MUST 使用原预设角色、当前授权范围和精确预期版本；选择器只列可管理的真实对象，不要求用户手输既有账号、空间、资料或版本标识，不将全局账号目录开放给普通工程成员。资料访问仅有工程内共享/指定可见；移除成员或收窄资料授权在下一读取生效，历史身份不删除。无管理权但有工程数据读权时，资料和监测仍可独立使用。（RI-S14）

#### Scenario: PJ-S07 无工程开通与业务身份分离

- **WHEN** 当前有效系统管理员尚无工程成员身份
- **THEN** 可从工程开通入口使用既有开通表单并取得管理回执，不能因此读取工程上下文、资料或监测；普通用户不会因能力列表为空而看到可执行开通动作

#### Scenario: PJ-S08 成员及来源权限立即生效

- **WHEN** 当前有权管理者确认成员、空间或某资料版本的访问修订
- **THEN** 使用当前精确版本提交原领域命令，新请求立即按新范围决定；同键重放不重复修订，冲突不覆盖，旧操作者与审计保留

#### Scenario: PJ-S09 工程读权不依赖其它域

- **WHEN** 用户拥有工程资料/监测读权但无知识治理、Agent 或访问管理权
- **THEN** 可查看其获准资料原件、监测与接入领域事实，不请求无权 Agent 正文或全局账号目录，管理区域不披露无权成员/来源

### Requirement: PJ-R3 接入任务必须展示已有精确处理事实

资料与监测区域 MUST 提供接入记录列表/详情，按当前工程和来源授权有界读取实际登记资料及其转换、资料段、清洗准备/正式结果和监测批次/快照关联；对象引用与版本始终保留，详情不依赖目录首页。未发生的阶段明确缺席，错误、部分可用、排除范围、确定性校验及实际预算由所属正式记录提供；可选 Agent 链接独立按 Agent 权限裁剪，无权不披露其存在性。该页面不得创建第二套接入任务状态机、把转换完成当清洗通过，或提供跳过必经 Agent、换模型、扩预算及假重试按钮。（RI-S1～RI-S2、RI-S14）

#### Scenario: PJ-S10 处理阶段与失败定位

- **WHEN** 用户打开含转换失败、清洗部分可用或尚无清洗结果的接入记录
- **THEN** 各阶段显示自身真实结果、精确来源和安全原因，正式排除范围可核对，不以另一阶段成功掩盖缺席或失败

#### Scenario: PJ-S11 历史精确读取与独立Agent权限

- **WHEN** 历史资料不在列表首页，或来源可读但用户无 Agent 权
- **THEN** 精确接入事实仍可读取；无权 Agent 引用及存在性被裁剪，不以无 Agent 权阻断领域结果或改读其它记录

### Requirement: PJ-R4 工程切换发布必须保全正式深链和可访问性

工程工作区 MUST 统一路由标题、页面主标题、工程二级导航及生产内部规范链接；五条已知 `/project` 别名永久保留精确查询语义，未知后缀不误匹配。新承载完成真实权限、正文、历史引用和原命令验收后同批替换旧内部链接和重复页面；不改造一次性 demo，不提前切断复核、评估或处置入口。页面使用生产语义令牌和有序区域组合，在三种桌面窗口的 100%/200% 原生缩放下键盘可操作；普通页面不用实现机制说明或技术标识充当主标题，质量/验收证据保留合成来源与待甲方复核标记。

#### Scenario: PJ-S12 规范入口与永久旧地址

- **WHEN** 用户从总览、证据抽屉、工程二级导航或已知旧地址打开精确工程对象
- **THEN** 进入同一规范承载，工程/修订/来源/对象版本/段定位不丢失，浏览器返回刷新可重建；未知旧后缀仍未找到

#### Scenario: PJ-S13 桌面键盘缩放与真实取证

- **WHEN** 用户在三种受支持桌面窗口及两种原生缩放下操作工程页签、表单、分页、错误与确认
- **THEN** 关键操作和焦点可达且不被遮挡，正文折行、二维内容局部滚动；真实环境缺失明确失败，不以编译、原型或关键场景 skip 计为通过
