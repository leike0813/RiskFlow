## Purpose

本能力把已冻结的工程输入、受治理识别知识、关系与混合检索、风险候选收口和人工复核组合为唯一、有限且可重放的 I0～I9 识别运行，并确保业务事实、检查点、权限与审计边界在暂停、恢复、重试和取消期间保持一致。

## ADDED Requirements

### Requirement: I0 至 I2 冻结单一输入快照和完整工序工作计划

系统 MUST 只从同一工程、同一父运行和当前获授权的精确识别准备快照启动识别子运行。I0 MUST 固定准备快照及触发原因；I1 MUST 按准备快照、业务时刻与记录时间解析同一版本组合的工序模型、风险机理、检索证据库和识别策略集，并把策略集中声明的检索、检索审阅、修正、合并、置信度、强制复核、重试、模型和提示版本冻结为一个 `IdentificationInputSnapshotV1`；I2 MUST 从该精确工序模型形成覆盖全部适用工序的不可变工作计划。工作项 MUST 固定工序节点、空间、资料版本、资料段范围和由受治理工序/机理事实形成的查询依据，不得接受自由调用方正文或隐式“最新版”。（RI-S1～RI-S6）

#### Scenario: 合格准备形成单一输入和工作计划
- **WHEN** 输入就绪信号引用一个当前可读、清洗已收口的准备快照，识别基础与策略集在双时间边界内完整有效
- **THEN** 运行依次保存 I0 准备结果、一个识别输入快照和一个包含全部适用工序工作项的 I2 工作计划
- **AND** 每个工作项都能回到同一准备、知识发布、策略集和资料段范围

#### Scenario: 知识或策略未就绪时等待
- **WHEN** 精确识别发布、组合成员或策略版本尚未生效、已停用、错工程或与准备快照不兼容
- **THEN** I1 保存类型化等待或失败引用且不形成半套输入快照或工作计划
- **AND** 恢复时重新校验原精确引用，不自动改选更新版本

#### Scenario: 工作计划不完整时拒绝
- **WHEN** 工序节点缺少冻结空间/资料范围、查询依据或策略要求的工作项，或者计划引用了输入快照之外的节点或资料
- **THEN** I2 返回结构化业务阻断并保持既有准备与知识事实不变
- **AND** 不以空工作项、自由文本或跳过节点继续检索

### Requirement: I3 为每个工作项完成必经检索审阅和五项上下文

系统 SHALL 为工作计划中的每个工作项使用同一识别输入和当前收窄授权执行关系检索、双索引基线检索及必经 `retrieval-review` 任务，并只在该任务完成且增量通过确定性校验后形成正式检索工件集和 RI-S56 五项上下文。工作项处理 MAY 有界并发，但每项的任务、预算、补搜、结果和失败身份必须独立；必经任务失败不得由基线、缓存或其它工作项结果替代。（RI-S53～RI-S56）

#### Scenario: 全部工作项形成五项上下文
- **WHEN** 每个工作项的关系事实、双路基线、Agent 审阅和五项上下文均在冻结版本与当前授权下完成
- **THEN** I3 保存全部正式检索工件集、Agent 任务和工作项结果引用并推进 I4
- **AND** 检索排序信号不进入模型置信度或综合置信度

#### Scenario: 单项检索审阅终止失败
- **WHEN** 一个工作项的必经 Agent 预算耗尽、工具/校验终止失败或来源资格失效，而其它工作项已完成
- **THEN** I3 保留该项失败引用和全部已成立证据，并继续保存其它合格工作项的正式结果
- **AND** 失败项不进入 I4，运行汇总不得把它报告为已识别或已复核

#### Scenario: Agent 尚未完成时暂停
- **WHEN** 任一必需检索审阅任务仍在运行、等待安全重试或其外部效果无法确认
- **THEN** 识别运行保存精确任务和等待引用并进入 `waiting`
- **AND** 恢复沿用原任务、预算、动作和线程，不另建替代任务或盲目重放已完成动作

### Requirement: I4 与 I5 只从正式五项上下文生成并校验候选

系统 SHALL 对每个具有正式五项上下文的工作项调用既有 RI-S57 专用推理入口生成候选，并立即进入共享 Schema、工序绑定、关系、证据、机理、规则及可选仿真/试验约束的确定性校验。仅字段、格式和冻结集合内引用错误 MAY 在原模型、提示、上下文、策略和总预算内修正；权限、来源资格、版本、规则冲突和仿真/试验失败 SHALL 终止该候选。I4/I5 MUST 保存每个工作项的候选版本、原始响应、校验和失败引用，不得创建同一 Agent 形式化复审。（RI-S57～RI-S59）

#### Scenario: 工作项候选通过校验
- **WHEN** 专用推理只使用冻结五项上下文且候选通过全部确定性校验
- **THEN** I4/I5 保存该工作项的候选集和已校验候选集精确引用
- **AND** 原候选、模型置信度、原始响应和每轮校验证据保持不可变

#### Scenario: 可修正错误有界闭环
- **WHEN** 候选只存在允许修正的字段、格式或冻结引用错误且原预算仍有余量
- **THEN** I5 可把结构化错误反馈给同一专用推理入口并登记新的候选版本
- **AND** 修正不更换模型、提示、上下文、策略、输入或预算

#### Scenario: 不可修正候选失败不伪装人工复核
- **WHEN** 候选发生权限、来源、版本、规则冲突、仿真/试验约束或预算终止失败
- **THEN** I5 保存失败候选和原因并将对应工作项记为失败
- **AND** 技术或确定性失败不得转换为人工通过路线

### Requirement: I6 至 I8 逐组完成合并、验收路由和原子入库

系统 SHALL 在全部可处理工作项达到 I5 终态后，以完整已校验候选集合执行一次全运行合并，再按冻结置信度与强制复核策略为每个组形成唯一验收路线。自动组 SHALL 使用匹配系统决定；人工组 SHALL 等待精确 `identification-group` 决定。I8 MUST 以组为幂等收口单位调用既有验收入口，使合格标准化风险记录、命令回执、审计和 `identification.risk-record-accepted.v1` 原子成立；一个等待、拒绝或失败组不得阻止其它已合格组入库。（RI-S61～RI-S65）

#### Scenario: 自动组和人工组并存
- **WHEN** I7 同时形成自动验收组和待人工复核组
- **THEN** I8 可先逐组入库自动验收组，运行保存人工组的复核任务和等待引用
- **AND** 已入库组不因其它组等待而回滚或重复入库

#### Scenario: 人工决定未成立时本轮待定而非错误
- **WHEN** 整集验收中某个 review 型 route 的精确人工决定尚未成立，而其它组的决定已齐备
- **THEN** 该组按本轮待定跳过、不产生任何标准化风险记录或事件，命令以合格组的入库结果成功收口
- **AND** 待定不被当作拒绝或失败，也不使已合格组的记录回滚；整集提交集仍必须恰等于全部 route

#### Scenario: 待定组在后续轮次有决定后恰入库一次
- **WHEN** 本轮待定的组在后续轮次取得决定并重新提交整集验收
- **THEN** 该组恰入库一次，本轮已入库的其它组按同一幂等身份重放为 no-op
- **AND** 不重复产生标准化风险记录、命令回执、审计或事件

#### Scenario: 人工决定恢复当前组
- **WHEN** `review.review-resolved.v1` 精确指向当前等待运行、任务和组版本，且决定允许原样通过或确认合并
- **THEN** 原线程恢复并只对匹配组继续验收，复用既有合并、路由、候选和决定事实
- **AND** 重复事件不重复恢复、审计或风险记录

#### Scenario: 修订或分立决定重新进入确定性路线
- **WHEN** 精确人工决定为修正并通过或保持分立
- **THEN** 运行从既有 C22 返回的重路由语义重新进入相应校验、合并和验收路线
- **AND** 不在图节点中复制候选校验、合并或置信度算法

#### Scenario: 拒绝与退回保持阻断
- **WHEN** 精确人工决定为拒绝或退回上游
- **THEN** 运行把该组记录为拒绝或退回且不形成标准化风险记录
- **AND** 其它已合格组仍可独立完成

#### Scenario: 混合合格组与拒绝组同集验收
- **WHEN** 一次整集验收中同时存在决定为通过/确认合并的合格组与决定为拒绝或退回的组
- **THEN** 合格组的标准化风险记录、命令回执、审计与 `identification.risk-record-accepted.v1` 在同一事务单元内成立
- **AND** 被拒绝或退回的组不产生任何记录、审计或事件，且不阻止合格组入库

#### Scenario: 全部组被封闭时按幂等空结果收口
- **WHEN** 整集验收中每个组的决定都是拒绝或退回
- **THEN** 命令以 `skipped` 结果成功收口、不产生任何标准化风险记录或事件
- **AND** 同一决定集重放返回同一回执且不产生重复记录或事件

### Requirement: I9 汇总明确区分每个工作项和分组终态

系统 MUST 仅在工作计划内每个工作项及其产生的每个合并组都已达到已验收、等待复核、拒绝、跳过、失败或取消之一时形成 I9 结果。汇总 MUST 固定输入、计划、阶段结果、已验收记录、待复核任务、拒绝组、失败工作项、取消原因和审计引用；等待中的运行不得伪装为完成，无合格候选时不得生成空成功记录。（RI-S1～RI-S6）

#### Scenario: 部分成功形成可解释汇总
- **WHEN** 部分组已入库、部分组被拒绝且部分工作项失败，并且不存在仍在执行或效果未知的动作
- **THEN** I9 形成包含各类别精确引用和计数的不可变运行结果
- **AND** 已验收记录、拒绝和失败均可沿阶段证据重放

#### Scenario: 仍有待复核组
- **WHEN** 至少一个人工组尚无有效决定
- **THEN** 运行保持 `waiting` 并保存等待与复核任务引用
- **AND** 不提前生成 completed 结果或把待复核组算作拒绝

### Requirement: 业务运行事实与 LangGraph 检查点严格分离

系统 MUST 以只追加业务事实保存识别策略集、输入快照、工作计划/工作项、阶段结果、运行状态版本、等待、错误和 I9 结果的精确引用，并以命令幂等、授权上下文、actor、双时间和审计关联使其可重放。LangGraph 检查点 MUST 只保存现有 `IdentificationGraphStateV1` 允许的小型版本化引用，并使用独立 checkpointer 身份与 schema；检查点丢失、回滚、清理或写入失败不得创建、覆盖或推断业务事实。（RI-S14、RI-S61～RI-S65）

#### Scenario: 真实 StateGraph 落检查点时仅豁免 LangGraph 控制通道
- **WHEN** 识别子图用真实 `StateGraph` 与 C03 PostgreSQL checkpointer 执行，检查点写入包含 `__start__` 与 `branch:to:<node>` / `join:<a>+<b>:<node>` 这类 LangGraph 调度控制通道
- **THEN** 控制通道与既有协议通道同等豁免，`channel_values` 在剔除它们后仍严格解析为 `IdentificationGraphStateV1`
- **AND** 非控制通道的未知键、非法写入类型与越权写入仍以既有 `CHECKPOINT_INCONSISTENT` 失败闭合，控制通道不承载任何业务事实

#### Scenario: 状态物化前的输入检查点仍严格可解析
- **WHEN** LangGraph 写入首个输入检查点，此时剔除协议/控制通道后没有已声明的状态通道
- **THEN** 系统改为把 START 通道的值交给同一批 GraphState Schema 严格解析，并把解析结果用于线程绑定校验
- **AND** 该值不是合法状态时仍以 `checkpointer.graph-state` 拒绝，不新增任何默认值、占位状态或放宽路径

#### Scenario: 业务提交后检查点失败
- **WHEN** 一个阶段业务事实、审计和命令结果已提交，但随后检查点写入失败
- **THEN** 已提交事实保持有效，运行以结构化可重试错误停止
- **AND** 恢复先按原幂等身份核对业务提交，再重建小型图状态而不重复领域副作用

#### Scenario: 检查点引用不存在的业务事实
- **WHEN** 恢复读取的检查点含有无法由当前工程精确业务窄读证明的输入、计划、阶段或结果引用
- **THEN** 系统返回不可伪造的检查点不一致错误并停止推进
- **AND** 不从检查点正文补写业务表、审计、事件或风险记录

#### Scenario: 业务事实同键异载荷冲突
- **WHEN** 调用方复用同一工程、命令类型和幂等键但改变冻结输入、目标版本或阶段载荷
- **THEN** 系统保留首次业务事实并返回不可重试冲突
- **AND** 不覆盖运行历史或分叉同一运行版本

### Requirement: 启动、恢复、重试与取消保持冻结身份和当前授权

系统 MUST 通过既有工作流命令和权限分支启动、恢复与取消识别运行，并在每次受保护读取、Agent/模型动作和业务写入前复验当前 actor、工程、空间、资料与精确分支授权。恢复和技术重试 MUST 沿用原运行、线程、准备、输入、计划、策略、模型、提示、预算和业务幂等身份；更换任一冻结版本必须创建新运行。取消只阻止未开始或可协作终止的工作，保留已成立的任务、工件、决定、风险记录、审计和事件。（RI-S1～RI-S6）

#### Scenario: 相同启动命令幂等重放
- **WHEN** 同一获授权启动命令以相同规范载荷重试
- **THEN** 系统返回原识别运行引用且不重复创建输入、计划、任务、阶段事实或检查点线程
- **AND** 同键异载荷返回不可重试冲突

#### Scenario: 当前授权撤销后停止推进
- **WHEN** 运行已冻结输入但 actor 的工程、空间或资料权限在后续阶段前被撤销
- **THEN** 下一次受保护读取或写入安全拒绝并留下不含无权正文的失败证据
- **AND** 原授权上下文、Agent 任务或检查点不能绕过撤权

#### Scenario: 协作式取消保留已成立事实
- **WHEN** 获授权用户以当前运行版本取消仍在执行或等待的识别运行
- **THEN** 系统记录取消结果并停止尚未开始的工作，I9 或取消结果引用明确列出已成立与未执行范围
- **AND** 已入库记录、人工决定、审计和事务事件保持不变

#### Scenario: Agent 任务等待原样复原
- **WHEN** 运行因一个必需的 C08 `retrieval-review` 任务未终结而进入 `waiting`，随后该任务以同一任务引用完成
- **THEN** 等待引用为 `WaitingRefV1` 的 `agent-task` 变体并携带该精确 `AgentTaskRefV1`，与 `ResumeCauseV1` 的 `agent-task-completed` 成对
- **AND** 系统用原线程、原任务引用、原预算与原冻结版本恢复，不新建替代任务，也不重复已成立的动作

#### Scenario: 等待引用缺失或类型不匹配时恢复失败闭合
- **WHEN** 恢复请求给出的等待引用缺失、kind 与登记事实不一致，或引用的任务/组与当前等待事实不是同一版本
- **THEN** 系统以稳定不可重试错误拒绝推进并保留最小诊断引用
- **AND** 不改用其它等待类型、不从关联字符串猜运行身份、不补写业务事实

### Requirement: 图节点只组合公开接口且失败路由保持类型化

识别图 SHALL 只通过既有工程数据、知识建模、风险识别、Agent、复核审计、工件和检查点公开接口读取或提交事实；不得直接读取其它模块数据库表、Qdrant、文件路径或私有对象。领域 Schema、检索、候选校验、合并、置信度、人工决定和业务入库错误 SHALL 保持原稳定代码、可重试性与诊断引用，图只据闭合结果选择继续、等待、重试、拒绝或终止路线，不得匹配完整文案或把技术失败改写为业务决定。

#### Scenario: 上游公开端口返回业务等待
- **WHEN** 精确知识、Agent 结果或人工决定尚未成立且上游返回类型化等待/阻断
- **THEN** 图保存对应引用并进入等待或受影响项阻断路线
- **AND** 不直接读取上游私表寻找替代结果

#### Scenario: 可重试技术错误按冻结策略处理
- **WHEN** 上游返回可重试技术错误且原重试策略仍有预算
- **THEN** 图以稳定阶段动作身份安排原策略内重试并保留失败证据
- **AND** 不更换模型、输入、策略或幂等键，也不重复已确认完成的副作用

#### Scenario: 终止错误封闭失败
- **WHEN** 上游返回权限、版本、契约、幂等冲突或其它不可重试错误
- **THEN** 图停止受影响工作项或运行并保存稳定错误与诊断引用
- **AND** 不通过循环重试、默认值或人工复核绕过该错误
