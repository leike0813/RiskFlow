# platform/electron-https-client Specification

## Purpose

为 RiskFlow 提供加载甲方内网 HTTPS 页面的小型 Electron 桌面客户端，使桌面与浏览器共用完整 Web 业务界面、身份授权和正式 API，同时明确本机能力、连接失败、版本发布及多平台验收的边界，不建立第二套业务事实或本机推理系统。

## Requirements

### Requirement: 桌面与浏览器必须共用完整 Web 业务界面

系统 MUST 由 `apps/web` 唯一提供 C32–C35 的完整业务界面和 C36 质量页面，Electron MUST 加载应用服务器批准的同一 HTTPS 入口。桌面与电脑浏览器 MUST 使用相同的正式 HTTP/SSE、工程上下文、权限、版本追溯和人工确认行为。桌面不得复制业务页面、运行本机领域服务或绕过正式业务命令；Web 业务界面 MUST 能独立于 Electron 运行。（横切 RI-S1～RI-S6；RA-S1～RA-S7）

#### Scenario: 两种入口访问同一业务对象

- **WHEN** 获授权用户分别通过桌面与电脑浏览器打开同一工程和精确对象深链
- **THEN** 两种入口读取相同正式事实与版本，均按当前服务端权限执行，页面不依赖 Electron 专有能力才能完成基础业务

#### Scenario: 原型数据或页面遗漏

- **WHEN** 生产构建缺少已交付业务路由，或页面依赖原型 fixture、审阅注入和静态业务数据
- **THEN** 发布验收失败，不以原型截图、独立 demo 构建或桌面外壳启动证明完整业务界面已交付

### Requirement: 桌面运行必须限制导航与本机能力

客户端 MUST 从受控部署配置读取唯一业务 HTTPS origin，验证协议、目标与用途；普通页面不得重定向到任意 origin、新建任意窗口或调用通用本机能力。业务渲染 MUST 关闭 Node 集成并开启上下文隔离、沙箱及生产内容安全策略。本机能力如被提供，MUST 使用有界具体接口并验证调用来源、参数与当前操作，不暴露通用 IPC、Shell、数据库、模型凭据或任意文件访问；文件选择和下载不得免除服务端授权。

#### Scenario: 越界导航或本机调用

- **WHEN** 页面尝试打开未批准目标、其它协议、新窗口或超出声明范围的本机调用
- **THEN** 客户端拒绝该动作，不使目标页面获得桌面权限，不执行任意代码或文件操作

#### Scenario: 基础上传与下载

- **WHEN** 当前获授权用户选择本地文件或下载正式报告工件
- **THEN** 业务通过既有上传/工件读取契约完成，下载保存位置由用户选择，不通过任意 URL 绕过资料或工件权限

### Requirement: 证书与会话必须沿用安全 HTTPS 边界

客户端 MUST 校验服务器证书与目标身份，私有 CA 通过受控系统信任配置接入，禁止因内网环境关闭 TLS 验证。页面、API 与 SSE MUST 保持同源，Cookie 由专用客户端会话容器管理且不暴露给页面脚本或桌面日志。客户端不得包含服务器秘密，不以安装客户端身份替代登录或工程授权；注销、会话失效和撤权 MUST 遵循既有服务端语义。

#### Scenario: 有效证书与真实登录

- **WHEN** 客户端连接已配置且受信任的业务 origin 并由用户登录
- **THEN** 页面使用真实服务端会话完成同源请求与订阅，桌面和普通浏览器的会话彼此独立

#### Scenario: 证书失败或权限撤销

- **WHEN** 证书不受信任、过期、目标不匹配，或已登录用户的权限被撤销
- **THEN** 前者拒绝业务加载且不降级至 HTTP，后者由服务端拒绝后续访问，不恢复旧权限或接受未经核验的目标

### Requirement: 连接恢复不得重启任务或自动提交写命令

客户端 MUST 在服务器不可达时提供安全连接状态和显式重试入口，不显示旧业务数据为当前正式结果。恢复后 MUST 重新核验会话并沿既有订阅游标和刷新预算读取结果；未知受理状态的命令不得因连接恢复自动重新提交。窗口关闭 MUST 只结束客户端连接，不取消已受理后台任务；业务取消仍须通过正式命令。客户端不维护本地业务事实库或离线写入同步队列。

#### Scenario: 首次连接失败与恢复

- **WHEN** 客户端启动时服务器不可达，随后用户重试连接
- **THEN** 先显示连接状态，再按正常登录/会话边界进入业务界面，不制造本地成功结果

#### Scenario: 窗口关闭后任务继续

- **WHEN** 服务端已受理任务后用户关闭并重新打开客户端
- **THEN** 原任务继续遵守服务端版本、预算与生命周期，新会话按权限读取同一任务，不因窗口重开启动第二个任务

#### Scenario: 命令响应丢失与订阅重连

- **WHEN** 写命令响应丢失或 SSE 断开后连接恢复
- **THEN** 订阅按既有游标恢复；写命令只能按既有确认与原身份重试语义显式处理，不自动复制、改载荷或重新确认

### Requirement: 桌面验收独立绑定同次运行与导出查询

桌面验收 MUST 从同份functional配置观察的唯一正式workflow.start-run回执绑定运行，从共享URL精确绑定同次risk-overview查询，并核验下载export请求的sourceRef与该查询一致。run-view观察和risk-overview导出分别遵循既有DTO，不得要求risk-overview携带workflowRunRef或用其它查询导出回执替代。

当活动评估运行的正式事件不足时，SSE场景 MAY 显式绑定同工程已有识别运行的事件流身份与读取快照身份、来源版本。两个身份 MUST 属于同一运行实体；当前会话 MUST 经所属读取核对精确快照及completed，随后两次订阅 MUST 保持同一精确事件流身份、2+2事件、游标不重放及零写断言。该样例不得替代同次活动任务的关窗证明；失败及分别取证的边界 MUST 保留。

#### Scenario: 正式观察和报告导出均绑定同次运行材料

- **WHEN** 同次回执包含被functional配置观察的唯一启动、run-view观察及risk-overview导出来源，且下载来自该导出来源
- **THEN** 桌面预检接受该正式绑定，其它工程/发布/来源/秘密校验保持

#### Scenario: 非导出查询或异查询下载

- **WHEN** 共享URL对应非risk-overview查询，或下载回执的请求来源不等于该精确查询
- **THEN** 预检拒绝，不生成真实Electron通过记录

#### Scenario: 活动运行事件不足时显式绑定SSE样例

- **WHEN** 同次活动任务已完成关窗续接，活动运行只有一条正式事件，另有同工程可读的精确识别运行事件流及状态快照
- **THEN** 当前会话核对该精确快照completed后，以同一事件流身份完成2+2游标续读且零写，关窗证据仍引用原活动任务；错实体、错快照或当前拒权不计通过

### Requirement: 桌面关窗继续使用同次活动任务证明

关窗前运行处于waiting时，桌面验收 MUST 以同次正式启动回执中的精确agentTaskRef，经当前会话读取所属任务并证明公共契约的pending/running；人审、已完成、失败及其它任务不得替代。关窗重开后 MUST 继续读取原运行并达到completed，submitted或等待不能计通过。

#### Scenario: LangGraph等待正在执行的内嵌Agent

- **WHEN** 同次运行waiting且其正式任务pending/running，客户端关闭后重开
- **THEN** 原服务端任务继续，最终核验同一运行completed；没有活动任务证明或终态失败必须失败

### Requirement: 桌面验收沿当前正式清单核验兼容

桌面预检 MUST 核验当前正式发布、配置、代码身份、同源地址与功能报告及客户端兼容，不得以历史固定数据库迁移号拒绝合法新发布。实际数据库迁移 MUST 由正式服务器启动按同一清单核验；桌面预检不得代替服务器迁移检查或完整功能实跑。

#### Scenario: 当前后端具有已批准新迁移

- **WHEN** 正式宿主已按当前清单验证000059，桌面当前发布及功能报告绑定合法
- **THEN** 桌面预检不因历史000058常量失败；错发布/工程/报告及不合格输入继续拒绝

### Requirement: 当前桌面原件与Agent行为必须和Web一致

Electron MUST 加载同一受信HTTPS的原件/PDF/Agent界面，下载只允许批准origin的原件及既有报告用途，用户选择保存位置。不得新增通用本机IPC、自动打开文件或放宽iframe/Node/窗口/TLS边界。

#### Scenario: 保存原件并查看任务

- **WHEN** 用户在当前平台真实Electron选择已有原件下载并打开Agent
- **THEN** 文件实际保存且与登记字节一致，任务与Chrome对应同一正式引用，无重启后台任务

### Requirement: 桌面功能验收与正式离线发布分阶段

后续功能阶段 MUST 以真实功能证据核验完整 Web 独立运行和当前平台 Electron 的导航、TLS/证书、权限、会话、命令确认/幂等、SSE 重连与已受理任务继续。桌面特有行为须有桌面证据，代码存在或浏览器测试不能替代。正式签名、多平台安装、三 VM 与硬件材料缺项不得阻塞已有完整功能证据的当前功能 PASS、集成和归档。

C38 MUST 按 Windows 11 x64、Ubuntu 24.04 x64、macOS 14+ arm64 矩阵提供签名/信任合规离线包及逐平台真实安装和功能证据；安装运行不依赖公网下载或自动更新。签名/公证缺项仍须拒绝正式制包，不增加未签名分发。工程、当前功能与 C38 正式证据分别记录，不能互相替代或冒称未来交付通过；三 VM/4090 取证沿最终部署规格。移动端、PWA 与脱离服务器业务不在范围内。

#### Scenario: C38 无公网环境安装正式客户端

- **WHEN** 操作者在声明的目标系统使用完整离线安装包与部署配置
- **THEN** 客户端无隐式下载地安装运行并连接批准的内网 HTTPS，报告记录平台、桌面与服务端发布身份

#### Scenario: 当前功能验收与 C38 平台证据缺失

- **WHEN** 当前功能证据满足要求，但 C38 的一个或多个正式平台、签名/公证、三 VM 禁网部署或 4090 性能/资源证据尚未取得
- **THEN** 功能阶段可记录功能 PASS 并继续集成与归档；C38 对应证据保持未完成，不将其记录为通过

#### Scenario: 兼容界面更新与正式平台证据

- **WHEN** 兼容的服务端界面更新，或 C38 某个声明桌面平台缺少正式签名材料、介质或真实安装环境
- **THEN** 前者由客户端加载同一 HTTPS 入口的新界面；后者仅将相应 C38 平台交付证据记为未完成，正式包不使用缺项回退
