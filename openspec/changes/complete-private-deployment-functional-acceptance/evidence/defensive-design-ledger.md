# 验收中发现的过度防御与设计冗余

本工件按用户要求，在继续功能验收时维护，供后续集中优化。只记录已有代码和复现证据支持的问题，不代表清理后的全仓审计。状态区分“已修复”“修复验证中”和“待优化”；待判断的问题单独注明，不预先认定所有校验都有问题。

当前验收 change：`complete-private-deployment-functional-acceptance`。代码位置以符号为准，详细修复设计见[design.md](../design.md)。受限证据均在隔离验收根下，本工件不复制凭据、Cookie、资料正文或模型思考内容。

## DD-01：用历史完整授权摘要代替当前资源权限

**确认，已修复；关联 D-162。**

- 冗余所在：把历史操作时的完整权限集合当作今天能否读取某个对象的必要条件。无关来源授权变化也影响该对象读取。

- 证据：`d155-report-export/report-export-v155.json`，本 change 的[知识编制与报告索引](knowledge-authoring-2026-10-17.md)。
- 后续方向：检查同类历史读取是否仍依赖整个旧授权快照相等；复用当前业务动作入口和对象拥有方的资源元数据，不再加一套影子权限状态。
- 桌面新增观察：`d172-functional-desktop/desktop-traces/`中共享报告深链已登录但导出历史为空。D174进一步确认，即使用户已声明来源，Web client也只向评估查询透传、向报告窄读丢弃。原报告browser用例扩展后三种请求来源先红（收到空集合），现复用既有选择解析修复并回归；桌面沿原来源选择UI声明同次overview实际范围。C31/C35仍依赖调用方重建范围，后续检查精确对象深链能否沿所属资源元数据取得所需来源，减少重复携带整套资料引用。不能省略当前权限检查，亦不能把未声明来源等同于有权。
- 必须保留：当前撤权、空间和来源限制、对象版本、跨工程拒绝、审计及工件完整性。查询游标绑定本次查询范围不等同于本问题，不应一并删除。

## DD-02：把准备读取的权限范围当作结果工件的权限范围

- 必须保留：父工件来源继承、当前权限、事务原子性、幂等、审计，以及提交前仍有效的业务前置条件。

## 不计入本记录的问题

CLI漏发服务端要求的Origin（D-167）属于普通实现缺陷；真实模型生成错误、硬预算耗尽也不能仅凭“被拒绝”判作过度防御。必要的权限、版本、预算或业务质量检查失败，应先检查输入和实现是否正确。

后续验收发现同一根因时补在原DD-ID下；只有出现新的机制问题才新增条目。每条修复仍以代码与实际验证更新状态，不能因本工件提出优化方向就视为已完成。
