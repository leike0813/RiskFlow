# 设计风险评估、预警与处置引擎

## Question

`assessmentGraph` 与确定性领域模块应怎样完成适用性元数据快照、规则结构化与发布、适用规则集、指标取值、P/C 计算、风险矩阵、动态预警、处置建议约束、反馈偏差和校准审核；完整产品与 MVP 各自覆盖到什么深度？

## Answer

采用“独立规则治理流程 + 有限 `assessmentGraph` 运行 + 确定性深模块”的总体设计。普通评估只消费已审核发布的适用规则集、指标映射、权重、受控评分策略、风险矩阵、两类阈值和措施库；缺失或不兼容时关联知识准备任务并暂停，不允许 LLM 临时选择规则。LLM 只生成结构化评分规则草案和在已发布措施候选集内组合排序，P/C、矩阵、四类触发、冲突/适用性校验及处置三项约束全部由确定性模块完成。

风险评估先冻结准备快照与完整输入快照，再完成指标取值、P/C、矩阵和触发判定，原子写入包含触发指标的不可变风险评估记录；之后才写入预警信息并安排通知。预警信息按触发类型分立，尚未关闭的预警处置任务按“工程 + 风险稳定身份 + 处置空间范围”归集，不使用固定时间窗口。

处置建议候选未通过触发指标一致性、规范合规性和现场可执行性三项校验前不能成为处置建议，也不能被人工强行通过。现场独立行动通过现场处置执行记录如实登记，不伪装成系统建议。处置效果预测是执行前形成的独立事实；反馈偏差使用预测时冻结的同一评分依据，规则后来变化时另做当前口径重评估。偏差超限只生成校准建议，仍须人工审核和新版本发布。

MVP 采用全链路覆盖、受限策略数量：真实跑通至少一条规范的结构化、审核、适用规则集发布和评分引用；实现一种甲方确认的 P/C 策略、四类预警触发、小规模措施库与三项校验、一种确定性监测趋势预测，并完成一次预测、执行反馈、偏差、校准建议和人工发布闭环。完整产品在同一事实与接口契约上扩展规则规模、策略类型、自动重评估、通知渠道和多工程能力。

完整规划见：[RiskFlow 风险评估、预警与处置引擎](../prototypes/assessment-warning-response-engine.md)。
