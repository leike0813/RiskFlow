# 确定知识库、混合检索与图谱查询策略

## Question

风险机理库、规范标准库、类比案例库、工序模型和评估知识应怎样统一版本与证据语义；BM25、向量检索、重排序、关系检索和工序风险关联图谱分别解决什么问题，索引构建、更新、删除、重放与质量验收如何设计？

## Comments

- 已确认采用“各知识集合独立版本化 + 知识基线快照”：检索证据库只精确组合风险机理库、规范标准库与类比工程案例库的已发布集合；识别与评估运行分别冻结所需知识和策略版本，不设置同步递增的全局知识库版本。
- 已确认采用双层证据语义：知识条目精确修订版说明所用知识，证据定位信息必须继续锚定一个或多个不可变资料段并可附结构位置；知识条目编号、Qdrant 载荷或检索分数均不得代替底层证据定位。
- 已确认混合证据检索与关系上下文检索是两条独立通道：前者由 BM25、向量检索和可选重排序形成 Top-K，后者从冻结工序模型与机理库确定性取得 RI-S56 必需上下文；工序风险关联图谱仅作只读查询投影，不参与识别推理或反向写回。
- 已确认混合检索默认采用加权倒数排名融合：双路各自召回 Top-N，按稳定证据身份去重并保留原始分数与排名；候选数、RRF 参数、通道权重和 Top-K 随检索策略版本冻结。检索综合得分只作单次查询相对排序，不等同置信度，也不跨查询比较。
- 已确认 MVP 不部署重排序模型，只保留默认关闭的重排序接口；后续仅在冻结中文标注集证明质量收益、延迟与单机资源均达门槛后，才通过新检索策略版本启用专用本地模型。重排序不得补召回、绕过过滤或在失败时静默回退，且不得使用 27B 主推理模型逐条打分。
- 已确认采用“不可变索引代际 + 旁路构建 + 原子切换”：每个代际精确绑定证据库、分块、分词、BM25、Embedding 与向量参数版本；双索引对账和质量校验通过后才整体生效。活动代际禁止原地更新，旧代际继续支撑已冻结运行；内容哈希复用只节省计算，不改变新代际的独立成员清单。
- 已确认正常撤回通过不可变撤回决定、后续发布集合排除和新索引代际生效，历史版本与冻结运行不改写。无活动运行依赖且满足保留期后可删除可重建的旧 Qdrant 代际；权限撤销由查询前过滤和 PostgreSQL 回查立即执行；法定或合同物理擦除另由私有化治理决策授权并留存擦除证明。
- 已确认索引重建采用“成员与配置精确、近似排名不要求逐分数复现”的契约：证据成员、修订、资料段、哈希、过滤元数据及全部策略版本必须一致，派生索引内部结构不升格为事实。历史候选、双路分数、融合顺序和最终上下文从 PostgreSQL 运行记录审计；重新检索或调用 LLM 创建新运行，不覆盖历史结果。
- 已确认索引 `ready` 验收分为硬完整性门槛与版本化质量门槛：成员、双索引、版本、哈希、回查、权限和过滤字段必须完全对账；冻结中文工程查询集分别衡量双路与融合检索，并按查询类型和三类证据来源切片。具体指标阈值与标注方法由“确定模型、检索与规则质量评测策略”形成版本化策略，任一必过门槛失败均不得切换新代际。
- 已确认候选资格过滤与相关性排序严格分离：双路召回前共用知识版本、发布/撤回、工程与资料权限、来源范围及明确适用性冲突等确定性过滤；适用性未知者保留并标记。过滤快照和排除原因审计，命中后由 PostgreSQL 再次复验并按冻结策略补足；RA-S4 的严格规则适配不得由 RAG 排名替代。
- 已确认检索查询由“确定性查询种子 → Agent 结构化规划 → 确定性校验与执行”自动生成：种子来自冻结工序、状态参数和适用性事实；Agent 只规划检索角度及 BM25/向量表达；系统固定附加版本、权限、发布和适用性过滤。用户无需逐次填写，Agent 无权决定证据可信度、Top-K 或风险结论；规划失败重试耗尽后暂停，不静默改用另一套行为。
- 上述查询生成结论经进一步讨论修订为“确定性基线检索 → Agent 审阅与受限补充检索 → 确定性校验收口”：基线查询、双路结果与 RRF 排序不可变保留；Agent 可结合工序事实和关系上下文发现覆盖缺口、调用有界检索工具并标记冲突或不确定证据；最终结果、补充查询及相对基线的差异全部审计。该自动环节统一称为 Agent 审阅，不得冒充复核人或替代人工复核。
- 已确认 Agent 审阅可以影响正式推理上下文，但不能改写基线检索事实：Agent 通过检索工具补充候选，并以独立处置字段作保留、提升、降级、重复、疑似无关、适用性不确定或冲突标记；确定性选择器据此形成最终上下文。硬性无资格项由规则移除，冲突和不确定项不得静默删除，未入选证据仍留在基线审计；调整后低于最小覆盖要求时补搜或暂停。
- 已确认工序风险关联图谱严格保持 RI-S62 的工序、机理与风险要素范围，完整端到端链路由独立追溯查询投影提供；关系上下文检索不读取该图谱投影。Agent 只通过限制工程、版本、边类型和深度的领域图查询工具访问，不能执行任意 SQL/Cypher；MVP 使用 PostgreSQL 关系投影与递归 CTE，固定查询实测失败后才评估图数据库。
- 已确认图谱投影延迟采用单一简化规则：未追平时界面与 Agent 工具统一显示“图谱更新中”，依赖图谱结果的操作等待，超时按技术故障重试或重建；不提供使用旧投影继续正式处理的分支。识别、评估和业务事实不依赖该查询投影，因此投影延迟或异常不得回滚、修改领域事实。
- 已确认 RI-S56 模型上下文由确定性、版本化预算策略组装，必须保留工序节点描述、状态参数描述、受力依赖关系、风险机理条目和检索证据五类内容。Agent 只能在检索证据预算内补充、提升或降级；超限候选留存审计，必含内容超窗时按规则拆分或暂停，不任意截断。实际输入的条目、资料段、顺序、截取范围和策略版本完整保存。

## Answer

### 知识版本与证据语义

风险机理库、规范标准库、类比工程案例库、站隧一体化施工工序模型和评估知识分别维护稳定身份、不可变条目修订与已审核发布集合，不设置要求所有知识同步递增的全局版本。检索证据库版本只精确组合风险机理库、规范标准库和类比工程案例库三个发布集合，保持 RI-S52 的定义不变；一次识别运行另以知识基线快照冻结工序模型、检索证据库和检索策略，一次评估运行冻结适用规则集及其指标、权重、矩阵和阈值依据。

证据采用两层语义：知识条目精确修订版说明系统采用了哪项知识，证据定位信息则必须继续指向一个或多个不可变资料段，并可附页码、条款号、表格坐标等结构位置。知识条目编号、Qdrant 载荷、检索分数和 Agent 判断都不能代替资料段标识。每次命中在 PostgreSQL 回查正文、修订、权限和资料段后才有资格进入上下文。

### 混合检索、关系检索与 Agent 审阅

检索分成两个接口清晰的通道：混合证据检索负责从检索证据库生成相关性候选，关系上下文检索依据冻结的工序模型和风险机理库确定性取得当前工序关联的机理条目、前后工序和依赖关系。关系结果是 RI-S56 的必需上下文，不参与 BM25/向量计分，也不占用 Top-K 名额。

每个工序检索工作项采用 Agent-native 的必经流程：

1. 系统从冻结的工序节点、状态参数、适用性元数据和受治理术语生成确定性基线查询，执行 BM25、向量检索和融合，形成不可变基线结果。
2. Agent 审阅基线查询、基线结果、工序事实与关系上下文，可在版本化轮次、工具次数、候选数和时间预算内发起补充检索，或对候选作保留、提升、降级、重复、疑似无关、适用性不确定和冲突标记。
3. 确定性模块校验 Agent 的结构化行动，拒绝越权过滤、错误版本和无效引用，再按冻结策略融合、去重并组装最终 Top-K。

Agent 审阅可以改变正式推理上下文，但不能修改基线候选、原始分数和融合顺序。Agent 处置是独立字段，不伪装成检索分数；冲突或适用性不确定证据不得静默删除，未进入上下文的候选仍保留审计。Agent 无权改变权限、发布状态、知识版本、硬适用性条件或证据正文，也不等同复核人。审阅失败重试耗尽后暂停工作项，不跳过 Agent 继续推理。

### 排序、过滤与上下文组装

BM25 重点解决规范编号、装备/构件名称、参数、单位和工程术语的精确命中；向量检索重点解决改写、近义表达和跨文档语义匹配。两路独立召回 Top-N，按稳定证据身份去重，默认以加权倒数排名融合形成 RI-S54 检索综合得分。候选数、RRF 参数、通道权重和 Top-K 全部随检索策略版本冻结；原始双路分数、排名、Agent 补充查询和最终差异完整保存。检索综合得分只在单次查询内表达相对相关性，不是概率或综合置信度，也不能跨查询比较。

重排序保留可插拔接口，但 MVP 不部署重排序模型，默认直接使用 RRF 结果。后续只有专用本地重排序模型在冻结中文查询集上证明质量收益，并满足单机延迟与资源门槛后，才能随新检索策略版本启用；不得使用 27B 主推理模型逐条打分，也不得在失败时静默改变排序策略。

候选资格过滤与相关性排序严格分开。双路召回前共用知识版本、已审核发布、未撤回、工程/资料权限、来源范围和明确适用性冲突等确定性条件；适用性未知者可以保留但必须标记。命中后 PostgreSQL 再次复验，不合格候选由同一冻结策略补取。RA-S4 的严格规则适配继续由适用规则集完成，检索排名不能代替规则筛选。

RI-S56 上下文使用版本化预算策略，必须保留工序节点描述、状态参数描述、受力依赖关系、风险机理条目和检索证据五类内容。Agent 只能在检索证据预算内调整；超限候选留存审计。必含内容超过模型窗口时按规则拆分工作项或暂停，不任意截断。实际送入模型的条目、资料段、顺序、截取范围与策略版本均可还原。

### 索引生命周期、重建与验收

索引采用不可变代际、旁路构建和原子切换。每个代际精确绑定检索证据库、分块、中文分词/词典、BM25、Embedding、向量和融合配置版本。新代际完成双索引构建、成员对账和质量校验后才标记 `ready` 并整体切换；活动代际禁止原地更新。内容哈希可以复用分词或向量计算结果，但新代际仍有独立、不可变的成员清单。索引落后、缺路或故障时等待、重试或暂停，不退化为旧版本或单路检索。

正常撤回通过不可变撤回决定、后续发布集合排除和新索引代际生效，不改写历史。旧 Qdrant 代际在无活动运行依赖且满足保留期后可以删除，因为它能从 PostgreSQL 事实重建；历史业务事实、证据引用和运行审计不能随之删除。权限撤销由查询前过滤和命中后回查立即生效。法定或合同物理擦除由私有化治理票另行规定授权、保留例外和擦除证明。

索引重建要求证据成员、修订、资料段、内容哈希、过滤元数据和全部策略版本精确一致，不要求近似向量索引的内部结构、原始分数或候选顺序逐位复现。历史结果使用已保存的候选、双路分数、融合顺序、最终上下文和原始输出审计；重新检索或调用 LLM 创建新运行，不覆盖历史记录。

`ready` 验收分两层：硬完整性门槛要求成员、双索引、版本、哈希、回查、权限与过滤字段完全对账；版本化质量门槛在冻结中文工程查询集上分别评测 BM25、向量和融合检索，并按规范号、设备名、数值里程、工程同义词、长查询、否定条件以及三类证据来源切片。Recall@K、MRR、NDCG@10、零结果率、p95、构建时间、峰值内存和索引体积的具体阈值由“确定模型、检索与规则质量评测策略”制定。Agent 审阅还须相对基线评测新增相关证据、误降级、无依据补充、工具成本和端到端延迟。

### 图谱与追溯查询

工序风险关联图谱严格保持 RI-S62 的工序节点、风险机理条目、风险源、风险因素、风险事件及规定关联范围，是只读、可重建的 PostgreSQL 查询投影。资料段到评估、预警、处置反馈的完整链路由独立追溯查询投影承担；关系上下文检索不读取工序风险关联图谱，任何投影也不得反向写回领域事实。

Agent 只能调用限制工程、版本、边类型和深度的领域图查询工具，不能执行任意 SQL 或 Cypher。投影未追平时，界面与 Agent 工具统一显示“图谱更新中”，依赖图谱结果的操作等待；超时按技术故障重试或重建，不维护使用旧投影继续正式处理的分支。MVP 采用 PostgreSQL 关系投影与递归 CTE，只有固定图查询在真实规模下不满足正确性或 p95 门槛时，才评估图数据库。

这些能力应分别收敛在知识基线解析、混合证据检索、关系上下文检索、Agent 审阅、模型上下文组装和图谱/追溯查询接口之后。调用方不接触 Qdrant collection、PostgreSQL 表、检索供应商分数或递归查询实现；本票不新增第三方依赖，具体包版本与 Schema 由后续 OpenSpec change 冻结。
