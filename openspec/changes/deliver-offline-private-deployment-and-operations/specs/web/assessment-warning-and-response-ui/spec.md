## MODIFIED Requirements

### Requirement: C34 页面必须复用 v2 设计并只展示真实事实

系统 MUST 在 `apps/web` 生产应用提供 v2 的 P-OV-01、P-RA-01～07、P-WR-01～04、P-RS-01～05 共 17 页，复用其页面分区、卡片、列表、运行阶段、版本引用与版本化矩阵设计；只从当前工程的公开 HTTP 接口取得事实。原型 fixture、角色镜像、注入状态和审阅覆盖层 MUST 不成为业务输入。工程或路由变化 MUST 清除旧结果、取消读取并忽略迟到响应；无工程、加载、空、异常、权限及不可用状态 MUST 有清晰且可访问的呈现。（RA-S1～RA-S7）

#### Scenario: 真实数据与页面可达
- **WHEN** 用户在获准工程访问 17 个合法页面
- **THEN** 页面显示服务端事实或明确的引导/空/不可用态，详情支持领域标识和精确版本深链
- **AND** 不出现静态样例对象、假成功或审阅参数控制的业务权限

#### Scenario: 工程切换与失败
- **WHEN** 旧工程读取尚未结束时切换工程，或者新查询失败/被拒绝
- **THEN** 旧结果不能覆盖新工程，页面显示对应安全状态与可用重试
- **AND** 不泄露未获授权对象的存在性或正文

### Requirement: C34 必须以真实浏览器验收业务接缝

系统 MUST 在 `apps/web` 生产构建上复用既有 Chromium、真实 PostgreSQL 迁移/会话/HTTP harness 验收 17 页、初评/重评入口、预警确认、采纳拒绝、两类执行、正式反馈、历史评分解释、校准治理与跨页精确追溯。测试数据可为合成样本但 MUST 明确待甲方复核并固定版本；不得以 Mock 浏览器、假后端、关键 skip 或静态成功页替代。失败必须保留 trace，服务不可用须非零退出。（RA-S1～RA-S7）

#### Scenario: 真实闭环与失败边界验收
- **WHEN** 在真实浏览器执行 C34 验收
- **THEN** 正式命令结果与持久事实一致，权限/陈旧版本/重试/缺失前置均得到预期结果
- **AND** 测试验证可观察事实与引用，不锁定完整文案、CSS、DOM 排序或截图
