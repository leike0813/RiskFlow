# C07：交付人工复核与审计运行时

## Why

C02 已冻结 `ReviewAuditPortV1`、五类人工复核决定和复核事件，C03 已提供 PostgreSQL 原子事务、幂等回执、只追加审计与事务 Outbox，C06 已提供本地身份、工程授权上下文和安全审计。当前仍缺少把这三组契约组合成可运行能力的领域状态、持久化适配器和可查询追溯链，后续识别、知识编制、规则冲突、处置建议与校准流程因而无法可靠暂停、复核和恢复。

本 change 交付 C07 的最小闭环：创建复核任务、按类型提交人工决定、拒绝过期或越权操作、以既有运行/版本/输入输出引用形成责任可归属的审计链，并提供中文活动投影所需的结构化查询来源。

## What Changes

- 新增复核任务与决定的领域状态，覆盖 `pending`、`decided`、`superseded` 及五类 C02 决定联合类型；状态只保存引用，不复制上游业务正文。
- 实现 C02 `ReviewAuditPortV1`：`requestReview`、`decideReview` 与 `trace`，不修改 C02 共享契约。
- 复用 C06 `LocalIdentityAccessV1.verify` 校验调用者、工程、分支能力和授权上下文有效性；核心与适配器不得读取 C06 身份、成员或策略内部表。
- 复用 C03 `TransactionUnitV1`，在同一 PostgreSQL 事务中提交任务/决定事实、`audit.entries`、命令回执以及 `review.review-requested.v1` / `review.review-resolved.v1` Outbox 事件。
- 对未形成业务事实的过期、目标不匹配和状态冲突决定写入只追加拒绝记录；审计写入失败时不返回业务成功。
- 新增只读活动投影，把 C03 业务审计、C06 安全审计和 C07 复核拒绝统一为闭合活动码及中文展示参数；敏感正文、凭据、连接信息和模型思维链不得进入投影。
- 明确并发领取语义：决定提交者通过行锁与任务版本在决定事务内原子取得处理权；首个有效决定胜出，其余非同一幂等命令按过期提交拒绝。
- 明确批量语义：批量复核由多个标准 `decideReview` 命令组成，每项独立授权、幂等、提交和审计，不增加批量端口或跨任务大事务。

## Scope

### In Scope

- 五类 C02 复核任务、类型化决定、任务状态与运行暂停/恢复引用。
- 任务创建、原子决定、同键重放、并发冲突和过期目标拒绝。
- PostgreSQL 迁移、C03 事务适配、C06 授权校验、结构化审计查询及中文活动投影。
- 单元、契约、PostgreSQL 集成与权限回归测试。

### Out of Scope

- C08 通用 Agent 任务运行时、模型调用、工具白名单和资源预算。
- HTTP API、Web 页面、通知、导出和交互式批处理界面。
- 识别、知识、规则、处置或校准模块自身的候选生成与发布逻辑。
- 修改 C02 端口、事件和联合类型；增加独立 `claimReview` 或批量决定契约。
- 法律意义的数字签名或外部时间戳服务；本 change 的不可抵赖性限于已认证主体归属、不可变版本引用、数据库只追加权限和事务一致性。

## Dependencies and Ownership

- **直接依赖 C03**：`TransactionUnitV1`、命令幂等回执、`audit.entries`、`outbox.events` 与 PostgreSQL 角色边界。
- **直接依赖 C06**：`LocalIdentityAccessV1.verify`、版本化授权上下文和 `business.security_audit_events` 的只读投影。
- **复用 C02**：`ReviewAuditPortV1`、`ReviewRequestV1`、`ReviewDecisionCommandV1`、`TraceQueryV1`、五类决定 Schema、复核引用及两类领域事件。
- **C07 所有权**：`packages/core/src/review-audit/**`、`packages/adapters/src/review-audit/**`、C07 PostgreSQL 迁移、复核表、复核拒绝审计与复核活动投影。
- 不修改 C03/C06 表定义或授权规则；迁移仅创建 C07 自有对象及跨审计源的只读投影。

## RI/RA Traceability

- RI-S36、RI-S58、RI-S61：校验不通过或记录不完整时创建显式复核任务，未经决定不得静默通过。
- RA-S3、RA-S4：无法可靠结构化的规则及规则冲突进入人工复核；适用规则发布决定保留版本与证据引用。
- RA-S7：知识发布和校准生效必须由人工决定；校准复核只能批准创建草案，不能直接覆盖生效配置。
- 横切运行契约：人工复核是显式状态；确定性校验与人工语义判断分离；每次运行记录输入、输出、路由、版本、主体和时间。

## Success Criteria

- 相同幂等键和相同载荷重放返回相同引用且不重复任务、决定、审计或 Outbox；同键不同载荷返回冲突。
- 并发决定同一任务时仅一个决定提交；失败者获得稳定的过期/状态冲突结果，且不会覆盖首个决定。
- 授权上下文失效、工程不匹配、分支不匹配或角色无权时统一拒绝，且不泄露目标是否存在。
- 任何成功业务事实都与 C03 审计、命令回执和 Outbox 同事务；审计故障回滚业务事实。
- `riskflow_app` 不能更新或删除 C03/C06/C07 审计记录，不能绕过适配器改写已决定事实。
- 追溯结果可关联复核任务、目标与版本、验证/证据快照、等待与恢复运行、人工决定、输入输出引用、授权上下文和三类时间。
