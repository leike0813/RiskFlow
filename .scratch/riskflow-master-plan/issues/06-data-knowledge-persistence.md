# 确定数据与知识持久化架构

## Question

资料原件、JSON-LD、业务实体、LangGraph 检查点、向量索引、BM25 索引、工序风险关联图谱、监测时序、规则版本和审计日志应分别由什么存储模型负责，怎样以最少的基础设施满足 SSOT、检索性能、历史重放和完全私有化要求？

## Answer

### 最小物理数据面

MVP 采用三个持久化单元：一套 PostgreSQL、一套本地不可变内容寻址目录和一套 Qdrant。PostgreSQL 是唯一业务事实源；内容目录保存不可变二进制与解析工件；Qdrant 是可从 PostgreSQL 重建的检索投影。首期不引入图数据库、专用时序数据库、OpenSearch 或独立对象存储服务，具体产品版本在后续 OpenSpec 实施 change 中冻结并验证。

各领域模块只通过自己的持久化接口读写事实，不向调用方暴露通用数据库客户端、表结构、文件路径或 Qdrant collection。检索、图谱和文件实现可以替换，但这种替换不能改变领域 DTO、版本语义和审计契约。

### 数据职责与唯一事实源

| 数据 | 持久化模型 | 事实与重建边界 |
|---|---|---|
| 资料原件、OCR 中间产物、完整 JSON-LD、解析附件 | 本地不可变内容寻址目录；PostgreSQL 保存工件清单、内容哈希、长度、MIME、处理版本和来源关系 | 工件是处理追溯与失败回溯依据；重新解析生成新工件，不覆盖旧结果 |
| 资料段、验收后的实体与关系、标准化风险记录、评估、预警、处置、复核等业务对象 | 各领域模块拥有的 PostgreSQL 规范化关系表 | PostgreSQL 是业务 SSOT；不维护可独立修改的全量 JSONB 事实副本 |
| 工序模型、机理条目、规范条文、规则、指标、权重、矩阵、阈值与措施 | PostgreSQL 中的稳定身份、不可变条目修订、发布集合及精确成员引用 | 正式运行只读取已发布集合和项目级冻结版本，不读取零散“最新版” |
| LangGraph 检查点 | 同一 PostgreSQL 实例中的独立 schema、owner 和运行角色 | 只保存小型版本化 DTO、实体标识、版本与运行引用；不是业务事实源，清理不得影响领域记录 |
| 审计事件与事务事件 | PostgreSQL 的独立审计、Outbox schema | 业务事实、审计事件和 Outbox 在同一领域事务提交；审计只追加，Outbox 至少一次投递并按业务幂等键去重 |
| 监测时序 | PostgreSQL 原生时间范围分区及不可变监测批次 | 更正与迟到数据通过新批次及关系追加，不覆盖原始样本；监测快照冻结运行窗口 |
| 工序风险关联图谱 | PostgreSQL 节点、边及必要路径表形成的查询投影 | 规范化领域关系仍是事实；图谱只读、可删除重建且不得反向写回 |
| 稠密向量与 BM25 | Qdrant 中相互独立、按证据发布版构建的两套索引 | 只保存精确事实版本标识、过滤元数据与派生索引；证据正文、版本和审核状态回查 PostgreSQL |

### 一致性与投影契约

PostgreSQL 至少按业务、审计、Outbox、LangGraph 检查点和查询投影划分 schema 与写入角色。共用实例只减少运维单元，不把 LangGraph 检查点事务、领域事务和外部检索投影合并成一个事务。

领域命令在同一事务中写入业务事实、审计事件和 Outbox。投影 Worker 采用至少一次消费和稳定幂等键，能够重复执行、对账和全量重建。文件使用“先耐久落盘并原子落位，后提交数据库引用”的协议：可以留下无引用孤儿文件等待安全回收，禁止数据库出现指向缺失文件的已提交引用。

Qdrant 以证据发布版为索引边界，稠密向量、BM25、中文分词、嵌入模型、融合策略和 Top-K 均有版本。新索引旁路构建并通过质量校验后切换。RI-S53～RI-S54 运行只能使用与冻结检索证据库版本一致且已就绪的双索引；索引落后、缺失或故障时暂停重试，不得静默使用旧索引或退化为单路检索。每次运行把候选标识、两路原始分数、融合结果和索引版本写回 PostgreSQL。

### 历史重放

历史重放分为两种承诺：

1. P/C 计算、指标聚合、适用性校验、风险矩阵映射和阈值判断必须精确重放。风险评估记录冻结指标实际值、适用性元数据快照、规则集、权重、矩阵、阈值和确定性算法版本，重放结果必须一致。
2. LLM 推理与近似检索承诺输入可重建、原结果可审计，不承诺再次执行逐字节相同。运行记录保存模型文件哈希、模型参数、提示模板、完整上下文引用、检索候选与分数、原始输出、Schema/规则校验结果及图和节点版本；再次运行形成新的记录并与原结果比较，不覆盖历史。

历史查询继续按业务发生时间和系统记录时间重建当时可见状态。检查点只用于恢复流程，不能代替上述重放证据。

### 备份与恢复

PostgreSQL 使用物理基础备份、连续 WAL 归档和时间点恢复。内容目录使用不可变快照，并用备份批次清单关联数据库恢复点；恢复后校验全部已引用工件的内容哈希。Qdrant snapshot 只用于缩短恢复时间，索引正确性的最终恢复路径是从 PostgreSQL 事实全量重建。

恢复顺序固定为：对齐恢复 PostgreSQL 与内容目录、校验引用和工件完整性、重建图谱与检索投影、抽查“资料段标识 → 工序节点 → 机理条目 → 风险记录 → 评估 → 预警 → 处置反馈”审计链。恢复演练必须记录 RPO、RTO、索引重建时间和失败处置。备份加密、密钥管理、保留期、异地介质与责任分工由“确定私有化部署与治理边界”继续决定。

### 延后组件的升级条件

- 只有原生分区在目标监测规模下无法满足写入、窗口查询、保留或恢复指标时，才评估专用时序扩展。
- 只有关系表对固定图查询的深度、规模或 p95 验收失败时，才评估图数据库或图扩展。
- 只有本地目录无法满足多机、容量、冗余或运维责任要求时，才引入对象存储。
- Qdrant 若在同一中文工程查询集上的相关性、Outbox 新鲜度、资源占用或恢复 RTO 不达标，再以完全相同的数据和故障脚本比较 PostgreSQL 向量/BM25 扩展路线；不得默认双写两套检索事实。
