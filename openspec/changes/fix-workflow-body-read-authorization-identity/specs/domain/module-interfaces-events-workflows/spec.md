## ADDED Requirements

### Requirement: 进程内配对的派生调用身份必须纳入调用主体维度

凡由签发方与复验方共用同一导出函数派生 `invocationId` 的进程内配对，派生结果 MUST 纳入调用主体或当前授权上下文的维度，不得只由 operation、工程与目标标识拼成。对同一目标的正文读取，身份 MUST 随本次读取所依据的授权上下文而变，使不同授权上下文之间不共用同一派生身份；C06 重放比对因此只可能在真正同一授权上下文上命中。签发方与复验方 MUST 继续使用同一导出函数与同一取值，端口 MUST NOT 为省略身份参数提供可选分支——可选身份会让调用方退回固定派生并复现「同一目标第二次起必然冲突」。该要求不改变任何数据可见性判断，也不放宽 C06 的重放比对项。（RI-S6；RA-S5～RA-S7）

#### Scenario: 同一授权下同一目标可被重复读取

- **WHEN** 同一工程内对同一份运行正文发起两次以上读取，每次读取各自复验得到当前授权上下文
- **THEN** 每次读取都以与本次授权上下文配对的独立身份完成签发与复验并成功返回正文，不因先前读取已占用该身份而失败闭合

#### Scenario: 不同授权读取同一目标互不冲突

- **WHEN** 两个不同主体（或同一主体的不同授权范围）先后读取同一份运行正文
- **THEN** 各自以自身授权上下文配对的身份签发并复验成功，互不占用对方身份，结果仍受各自可见性范围约束

#### Scenario: 省略身份的调用方不得静默退回固定派生

- **WHEN** 审查正文读取端口的调用点与其请求 Schema
- **THEN** 身份为必填字段且全部生产调用点显式按同一导出函数派生传入，不存在缺省身份或适配器内部固定派生的分支
