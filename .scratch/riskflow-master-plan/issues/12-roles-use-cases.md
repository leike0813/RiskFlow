# 确定用户角色、权限视角与端到端业务用例

## Question

完整产品面向哪些业务角色，每个角色需要发起、查看、审核、发布或处置哪些对象；从项目初始化、资料接入、识别评估、预警处置到审计导出的端到端用例如何划分，哪些权限与职责分离必须进入 MVP？

## Answer

### 角色与权限原则

- RiskFlow 以工程内职责授权为主，不把甲方实际岗位名称固化为系统角色。用户可在不同工程拥有不同角色，同一账号可叠加多个角色。
- MVP 不强制提交人与审核人分离。具备相应权限的同一用户可以提交、人工确认并发布同一对象版本；关键动作必须显式确认并记录操作者、时间、对象版本和确认依据。
- 完整产品可以按工程配置多人审批，但默认关闭。是否启用由甲方管理要求决定，不能成为小团队或单人使用的前置条件。
- 系统管理员权限与工程业务权限相互独立，但可授予同一账号。系统管理员不会仅因负责运维而自动获得全部工程业务权限。
- 所有业务访问受工程成员关系约束。业务查看者对原始工程资料的访问继续服从资料自身权限，不能通过只读角色绕过资料分级。

### 预设角色

1. **工程风险管理员**是 MVP 的核心业务角色，可连续承担工程配置、资料接入、识别与评估运行、人工确认、受治理定义发布、预警处置、反馈校准和报告导出。
2. **系统管理员**负责账号、工程开通、基础配置、备份和运行维护；需要参与工程业务时，为同一账号另行授予工程风险管理员角色。
3. **复核人**查看指定对象并处理复核任务，可以是工程风险管理员、技术负责人或受邀专家。外部专家无需注册账号，其会议纪要、书面意见或签字文件可由工程风险管理员代录，系统保留专家身份、意见来源和录入人。
4. **现场处置人员**查看分配的处置任务并提交执行反馈。MVP 不要求现场人员登录，工程风险管理员可以代录，但必须分别记录实际执行人和系统录入人。
5. **业务查看者**在获授权工程内查看风险态势、风险闭环事实、版本信息和追溯链，并按权限导出；不能修改、确认或发布业务对象。

底层权限按业务能力控制，MVP 只提供上述预设角色，不建设任意拼装权限的角色设计器。完整产品在甲方提出明确组织差异后再扩展自定义角色模板。

### 端到端业务用例

#### 工程初始化

- 完整产品由系统管理员开通工程，工程风险管理员补充施工工法、地层条件、工程阶段、空间区段等业务信息，并选择初始工序模型、规则、矩阵和阈值版本。
- 同一账号兼任两个角色时可连续完成开通和业务配置。
- MVP 可预先创建唯一验收工程，但工程风险管理员必须能在界面检查并确认业务配置，日常业务不能依赖直接修改数据库或部署脚本。

#### 资料与监测接入

- 工程风险管理员可上传资料、填写元数据和资料权限、启动解析、查看失败原因并重新处理，不设置必须参与的独立资料管理员。
- 数据库、API 或实时监测连接的技术参数可由系统管理员配置；接入工程与业务用途由工程风险管理员确认。
- 系统分别记录资料提供方、系统录入人和连接配置人，但不要求由不同人员承担。

#### 知识、规则与矩阵治理

- 完整产品覆盖受治理定义的编制、导入、校验、版本对比、发布、停用和回滚。
- MVP 以导入甲方确认的版本化配置包为主，不建设从零设计复杂规则的通用编辑器。工程风险管理员可检查、发布或回滚版本，也可从校准建议创建新草稿、调整有限参数并显式发布。
- 同一用户可以编制并发布，不设置必须参与的独立规则管理员或强制专家审批。
- 风险评估记录始终固定引用实际使用的适用规则集、权重、风险矩阵和阈值版本。

#### 风险识别、评估与人工复核

- MVP 的风险识别、风险评估和重新评估均由工程风险管理员显式启动。资料、监测摘要、适用性元数据、适用规则集或风险矩阵变化时，系统只形成“待识别”或“待重新评估”提示并记录原因，不在后台自动运行。
- 工程风险管理员确认本次输入及版本后启动运行；每次运行生成新记录，历史记录只追加、不覆盖。
- 完整产品可按工程开启事件驱动的自动重新评估，默认仍为显式启动。
- 字段或证据不完整、低置信度、重大风险、规则冲突、处置建议校验失败、校准建议准备发布等场景进入统一复核任务。工程风险管理员可直接处理自己的待办，也可录入外部复核意见。
- 复核决定支持通过、退回修改、作废或取消，并记录理由；系统不得静默降级后继续运行。

#### 预警、处置与反馈校准

- MVP 在一次显式评估运行中命中阈值后，可以自动生成并可靠保存预警信息，但不自动向外部渠道发送消息。
- 工程风险管理员查看触发指标和证据后显式确认预警，通过系统内待办或线下方式通知现场，并登记通知结果。
- RiskFlow 输出处置建议，不把建议直接当成现场施工指令。工程风险管理员可采纳、调整或不采纳建议，并登记实际采用的处置方案。
- 现场执行后，由现场处置人员或工程风险管理员记录执行结果与监测反馈。系统分别保存系统建议、实际采用方案和实际执行结果。
- 系统依据反馈生成偏差记录和校准建议；规则、权重、阈值或分级区间是否形成新版本，必须由工程风险管理员显式确认。
- 完整产品可配置短信、企业微信等外部通知渠道，但始终遵守“预警先入库，通知后执行”；通知失败不影响预警事实。

#### 智能 Agent

- 智能 Agent 是当前登录用户的操作入口，不是独立业务角色，也不拥有独立权限或业务事实。
- 用户在 Agent 工作台明确发起识别或评估，Agent 展示将使用的工程、资料和规则版本并取得确认后执行，属于显式启动。
- Agent 只能调用当前用户有权执行的正式领域命令，不能绕过确认、复核或发布步骤。审计记录同时保存实际用户、操作入口和 Agent 运行标识。

#### 报告与审计导出

- 工程风险管理员和获授权的业务查看者可直接导出工程范围内的业务报告，无需新增审批流程；系统记录导出事件。
- 默认报告包含风险结论、P/C 分值、风险等级、触发指标、处置结果，以及所用资料、规则、权重和矩阵的版本标识。
- “附带审计证据”开关默认关闭。开启后追加审计证据包，包含获准导出的证据定位、审计事件、运行记录、模型与提示模板版本、规则计算明细和证据片段。
- 原始工程资料不属于审计证据包，是否附带原件由独立选项和资料权限控制。

### MVP 权限验收边界

- 一个账号可同时拥有系统管理员和工程风险管理员角色，并通过界面完成工程初始化、资料接入、规则发布、显式识别评估、人工复核、预警处置、反馈校准和报告导出的完整闭环。
- 实际验收流程不要求复核人、现场处置人员和业务查看者分别登录，也不验证提交人与审核人分离。
- 系统必须真实实现工程范围授权、只读限制和资料权限继承，并至少使用一个只读测试账号验证“可查看和按权限导出、不可修改或发布”。
