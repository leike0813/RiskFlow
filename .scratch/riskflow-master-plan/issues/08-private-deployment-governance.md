# 确定私有化部署与治理边界

## Question

在甲方内网私有化部署前提下，系统的身份认证、角色权限、资料分级、审计、密钥、模型与规则版本发布、备份恢复、监测数据接入和外部风险管理系统集成应采用什么责任边界与部署拓扑？

## Comments

- 用户确认：甲方主要承担出资责任，具体技术、部署与治理方案由乙方制定。甲方仍需提供合同约定的业务资料、目标内网条件与最终验收，但这些输入不转移乙方对方案完整性和可实施性的责任。
- 用户确认：MVP 只提供一台物理服务器，不配置独立备份设备；服务器内采用约三台虚拟机，分别承载推理服务、主程序和存储。该拓扑只有资源与进程隔离，不提供物理故障域隔离、高可用或灾难恢复；同机快照与副本只能用于逻辑回退，不能表述为独立备份。
- 用户确认：MVP 使用 RiskFlow 本地账号，不接 LDAP、OIDC 或甲方统一身份平台；账号由系统管理员创建、停用和重置，禁止自助注册。智能 Agent 沿用当前登录用户身份，不拥有独立账号或扩大权限。角色与工程授权继续采用“确定用户角色、权限视角与端到端业务用例”票已确认的模型。
- 用户确认：工程资料只设置“工程内共享”和“指定可见”两种访问范围，不虚构甲方尚未定义的保密等级；新上传原始资料默认“指定可见”。资料段及解析工件继承原始资料版本权限；下游业务事实按工程权限展示，证据正文和原件仍独立校验资料权限。查看与导出均写入审计。
- 用户确认：业务审计事件在 PostgreSQL 中只追加，应用角色不得更新或删除；覆盖认证、越权、资料访问与导出、业务变更、复核、发布回滚、Agent 行动、备份恢复和外部同步。MVP 不提供审计清理或自动删除，业务事实、版本和审计随项目持续保留；普通日志与链路不能替代审计。不增加同机哈希链或 WORM，并明确无法对抗宿主机或数据库最高权限恶意篡改。
- 用户确认：MVP 不部署独立 Vault/KMS。数据库密码、会话签名密钥、TLS 私钥和外部连接凭据在部署时分别生成，保存在对应虚拟机上仅运行账号可读的系统级秘密文件中，禁止进入源码、镜像、模板和日志；按最小权限加载、受控轮换并审计，不使用同机“总密钥”制造虚假安全。
- 用户确认：系统发布与业务发布分离。软件、迁移、模型、Embedding 和推理配置由系统管理员按维护发布包部署；工序模型、知识、提示模板、规则、指标、权重、矩阵、阈值和措施库由工程风险管理员显式发布，同一人可编制并发布。版本发布后不可修改，回滚形成新的生效决定；运行冻结启动时版本；Agent 无权发布、回滚或迁移。
- 用户修正恢复定位：系统实际使用概率和甲方运维能力均有限，乙方也不承担长期维护，因此不建设持续备份、定期恢复演练或生产级 RPO/RTO 体系；最多交付主机与冷备机的双机冷备，人工恢复且无自动切换。交付时应至少实际启动冷备一次验证可用，之后不要求周期性演练。
- 用户最终确认：冷备不是 MVP 必选交付物，只作为后续可选项。若采购冷备，冷备机只恢复到最近一次人工同步状态，不做自动或定期同步；仅在该选项交付时启动验证一次。

## Answer

### 交付定位与责任边界

- 甲方主要承担出资责任，并提供合同约定的业务资料、目标内网条件和最终验收；具体技术、部署、安全与治理方案由乙方制定，方案完整性和可实施性不转移给甲方。
- RiskFlow 按低频使用、项目验收型私有系统交付，不按持续在线的生产关键系统设计。乙方交付可运行系统、离线制品、配置清单和操作手册，但不承诺长期代运维、持续升级或可用性服务等级。
- 系统仍须真实实现权限、审计、版本、追溯和人工复核；低使用概率不能作为省略业务闭环或以 Demo 代替系统的理由。

### 必选部署拓扑

- MVP 必选基线是一台位于甲方内网的物理服务器，在同一物理故障域内运行三台虚拟机：
  1. **推理虚拟机**：GPU 直通，运行 `llama.cpp`、模型文件及其受控模型服务；
  2. **应用虚拟机**：运行 Web、API、LangGraph Worker、反向代理和必要的解析进程；
  3. **数据虚拟机**：运行 PostgreSQL、Qdrant 和本地不可变工件目录。
- 内网用户只访问应用虚拟机暴露的 HTTPS 入口；数据库、Qdrant 和推理端口只在虚拟机内部网络开放，管理入口与普通业务入口分离。运行时默认不依赖公网，升级使用冻结版本的离线制品包。
- 三台虚拟机用于资源、进程和权限隔离，不提供物理故障隔离、自动故障切换或高可用。宿主机、磁盘阵列或机房整体故障可能导致系统和数据同时不可用或丢失。

### 冷备与恢复边界

- 独立冷备机不是 MVP 必选交付物，只作为后续单独采购的可选项；MVP 不承诺独立备份、生产级 RPO/RTO、自动切换或周期性恢复演练。
- 如采购冷备，冷备机保存一次完整部署与数据副本，平时不参与服务；数据通过人工全量同步更新，主机故障时人工启动。它只保证恢复到最近一次人工同步状态，之后产生的数据可能丢失。
- 冷备选项交付时实际启动验证一次，证明应用、模型、配置和同步数据可运行；此后不要求定期演练。主机内虚拟机快照或同机副本只用于部署和升级回退，不表述为独立备份。

### 身份、角色与资料访问

- MVP 使用 RiskFlow 本地账号，不接 LDAP、OIDC 或甲方统一身份平台。账号由系统管理员创建、停用和重置，禁止自助注册；密码只保存强哈希，会话支持超时和强制失效。
- 继续采用已确定的预设角色和工程授权：系统管理员权限与工程业务权限分离，同一账号可兼任；工程风险管理员、复核人、现场处置人员和业务查看者按工程获得能力。智能 Agent 沿用当前登录用户身份，不拥有独立账号或扩大权限。
- 有效权限是“角色能力、工程成员授权、资料访问范围”的交集。工程资料只设“工程内共享”和“指定可见”两种访问范围，新上传原始资料默认“指定可见”；不虚构甲方尚未定义的保密等级。
- 资料段、OCR 结果、JSON-LD 和其他解析工件继承原始资料版本的访问范围。下游风险、评估、预警和处置事实按工程业务权限展示；无原件权限者可以看到结论和证据定位，但不能打开证据正文或导出原件。

### 审计与秘密管理

- 业务审计事件在 PostgreSQL 中只追加，应用角色不得更新或删除。审计覆盖认证与失败、越权拦截、资料查看与导出、业务变更、人工复核、版本发布与回滚、Agent 工具行动、恢复操作和外部同步。
- MVP 不提供审计清理界面或自动删除；业务事实、历史版本与审计随项目保留。Pino 日志、指标和链路追踪只用于运维，不能替代业务审计。
- 不增加同机哈希链或 WORM。系统保证普通应用用户不能经产品能力改写审计，但不声称能够对抗宿主机或数据库最高权限的恶意篡改。
- MVP 不部署独立 Vault/KMS。数据库密码、会话签名密钥、TLS 私钥和外部连接凭据在部署时分别生成，保存在对应虚拟机上仅运行账号可读的系统级秘密文件中，禁止进入源码、镜像、模板和日志；凭据按最小权限加载，轮换与失效操作留痕，不使用同机“总密钥”。

### 系统发布与业务发布

- 软件、数据库迁移、模型文件、Embedding 和推理配置属于系统级发布包，由系统管理员在维护操作中部署；发布包记录精确版本、哈希、兼容关系、迁移步骤、验证步骤和可用的回退路径。
- 工序模型、知识库、提示模板、规则、指标、权重、风险矩阵、阈值和措施库属于业务定义，由工程风险管理员在界面校验、比较并显式发布。同一人可以编制和发布，不设置强制双人审批。
- 发布后的版本不可修改；回滚是重新指定既有版本为当前生效版本，并形成新的发布决定和审计记录。已经开始的运行继续使用启动时冻结的版本，历史运行不被发布或回滚改写。
- 智能 Agent 可以形成草稿、候选或校准建议，但不能执行发布、回滚或数据库迁移。

### 监测数据与外部系统

- MVP 只依赖统一数据接入模块导入 XLSX/CSV 等批次监测数据，并保证应用内通知；甲方风险管理系统、数据库、HTTP API、实时监测流、外部通知渠道和 MCP 均不是 MVP 运行依赖，也不建设无真实对象支撑的空连接器。
- 完整产品在具体连接对象、样例和认证条件明确后，通过提供方无关的适配器和版本化集成消息扩展。外部系统只提供受控输入或接收 RiskFlow 已可靠保存的结果，不能共享数据库或直接覆盖 RiskFlow 事实。
- 外部连接使用“工程权限、来源授权、集成策略”的交集；连接凭据不能扩大用户或 Agent 权限。预警和其它结果先可靠入库，再创建通知或同步任务；外部失败不回滚内部事实。

### 验收与移交

- MVP 验收在主服务器上完成离线启动、账号与权限、资料接入、识别评估闭环、审计追溯和冻结版本发布包验证。交付物包含虚拟机与网络拓扑、端口清单、离线制品与哈希、秘密项清单、版本清单以及启动、停止、升级、回退和常见故障操作手册。
- 冷备只有在后续选购时才进入交付与验收；未选购时不得在报告或验收材料中宣称系统具备双机冷备、灾难恢复或高可用能力。
