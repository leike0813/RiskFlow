# module-interfaces-events-workflows Specification

## Purpose

为 RiskFlow 六个领域模块及应用模块提供闭合、版本化、可运行时校验的跨模块调用、领域事件和有限工作流契约，使后续实现保持事实所有权、权限、幂等、追溯与暂停恢复语义一致。

## Requirements
### Requirement: 六个领域模块只暴露用例级 interface

系统 MUST 为工程数据、知识建模、风险识别、风险评估、预警处置、复核审计六个领域模块提供少量用例级命令或查询分支。每个分支 MUST 是闭合的可辨识联合类型，输入输出只含调用所需的身份、精确版本、授权上下文、幂等身份和结果引用；不得暴露通用 `execute`、任意仓储/查询器、SQL、文件、URL、JSON Patch 或自由字段袋。工程数据 MUST 以独立的 `StructuredDocumentConversionPortV1` 暴露结构化文档转换，保持既有 `EngineeringDataPortV1` 分支与签名不变，并以共享 strict Schema 表达 DOCX、文本型 PDF、XLSX、CSV 与 OCR 版面结果输入，使 C12 和 C13 复用同一结构化块、坐标、资料段与失败诊断契约。六个模块的事实归属固定，一个模块不得通过 interface 修改另一个模块拥有的事实。（RI-S1～RI-S6；RA-S1～RA-S7）

#### Scenario: 调用所属模块完成用例
- **WHEN** 调用方提交一个已声明的模块命令或查询分支，并提供合法授权上下文与精确输入引用
- **THEN** interface 返回该分支声明的类型化结果引用或类型化错误
- **AND** 调用方无需了解事务、重试、持久化或第三方协议

#### Scenario: 结构化转换使用独立共享端口
- **WHEN** C12 转换结构化文档或 C13 规范化 OCR 版面结果
- **THEN** 两者调用 `StructuredDocumentConversionPortV1` 并返回相同契约定义的转换、工件、资料段或诊断引用
- **AND** 既有 `EngineeringDataPortV1` 的命令和查询分支保持不变

#### Scenario: 拒绝开放式调用
- **WHEN** 调用方尝试提交未声明的动作、任意对象补丁、存储查询或契约外字段
- **THEN** 运行时 Schema 拒绝该输入
- **AND** 不把未知字段透传给领域实现

#### Scenario: 评估不复制识别事实
- **WHEN** 风险评估模块接收识别产生的风险输入
- **THEN** 输入只引用标准化风险记录的身份与精确版本
- **AND** 不复制或改写风险事件、证据或模型置信度正文

#### Scenario: 六个领域模块的事实归属
- **WHEN** 任一模块通过 interface 读取或写入跨模块数据
- **THEN** 工程数据拥有工程资料、资料段、监测与适用性快照；知识建模拥有工序模型、风险机理、检索证据、评估知识与措施的受治理版本；风险识别拥有候选/合并工件、标准化风险记录和关联事实；风险评估拥有评估快照、指标结果和风险评估记录；预警处置拥有预警、处置、预测、反馈、偏差与校准建议；复核审计拥有复核任务、类型化决定和只追加审计
- **AND** 一个模块不得通过 interface 修改另一个模块拥有的事实

### Requirement: 应用模块只能组合领域 interface

系统 MUST 为 Agent 任务、LangGraph 工作流、查询与交付投影提供独立应用 interface。Agent 任务只管理有界任务与任务产物引用；LangGraph 只管理有限运行、阶段、检查点关联和路由；查询与交付投影只组合已成立事实的只读引用。应用模块 MUST 依赖领域模块公开 interface，领域模块不得反向依赖应用模块、应用、适配器或 LangGraph。

#### Scenario: 工作流通过公开 interface 编排
- **WHEN** 工作流推进识别、评估、预警或处置阶段
- **THEN** 它只提交已声明的领域命令或查询并保存返回引用
- **AND** 不直接读取数据库、Qdrant、文件工件或模块内部结构

#### Scenario: 查询投影不成为事实源
- **WHEN** 查询投影被删除后重建或返回组合视图
- **THEN** 所有业务事实仍由六个领域模块拥有
- **AND** 投影不能反向写回任何领域对象

#### Scenario: Agent 不能越权写事实
- **WHEN** Agent 任务产生任务类型化候选或命令提案
- **THEN** 正式写入仍调用原领域 interface 并重新执行其权限与确定性校验
- **AND** Agent 任务引用不能代替正式业务结果引用

### Requirement: 命令、结果和错误具有稳定幂等语义

写命令 MUST 通过稳定业务幂等键避免重复效果，并以类型化结果表达成功、等待、冲突或失败；同键相同业务载荷返回原结果，同键不同业务载荷保留冲突语义。访问时间、当前授权记录及临时调用编号不得改变业务内容身份。仅返回已有对象的查询 MUST 使用只读语义并追加访问记录；会物化正式查询结果的操作仍按稳定业务输入去重。错误按稳定代码和结构路由。

#### Scenario: 重复命令返回原结果

- **WHEN** 调用方以相同作用域、命令类型、幂等键和有效载荷重试已完成命令
- **THEN** 模块返回原业务结果引用
- **AND** 不重复写事实、审计、事务事件或外部意图

#### Scenario: 同键不同载荷冲突

- **WHEN** 调用方复用同一幂等键提交不同的类型化载荷
- **THEN** 模块返回幂等冲突错误
- **AND** 保留原命令与结果不变

#### Scenario: 陈旧版本提交被拒绝

- **WHEN** 命令目标的精确版本已被取代、作废或不再可决定
- **THEN** 模块返回类型化陈旧版本或并发冲突
- **AND** 不把提交静默应用到当前版本

#### Scenario: 双击提交不重复效果

- **WHEN** 同一有效写命令重复提交
- **THEN** 只产生一份业务结果及其事务审计和事件

#### Scenario: 普通查询不占用命令去重键

- **WHEN** 用户多次查看已有对象
- **THEN** 每次独立返回当前可见结果，不创建业务完成回执或载荷冲突

### Requirement: 已入库事实通过事务领域事件衔接

系统 MUST 使用版本化事务领域事件表达已可靠成立的跨阶段事实。事件信封 MUST 固定事件身份、事件类型、契约版本、工程、聚合身份与版本、业务发生时间、系统记录时间、因果/关联运行、生产命令和业务幂等键；事件载荷只包含下游所需的精确事实引用和原因，不复制完整业务记录。业务事实、审计和待发布事件 MUST 原子提交；事件至少一次投递时，消费者 MUST 幂等处理。

事件至少覆盖：资料输入已就绪、标准化风险记录已验收入库、评估输入变化、受治理识别知识基础已发布、受治理评估版本已发布、风险评估记录已入库、预警信息已入库、处置反馈已记录、校准建议已创建、复核已请求和复核已解决。（RI-S14、RI-S53～RI-S56、RI-S62～RI-S65；RA-S4～RA-S7）

#### Scenario: 风险记录事件启动评估候选
- **WHEN** 标准化风险记录通过 RI-S61 完整性检查并与事务事件原子入库
- **THEN** 评估消费者只使用风险记录身份与精确版本创建评估候选
- **AND** 不从事件载荷复制风险事件定义

#### Scenario: 识别知识基础发布事件只携带精确引用
- **WHEN** `retrieval-evidence-base` 经 C16 发布或历史版本重新发布，并形成覆盖 `process-model`、`risk-mechanism`、`standard-library`、`case-library`、`retrieval-evidence-base` 的完整唯一识别知识发布集合
- **THEN** 系统在同一发布事务中产生 `knowledge.identification-basis-published.v1`，以事件信封固定工程、聚合、审计、命令、幂等和版本，并在载荷中固定五类定义及其精确 `KnowledgeReleaseRefV1` 和精确 `RetrievalEvidenceBaseReleaseRefV1`
- **AND** 事件不包含知识正文、证据正文、检索片段、模型响应或契约外自由字段

#### Scenario: 事件发布失败不伪装成功
- **WHEN** 业务事务无法同时保存事实、审计和待发布事件
- **THEN** 整个业务提交失败或回滚
- **AND** 不留下下游不可追踪的孤立事实

#### Scenario: 重复投递不重复产生事实
- **WHEN** 同一事件因至少一次投递语义被重复消费
- **THEN** 消费者以事件身份和业务幂等键返回原处理结果
- **AND** 不重复创建评估、预警、处置任务、索引代际或通知意图

### Requirement: 识别工作流具有 I0 至 I9 的版本化阶段契约

系统 MUST 以 `I0`～`I9` 闭合阶段表示一次有限识别运行：I0 资料准备与输入冻结，I1 知识就绪，I2 工序工作项规划，I3 混合/关系检索与必经 Agent 审阅，I4 五项上下文组装与 RI-S57 专用 LLM 推理，I5 有界结构修复与确定性校验，I6 全运行重复检测与多来源合并，I7 综合置信度与验收路由，I8 业务入库与评估事件，I9 结果汇总。

每阶段 DTO MUST 只携带精确快照、工作项、候选集、正式零结果、Agent 任务、合并计划、复核任务、业务结果、路由、错误或汇总引用。I0 MUST 以非空 `sourceVersionRefs` 与非空 `includedSourceSegmentSetRefs` 冻结资料输入，两数组 MUST 等长并按相同索引一一对应；一次识别运行 MUST 以单个 `IdentificationInputSnapshotV1.preparationSnapshotRef` 引用该聚合准备快照。I0～I9 MUST 完整追踪 RI-S1～RI-S6；任一技术错误不得伪装成业务复核或正式零结果。（RI-S1～RI-S6）

#### Scenario: 识别正常完成

- **WHEN** 冻结输入与知识版本兼容，全部必经 Agent/LLM 和确定性校验完成，且所有合并组均达到终态
- **THEN** 运行依次形成 I0～I9 的阶段结果引用并返回识别汇总
- **AND** 每个已验收合并组只产生一个标准化风险记录版本及评估事件

#### Scenario: 多资料版本形成单个可重放准备快照

- **WHEN** I0 为多个精确资料版本冻结输入，且每个版本都有一个属于该版本的不可变资料段集合引用
- **THEN** `IdentificationPreparationSnapshotV1` 按相同索引保存等长的 `sourceVersionRefs` 与 `includedSourceSegmentSetRefs`
- **AND** I1 仍通过单个 `preparationSnapshotRef` 冻结整组准备结果

#### Scenario: 拒绝不完整或错配的资料段集合引用

- **WHEN** `includedSourceSegmentSetRefs` 为空、与 `sourceVersionRefs` 数量不同，或任一资料段集合不属于相同索引的精确资料版本
- **THEN** I0 在形成准备快照前返回类型化校验失败
- **AND** 不创建有损准备快照或为各资料版本拆分准备快照

#### Scenario: 知识未就绪时暂停

- **WHEN** I1 发现发布版本缺失、停用或与冻结输入不兼容
- **THEN** 运行保存知识准备任务与复核引用并进入等待
- **AND** 恢复时重新校验精确版本，不自动切换到“最新版”

#### Scenario: 争议合并组不阻塞其它组

- **WHEN** I6/I7 中一个合并组等待复核而其它合并组通过全部约束
- **THEN** I8 可以幂等入库其它合格组
- **AND** 运行在 I9 汇总中明确区分已验收、等待复核、拒绝、跳过和失败

#### Scenario: 必经检索审阅失败不降级

- **WHEN** I3 的检索审阅 Agent 预算耗尽或重试耗尽
- **THEN** 相应工作项进入类型化失败
- **AND** 不以基线检索冒充最终检索继续 I4

#### Scenario: I4 返回正式零结果引用

- **WHEN** RI-S57 专用推理返回合法零候选且 C22 已正式登记对应事实
- **THEN** 分析端口返回独立的零结果成功分支，I4 阶段结果只保存该精确零结果引用而不伪造候选集引用
- **AND** 工作流状态、恢复与 I9 汇总均能从该引用回到授权范围内的原始推理证据

#### Scenario: 识别分析结果区分候选成功与正式零结果终态
- **WHEN** 识别分析端口返回非空候选成功或正式零结果终态
- **THEN** 结果 MUST 用闭合联合区分两种终态，不用空候选集表达零结果

### Requirement: 评估工作流具有 A0 至 A9 的版本化阶段契约

系统 MUST 以 `A0`～`A9` 闭合阶段表示一次有限评估运行：A0 输入准备，A1 知识就绪，A2 输入冻结，A3 指标取值，A4 确定性评分与触发判定，A5 评估入库，A6 预警入库与任务归集，A7 处置建议候选，A8 三项约束校验与建议入库，A9 结果汇总。处置效果预测和处置反馈 MUST 作为使用同一图契约的独立有限入口，不跨越数日等待现场动作。

A0～A9 MUST 完整追踪 RA-S1～RA-S7。A3～A6 不创建必经 Agent 任务；P/C、矩阵、四类触发、三项处置约束与业务入库 MUST 由领域模块确定性完成。预警和处置只能在已入库风险评估记录之后推进。（RA-S1～RA-S7）

#### Scenario: 无预警的确定性评估完成
- **WHEN** A3/A4 产生完整 P/C、风险等级和空触发指标集合
- **THEN** A5 原子保存完整风险评估记录并直接进入 A9
- **AND** 不创建预警、处置任务或 Agent 任务

#### Scenario: 预警先入库再通知
- **WHEN** A4 命中一个或多个触发类型
- **THEN** A5 先保存包含触发指标的评估记录，A6 再幂等保存预警与处置任务关联
- **AND** 只有预警可靠入库后才安排通知意图

#### Scenario: 处置候选不能越过三项校验
- **WHEN** A7 形成处置建议候选但 A8 任一确定性约束失败
- **THEN** 候选保持为运行工件并创建复核任务
- **AND** 任何人工决定都不能把失败结果强制标记为正式处置建议

#### Scenario: 反馈运行不自动校准
- **WHEN** 独立反馈入口形成偏差记录且超过冻结阈值
- **THEN** 系统创建有界校准建议 Agent 任务及待审核建议引用
- **AND** 不覆盖当前规则、权重、阈值、区间或矩阵版本

### Requirement: 图状态只保存小型版本化引用

识别、评估和顶层图状态 MUST 由 Zod Schema 定义并派生 TypeScript 类型，固定 schema/graph 版本、运行与线程、触发/入口模式、授权主体引用、阶段、有限状态、快照/工件/业务结果/Agent/复核/路由/错误引用及因果关系。图状态 MUST 拒绝原始文档、完整 JSON-LD、监测序列、完整检索片段、模型响应、业务记录正文、规则正文、建议正文、通用对象袋和模型内部思维链。

#### Scenario: 小型引用状态通过校验
- **WHEN** 状态只包含声明的标识、版本引用、枚举状态、阶段与结果引用
- **THEN** 对应图状态 Schema 接受该对象

#### Scenario: 大对象不能进入检查点
- **WHEN** 调用方把标准化风险记录正文、风险评估记录正文、检索片段或任意未知对象加入图状态
- **THEN** strict Schema 拒绝该状态
- **AND** 调用方必须先把内容交给事实所属模块或工件存储并取得引用

#### Scenario: 检查点不替代业务事实
- **WHEN** 检查点存在但其引用的业务提交不存在
- **THEN** 恢复流程返回结构化不一致错误
- **AND** 不从检查点内容伪造业务记录

### Requirement: 暂停、恢复、重试和取消保持业务事实完整

工作流运行 MUST 使用闭合有限状态表达待运行、运行中、等待、可重试失败、已完成、终止失败和已取消，并用类型化等待原因区分知识准备、人工复核和交互确认。恢复 MUST 沿用原线程、冻结输入、策略、模型、提示模板和业务幂等键；需要更换任一冻结版本时 MUST 创建新运行。取消只停止未开始或可协作终止的工作，不回滚已可靠成立的事实、决定、审计或事务事件。

#### Scenario: 人工复核后幂等恢复
- **WHEN** 复核模块保存指向精确目标版本的类型化决定并发布复核已解决事件
- **THEN** 原线程从等待点恢复并复用已完成工件
- **AND** 不重复调用已完成模型步骤或重复入库

#### Scenario: 技术故障按原策略重试
- **WHEN** 可重试技术错误发生且冻结重试策略仍有预算
- **THEN** 运行在原工作项和原业务幂等键下重试
- **AND** 不切换模型、知识、工具、预算或输入版本

#### Scenario: 取消保留已入库事实
- **WHEN** 用户取消仍在运行的识别或评估流程
- **THEN** 未开始的工作被停止并生成取消汇总
- **AND** 已入库风险、评估、预警、决定和审计仍可追溯

### Requirement: Agent 与人工复核使用不同引用和决定边界

系统 MUST 使用不同的版本化引用表示 Agent 任务与人工复核任务。Agent 任务引用 MUST 固定任务类型、触发方式、冻结策略和任务版本；复核任务引用 MUST 固定复核类型、目标对象与目标精确版本。Agent 结果只能是任务专属增量、候选、校验、命令提案或正式结果引用，不能成为人工决定；复核决定 MUST 是闭合、类型化联合，不能使用通用补丁或整对象覆盖。

#### Scenario: Agent 候选进入确定性收口
- **WHEN** 必经 Agent 任务完成并返回任务专属增量引用
- **THEN** 所属领域模块校验并逐项记录接受或拒绝
- **AND** Agent 无权直接发布、批准、采纳、作废或回滚事实

#### Scenario: 复核决定针对精确版本

- **WHEN** 正式冻结输入经 C25 得到完整评估记录且触发集合为空
- **THEN** 评估运行保存记录和阶段/汇总引用并完成
- **AND** 不创建预警、处置建议或必经 Agent 任务

#### Scenario: 有预警时依次形成处置链
- **WHEN** 已入库评估记录包含一个或多个触发事实
- **THEN** 运行先取得持久化预警与任务引用，再以冻结候选和正式处置结果推进汇总
- **AND** 处置候选任一约束失败时只保留候选和复核/失败引用，不成为正式建议

#### Scenario: 重评估与历史补算保留旧结论
- **WHEN** 显式监测、适用性或评估依据变化触发重评，或以历史业务时点和精确适用性/依据补算
- **THEN** 系统建立新的冻结输入与评估记录，关联前次记录或历史时点
- **AND** 原记录及其 P/C、等级、预警和审计不被覆盖

#### Scenario: 反馈越限只形成校准候选
- **WHEN** 独立反馈入口取得执行后实际评估、正式反馈与偏差，且偏差超过冻结阈值
- **THEN** 系统驱动有界校准建议任务并保留待人工审核的精确引用
- **AND** 不自动发布或覆盖权重、阈值、区间、矩阵或人工决定

交付归属：从合法人工决定、执行后评估到正式反馈的成功路径由后续 C41 承接；C30 已成立反馈引用之后的偏差与待审校准切片可独立核验，不代表该入口成功路径已闭合。

### Requirement: 工作流生命周期以耐久业务事实和冻结身份收口

系统 MUST 以公共 `startRun`、`resumeRun`、`cancelRun` 语义只追加记录父子运行身份、输入快照、阶段、路由、等待、错误、汇总、审计与回执；LangGraph 检查点只保存公共小型引用，不代替业务事实。恢复与重试 MUST 使用原线程、输入、图版本、策略、模型/提示、预算和业务幂等身份；同键异载荷或预期状态版本陈旧 MUST 拒绝。取消只停止未开始或可协作终止的动作，不撤销已成立事实。运行进入等待态时，`startRun` MUST 在返回真实运行引用的同时交出该运行**停在等待点时的运行状态版本**，使调用方能以同一版本恢复；不得以登记身份或最新版本代替该值，也不得为取得该值额外发起未受控读取。（RI-S1～RI-S6；RA-S1～RA-S7）

系统 MUST 以**授权覆盖**而非上下文摘要等值判定运行只读证明的准入：调用方上下文的空间范围与来源授权 MUST 覆盖该运行已登记事实的范围，才承认这些登记行；跨工程、范围不足或来源授权缺失 MUST 拒绝，判定失败与事实缺失同型。写入登记行时仍 MUST 记录当时的授权范围摘要供审计与追溯。

#### Scenario: 等待决定后以原运行恢复
- **WHEN** 精确复核或 Agent 任务完成，且运行仍等待该引用、当前授权有效
- **THEN** 原线程继续并复用已提交阶段结果
- **AND** 不重复模型调用、正式写入、审计或事务事件

#### Scenario: 检查点与业务事实不一致
- **WHEN** 检查点引用不存在的业务提交，或业务提交领先检查点且无法由已登记事实证明
- **THEN** 恢复返回稳定不一致错误并保留已提交事实
- **AND** 不从检查点伪造记录、不猜测最新状态或补写无依据结果

#### Scenario: 取消和技术失败保留追溯
- **WHEN** 父运行或子运行在部分领域事实提交后取消，或在冻结预算内遇到瞬态失败
- **THEN** 已提交事实、审计、事件及父子关联保持可查询，未开始动作被停止或以原身份重试
- **AND** 权限、版本和业务规则冲突不通过自动重试绕过

#### Scenario: 按收窄上下文证明更宽范围启动的运行
- **WHEN** 获授权调用方持有覆盖该运行空间范围与来源授权的上下文，按精确运行引用请求只读证明
- **THEN** 证明按该运行已登记事实返回，不再要求调用方上下文与写入时的上下文逐字相同
- **AND** 证明结果中的工程、运行与评估记录引用仍逐字来自该精确运行

#### Scenario: 范围不足时仍然拒绝
- **WHEN** 调用方上下文的空间范围或来源授权不覆盖该运行已登记事实的范围
- **THEN** 证明以稳定失败关闭，不返回部分运行事实、不枚举目标是否存在
- **AND** 跨工程请求与事实缺失表现相同

#### Scenario: 写入侧授权摘要仍被审计保留
- **WHEN** 某条运行登记行在特定授权上下文下写入
- **THEN** 该行保存当时的授权范围摘要，可回答「这份事实是在哪份授权下形成的」
- **AND** 该摘要不参与后续读取的准入判定

#### Scenario: 以陈旧等待点版本恢复被拒绝
- **WHEN** 调用方以不属于该运行当前状态的版本发起恢复
- **THEN** 恢复以稳定的版本冲突失败，不推进任何阶段、不改按当前最新版本继续
- **AND** 已成立事实、审计与事务事件保持不变

#### Scenario: 等待结果交出可恢复的等待点状态版本
- **WHEN** 获授权调用方启动有限入口且运行停在等待点
- **THEN** 结果同时给出等待引用、真实运行引用与该等待点的运行状态版本
- **AND** 同一命令身份重试取得同一等待点版本，不重新读取或推进运行

### Requirement: C30 自有运行与追踪投影有界且只读

系统 MUST 为获权调用方提供 C30 运行视图和链路追踪视图，按当前工程、空间、资料权限和精确版本组合父子运行、识别、评估、预警、建议、偏差与校准的公开事实引用、阶段状态、审计引用及允许披露的证据定位。投影 MUST 可由已成立事实重建，且不得反写领域对象、复制领域正文或直接读取其它模块私有表；投影记录和受保护读取 MUST 使用最小权限与只追加审计。（RI-S1～RI-S6；RA-S1～RA-S7）

#### Scenario: 已授权调用方查询历史运行
- **WHEN** 调用方按精确父运行或链路目标查询并具备对应工程、空间、资料读取权限
- **THEN** 投影返回版本化父子运行、结论与审计引用，以及其获准的定位或脱敏摘要
- **AND** 后续领域版本发布或投影重建不改变历史链指向

#### Scenario: 无权或跨工程读取不可枚举
- **WHEN** 调用方无权限、目标跨工程/空间或来源资料不可见
- **THEN** 投影在披露目标或证据前安全拒绝或仅返回获准的最小视图
- **AND** 错误、订阅事件和普通日志不暴露受限目标存在性或正文

#### Scenario: 精确结果引用可读取有界内容
- **WHEN** 获权调用方按精确查询结果或风险记录引用请求页面与链路内容
- **THEN** 独立只读接缝返回有界、分页的版本化摘要及获准证据定位
- **AND** 原查询端口签名保持不变，读取不造成跨模块 N+1、全库投影或领域事实反写

### Requirement: 端到端链路可以按精确引用重放

系统 MUST 使每条完整路径从资料段标识、工序节点、风险机理条目、标准化风险记录、评估记录、预警、处置建议至偏差/校准建议均可用领域事实引用、冻结版本、运行阶段、审计与事件证据核验；分支未触发或正式事实尚未成立时 MUST 明示缺席原因，不得补造占位事实。可重复的验收命令 MUST 在真实持久化和公开端口下证明路径、幂等及失败收口。（RI-S1～RI-S6；RA-S1～RA-S7）

#### Scenario: 完整链路具有耐久证据
- **WHEN** 合成样本、待甲方复核的识别记录和甲方已审核或明确标注版本的评估依据完成预警、建议及反馈/校准路径
- **THEN** 验收可逐跳读取精确引用、证据定位、冻结规则/权重/矩阵版本、决定、审计和事件
- **AND** 同一输入重放不增加正式事实或改变 P/C 与等级

交付归属：真实 C24→C30 同容器链路依赖 C40；人工决定及正式反馈命令成功链路依赖 C41。C30 分段验收与缺席链尾证据不能替代这两段，完整端到端通过结论由后续 change 承接。

#### Scenario: 无触发和失败路径不伪造链尾
- **WHEN** 评估无预警、建议三项校验失败、偏差不可计算或必经 Agent 失败
- **THEN** 追踪结果保留最后成立的事实及类型化原因
- **AND** 不把缺席链尾展示成已产生的预警、建议、偏差或校准结果

### Requirement: C31 工序风险关联图按已成立的精确链边呈现

系统 MUST 使获权调用方以精确主题引用查询工序风险关联图，并分页取得同一工程、同一授权范围内已成立的工序、机理、风险记录、评估、预警、建议及后续反馈关系。节点身份 MUST 来自版本化事实引用，边 MUST 带关系、阶段/审计引用及当前允许披露的证据定位；关系不能被证明时 MUST 明确失败或标注缺席原因，不得补造边、风险等级或领域正文。（RI-S3～RI-S6；RA-S1～RA-S7）

#### Scenario: 获权主题返回可追踪关联图
- **WHEN** 调用方持有当前工程、空间、资料读取权限，并以精确风险记录引用查询已有跨阶段关系
- **THEN** 返回的每条边均指向已成立的版本化事实，包含可核验的关系及审计引用
- **AND** 资料段、工序、机理、风险、评估及后续已成立关系可沿获准引用追踪，不暴露领域正文

#### Scenario: 未触发或未能证明的分支
- **WHEN** 主题所在运行尚未产生预警、建议或反馈，或某条关系的来源资格无法证明
- **THEN** 结果仅呈现最后成立的事实及其已登记缺席原因，或者以稳定的不完整失败收口
- **AND** 不把空链尾、猜测的图节点或推断等级当作正式结果

### Requirement: C31 工程风险总览和报告投影可由同一事实重放

系统 MUST 接受精确工程修订和可选空间范围，以只读方式提供有界的风险总览/报告投影。每项 MUST 由已成立的运行、标准化风险记录、评估及后续结果引用组成，并保留可获准的证据、版本与审计引用；聚合值只能从实际披露的事实计算，不能用链边代替评估记录的 P/C、等级或预警判定。投影 MUST 可在历史时点和原版本组合下重建，不反写领域事实。（RI-S6；RA-S5～RA-S7）

#### Scenario: 同一修订生成一致报告
- **WHEN** 同一调用方按同一工程修订、空间、授权范围与查询结果引用重复读取报告页面
- **THEN** 返回稳定排序的事实引用、已成立结论与可核验审计/证据引用
- **AND** 后续领域发布不改变原查询所指向的历史版本

#### Scenario: 结果缺失或依据不足
- **WHEN** 修订下尚无已成立风险，或风险存在但评估/预警/反馈尚未成立
- **THEN** 返回真实的空结果或最后成立的结果及明确缺席原因
- **AND** 不生成占位评估、预警、处置或所谓默认风险等级

### Requirement: C31 投影读取保持当前权限、有限读取与既有端口兼容

系统 MUST 通过既有查询登记和有界读取接口交付关联图、总览与报告，保留精确查询引用、登记时点、业务范围和稳定分页。已有查询读取 MUST 从登记事实解析资源范围，检查当前权限，不要求当前完整授权摘要与历史摘要相等。游标 MUST 绑定精确查询及其冻结范围，不能绑定调用方不断变化的完整权限。报告内部读取复用同次业务决定；独立分页请求重新检查当前权限。跨工程、无权或未知类型 MUST 明确失败，不扩大披露范围或反写领域事实。

#### Scenario: 历史查询在撤权后不可继续读取

- **WHEN** 调用方失去原查询所需工程、空间或资料权限
- **THEN** 后续请求不披露目标或证据

#### Scenario: 无关授权变化不阻断读取

- **WHEN** 查询所需来源仍有权，但当前完整授权集合与登记时不同
- **THEN** 原查询及报告可读取，冻结范围与已导出正文不被重写

#### Scenario: 有界分页和伪游标

- **WHEN** 查询超过一页，或收到错查询、错范围及非法位置游标
- **THEN** 合法游标取得稳定下一页，非法游标被拒绝，不全库展开或返回部分成功报告

#### Scenario: 旧分支和未知分支

- **WHEN** 使用原运行、追溯分支或未知查询类型
- **THEN** 原业务结果形状保持，未知类型明确失败

### Requirement: C30 加法式证明决定所需的真实路由与运行

系统 MUST 由工作流所有者提供独立、strict 且有界的只读证明，按工程和精确正式建议引用读取已经登记的路由决定、预测运行、空间及冻结输入身份。读取只允许使用既有 C30 持久运行事实，必须核对引用、正文、运行状态和摘要一致；不得从当前最新状态、客户端字段、任意图检查点或其它工程合成绑定。现有 `WorkflowPortV1` 写命令和 `ProjectionPortV1` 查询结果保持原样，新增只读证明不得写入 C30 或 C28 事实。（RA-S7）

#### Scenario: 精确正式建议取得真实决定绑定
- **WHEN** 获授权调用方针对同工程、同空间的正式建议精确版本读取已登记决定路由与预测运行
- **THEN** C30 返回匹配该建议的路由决定、运行、空间、版本和审计引用
- **AND** C28 可据此对账人工决定命令，不需要调用方伪造运行身份

#### Scenario: 事实缺失、越权或内容不一致时失败关闭
- **WHEN** 目标路由或运行尚未成立、跨工程或空间、当前授权不足，或持久引用与正文/运行状态不一致
- **THEN** C30 返回安全的类型化失败，不披露目标存在性或内部正文
- **AND** 不创建路由、运行或默认引用来满足读取

### Requirement: C30 预测运行允许人工采纳前等待

系统 MUST 允许 C41 通过公共 `WorkflowPortV1.startRun` 以精确正式建议和决定幂等身份创建真实的 `forecast-response` 运行，并在人工采纳事实形成之前停留在等待态；此时不得执行预测、形成正式效果预测或自动提交采纳。重复的同一命令身份 MUST 返回同一运行引用，采纳成立后才按既有触发语义继续。若现有入口需要表达等待意图，只允许增加不改变原有调用方默认语义的可选闭合参数。（RA-S7）

#### Scenario: 采纳前等待与幂等重放
- **WHEN** C41 针对同一工程、正式建议和决定幂等身份调用 `startRun`，随后在 C28 决定提交前重试
- **THEN** C30 返回同一精确运行引用，并保持等待、不执行效果预测
- **AND** C41 可在采纳事实成立后通过既有恢复语义推进该运行

### Requirement: C32 查询结果再读取必须有界且复验当前授权

系统 MUST 为 engineering-data 已登记查询提供只读结果再读取：调用方提交精确 `queryResultRef`，服务端按登记时的授权摘要复验当前调用方授权，仅对 `source-segments` 返回段集正文与来源访问授权引用，仅对 `evidence-access` 返回有界证据条目（证据引用、来源版本引用、段集引用、访问授权引用与获准段正文），仅对 `monitoring-snapshot` 返回该快照的监测结果。再读取 MUST 复用拥有方既有校验实现，不重新执行查询、不产生新业务事实、不返回登记范围之外的条目；引用不存在、查询类型不符、授权摘要漂移或当前调用方越权时 MUST 返回同形安全失败，不披露目标存在性。（RI-S1～RI-S2；RA-S1）

#### Scenario: 授权一致时返回登记范围内的正文

- **WHEN** 调用方持有精确 `queryResultRef` 且当前授权与登记授权摘要一致
- **THEN** 按登记的查询类型返回对应内联结果，条目集合与登记时一致，重放得到同一内容

#### Scenario: 越权、漂移或类型不符同形失败

- **WHEN** 引用不存在、属于其它工程、授权摘要漂移、当前授权被撤销，或该引用登记的查询类型与请求读取分支不符
- **THEN** 返回同形安全失败，响应不可用于区分目标是否存在或属于哪种查询

### Requirement: C32 工程上下文与资料监测目录只读必须有界

系统 MUST 提供三类只读目录：工程上下文读返回当前工程身份、当前工程修订引用、适用性元数据（施工工法/地层条件/工程阶段三维度）与空间区段树；资料目录按工程返回有界分页的资料版本条目（来源版本引用、类型、形成时间、来源单位、解析状态与清洗可用性摘要）；监测目录按工程返回有界分页的监测序列条目，并按精确序列引用返回其批次与冻结快照列表。列表页大小 MUST 有上界（不超过 50）并使用稳定游标；每条目 MUST 在返回前按当前授权复验工程、空间与资料可见性；无权、跨工程或不存在的目标 MUST 同形失败且不可枚举。目录只组合拥有方既有登记事实，不反写领域对象。（RI-S1；RA-S1）

#### Scenario: 获授权调用方读取目录页

- **WHEN** 调用方在当前工程具备读能力并请求目录首页或后续游标页
- **THEN** 返回有界条目与稳定下一游标，条目只含获准摘要，重复读取不追加业务事实

#### Scenario: 清洗可用性摘要来自已成立清洗事实

- **WHEN** 资料版本已有正式清洗结果
- **THEN** 目录条目呈现其可用性判定（可用/部分可用/不可用）与排除计数；无正式清洗结果时显式标注未清洗，不猜测状态

#### Scenario: 越权或跨工程不可枚举

- **WHEN** 调用方请求其它工程目录、被撤销授权后再次请求，或翻页游标指向已不可见区段
- **THEN** 返回同形安全失败，不返回条数、名称或存在性线索

### Requirement: C32 知识治理只读必须覆盖列表、精确读取与当前发布集合

系统 MUST 为受治理定义提供只读取面：按工程与定义类型（`KnowledgeDefinitionTypeV1` 全集）列出有界分页的定义条目，支持按治理生命周期状态（草稿/待审核/已发布/已停用）与关键字筛选，条目含定义标识、当前修订/发布引用、审核状态与版本摘要；按精确修订引用或发布引用返回该版本的条目正文（机理条目、工序模型、结构化评分规则、适用规则集、风险矩阵、措施库等各自的已治理形态）；按工程返回当前治理发布集合引用。已发布版本 MUST 只读且不可变，返回内容 MUST 可由该精确版本重放；列表不返回正文；无权、跨工程或不存在目标 MUST 同形失败。该读面 MUST 由知识治理拥有方实现，不得由调用方直读治理私有表，不得反写治理事实。（RI-S3～RI-S4；RA-S2～RA-S4、RA-S7）

#### Scenario: 按类型与状态筛选定义列表

- **WHEN** 调用方在当前工程具备知识读能力并按定义类型、生命周期状态或关键字请求列表
- **THEN** 返回有界条目与稳定游标，条目只含标识、版本与审核状态摘要，关键字只匹配获准条目

#### Scenario: 精确版本读取可重放

- **WHEN** 调用方按精确发布引用读取机理库或风险矩阵版本
- **THEN** 返回该版本完整条目正文，同一引用重放得到同一内容；发布后任何时刻读取不回退到旧版本也不混入新修订

#### Scenario: 越权或不存在同形失败

- **THEN** 返回同形安全失败，列表与精确读取均不可用于推断目标存在性

### Requirement: C32 检索结果再读取必须限于已登记检索事实

系统 MUST 为 `hybrid-evidence` 与 `relationship-context` 已登记检索结果提供只读再读取：调用方提交精确 `knowledgeQueryResultRef`，服务端复验当前授权与登记授权摘要后返回对应载荷——混合检索返回有界命中列表（条目引用、融合得分、证据定位）与策略/代引用，关系上下文返回邻接工序节点、依赖边、入选与筛除机理条目及筛除原因。再读取 MUST 复用拥有方既有读取实现，不触发新检索、不调用模型、不产生新事实；引用不存在、类型不符或越权时同形失败。界面 MUST NOT 经此读面发起脱离识别运行的临时检索。（RI-S5；RA-S3）

- **THEN** 按登记类型返回混合命中或关系上下文载荷，重放内容一致

#### Scenario: 越权或类型不符同形失败

### Requirement: C32 投影结果读取必须沿既有端口语义公开

系统 MUST 为既有 `ProjectionResultReadPortV1.readPage` 提供公开只读通路：输入精确 `queryResultRef`、可选游标与不超过 100 的页大小，输出保持既有 `ProjectionResultReadResultV1` 判别（`queryType` 限于 `run-view`、`trace-chain`、`association-graph`、`risk-overview`；条目为既有 `run-summary`、`trace-link`、`report-fact`、`report-absence` 分支）。通路 MUST 复用端口的授权摘要比对与游标绑定，不改变既有查询登记语义，不引入新的物化结果表，读取不造成跨模块逐项查询或全库投影。（RI-S6；RA-S5～RA-S7）

#### Scenario: 按登记查询分页读取投影条目

- **WHEN** 调用方先经既有投影查询登记，再持 `queryResultRef` 分页读取
- **THEN** 返回该查询类型对应的有界条目与下一游标，条目只含公开事实引用与获准证据定位

#### Scenario: 未登记、漂移或越权同形失败

- **WHEN** 引用未登记、游标被篡改、授权摘要漂移或调用方越权

### Requirement: C33 识别运行与风险记录只读必须有界且复验当前授权

系统 MUST 为风险识别域提供四类只读：运行列表按工程返回有界分页的识别运行条目（运行引用、状态、阶段、启动者、启动时间、验收/待复核/拒收计数；触发原因仅在有登记事实时输出，无登记事实时不得伪造）；运行详情按精确运行引用返回该运行的阶段进度（I0–I9）、工序工作项覆盖、合并组与验收路由摘要、关联 Agent 与复核任务引用及结果汇总；风险记录目录按工程返回有界分页的标准化风险记录条目（记录引用、工序节点、风险事件摘要、综合置信度、验收方式、当前效力），支持按工序节点与验收方式筛选；记录详情按精确记录版本引用返回该版本的识别侧正文（七字段、记录信封、证据定位、机理条目与资料来源引用、识别运行引用、验收决定与取代/作废关系）。列表页大小 MUST 有上界（不超过 50）并使用稳定游标；每条目 MUST 在返回前按当前授权复验工程可见性；无权、跨工程或不存在的目标 MUST 同形失败且不可枚举；返回内容 MUST 可由精确版本重放。该读面 MUST 由识别拥有方模块内部组合既有登记事实实现，不反写领域对象、不触发新识别、不调用模型。（RI-S5～RI-S6）

#### Scenario: 获授权调用方读取运行与记录

- **WHEN** 调用方在当前工程具备识别读能力并请求列表首页/游标页或精确详情
- **THEN** 返回有界条目或该精确版本正文，重复读取得到同一内容，不追加业务事实

#### Scenario: 越权或跨工程不可枚举

- **WHEN** 调用方请求其它工程的运行或记录、被撤销授权后再次请求，或引用不存在
- **THEN** 返回同形安全失败，不返回条数、名称或存在性线索

#### Scenario: 等待复核与失败状态如实呈现

- **WHEN** 运行处于等待复核或 Agent 可重试失败状态
- **THEN** 运行详情如实返回该状态、关联复核任务引用或失败阶段与错误码，已入库事实计数不回退，不把暂停或失败伪装为完成

### Requirement: C33 复核队列只读必须携带可决定的精确任务引用

系统 MUST 为复核域提供队列只读：按工程返回有界分页的复核任务条目，每条 MUST 携带完整 `ReviewTaskRefV1`（含复核类型、目标引用与等待运行引用）、复核类型、提交时间与状态；复核对象标签由调用方从目标引用确定性渲染；触发原因仅在有登记事实时输出，不得伪造；目标版本已被取代的任务 MUST 由拥有方计算并标记过期。队列 MUST 支持按复核类型与状态筛选，页大小有上界（不超过 50）并使用稳定游标；条目在返回前按当前授权复验；无权、跨工程或不存在 MUST 同形失败且不可枚举。该读面 MUST 由复核审计拥有方实现，只组合既有复核任务与决定登记事实，不反写、不代为决定。（RI-S6）

#### Scenario: 队列条目足以构造既有决定命令

- **WHEN** 获授权复核人读取队列页
- **THEN** 条目携带的完整任务引用可直接作为既有 `decide-review` 命令的 `reviewTaskRef`，无需第二次取数

#### Scenario: 过期任务显式标记

- **WHEN** 任务目标版本已被更新版本取代
- **THEN** 条目携带过期标记，调用方无需自行比对版本

#### Scenario: 越权或不存在同形失败

- **WHEN** 调用方无复核读能力、请求其它工程队列或游标指向不可见区段
- **THEN** 返回同形安全失败，不披露任务数量或类型分布

### Requirement: 评估候选来源授权必须通过所属事实有界继承

系统 MUST 由 C11 提供有界窄读取，以 C25 当前读取的原调用身份和 risk-assessment.read 授权复验工程、主体与空间，将当前已验证的来源授权引用定位为精确来源版本，最多 256 项。C25 MUST 仅用这些版本重签每次目录授权并检查空间及来源授权保持或收窄原范围；定位不得读取跨域私表、产生业务写入或增加页面必填字段。（RA-S1；RI-S14）

#### Scenario: 真实来源范围继承
- **WHEN** C25 当前授权包含外部事件证据所需的来源授权，且对应 C11 就绪来源登记存在
- **THEN** C11 返回匹配来源版本，C25 以这些版本为每个目录签发配对授权，外部事件目录可以复验实际来源
- **AND** 页面无需提交额外来源版本字段

#### Scenario: 缺失错配或越界来源不得继承
- **WHEN** 来源授权已撤销、登记不存在或引用错配，或者下游签发包含原范围外的来源授权或空间
- **THEN** 读取返回安全类型化失败，不补成全工程资料权限或成功空目录

#### Scenario: 无来源授权保持空范围
- **WHEN** 当前获权上下文没有来源授权引用
- **THEN** 定位返回空来源集合，不扫描工程资料以自动扩大授权

### Requirement: 风险输入事实接缝由各所有者实现并保持统一投影

系统 MUST 为标准化风险记录和外部风险事件提供同一风险事实读取契约；请求固定读取身份、时间、授权及风险输入 XOR，结果固定原工程、原风险输入、字段和证据。各分支由自身所有者读取，组合能力仅按输入种类分派。C11 准备冻结与 C25 评估 MUST 消费同一生产接缝，字段类型只定义一次，调用身份和精确分支必须与 C06 签发事实匹配。（RA-S1；RI-S14）

C11 MUST 从当前复验的来源授权解析精确资料范围，C25 MUST 从已复验准备快照的空间和来源证据取得精确范围；两者向事实读取分支签发的上下文必须包含待读目标所需范围且不超出调用方有效授权。reader 的第二阶段复验保持对保存来源和空间的完整校验，不能以资料资格核对替代来源授权。

#### Scenario: 两个消费者使用同一事实提供者
- **WHEN** C11 冻结准备快照及 C25 读取同一精确风险输入
- **THEN** 两者通过相同生产契约获得一致的输入身份、字段和证据
- **AND** 装配代码只注入依赖，不内嵌或伪造业务事实

#### Scenario: XOR 或读取身份不合法时关闭失败
- **WHEN** 请求缺少风险输入、同时表达两个分支、包含未知字段，或读取身份和授权签发身份不匹配
- **THEN** 系统返回类型化契约或授权失败，不选择默认分支或改换调用身份

#### Scenario: 冻结来源范围贯穿正式评估读取
- **WHEN** C25 当前调用方获准读取准备快照全部空间和来源，并评估其中的精确风险输入
- **THEN** C25 按已复验准备范围签发事实读取上下文，正式 reader 返回原身份、字段和证据
- **AND** 来源缺失、撤权或下游范围扩张时失败闭合，不保存评估成功事实、业务收据或 Outbox

### Requirement: 预测执行只消费有界正式输入及评估所有者的计算接缝

预测执行契约 MUST 显式固定当前受权请求、正式建议与措施、冻结监测和基线评估、预测策略及精确模型版本。预测风险状态 MUST 由评估所有者按冻结依据计算，预测执行器不得直接读取评估、知识或工程私表，不得改写正式事实或创建另一套评分与矩阵规则。（RA-S3～RA-S5、RA-S7）

#### Scenario: 预测指标进入同一冻结评分依据
- **WHEN** 正式模型产生合法目标预测值，且当前授权允许读取建议追溯的精确评估依据
- **THEN** 执行器通过评估所有者的窄计算能力取得与该依据一致的预测风险状态

#### Scenario: 接缝拒绝不能被执行器绕过
- **WHEN** 精确依据、措施绑定、版本或当前权限不符
- **THEN** 预测按类型化不可用或失败收口，不直接读私表、复制基线风险状态或选择其它版本

### Requirement: C34 评估只读端口必须解释精确版本并提供有界候选

系统 MUST 提供独立风险评估只读端口，包含评估候选、启动上下文、记录目录、精确记录解释和重评历史的闭合操作，复用既有风险输入 XOR、风险评估记录、版本/证据/错误 Schema。目录 MUST 有界分页并限定当前授权空间；启动上下文只提供已成立输入引用和部署注入的运行策略，不创建快照。解释 MUST 由评估所属模块读取保存的实际值、决策工件与冻结准备/输入，矩阵定义由知识所属接口读取；识别与外部输入由各自所属公共读取接缝验证，不跨表反查。（RA-S1～RA-S6）

所有成功读取，包括显式版本解析，MUST 返回当前已验证主体与最多八项动作可用性。启动上下文的图版本和重试策略 MUST 与既有启动命令使用同一种精确版本引用形状，调用方可原样提交，不补造引用种类。pending-catalog 的外部事件分支 MUST 选择精确空间，风险记录分支空间可选；两分支均不要求或接受工程修订。下游目录 MUST 逐次使用与签发身份一致的 queryId，并保持或收窄当前已验证权限范围。

#### Scenario: 有界目录与精确解释
- **WHEN** 获授权用户查询一个候选页或精确记录版本
- **THEN** 返回有界条目或真实冻结解释，游标绑定工程、筛选与授权作用域
- **AND** 不改历史记录、不读取全库再由 UI 截断

#### Scenario: 版本权限或解释不完整
- **WHEN** 输入跨工程、授权失效、引用错配、解释缺失或超界
- **THEN** 返回既有类型化安全失败
- **AND** 不解析 latest、不重新评分或用当前发布补齐

#### Scenario: 预览策略可原样启动
- **WHEN** 获授权调用方取得可用的启动策略与完整登记输入
- **THEN** 图版本与重试策略引用可原样用于既有启动命令
- **AND** 无需包装、解包或猜测策略引用种类

### Requirement: C34 重评入口事实必须原样保存并可恢复

系统 MUST 在重评产生运行副作用前固定精确前驱、调用方显式原因及一至六十四项变化引用，并在既有运行工件与登记事务中保存。父运行、评估子运行、等待/失败恢复和历史解释 MUST 使用同一入口事实；变化引用不得由冻结输入并集反推或被静默裁切。公开原因使用既有工作流原因集合，进入评估用例时只作明确的原因码映射，不按引用类别重新判断原因。工程、空间、来源授权及历史不可变约束保持成立。（RA-S1、RA-S5～RA-S7）

运行入口身份 MUST 区分不同前驱、显式原因或变化集合。原命令身份与原载荷重试返回同一运行；同键异载荷 MUST 在创建另一运行或调用评估前失败。已保存输入只包含精确引用，不复制领域正文。

#### Scenario: 重评原因和变化引用经过恢复仍一致
- **WHEN** 重评在运行中等待或失败，随后按合法精确运行引用恢复
- **THEN** 父子运行和历史解释保留原前驱、原因及变化引用，评估用例取得与该原因对应的既有码
- **AND** 矩阵变化不会被解释为适用性变化，变化引用不会混入全部基础输入

#### Scenario: 原因或前驱变化不会复用旧入口
- **WHEN** 新命令改变前驱、原因或变化集合，或者原幂等键被用于不同载荷

#### Scenario: 缺失历史重评事实时失败闭合

- **AND** 不从引用数量、准备快照触发码、checkpoint 或当前配置补猜原因及变化引用

#### Scenario: 不使用监测输入时仍可冻结入口
- **WHEN** 合法初评或重评无需监测输入且未提交监测引用
- **THEN** 入口按已声明的无监测语义继续冻结与运行
- **AND** 显式空数组和互相冲突的监测引用仍被拒绝，不自动选择快照

### Requirement: C34 预警处置只读端口必须组合所属事实

#### Scenario: 所属事实经公开接缝组合
- **WHEN** 用户读取一个有合法预警与反馈链的任务或建议
- **THEN** 返回精确且有界的领域结果、确认/决定/执行/反馈关联与获准解释
- **AND** 缺席关系显式呈现，未越限偏差不生成公共校准记录

#### Scenario: 非法读取不泄露存在性
- **WHEN** 目标不存在、跨工程、无空间/来源权限或调用方请求契约外字段
- **THEN** 输入被拒绝或返回不可枚举失败
- **AND** 不暴露正文、私有状态、SQL 或目标计数

### Requirement: C34 态势摘要与 C31 历史投影必须保持独立口径

系统 MUST 保留既有风险总览投影的查询登记、精确结果引用、查询时点和有界分页。新增评估与预警任务摘要 MUST 只描述当前获准空间的已入库评估记录版本及开放任务关联事实，明确统计时点和口径；不得覆盖既有历史投影、改变报告重放输入，或将不同口径相加为风险事件总数。运行和证据链 MUST 继续从原投影取得，P/C 与阈值解释从所属精确记录取得。（RI-S6；RA-S5～RA-S7）

#### Scenario: 当前摘要与历史引用同时可读

- **WHEN** 获授权用户读取当前态势摘要及原风险总览的一页事实引用
- **THEN** 各来源分别返回其统计时点或精确查询结果，并按自身授权与分页规则呈现
- **AND** 当前新增领域事实不改写原查询的历史内容

#### Scenario: 独立来源失败不冒充完整态势

- **WHEN** 一个摘要或历史投影来源失败、权限失效或仍有后续页
- **THEN** 对应来源显示失败或可继续分页，其它来源保持各自有效范围
- **AND** 不用当前计数替代历史投影，不循环读尽投影取得全工程总量

### Requirement: C35 只读端口必须复用 Schema 事实源和所属模块

系统 MUST 用唯一 strict Schema 为任务、复核活动、管理目录、报告策略及报告读取定义用例级接口；共享版本/证据/授权引用必须复用已有契约。预算、工具行动和逐项校验字段必须从原 C08 唯一 Schema 派生安全投影，不建立原型同名第二套事实。接口由所属模块读取已登记事实，不开放上游内部表、通用工件正文或无限关联展开。（RI-S1～RI-S6；RA-S1～RA-S7）

#### Scenario: 各拥有方实现自己的事实读面
- **WHEN** API 请求任务、复核、管理或报告数据
- **THEN** 只调用对应公开用例，字段与运行时验证来自唯一 Schema，UI 不读取内部持久化结构

#### Scenario: 超界或错误结果族
- **WHEN** 输入超分页/集合上限或端口返回契约外结果
- **THEN** 共享边界失败关闭，不截断为成功、不用自由字符串推断结果类型

### Requirement: C35 报告导出必须沿 C31 与 C04 形成可重放结果

系统 MUST 实现已有 `projection.export` 的报告用途：只消费同工程精确登记的 C31 查询结果及已配置的不可变导出策略，按策略固定格式、章节、范围和资源上限，完整读取允许的投影事实并生成 JSON 内容工件。成功只返回真实 `ExportArtifactRefV1`；原内容工件映射、查询/策略/权限关联和生成审计必须耐久，重放复用同一身份。未登记查询、策略缺失、权限漂移、分页/字节超限或工件/审计失败不得成功；报告不更改领域事实、P/C 或现行配置。

#### Scenario: 同源同策略形成同一逻辑报告
- **WHEN** 导出请求在相同身份、查询结果和策略下重放
- **THEN** 返回原工件引用并可按原来源版本重建安全报告，不重复审计或创建第二份逻辑报告

#### Scenario: 工件或审计失败
- **WHEN** 内容尚未耐久、尾登记事务失败或审计写入失败
- **THEN** 不发布成功导出引用；原请求可安全重试，未登记工件沿现有工件维护规则处理

#### Scenario: 报告再读取权限收窄
- **WHEN** 工件生成后调用方失去原工程、空间、来源或导出权限
- **THEN** 正文读取安全失败，不用已保存的旧授权快照或下载链接绕过当前权限

### Requirement: Worker 按精确因果事实耐久消费父图事件

识别准备事件 MUST 沿正式 C06 因果引用及精确启动登记定位父运行；风险验收 MUST 沿精确 parent-child 链边定位。assessment 准备与正式来源可证明的独立事件 MUST 保存无匹配后台运行的耐久回执。关联暂缺、不唯一、拒权、版本冲突及技术失败 MUST 保持失败和原重投，不得以未找到关联替代独立来源证明。图 MUST 在消费短事务外执行，事务内只复验已提交的精确输入及消费状态再写原回执；取消态、非空 outcome 或单独输入登记不得替代消费证明。

#### Scenario: 子事件先于父关联提交
- **WHEN** 子事件已存在而精确父子链边尚未提交
- **THEN** Worker 不 acknowledge，按原投递策略重投

#### Scenario: 图已消费但回执提交失败
- **WHEN** 原图已提交精确消费事实而消费回执失败
- **THEN** 重投复验当前权限与已提交状态后补回执，不重复推进业务

#### Scenario: 验收子运行版本不符
- **WHEN** 验收事件的子运行版本与父运行登记不符
- **THEN** 原图拒绝事件且不新增验收路由事实

### Requirement: 识别规划接口返回正式已登记计划

riskIdentification.plan MUST 按输入快照读取 C24 I2 已登记的精确工作计划，返回原 IdentificationPlanResultV1。读取 MUST 使用本次命令签发身份及当前完整工程、空间和来源授权，核验登记与正文同一性，不启动完整图或生成第二计划。

#### Scenario: 正式计划按精确输入返回
- **WHEN** 本次授权有效且该精确输入快照的工作计划已正式登记
- **THEN** 接口返回该精确 workPlanRef，重复调用不新增工作计划

#### Scenario: 缺计划或拒权保持失败边界
- **WHEN** 计划缺失、错版本或正文与登记不一致，或当前权限不成立
- **THEN** 接口分别返回业务阻断或授权失败，不返回未成立的引用

### Requirement: 反馈校准检查点只登记已提交公共偏差

独立反馈入口的 A3 MUST 只冻结 C29 校准输入并推进 A4，不登记尚未落库的公共偏差引用或 feedback-deviation 链边。A4 MUST 在正式建议原子提交成功后，通过 C29 受权窄读取得该精确建议创建时的公共偏差版本，同时登记图状态、游标、feedback-deviation 与 deviation-calibration 两条链边。窄读 MUST 按精确工程、建议、父运行和当前完整空间授权证明已提交建议与偏差正文，返回该建议创建时的 pending 版本；不得用派生首版本、最新偏差版本或后续复核版本替代。

#### Scenario: 输入冻结与 Agent 等待不冒充公共记录
- **WHEN** A3 完成输入冻结，或 A4 等待 Agent 或正式建议失败

#### Scenario: 正式建议成功后登记精确版本
- **WHEN** A4 正式建议原子成功，且 C29 证明该建议创建时的公共偏差版本
- **THEN** 图保存该精确偏差引用及建议引用，并在 A4 登记两条链边
- **AND** 后继建议与幂等重放仍返回其创建版本，后续复核不改变该引用

#### Scenario: 缺失或越权的创建记录拒绝推进
- **WHEN** 建议、创建时偏差正文、运行归属或当前完整授权不成立
- **THEN** 窄读不返回偏差引用，A4 不推进成功或登记校准链边

### Requirement: 适用规则集组装命令返回正式派生发布

系统 MUST 保留正式适用规则集组装入口，只接收精确评估准备、业务时刻及用户需要选择的评分配置。工程、操作者、组装策略与成员由服务端按运行清单解析。已批准内容的确定性组装成功时，返回候选内容及正式派生发布、评估依据引用；有内容冲突时返回对应等待，不创建虚假人工批准。

#### Scenario: 原组装入口直接得到可用依据

- **WHEN** 有权用户提交匹配当前准备的组装请求且内容已批准、无未决冲突
- **THEN** 通过原 C19/C16 事务形成正式派生发布，返回评估可消费的依据，无额外人工送审步骤

### Requirement: 可信内部调用复用业务上下文

系统 MUST 由业务入口确定发起者、工程、任务及获准资源范围，通过现有用例级接口向内部模块传递；同一动作内复用当前权限决定，后续新读取或提交在统一入口检查当前权限。接口只接收业务必要输入，能够从登记对象取得的操作者、策略和因果关联由服务端解析。模块保留事实所有权、类型化输入和工程归属，不另建逐层授权与调用身份配对。

#### Scenario: 业务入口向内部传递上下文

- **WHEN** 有权用户通过既定界面发起业务
- **THEN** 模块直接使用入口确定的上下文完成动作，关联同一审计来源

#### Scenario: 内部无需客户端重复声明策略

- **WHEN** 系统能够从选定业务对象取得策略和来源版本
- **THEN** 客户端只提交对象引用和用户需要选择的业务参数，服务端读取对应版本

### Requirement: 评估候选按业务条件和当前权限读取

评估候选读取 MUST 保留精确工程修订与空间等业务筛选条件，适用性目录要求工程修订和空间，外部事件目录要求空间，风险记录候选允许可选空间。入口检查当前权限后，组合读取复用同一上下文；内部目录读取不逐次签发 queryId 与 invocationId 配对授权。

#### Scenario: 两类目录使用业务条件读取

- **WHEN** 评估页面组合适用性与风险输入候选
- **THEN** 目录受相同工程和当前权限限制，结果可用于后续准备

#### Scenario: 目录缺少业务条件

- **WHEN** 适用性目录缺工程修订或外部事件目录缺空间
- **THEN** 返回类型化输入错误，不以空目录代表成功

### Requirement: 评估与后续阶段分别冻结所需配置

评估启动 MUST 提供业务必需的风险输入、工程修订、适用性及监测选择；服务端根据选定配置形成只包含评分和触发所需成员的输入快照。预警、处置、预测及校准策略在对应阶段从指定运行清单解析并单独冻结，不作为评分启动的必填输入。人工指定的序列、截止点、重评原因和因果关系仍按原输入保存。

#### Scenario: 评分启动不要求后续策略

- **WHEN** 评分输入和规则齐全，处置或校准尚未配置
- **THEN** 评分可以形成正式结果，后续阶段单独显示待准备

#### Scenario: 后续阶段准备自己的依据

- **WHEN** 进入预警、处置或校准阶段
- **THEN** 该阶段保存实际使用的配置版本，追溯回原评估但不修改评分快照

### Requirement: 工作流显式冻结现场工件

公开assess/reassess/historical-backfill启动载荷及identify-and-assess逐空间上下文 MUST 支持可选siteContextArtifactRef，引用既有精确ContentArtifactRef。入口 MUST 将其纳入不可变冻结集合与运行身份，并传递到评估子运行。处置组合 MUST 仅从本次冻结content-artifact匹配同工程配置的现场artifactRef，再沿原现场reader检查当前权限、用途、逻辑身份、空间及观察时刻，恰一项才可用于A8。缺失、不符或歧义 MUST 拒绝，不推断最新现场或修改历史运行。

#### Scenario: 公开入口携带精确现场工件

- **WHEN** 有权调用方在评估启动或逐空间上下文声明已登记现场工件
- **THEN** 该引用进入父/子运行冻结集合，改变版本产生不同运行身份，三项校验只消费原精确现场

#### Scenario: 冻结引用不匹配现场

- **WHEN** 没有现场工件、错工件、异工程/空间或多项匹配
- **THEN** 不生成通过的处置建议，保留原现场权限与三项约束，不回落配置默认值

#### Scenario: 多空间交换现场工件

- **WHEN** 两个合法逐空间上下文包含相同现场工件集合，但工件与空间的配对发生交换
- **THEN** 新启动产生不同入口身份；上下文顺序改变不改变身份，子运行与恢复只传各自空间的现场工件；没有现场工件的历史输入保持原身份

### Requirement: 报告预览保留所属分页游标契约

报告预览 MUST 接受所属C31分页端口生成的完整游标，复用其Schema并保持查询、排序键、授权范围绑定；不得因另设更小字符串上限而拒绝合法分页。历史查询登记及导出资源预算保持。

#### Scenario: 真实长引用生成续页游标

- **WHEN** 合法查询/运行引用使所属分页游标超过512字符
- **THEN** 预览响应通过HTTP Schema且原游标可在所属分页端口续页，错查询或错范围仍拒绝

### Requirement: 部署复验按原上下文范围计算当前权限

部署普通verify及工件/模型verifyDeploymentContext复用审计上下文时，空资源请求 MUST 沿C06既有语义使用该精确上下文持久来源的空间及来源版本，不能丢失grant或使用环境更宽范围。新authorize的显式空资源集合、复验的显式非空请求 MUST 保持原语义。当前权限、主体/工程/能力、任务冻结及租约仍由原C06/C08检查，未知上下文不得回退环境来源或复制旧grant。

#### Scenario: 精确小范围上下文在较宽环境中复验

- **WHEN** 复验目标上下文仅含环境来源的子集，且当前仍有权
- **THEN** 复验返回该子集的当前决定，报告分页和C04/C03可消费，既不清空也不扩大范围

#### Scenario: 明确资源请求、未知上下文及撤权

- **WHEN** 新授权明确请求空集合、复验明确请求非空集合、上下文未知或当前撤权
- **THEN** 前两者保留实际请求语义，后两者拒绝且不产生受保护业务写入

### Requirement: 部署人员入口按当前会话和当前业务权限处理重放

部署人员请求 MUST 从真实当前会话确定主体并使用既有当前业务动作授权通路，原命令调用编号仅关联日志和业务幂等，不以历史五分钟上下文是否到期决定权限。不得修改旧授权或延长TTL，当前会话失效、账号/工程/资料拒权继续阻止业务动作。

#### Scenario: 原命令授权历史记录已过期

- **WHEN** 当前会话和当前业务权限有效，重放已提交反馈的原命令但历史调用授权已到期
- **THEN** 按当前权限消费原已提交事实和稳定幂等，不返回历史上下文到期或重新登记反馈

#### Scenario: 当前会话或业务权限失效

- **WHEN** 当前会话失效或当前业务权限拒绝
- **THEN** 在业务推进前拒绝，不因原命令曾成功而放行

### Requirement: 当前有权运行读取保留跨恢复历史阶段

运行读面 MUST 在当前工程权限、精确C04状态及完整父子链边核验后，按精确运行有界读取已登记阶段和结果引用；合法恢复导致的历史授权摘要变化 MUST NOT 拆散同一运行。原摘要保留用于审计，不要求关系、阶段和最新状态的历史摘要相同。

#### Scenario: 同一运行恢复时授权上下文发生合法变化

- **WHEN** 当前有权用户读取已完成运行，精确父子关系成立但阶段、关系与状态的历史摘要不同
- **THEN** 返回同一运行的完整已登记阶段和结果，保留精确引用及分页边界

#### Scenario: 缺失关系或当前拒权

- **WHEN** 父子链边缺失、引用版本不符或当前状态工件不可读取
- **THEN** 拒绝读取，不猜测父子关系或补写历史

### Requirement: 人工采纳门禁使用当前等待

C30 MUST 仅在当前状态为waiting且lastWaitingRef为human-decision时阻断其它恢复原因。正式采纳证明及路由已经成立后，历史人工等待行 MUST 保留且不得阻断后续配置或Agent等待的精确恢复；首次采纳的唯一等待、C41证明、版本及当前权限检查保持。

#### Scenario: 已采纳运行继续配置等待

- **WHEN** 原预测已正式采纳并转入评估配置等待，当前精确准备已完成
- **THEN** 恢复原子运行，不重新采纳或创建第二子运行，历史人工等待及审计保持

### Requirement: 内嵌任务恢复观察原正式任务

C27/C29内嵌任务ensure MUST 在现有当前权限检查后按唯一agentTaskRefFor身份精确读取已登记任务，以同一校验验证原工程、主体、命令、父运行、冻结输入及模型/策略引用。已有任务 MUST 按真实状态返回，不再次startTask；缺任务才沿原启动路径。失败或取消不得重开，当前拒权和身份错配不得返回候选。

#### Scenario: 完成通知携带当前授权

- **WHEN** 原任务已完成且本次当前合法恢复授权与历史启动授权不同
- **THEN** 读取并核验原任务后返回其正式结果，不重提原启动命令、不新增模型或改变历史任务

### Requirement: 独立子运行使用自己的检查点边界

识别和评估独立子运行 MUST 在父节点内外使用同一自身线程、根命名空间和所属saver，执行及回读均清除继承父checkpoint_id、checkpoint_map及scratchpad。既有原检查点不得删除或修改，不得因独立回读缺失而重跑已完成评估或创建替代Agent。当前权限、检查点Schema、引用和持久化校验保持。

#### Scenario: 父节点内等待后独立回读和恢复

- **WHEN** 父StateGraph节点启动或恢复独立评估子运行并进入等待
- **THEN** 子检查点属于自身线程根命名空间及所属saver，独立回读命中同一状态，后续恢复不消耗父检查点

#### Scenario: 原检查点落在父任务命名空间

- **WHEN** 已登记等待的原子检查点可经唯一已观察精确命名空间、当前权限及正式登记证明
- **THEN** 仅可在保留原记录、核验完整原状态及禁止业务和模型写入的受控恢复中，按同一线程登记其根等待检查点；不得猜测其它命名空间或重跑业务

### Requirement: 公开Agent完成通知转交原评估等待

C30 MUST 将公开agent-task-completed的完整结果引用转交给等待同一精确Agent任务的原评估子运行，按原冻结输入核验子身份并使用当前子状态版本与当前恢复权限。恢复后 MUST 回读子运行正式状态再聚合父结果；错任务通知拒绝，其它兄弟与终态不得推进或重开。不新增评估、任务或模型额度，C25继续核验原任务真实完成结果。

#### Scenario: 原评估Agent已完成

- **WHEN** 有权主体用当前父版本通知原评估等待的同一Agent完成
- **THEN** 原完整结果及恢复上下文交给同一子运行，父按恢复后的正式状态继续聚合

#### Scenario: 其它任务或终态子运行

- **WHEN** 完成通知不是当前评估等待任务，或者其它子运行已经终态
- **THEN** 错任务通知拒绝，终态及未匹配兄弟不恢复，不新增模型调用

### Requirement: 评估入口恢复按当前权限读取原A0引用

readAssessmentEntrySnapshot MUST 从同工程同运行的唯一A0入口行读取原inputSnapshotRef，并通过该行精确C04正文的当前权限与正文工程/运行归属检查，不要求当前授权增量与历史完整摘要相等。缺正文、损坏、撤权、错目标、非A0或多义 MUST 拒绝，不重建指针或重跑已完成任务。

#### Scenario: 已完成Agent后的等待恢复

- **WHEN** 原评估等待任务已完成，当前合法授权来源增量变化
- **THEN** 原入口快照仍可按当前权限读取，继续原运行与任务结果，不新增评估、模型或放宽来源权限

### Requirement: 评估追溯分别核对运行入口与冻结准备

C30 MUST 使用已登记入口方式、冻结引用及重评入口事实，沿唯一workflowEntryIdentityFor验证运行入口身份；A0入口行存在inputSnapshotRef时，其entryIdentity MUST 与该快照引用一致。运行入口摘要与准备引用不得被当作同一种标识比较。工程、运行、状态版本、入口方式、评估结果归属、前驱和原因检查保持。

#### Scenario: 原运行引用独立准备并在A0冻结因果准备

- **WHEN** 运行入口摘要由原冻结输入确定，A0登记另一个带本次因果的准备引用
- **THEN** 两种身份分别核验成功，原评估可追溯，无需重跑或修改历史记录

#### Scenario: 运行入口或准备身份错配

- **WHEN** 运行入口摘要与登记输入不符，或A0准备身份与其快照引用不符
- **THEN** 入口元数据读取明确失败，不返回部分追溯

### Requirement: 评估入口绑定精确独立准备

公开assess启动载荷 MUST 支持可选assessmentPreparationSnapshotRef，并将其纳入冻结引用及入口身份。A0 MUST 经C11当前受权窄读，精确匹配工程修订、风险、空间、适用性、assess入口、发起人与完整监测集合；只接受未绑定旧父因果的独立准备。匹配后 MUST 经原C11路径幂等冻结原资料字段/证据/监测及本次运行因果，原独立准备保持不可变；缺省沿既有冻结路径。

#### Scenario: 当前有权主体使用匹配准备

- **WHEN** 显式准备与全部入口引用及主体一致，资料与空间当前可读
- **THEN** A0保存本次绑定准备，后续阶段只消费原精确值和本次因果，原独立准备可经根入口追溯，准备引用改变时形成不同入口身份

#### Scenario: 错绑定拒绝且无下游效果

- **WHEN** 准备错修订、风险、空间、适用性、监测集合、主体或入口，已有旧父因果，或者当前无权
- **THEN** A0拒绝，不冻结新准备、不创建依据或评估记录，历史准备保持

### Requirement: 确定性评估按真实输入权限执行

C25评估 MUST 按真实准备空间和来源复验当前工程/主体/分支/调用权限，并由风险、监测、依据和工件所属入口逐项核验实际消费范围。身份检查与范围检查返回不同资料增量时，不得要求二者完整集合包含或相等；redacted或实际输入当前无权仍 MUST 拒绝。输入快照、提交前复验、审计及原子事务保持，终态任务和失败不复活。

#### Scenario: 身份检查与准备范围增量不同

- **WHEN** 当前身份读取不携资料增量而准备范围读取合法返回真实来源，实际风险/监测/依据均有权且版本正确
- **THEN** 评估继续原确定性流程，不因两份授权增量集合不同阻断

#### Scenario: 实际消费范围被撤权

- **WHEN** 任一真实输入或父工件当前无权、脱敏或版本不符
- **THEN** 读取或提交前拒绝，不产生正式评估记录或成功事件

### Requirement: 父事件证明使用当前权限及正式运行事实

C30父事件证明 MUST 按当前工程/主体/调用权限、精确父子链边、正式运行绑定与同版本C04状态和消费事实核验，不得要求本次事件与历史登记的完整授权摘要相同。当前空间 MUST 覆盖该运行唯一精确入口冻结的空间集合；根入口缺失、多义、错空间、撤权、错父子或不可证明消费均拒绝。证明为有界只读，来源资格仍由实际消费资料的所属入口验证，原事件投递台账不得重置。

#### Scenario: 合法业务事件未携带整批历史资料授权

- **WHEN** 已提交风险记录事件的当前权限覆盖原父运行空间，主体/父子/运行与消费事实均成立，但资料授权集合与启动时不同
- **THEN** 可读取原父并核验真实消费，不因历史授权摘要不同拒绝，也不扩充本次资料权限

#### Scenario: 当前空间不能覆盖原运行

- **WHEN** 当前事件授权缺少根入口的任一冻结空间或当前撤权
- **THEN** 父事件证明拒绝且不推进图、模型或消费回执

### Requirement: 原识别等待支持精确Agent失败通知

workflow.resume-run MUST 支持strict原因agent-task-failed，仅携带retrieval-review且embedded的精确agentTaskRef。C30 MUST 按当前恢复权限、状态版本及原识别等待转交C24，不构造完成或失败结果引用；父可重试技术失败后仍 MUST 保留原通知并按冻结重试策略恢复原阶段。不得更换任务、重开批次或增加模型额度。

#### Scenario: 公开通知原等待任务失败

- **WHEN** 原有权主体以当前父版本通知同一识别等待任务终态失败
- **THEN** 原任务引用交给原C24子运行核验并收口失败项，原成功事实及预算保留

#### Scenario: 通知载荷越界

- **WHEN** 失败通知携带非检索审阅/非内嵌任务、结果正文或其它额外字段
- **THEN** 公开Schema拒绝，不启动或推进任务

### Requirement: 父图按子运行稳定错误分类

C30 MUST 在没有顶层稳定code时读取子运行异常的一层.error，沿既有错误分类规则保留详情和不可重试边界。不得按异常文案或递归cause猜测分类，不得把权限、冲突和检查点错误折为未知可重试失败。

#### Scenario: 子运行稳定异常进入父恢复

- **WHEN** C24恢复抛出携带稳定错误的运行异常
- **THEN** 父按该稳定错误分类并记录当前父阶段，保持原预算及已成立事实

### Requirement: 显式识别执行批次

identify-and-assess公开启动载荷 MUST 支持可选executionBatchId，按既有IdentifierSchema校验，并经唯一workflowEntryIdentityFor纳入入口摘要。批次不同 MUST 形成独立运行和线程；同批次重投 MUST 保持原运行及幂等约束。缺省时 MUST 保持原身份，不把批次混入业务frozenRefs或改变准备匹配、权限和预算。

#### Scenario: 同输入启动独立批次

- **WHEN** 同一工程、图与业务冻结引用使用两个不同executionBatchId启动
- **THEN** 形成不同运行和线程，分别固定各自输入时刻；旧运行和历史结果保持

#### Scenario: 批次重投与同键冲突

- **WHEN** 同批次同载荷重投，或在同幂等键下更换批次
- **THEN** 前者返回原运行且无重复业务效果，后者按异载荷拒绝

### Requirement: 父运行通过显式命令绑定匹配识别准备

系统 MUST 在workflow.resume-run中支持strict原因identification-preparation-ready，仅接收精确identificationPreparationSnapshotRef。C30 MUST 复验当前恢复权限、原主体、预期状态版本及识别准备等待，经C15/C04核验正式准备和完成结果，匹配原工程修订、完整空间/来源集合及已有监测范围。绑定 MUST 是本次命令的新审计事实，原独立清洗因果、冻结图版本、预算和结果保持不可变；父运行只可绑定一个准备引用，沿既有事务、入口快照和LangGraph恢复。

#### Scenario: 当前有权用户绑定匹配独立准备

- **WHEN** 当前有权的原主体提交匹配冻结输入的正式准备和有效等待点版本
- **THEN** 记录本次命令和精确准备绑定，沿原父运行继续识别，不重新清洗或伪造父任务事件

#### Scenario: 错范围或无效等待拒绝

- **WHEN** reader缺失、准备不存在/未完成/损坏/错主体/工程修订/空间/来源，或当前撤权、游标过期、运行取消/终态及不在识别准备等待
- **THEN** 拒绝绑定和业务推进，不创建识别子运行，不用其它资料集合替代

#### Scenario: 并发及回执重投保持唯一绑定

- **WHEN** 不同准备竞争同一父运行，或恢复命令重投
- **THEN** 原事务及幂等身份只允许一个准备绑定，异准备冲突；同引用沿当前权限和原状态版本规则处理，不覆盖历史或重复创建识别子运行

- **THEN** 已核验准备先登记为同一父运行入口快照，恢复方据该精确登记事实继续，检查点只保存进度，不仅凭恢复载荷或其它运行的准备放行

系统 MUST 从已登记运行状态的graphVersion构造父图检查点；该可选值缺失时只使用同运行上下文的graphVersion。不得以入口摘要或当前部署最新图替换，原图版本及阶段结果保持有效，检查点不递归验证正文。

#### Scenario: 节点推进及恢复保持图版本

- **WHEN** 父图完成准备、进入等待或从已登记状态恢复
- **THEN** 检查点图版本保持启动时冻结的精确版本，入口摘要与图版本不同不导致合法运行被拒绝

- **THEN** 按既有阶段到节点映射恢复原运行，保留检查点的历史启动授权引用，当前授权独立复验并记入本次业务审计
- **AND** 复用原运行与已完成结果，历史启动授权仅用于追溯
