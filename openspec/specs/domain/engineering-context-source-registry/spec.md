# domain/engineering-context-source-registry Specification

## Purpose
为 RiskFlow 提供唯一、版本化且受工程授权约束的工程上下文与工程资料登记事实，使 RI-S1 与 RA-S1 的下游流程能够按精确工程、空间、资料、资料段及适用性快照重放输入。

## Requirements

### Requirement: 工程与空间区段业务上下文只通过不可变修订演进

系统 MUST 以稳定工程身份和稳定空间区段身份归集不可变业务修订。工程修订 MUST 记录工程名称、业务生命周期状态和适用性元数据；空间区段修订 MUST 绑定同一工程中 C06 已存在的稳定 scope identity，并记录父区段、工点位置和可选里程边界，不得复制或改变 C06 的授权树。修订生效 MUST 使用预期当前版本收口并发，历史事实始终引用原精确修订。（RA-S1）

#### Scenario: 创建首个工程业务修订

- **WHEN** 获授权的工程风险管理员为 C06 已开通且有效的工程提交完整业务上下文
- **THEN** 系统创建稳定工程身份的首个不可变修订并返回精确 `ProjectRevisionRefV1`
- **AND** 修订同时含施工工法数据、地层条件数据和工程阶段数据

#### Scenario: 修订工程上下文不覆盖历史

- **WHEN** 管理员基于当前工程修订改变工程阶段或其它业务上下文
- **THEN** 系统追加新修订并原子推进当前指针
- **AND** 原修订以及引用它的资料、快照和运行保持不变

#### Scenario: 拒绝陈旧或越界空间修订

- **WHEN** 命令引用陈旧工程/区段版本、另一工程的 scope identity、失效父区段或不合法里程边界
- **THEN** 系统返回结构化陈旧版本、授权或校验失败
- **AND** 不产生新修订、当前指针变更、事件或部分审计成功

#### Scenario: 已结束或归档工程限制新增业务事实

- **WHEN** 工程业务修订处于结束或归档状态后提交普通资料登记或上下文修订
- **THEN** 系统拒绝新增普通业务事实
- **AND** 已授权的历史查询、审计与导出仍可引用既有精确版本

### Requirement: 来源交付与工程资料版本形成不可变登记事实

系统 MUST 通过既有 `register-source-delivery` 公共分支登记文件上传、数据库直连或 API 接口形成的冻结交付；每次交付 MUST 归属一个稳定工程资料项，并创建新的不可变工程资料版本与资料 ID。交付 MUST 固定工程/空间修订、接入方式、来源单位、提供方、资料类型、形成时间、工点位置、区间里程、外部版本号、来源指纹、原始内容工件、元数据工件和记录时间；RI-S12 至少一项来源元数据必须存在，但 RA-S1 的三项适用性元数据不得因此缺失。原始正文只通过 C04 内容工件引用保存。（RI-S11、RI-S12、RI-S14；RA-S1）

#### Scenario: 文件交付登记成功

- **WHEN** 获授权调用方提交可用的 C04 原始内容/元数据工件、当前工程/空间修订和完整登记信息
- **THEN** 系统原子创建来源交付事实、工程资料项或其关联、不可变资料版本和资料 ID
- **AND** 返回既有 `SourceDeliveryRefV1` 与 `SourceVersionRefV1`

#### Scenario: 数据库或 API 交付只登记冻结载荷

- **WHEN** 接入方式为数据库直连或 API 接口且提交已冻结的查询结果/响应工件与可重放来源指纹
- **THEN** 系统按同一资料版本模型登记交付
- **AND** 不在运行期间保存通用连接凭据、自由 URL 或供下游直连外部系统的句柄

#### Scenario: 新交付只追加资料版本

- **WHEN** 同一工程资料项收到新上传、外部快照或修正交付
- **THEN** 系统创建新的资料版本和资料 ID，并用显式前序关系归集到同一资料项
- **AND** 旧版本、旧工件、元数据、权限引用和历史下游引用不被覆盖

#### Scenario: 不可用工件或元数据整体失败

- **WHEN** 原始/元数据工件不存在、未耐久、工程不匹配、校验失败，或调用方无对应工件与空间权限
- **THEN** 系统在写入资料事实前拒绝交付
- **AND** 不留下悬空资料版本、放宽权限、C11 业务成功审计或输入就绪事件；已经完成的 C04 受权读取审计仍按其事实保留

### Requirement: 资料段标识具有确定格式和单一归属

系统 MUST 确定性生成并校验资料段标识（Source-Segment ID）为 `资料ID-章节ID-资料段ID`，三个组成部分 MUST 使用不会与分隔符混淆的规范标识。每个资料段 MUST 只属于一个精确资料版本，可关联一个或多个该工程空间区段，并保存章节/表格/监测时间段身份及页码、单元格、记录键或时间范围等来源内定位。C11 只登记段身份与定位，不生成解析正文、JSON-LD、相邻指针或 512 字符语义块。（RI-S13）

#### Scenario: 登记可追溯资料段集合

- **WHEN** 资料处理方为一个精确资料版本提交非空、唯一且定位完整的章节与资料段身份集合
- **THEN** 系统创建不可变资料段集合并返回既有 `SourceSegmentSetRefV1`
- **AND** 每项资料段标识都可拆解并回溯到同一资料 ID、章节 ID、资料段 ID 和来源内定位

#### Scenario: 拒绝不一致资料段

- **WHEN** 资料段标识格式非法、资料 ID 不属于目标版本、同一集合重复、引用另一工程/版本或位置范围倒置
- **THEN** 整个资料段集合登记失败
- **AND** 不接受部分资料段或自动改写近似标识

#### Scenario: 历史段身份不跨版本复用

- **WHEN** 同一工程资料项产生新资料版本并登记结构相同的章节与资料段
- **THEN** 新段使用新资料 ID 形成新的资料段标识
- **AND** 旧资料段继续只指向旧资料版本

### Requirement: 资料权限登记与派生继承不得扩大来源可见性

每个资料版本 MUST 在可被处理或读取前绑定 C06 当前 `SourceAccessGrantRefV1`，新资料默认使用“指定可见”且包含登记人；“工程内共享”和“指定可见”仍同时受工程成员和空间覆盖约束。资料段、定位和后续含正文派生工件 MUST 继承来源资料版本权限，多来源派生取来源权限交集；历史事实保存当时精确授权修订，但每次当前正文读取仍由 C06 复验最新授权。（RI-S14）

#### Scenario: 权限成功绑定后资料才就绪

- **WHEN** 资料版本已写入且 C06 成功创建匹配同一工程、资料版本和全部关联空间的访问修订
- **THEN** 系统把精确授权引用绑定到资料版本并允许后续处理
- **AND** 操作者、时间戳、变更日志和授权引用进入同一可追溯链

#### Scenario: 权限绑定失败时保持不可读

- **WHEN** C06 授权创建、当前验证或审计写入失败
- **THEN** 资料版本保持未就绪且正文默认拒绝
- **AND** 系统不通过补偿性共享、空授权或输入就绪事件继续处理

#### Scenario: 重试未完成的权限收口

- **WHEN** 来源交付事务已经提交但 C06 权限创建或 C11 最终绑定失败，调用方以相同命令和幂等键重试
- **THEN** 系统返回首次资料版本并继续原确定性权限收口步骤
- **AND** 只有资料版本达到就绪状态后才返回公共业务成功，不重复创建交付、资料版本或访问修订

#### Scenario: 无正文权限只返回安全定位

- **WHEN** 调用方可查看业务结论但不满足资料版本当前正文授权
- **THEN** 资料查询最多返回获准的资料段定位和脱敏摘要引用
- **AND** 不通过错误、事件、审计、查询或派生工件泄露原文

### Requirement: 适用性元数据快照冻结三个必含维度

系统 MUST 从一个当前工程修订和一个当前空间区段修订确定性创建不可变适用性元数据（Applicability Metadata）快照，且同时包含 `constructionMethod`、`stratumCondition`、`engineeringStage` 三个非空维度。形成时间、工点位置和空间区段标识可以作为扩展定位，但不得替代必含维度；快照 MUST 保存来源工程/区段精确修订和创建时审计引用。（RA-S1、RA-S4）

#### Scenario: 创建完整适用性元数据快照

- **WHEN** 当前工程与空间区段修订可共同解析出三个必含维度
- **THEN** 系统创建不可变快照并返回既有 `ApplicabilityMetadataSnapshotRefV1`
- **AND** 后续评估可以只凭该快照和精确来源修订重放当时适用性上下文

#### Scenario: 缺少任一维度时拒绝快照

- **WHEN** 施工工法数据、地层条件数据或工程阶段数据任一缺失、为空或来源冲突
- **THEN** 系统拒绝创建快照
- **AND** 不用工点位置、空间区段、默认值或 LLM 推断补齐

#### Scenario: 上下文变化生成新快照

- **WHEN** 工程或区段适用性上下文产生新修订
- **THEN** 新评估准备必须创建新的适用性元数据快照
- **AND** 既有快照及历史评估引用保持不变

### Requirement: 登记、修订与查询遵守授权幂等和原子审计边界

系统 MUST 在任何目标存在性读取、业务写入或正文读取前调用 C06 `verify` 校验精确工程数据分支、工程、空间和资料授权。每个写能力 MUST 使用 C03 `(projectId, commandKind, idempotencyKey)` 和 strict 载荷摘要；同键同载荷返回原结果，同键异载荷失败。业务事实、当前指针、C07/C03 只追加审计、命令收据和适用 Outbox 事件 MUST 在一个本地事务提交；事件仅含精确引用，不含正文。（RI-S14）

#### Scenario: 重放相同来源交付

- **WHEN** 调用方以相同工程、命令类型、幂等键和相同冻结载荷重试来源交付
- **THEN** 系统返回首次创建的来源交付与资料版本引用
- **AND** 不重复创建资料项、资料 ID、授权绑定、审计或事件

#### Scenario: 同键不同载荷冲突

- **WHEN** 调用方复用已完成幂等键但改变工件、元数据、资料项、工程或空间引用
- **THEN** 系统返回不可重试的幂等冲突
- **AND** 原登记事实和引用保持不变

#### Scenario: 未授权与不存在不可区分

- **WHEN** 无当前工程/空间/资料授权的调用方请求存在或不存在的上下文、资料版本或资料段
- **THEN** 两种情况返回同一外部授权拒绝类别
- **AND** 不产生业务事实或泄露存在性和正文

#### Scenario: 审计或 Outbox 失败整体回滚

- **WHEN** 业务事实、命令收据、审计或必要 Outbox 任一步无法写入
- **THEN** 整个命令事务回滚且不返回业务成功
- **AND** 原命令身份可以安全重试

### Requirement: C11 保持既有工程数据公共端口边界

系统 MUST 保持 C02 `EngineeringDataPortV1` 的 `apply`、`freeze`、`read` 方法及其闭合公共分支不变，并在 C11 PostgreSQL adapter 内实现 C02 已声明的 `source-segments` 与 `evidence-access` 读取分支。C11 的工程/区段业务修订、资料段集合登记、适用性元数据快照和工程资料查询结果是工程数据模块拥有的领域能力；它们不得伪装成开放 repository、任意 JSON patch 或 `metadataArtifactRef` 内不可校验的自由字段。跨模块消费者若需要新增公共命令、查询分支或成功形状，MUST 先通过独立契约演进 change 明确 Schema、授权和结果。（RI-S1、RI-S13、RI-S14、RA-S1）

#### Scenario: 现有来源交付端口完成公共登记

- **WHEN** 调用方通过 `register-source-delivery` 提交既有 strict 公共载荷
- **THEN** 模块以 `metadataArtifactRef` 解析并验证 C11 所需来源元数据，返回既有成功引用
- **AND** C02/C09 的公共方法、分支名称和 transport route 无需改变

#### Scenario: 拒绝借自由元数据扩张公共调用

- **WHEN** 调用方试图把任意命令、连接凭据、跨工程引用或未经 Schema 验证的领域写入塞入元数据工件
- **THEN** C11 在产生业务事实前拒绝该内容
- **AND** 不把元数据工件当作通用扩展协议

#### Scenario: 既有读取分支通过公共端口返回结果引用

- **WHEN** 调用方通过 C02 已声明的 `source-segments` 或 `evidence-access` strict 查询分支读取 C11 资料事实
- **THEN** C11 返回既有 `{queryResultRef}` 成功形状并提供同所有者窄 resolve 能力
- **AND** 不修改 `packages/contracts`、新增公共端口、分支、能力或 transport route

### Requirement: 资料段与证据读取形成受权且脱敏的查询结果

系统 MUST 通过既有 `EngineeringDataPortV1.read` 的 `source-segments` 与 `evidence-access` 分支读取 C11 已登记的资料段事实。系统 MUST 在记录或返回查询结果前调用 C06 `verify`，校验与请求一致的精确工程数据分支、工程、空间区段和资料版本；目标定位所需的最小内部查找不得产生外部可观察差异，并且必须在精确复验失败时丢弃。查询成功 MUST 在 C11 自有事实内只追加保存查询分支、输入精确引用、用途、授权上下文、操作者、记录时间和审计引用，并返回既有 `{queryResultRef}` 成功形状；resolve MUST 重新校验当前授权后，依据该引用解析不可变 C11 资料段事实，不复制资料段、C04 工件或其它模块事实。（RI-S13、RI-S14）

#### Scenario: 读取完整资料段集合定位

- **WHEN** 调用方通过 `source-segments` 分支请求同一工程中已存在、已就绪且当前获准的资料段集合
- **THEN** 系统只追加查询结果与成功审计并返回稳定 `queryResultRef`
- **AND** 受权 resolve 返回该集合的精确引用、来源版本、继承的 `SourceAccessGrantRefV1` 及类型化资料段定位，不返回资料正文

#### Scenario: 按证据引用读取安全定位

- **WHEN** 调用方通过 `evidence-access` 分支提交非空证据引用和用途代码，且每项资料版本、资料段与空间区段均属于同一工程并获当前授权
- **THEN** 系统只追加一个覆盖全部请求证据的查询结果并返回稳定 `queryResultRef`
- **AND** 受权 resolve 最多返回原证据引用、资料段定位、资料段集合引用和继承的 `SourceAccessGrantRefV1`，不打开或返回原始正文

#### Scenario: 缺失跨工程与越权使用同类拒绝

- **WHEN** 任一读取或 resolve 请求缺少所需能力、引用另一工程、超出空间或资料授权，或者目标查询结果、资料版本、资料段集合或资料段不存在
- **THEN** 系统对这些情况返回同一外部 `AUTHORIZATION_DENIED` 类别
- **AND** 不泄露目标存在性，不返回部分证据，不写入查询结果或业务成功审计

#### Scenario: 当前授权撤销后不能解析历史查询

- **WHEN** 查询结果创建后，调用方的工程、空间或资料当前授权被撤销或不再覆盖原查询全部目标
- **THEN** resolve 以 `AUTHORIZATION_DENIED` 拒绝访问
- **AND** 历史查询结果、资料段和原授权引用保持不可变，系统不以创建时授权替代当前复验

#### Scenario: 查询结果不形成正文旁路

- **WHEN** 调用方成功读取资料段或证据查询结果
- **THEN** 返回内容不包含原文、解析正文、完整 JSON-LD、任意工件字节或可绕过 C04 的读取句柄
- **AND** 正文仍只能通过 C04 的受权工件读取并按其契约审计；C11 不拥有脱敏摘要事实时不虚构摘要引用

#### Scenario: 相同查询重放不重复结果与审计

- **WHEN** 调用方以相同工程、分支、`queryId` 和相同 strict 查询载荷重试
- **THEN** 系统返回首次创建的 `queryResultRef`
- **AND** 不重复写入查询结果或成功审计；相同 `queryId` 攀附不同载荷时返回幂等冲突

#### Scenario: 查询结果或审计失败整体回滚

- **WHEN** C11 查询结果、命令收据或只追加审计任一步无法在本地事务写入
- **THEN** 整个查询记录事务回滚且不返回业务成功
- **AND** 原查询身份可以安全重试，不引入新的事务或补偿模型

### Requirement: 外部风险事件通过既有工程数据分支登记为不可变输入事实

系统 MUST 实现既有 `EngineeringDataPortV1.apply(register-external-risk-event)`，将一次获授权外部交付登记为唯一的不可变 `ExternalRiskEventRefV1`。登记事实 MUST 固定工程、外部来源精确版本、外部事件键、事件内容工件引用、业务发生时间、证据引用、证据所属精确资料版本以及证据资料段确定的空间区段；正文 MUST 只保存在 C04 内容工件中，不得写入事件表、审计或 Outbox，也不得增加自由 metadata、第二套事件身份或标准化风险记录副本。该精确引用可作为 `RiskInputVersionRefV1` 的 external 分支交给后续评估，不能同时冒充 `riskRecordId`。（RI-S14；RA-S1、RA-S5）

#### Scenario: 登记可追溯的外部风险事件

- **WHEN** 获授权调用方通过精确 `engineering-data.register-external-risk-event` 分支提交可用事件工件、外部来源版本、外部事件键以及至少一项同工程已就绪资料版本的有效资料段证据
- **THEN** 系统返回一个不可变 `ExternalRiskEventRefV1`
- **AND** 该引用唯一绑定提交工程、外部来源版本、外部事件键、事件工件、证据资料版本和证据资料段确定的空间区段
- **AND** 后续评估可仅以该引用选择风险输入 XOR 的 external 分支

#### Scenario: 证据绑定不能被覆盖或伪装

- **WHEN** 已登记外部来源版本与外部事件键的调用方尝试以另一命令改换工程、空间、事件工件、资料版本、资料段证据或业务发生时间
- **THEN** 系统拒绝覆盖既有外部风险事件事实或创建同一外部事件身份的可变修订
- **AND** 既有引用、证据链和审计保持不变，且不创建标准化风险记录副本

#### Scenario: 精确授权先于目标存在性判断

- **WHEN** 调用方登记存在或不存在的事件工件、来源资料版本或资料段，或其当前授权不覆盖命令工程、证据空间和全部来源资料版本
- **THEN** 系统在任何目标存在性结果可观察前复验精确工程数据分支、工程、空间和资料授权，并对缺失、跨工程、越权、非就绪资料及不匹配资料段返回同一不可枚举授权拒绝类别
- **AND** 不产生外部风险事件、命令成功收据、业务成功审计或 Outbox 事件

#### Scenario: 相同幂等命令重放原引用

- **WHEN** 调用方使用相同 `projectId`、命令类型、幂等键和完全相同的 strict 载荷重试登记
- **THEN** 系统返回首次登记的同一 `ExternalRiskEventRefV1`
- **AND** 不重复写入事件事实、审计或 Outbox 事件

#### Scenario: 同键异载荷发生幂等冲突

- **WHEN** 调用方复用已完成命令的 `projectId`、命令类型和幂等键，但改变外部来源、外部事件键、事件工件、证据、时间或其它 strict 载荷内容
- **THEN** 系统返回不可重试的类型化幂等冲突
- **AND** 首次登记事实和引用保持不变

#### Scenario: 业务事实、收据和审计原子提交

- **WHEN** 外部风险事件事实、C03 命令收据或 C07/C03 只追加审计任一步写入失败
- **THEN** 整个本地事务回滚且不返回业务成功
- **AND** 原命令身份可安全重试
- **AND** 因现有 Domain Event 联合没有适用于单独登记外部风险事件的事件类型，本次成功登记不写 Outbox；未来若经契约演进引入适用事件，该事件只能包含精确引用且必须与事实、收据和审计同事务提交

### Requirement: 工程上下文与资料操作绑定 C06 已验证主体

系统 MUST 在任何 C11 业务事实、查询结果、命令收据、审计或资料权限收口写入前，校验命令、查询或 resolve 声明的主体与 C06 当前验证所得授权上下文主体完全一致。声明主体只是一致性输入；成功结果中的操作者、`requestedBy`、命令收据、审计及后续权限登记 MUST 统一使用 C06 已验证主体。主体不一致 MUST 返回与其它越权或目标不可解析情形相同的不可枚举 `AUTHORIZATION_DENIED`，不得降级为契约错误、幂等冲突或存在性错误。（RI-S14；RA-S1）

#### Scenario: 伪造主体不能写入工程资料事实或审计

- **WHEN** 调用方提交工程/空间修订、资料段集合、适用性快照或来源交付命令，并让命令和所携授权快照共同声明一个不同于 C06 当前验证结果的主体
- **THEN** 系统返回不可枚举 `AUTHORIZATION_DENIED`
- **AND** 不创建或修改领域事实、当前指针、查询结果、命令收据、业务审计、Outbox 事件或资料权限收口

#### Scenario: 伪造主体不能读取或登记查询结果

- **WHEN** 调用方以不同于 C06 当前验证结果的主体请求资料处理输入、资料版本、资料段、证据定位或历史查询结果 resolve
- **THEN** 系统返回与缺失、跨工程或无权目标相同类别的 `AUTHORIZATION_DENIED`
- **AND** 不返回目标内容或部分结果，不写入查询结果、命令收据或业务成功审计

#### Scenario: 合规主体保持既有成功与幂等语义

- **WHEN** 命令或查询声明主体、所携授权快照主体与 C06 当前验证主体相同，且其它授权、版本和业务条件均满足
- **THEN** 系统继续按既有事务与幂等语义完成相应写入、读取或 resolve
- **AND** 领域事实、查询记录、命令收据、审计和资料权限登记中的主体均为该 C06 已验证主体

#### Scenario: 伪造主体不能借用既有幂等结果

- **WHEN** 一个已完成命令或查询的身份被不同于 C06 当前验证结果的声明主体重放
- **THEN** 系统先返回不可枚举 `AUTHORIZATION_DENIED`，不返回或泄露既有业务结果
- **AND** 原事实、查询结果、收据、审计和当前指针保持不变
