## Context

固定基线 `3a88273781a1f9473cbf2d813786799a0e7d7633`，工作区初始 clean。用户批准四项减负及移除针对系统外改库、文件篡改的重复验真。台账已修复项不重复实施；C31 500 原因尚未证明，DD-04/DD-06 不纳入本 change。

## Goals / Non-Goals

**Goals:** 已有查询和报告直接按引用读取；集合只在工件边界整理；内部消费登记事实；合法长游标可往返。

**Non-Goals:** 不改变评分、模型预算、专业内容审核及人工决定，不部署、不启动开发服务器、不修改 Git 历史或提交，不增加依赖及迁移。

## Decisions

### D-01 读取范围属于登记对象

C31/C35 复用 C06 已有 `readDeploymentAuthorizationSource` 解析登记 `authorizationContextRef` 中的冻结空间/来源，仅作为对象资源范围；以当前 actor/project/branch 调用既有 `authorizeBusinessAction` 检查当前权限。提供同一组合接缝，输入当前上下文、登记授权引用和业务分支，输出当前上下文；无登记范围或 redacted 拒绝，不使用全工程来源扫描或客户端补齐。授权元数据不新增表，不把旧授权当当前凭据。范围解析只允许服务端登记引用。

C31 用登记的 `authorizationScopeDigest` 选择历史投影事实与绑定游标；删除它与当前完整授权摘要的全等门禁。原查询的工程、目标、空间、时点、历史事实范围及已导出正文保持。当前授权修订可以变化，原来源必须仍有权。初始查询继续保留显式业务筛选；精确读取不依赖客户端选择的额外来源。

### D-02 可信内部读取复用业务决定

C31 提供包内 `readAuthorizedPage` 供同属报告服务消费，复用原请求 DTO 和已授权上下文，不暴露 HTTP 旁路、通用跳过校验参数或新的权限令牌。外部 `readPage` 先执行 D-01，再进入同一分页实现。C35 预览/生成/工件/历史按已登记 sourceRef 解析范围并检查当前 `projection.export`，内部分页不另签 projection.query。正式导出提交前仍检查当前权限。

删除 `ReportResultReadAuthorizationIssuerV1` 和逐页配对签发。C30 `bodies.readBody` 消费入口决定，保留主体/工程一致、C04 用途/来源、正文 Schema、大小与 I/O；C31 不再为每个正文另签调用身份。请求编号仅关联访问，不作为权限凭据。同步已有调用方、组合根和测试；不改其它拥有方写命令的授权。

### D-03 集合只在工件入口规范化

`ArtifactPutCommandV1Schema` 的父工件、证据、附加空间及来源授权集合在字段验证后排序去重。复用现有规范化键，精确版本与资料段共同确定证据身份，不修改输入数组。清单、访问快照和维护输出继续规范表示，原父来源交集及事务引用检查保持。移除 C29 仅为工件格式增加的 `normalizeEvidenceReferences`；其它用于领域摘要或业务集合的整理保留。

### D-04 日常写入信任已登记内容

新输入仍流式计算 SHA-256、长度，检查显式期望并耐久落位。同摘要旧对象及并发 EEXIST 只检查普通文件与长度，不读旧文件全文，不自动隔离旧对象。`verifyObjectForMaintenance`/`verifyPathForMaintenance` 保留全文核验。

registry 的普通父引用、重放、登记回读和 assertUsable 消费已登记行与 stored digest，不重新计算清单摘要或为同一清单单独再查询 digest。登记时计算新清单摘要一次；普通输入 Schema、父存在/工程/用途/来源、事务原子性、写幂等、审计保持。维护 snapshot/list 的显式摘要核验保留。删除没有剩余调用方的私有方法；不改旧数据库约束及记录。

### D-05 游标容量由请求边界控制

移除 contracts 中所有读取游标的 512 字符上限及 quality decoder 同类检查，保留非空、编码、结构、查询/范围及位置检查；页大小和 HTTP 1MiB 输入上限不变。编码格式保持，不增加协议、签名或新配置。

### D-06 验证、文件所有权及接续

生产与测试文件按 implementation-plan 的 IP-ID 所有权修改。扩展既有行为测试，不为指令文本或内部调用顺序加测试；原锁定已取消配对签发的断言改为结果、撤权与重复读取行为。权限/事务由一次独立限定审查收口，无新增审计框架或监控服务。更新台账、原验收 handoff 和项目 AGENTS 的当前约束。RI-S6/RI-S14、RA-S5～RA-S7 的版本、来源及业务审计保留。

## Risks / Trade-offs

普通流程不发现系统外同长度文件替换，独立维护负责核验。登记授权快照只能恢复冻结资源，不能授权；新增来源权限不能扩大历史查询范围。包内分页只供已检查的业务动作使用，每次独立 HTTP 请求仍检查当前权限。旧手册中逐层签发要求由本设计替代，已导出报告不改写。

## Migration Plan

无数据库迁移和数据重写。按 IP-02/IP-03/IP-04 与 IP-01 独立修改后集成，同版发布 API/Worker/Web。新 change 验证后原功能验收继续真实浏览器/Electron 与现场取证；工程回归不冒充现场通过。本轮不归档原验收 change。
