## Purpose

为 RiskFlow 建立可审核发布、可精确解析和可由证据重建的识别知识事实源，并使非结构化知识编制在统一有界 Agent 运行时内形成待审修订或显式人工复核。

## ADDED Requirements

### Requirement: 识别知识包使用独立稳定定义身份

系统 MUST 在同一工程内分别以 `process-model`、`risk-mechanism`、`standard-library`、`case-library`、`retrieval-evidence-base` 管理五类识别知识；每类只有一个稳定定义身份，正文采用带 `schemaVersion`、工程、适用性、条目、关系和证据引用的严格不可变内容包。规范库、案例库和风险机理库 MUST 能独立修订、送审、发布、停用和回滚；系统不得建立第二套类型表、发布状态或按名称推断的“最新版”。（RI-S3、RI-S4）

#### Scenario: 五类知识独立演进

- **WHEN** 获授权用户分别提交风险机理、规范和案例内容包的新修订
- **THEN** 系统把它们登记到三个不同的稳定定义身份，并分别保留基线发布和修订链
- **AND** 任一类型的修订不改变另两类的发布引用

#### Scenario: 未声明字段和错类型内容被拒绝

- **WHEN** 内容包带有未知字段、错工程身份、错定义类型或缺少版本和证据清单
- **THEN** 系统在形成可送审修订前返回结构化校验失败
- **AND** 不把该内容登记为其它知识类型或宽松保存

### Requirement: 工序模型覆盖必含工序与可执行关系

工序模型 MUST 至少覆盖 `扩径准备`、`变径空间扩挖`、`刀盘扩径`、`盾体扩径`、`缩径转换` 五类工序。每个工序节点 MUST 固定输入、输出、关联设备/部件、状态参数、监测指标、适用性和证据；依赖边只能使用共享领域词汇中的 `时间先后关系`、`资源依赖关系`、`受力依赖关系`、`作用关系`，且两端节点必须存在、不得自指或重复，时间先后关系不得成环。（RI-S3、RI-S51）

#### Scenario: 完整工序模型通过结构校验

- **WHEN** 内容包包含五类必含工序，节点字段齐全，所有关系端点存在且时间关系无环
- **THEN** 系统逐项接受节点与关系，并生成可复读的结构校验结果

#### Scenario: 缺失工序或关系不一致被拒绝

- **WHEN** 内容包缺少任一必含工序，或关系存在未知端点、自指、重复、非法关系类型或时间环
- **THEN** 系统以对应节点或关系为单位记录拒绝和稳定原因码
- **AND** 不形成可发布的工序模型修订

### Requirement: 风险机理库覆盖六类机理并连接工序证据

风险机理库 MUST 至少覆盖 `掌子面稳定性失效`、`支护结构失效`、`渗流突涌`、`过挖与地表沉降`、`施工装备故障`、`装配连接失效` 六类机理。每个机理条目 MUST 固定适用性元数据、前置条件、触发因素、演化或失效路径、后果、关联工序节点、状态参数、监测指标及证据；其引用对象必须属于同一工程的精确工序模型或共享领域枚举。（RI-S3、RI-S52～RI-S54）

#### Scenario: 六类机理形成闭合关系

- **WHEN** 六类机理均有至少一个条目，且每个条目都连接已声明工序、参数或指标及合格证据
- **THEN** 系统接受机理条目并保存可由机理反查工序和证据的关系

#### Scenario: 孤立机理或跨工程引用被拒绝

- **WHEN** 机理条目没有工序或证据，引用不存在的参数/指标，或连接其它工程的工序发布
- **THEN** 系统逐项拒绝并指出关系或工程边界原因
- **AND** 不以自由文本关系替代缺失引用

### Requirement: 规范与案例条目保留原始依据和适用性

规范标准库 MUST 以独立条目记录国家、行业或企业标准的精确版本、条款定位、适用性和来源证据；类比工程案例库 MUST 记录盾构、顶管、矿山法、扩挖或地下工程风险案例的工程条件、过程/事件、结果、处置及来源证据。条目不得把未审核常识、模型记忆或无定位摘要当作正式知识。（RI-S3、RI-S53）

#### Scenario: 规范条款与案例可追溯

- **WHEN** 条目提供精确来源资料段、版本、定位和适用性，并通过当前工程资料授权
- **THEN** 系统接受条目，且下游能从条目反查原资料段和发布版本

#### Scenario: 无定位知识不进入正式库

- **WHEN** 条目只有自然语言结论、文件名或模型声称的出处，无法解析到合格证据
- **THEN** 系统拒绝该条目并记录证据不合格原因

### Requirement: 证据可达性和关键工序覆盖由确定性策略收口

系统 MUST 使用获审核的精确知识校验策略检查每个工序、关系、机理、规范和案例条目的证据可达性，以及策略声明的关键工序覆盖门槛。证据 MUST 属于精确识别准备快照的保留资料段集合，或属于同一工程内经公共证据访问分支确认可读的精确资料段；检查时必须复验当前工程、空间和资料授权。策略缺失、证据不存在/被排除/越权、关键工序无机理或证据覆盖时 MUST 封闭失败，不得使用内置默认知识补齐。（RI-S3、RI-S51～RI-S56）

#### Scenario: 关键工序达到审核策略门槛

- **WHEN** 内容包覆盖校验策略列出的全部关键工序，且每个关键工序具有要求数量和类别的机理与可达证据
- **THEN** 系统记录策略版本、逐项证据检查和覆盖决定，并允许内容进入送审

#### Scenario: 清洗排除或授权撤销使证据失效

- **WHEN** 条目引用了识别准备中已排除的资料段，或当前来源授权已撤销
- **THEN** 系统以不可枚举的证据资格/授权失败拒绝消费
- **AND** 不读取或泄露目标正文，也不换用相似资料段

### Requirement: 检索证据库组合精确冻结三个发布集合

每个 `retrieval-evidence-base` 内容包 MUST 精确引用同一工程的一个 `risk-mechanism` 发布、一个 `standard-library` 发布和一个 `case-library` 发布，且三者在组合要求时刻和记录时间边界内均已人工批准、生效且未停用。组合一经形成不得原地替换成员；任一成员变化必须创建新的组合修订和发布。（RI-S3、RI-S53～RI-S56）

#### Scenario: 三个合格发布形成组合

- **WHEN** 获授权用户提交三个同工程、同时有效且类型匹配的精确发布引用
- **THEN** 系统形成仅含这三个成员及校验依据的不可变组合候选
- **AND** 后续解析能证明组合中的机理发布与识别基础返回的机理发布一致

#### Scenario: 成员缺失或停用时组合不可消费

- **WHEN** 组合缺少任一成员、成员跨工程/错类型/未生效，或成员在查询记录时间边界内已停用
- **THEN** 系统返回结构化等待或失败，不用其它发布替换该成员
- **AND** 已冻结历史运行仍可按原业务时刻和记录时间重放当时的精确组合

#### Scenario: 组合发布绑定与事件原子成立

- **WHEN** 人工批准发布或按历史版本回滚产生新的 `retrieval-evidence-base` 发布
- **THEN** 系统在 C16 同一发布事务内依次成立 C16 发布、C17 精确发布绑定、事实审计、命令回执和 `knowledge.identification-basis-published.v1` Outbox 事件
- **AND** 事件只包含同工程、类型匹配、版本精确且在双时间边界内有效的工序、机理、规范、案例和检索证据库五个发布
- **AND** 任一成员、绑定、审计、回执、事件校验或 Outbox 写入失败时事务整体回滚，不返回成功发布，也不在事务后补绑定或补发事件

### Requirement: 配置导入与 Agent 编制进入同一治理事实模型

甲方已审核配置包 MUST 直接经过同一严格内容和证据校验后形成 C16 待审修订，不强制 Agent 重新解释；非结构化知识编制的合格结果 MUST 经过相同校验并形成相同类型的待审修订。两条入口 MUST 共享修订绑定、校验结果和发布门，不得产生“导入版”与“Agent 版”两套正式知识。（RI-S4）

#### Scenario: 已审核配置包直接导入

- **WHEN** 获授权用户提交结构合法、证据合格且覆盖达门的审核配置包
- **THEN** 系统跳过 Agent 任务并创建一个不可变待审修订
- **AND** 后续仍须经过独立人工复核和发布决定

#### Scenario: Agent 合格候选形成同类修订

- **WHEN** `knowledge-authoring` 任务的全部增量通过确定性校验并成功收口
- **THEN** 系统创建与直接导入相同定义身份、内容 Schema 和生命周期约束的待审修订

### Requirement: 非结构化知识编制使用统一有界 Agent 任务

系统 MUST 通过 C08 `knowledge-authoring` 任务固定工程、发起者、父运行、精确识别准备快照、目标定义类型、可选基线发布、模型、提示、工具、预算、增量和校验策略版本。工具只能按冻结清单读取获授权资料段切片或精确基线知识，不得提供通用数据库、文件系统、Shell、自由联网、任意外部系统或发布写能力；恢复、修正和重试不得扩大输入或重置预算。（RI-S4）

#### Scenario: Agent 在冻结范围内读取并编制

- **WHEN** Agent 请求白名单中的资料段切片或精确基线知识，且目标属于冻结清单和当前授权
- **THEN** 系统返回有界观察工件并累计工具、对象、字节和墙钟预算

#### Scenario: 越界工具请求被拒绝

- **WHEN** Agent 请求冻结清单外对象、未注册工具、自由联网、写命令或超过对象/预算上限
- **THEN** C08 记录结构化拒绝和资源消耗，C17 不执行目标读取或写入

#### Scenario: 工具对象必须属于冻结清单

- **WHEN** Agent 使用已注册工具，但请求的资料段集合或资料段不属于冻结准备的保留成员，或请求的基线发布、定义类型与清单固定的精确基线不一致
- **THEN** 确定性成员校验在目标读取前拒绝请求，C08 保存稳定原因码和已消耗预算
- **AND** 不把“工具已在白名单”解释为可以读取同工程内任意对象

#### Scenario: 生产组合依赖或授权来源缺失时关闭失败

- **WHEN** 正式准备窄读、领域策略、C08 任务能力、C07 复核能力、C16 生命周期接缝或 C06 受信调用来源任一未注入或不可用
- **THEN** 系统在对应任务、读取、修订、复核或发布副作用前返回结构化失败
- **AND** 不使用任务信封中的其它能力、调用方自报 capability、测试替身或默认策略补位

### Requirement: Agent 增量逐项确定性校验且无发布权

`knowledge-authoring` 候选 MUST 由目标知识类型限定的封闭领域操作组成，不得使用通用 JSON Patch、整对象覆盖或自然语言写命令。确定性模块 MUST 对每项操作记录接受/拒绝、稳定原因码和证据；存在拒绝项时不得收口正式内容，可修复错误只能在同一任务剩余预算内生成新候选。Agent 或 Agent 派生身份不得发布、停用、回滚知识或替代人工决定。（RI-S4）

#### Scenario: 类型化增量全部通过

- **WHEN** 候选只包含目标定义允许的操作，且字段、引用、关系、证据和覆盖均合格
- **THEN** 系统逐项记录接受并由确定性模块生成不可变候选内容
- **AND** 结果仅为待审知识修订，不是已发布知识

#### Scenario: 发布或绕过校验的增量被拒绝

- **WHEN** Agent 提交发布/停用/回滚动作、通用路径补丁、整对象载荷或试图修改人工决定
- **THEN** 系统在副作用前拒绝，记录终止类原因且不允许修正循环绕过

### Requirement: 编制失败必须进入人工复核而非静默通过

模型不可用、工具失败、预算耗尽、租约恢复失败、确定性终止拒绝或任务取消而未形成合格修订时，系统 MUST 保存失败诊断和已成立的动作/候选/校验证据，并幂等创建一个指向该次失败知识修订的 C07 `knowledge-revision` 复核任务。失败修订 MUST 明确标记为不可发布；人工复核可决定补充资料或重新编制，但不得把失败载荷直接批准为正式发布。（RI-S4）

#### Scenario: 预算耗尽创建一次失败复核

- **WHEN** 编制任务耗尽任一硬预算且没有合格候选
- **THEN** 系统进入显式失败终态，保存诊断引用并创建一个知识修订复核任务
- **AND** 重放失败收口不创建第二个修订或复核任务

#### Scenario: 失败不触发替代结果

- **WHEN** 模型、工具或恢复失败且缓存中存在旧候选或基线发布
- **THEN** 系统不切换模型、不扩容、不把缓存/基线冒充本次结果，也不自动发布

#### Scenario: 失败复核使用独立工程授权

- **WHEN** 终态失败需要创建不可发布修订并请求 `knowledge-revision` 人工复核
- **THEN** 组合根分别通过 C06 为 `knowledge-modeling.submit-revision`、`knowledge-modeling.request-review` 和 C16 内部的 `review-audit.request-review` 签发同工程、同 actor、精确调用身份的授权上下文
- **AND** 任一授权缺失、过期、撤销、工程或 actor 不一致时停在最后已成立阶段，后续重放只补未完成阶段且不重复修订或复核

### Requirement: 识别基础按准备快照和双时间精确解析

系统处理 C02 `identification-basis` 时 MUST 先经上游窄读取能力取得精确识别准备快照及其 C15 已收口保留结果，并按当前授权验证工程、空间和资料范围；随后以 `requiredAt` 为业务时刻、命令 `issuedAt` 为记录时间边界，通过 C16 解析同工程有效的 `process-model`、`risk-mechanism` 和 `retrieval-evidence-base` 发布，复验组合的三个成员。`identificationPolicySetRef` MUST 由组合根注入、归 C21/C24 所有的精确策略提供者返回；C17 不定义或治理该策略。成功结果必须使用 C02 已有四个类型化引用，任何输入、发布、组合、策略或授权缺失均封闭失败。（RI-S3、RI-S4、RI-S55～RI-S56）

#### Scenario: 精确识别基础解析成功

- **WHEN** 准备快照可读，三类知识发布及组合成员在双时间边界内有效，且策略提供者返回精确版本
- **THEN** 系统返回类型化的工序模型、风险机理、检索证据库和识别策略集引用
- **AND** 所有引用均属于请求工程且不会随之后发布变化

#### Scenario: 缺失策略或组合不一致时封闭失败

- **WHEN** 策略提供者无精确引用，或组合中的风险机理发布不同于独立解析结果
- **THEN** 系统返回类型化失败，不硬编码默认策略、不改选其它组合，也不返回半套基础

#### Scenario: 评估解析行为保持不变

- **WHEN** 既有调用方以 `knowledge-modeling.assessment-basis` 权限解析评估知识
- **THEN** 系统仍使用评估能力分支并逐字段返回与 C16 既有实现相同的结果或错误

### Requirement: 识别知识事实支持幂等审计和有界下游读取

系统 MUST 先使 C04 内容、校验或诊断工件耐久，再以 C03 事务追加 C17 校验收据、修订/发布绑定、编制任务绑定、命令回执和事实审计；数据库只保存受约束索引和引用，不复制知识正文。相同幂等键和规范化载荷 MUST 返回原引用且不重复 Agent、修订、复核或发布绑定；同键异载荷 MUST 返回不可重试冲突。C20/C24 只能按工程、精确发布/准备引用和当前授权经显式窄接口读取，C17 不实现双索引、检索排序或识别图。（RI-S3、RI-S4、RI-S51～RI-S56）

#### Scenario: 相同请求幂等重放

- **WHEN** 调用方以相同命令、幂等身份和规范化载荷重试导入、编制启动、失败收口或发布绑定
- **THEN** 系统返回原有引用，Agent/修订/复核/索引和审计计数不增加

#### Scenario: 工件或事务失败不成立正式绑定

- **WHEN** 工件写入、引用守卫、业务事务、审计、命令回执、发布事件或 Outbox 任一步失败
- **THEN** 系统不暴露可消费的修订/发布绑定；发布事务中的 C16 release、C17 binding、审计、回执和事件整体回滚，并保留可安全重试的事务前工件

#### Scenario: 下游读取严格有界

- **WHEN** C20 或 C24 以获授权工程和精确发布引用读取内容
- **THEN** 系统只返回该引用绑定的严格知识包和验证元数据
- **AND** 不扫描其它工程、其它类型或全部历史，不执行索引或检索逻辑
