## ADDED Requirements

### Requirement: 外部风险事件通过既有工程数据分支登记为不可变输入事实

系统 MUST 实现既有 `EngineeringDataPortV1.apply(register-external-risk-event)`，将一次获授权外部交付登记为唯一的不可变 `ExternalRiskEventRefV1`。登记事实 MUST 固定工程、外部来源精确版本、外部事件键、事件内容工件引用、业务发生时间、证据引用、证据所属精确资料版本以及证据资料段确定的空间区段；正文 MUST 只保存在 C04 内容工件中，不得写入事件表、审计或 Outbox，也不得增加自由 metadata、第二套事件身份或标准化风险记录副本。该精确引用可作为 `RiskInputVersionRefV1` 的 external 分支交给后续评估，不能同时冒充 `riskRecordId`。（RI-S14；RA-S1、RA-S5）

#### Scenario: 登记可追溯的外部风险事件

- **WHEN** 获授权调用方通过精确 `engineering-data.register-external-risk-event` 分支提交可用事件工件、外部来源版本、外部事件键以及至少一项同工程已就绪资料版本的有效资料段证据
- **THEN** 系统返回一个不可变 `ExternalRiskEventRefV1`
- **AND** 该引用唯一绑定提交工程、外部来源版本、外部事件键、事件工件、证据资料版本和证据资料段确定的空间区段
- **AND** 后续评估可仅以该引用选择风险输入 XOR 的 external 分支

#### Scenario: 证据绑定不能被覆盖或伪装

- **WHEN** 已登记外部来源版本与外部事件键的调用方尝试以另一命令改换工程、空间、事件工件、资料版本、资料段证据或业务发生时间
- **THEN** 系统拒绝覆盖既有外部风险事件事实或创建同一外部事件身份的可变修订
- **AND** 既有引用、证据链和审计保持不变，且不创建标准化风险记录副本

#### Scenario: 精确授权先于目标存在性判断

- **WHEN** 调用方登记存在或不存在的事件工件、来源资料版本或资料段，或其当前授权不覆盖命令工程、证据空间和全部来源资料版本
- **THEN** 系统在任何目标存在性结果可观察前复验精确工程数据分支、工程、空间和资料授权，并对缺失、跨工程、越权、非就绪资料及不匹配资料段返回同一不可枚举授权拒绝类别
- **AND** 不产生外部风险事件、命令成功收据、业务成功审计或 Outbox 事件

#### Scenario: 相同幂等命令重放原引用

- **WHEN** 调用方使用相同 `projectId`、命令类型、幂等键和完全相同的 strict 载荷重试登记
- **THEN** 系统返回首次登记的同一 `ExternalRiskEventRefV1`
- **AND** 不重复写入事件事实、审计或 Outbox 事件

#### Scenario: 同键异载荷发生幂等冲突

- **WHEN** 调用方复用已完成命令的 `projectId`、命令类型和幂等键，但改变外部来源、外部事件键、事件工件、证据、时间或其它 strict 载荷内容
- **THEN** 系统返回不可重试的类型化幂等冲突
- **AND** 首次登记事实和引用保持不变

#### Scenario: 业务事实、收据和审计原子提交

- **WHEN** 外部风险事件事实、C03 命令收据或 C07/C03 只追加审计任一步写入失败
- **THEN** 整个本地事务回滚且不返回业务成功
- **AND** 原命令身份可安全重试
- **AND** 因现有 Domain Event 联合没有适用于单独登记外部风险事件的事件类型，本次成功登记不写 Outbox；未来若经契约演进引入适用事件，该事件只能包含精确引用且必须与事实、收据和审计同事务提交
