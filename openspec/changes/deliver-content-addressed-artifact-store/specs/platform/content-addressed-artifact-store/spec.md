## Purpose

为 RiskFlow 提供单机可恢复的不可变内容寻址工件存储，使原始资料、解析与模型产物、Agent 增量、诊断和导出在不进入数据库正文或工作流状态的前提下，仍能通过精确版本、证据、权限与审计引用被安全复用。

## ADDED Requirements

### Requirement: 工件接口只接受版本化清单与受控字节流

系统 MUST 以 strict Zod V1 Schema 定义工件写入、读取、引用校验、哈希清单、孤儿维护和恢复核对 DTO，并从对应 Schema 推导 TypeScript 类型。工件引用 MUST 复用 C02 `ContentArtifactRefV1` 或 `DiagnosticArtifactRefV1`；清单 MUST 固定工件种类、精确引用、SHA-256、字节长度、MIME、工程、空间范围、资料访问授权、授权策略版本、父工件引用、C01 `EvidenceReference` 集合和双时间。二进制正文 MUST 通过有背压的字节流传递，不得进入 DTO、数据库、Outbox、审计、错误、日志或 LangGraph checkpoint。（RI-S14、RI-S21～RI-S23、RI-S42、RI-S44、RI-S52～RI-S58、RI-S61～RI-S65；RA-S1、RA-S3～RA-S7）

#### Scenario: 接受内容工件清单
- **WHEN** 调用方提供 V1 写入元数据、合法授权上下文和有限字节流
- **THEN** 系统返回 `ContentArtifactRefV1` 与完整 V1 清单
- **AND** 清单的精确版本由实际内容摘要确定

#### Scenario: 接受诊断工件清单
- **WHEN** 基础设施或领域模块按同一写入契约保存受保护诊断内容
- **THEN** 系统返回 `DiagnosticArtifactRefV1` 与同形权限/摘要清单
- **AND** 诊断引用不能被误作内容工件引用

#### Scenario: 证据与版本不可含糊
- **WHEN** 写入元数据携带证据引用或父工件引用
- **THEN** 每项引用必须包含精确实体与版本，证据必须包含非空资料段标识及精确资料版本
- **AND** 空值、“当前版本”、契约外字段或裸路径被拒绝

#### Scenario: 原始输入可以尚无资料段证据
- **WHEN** 原始上传发生在 RI-S13 资料分段之前
- **THEN** 清单允许证据引用集合为空但仍固定工程、权限、内容摘要和父工件集合
- **AND** 后续派生工件在已有资料段证据时必须保留继承的证据链

### Requirement: 内容按 SHA-256 不可变落位并安全去重

系统 MUST 从实际字节流计算 SHA-256 与长度，以摘要派生不含用户文件名的规范存储键，并在专用 staging 中完成写入、长度/期望摘要校验、文件与父目录耐久刷新后原子落位。已存在同摘要对象时 MUST 验证其长度和摘要后复用，绝不覆盖或就地修改；同摘要不同字节、既有对象损坏或路径类型异常 MUST 终止。（RI-S21～RI-S23、RI-S44、RI-S52、RI-S62、RI-S65；RA-S1、RA-S3、RA-S7）

#### Scenario: 首次写入耐久落位
- **WHEN** 一个新字节流完整写入且实际摘要/长度符合调用方期望
- **THEN** 对象在引用提交前已位于由 SHA-256 派生的不可变位置并完成耐久刷新
- **AND** 用户文件名、相对路径和 MIME 不参与物理路径选择

#### Scenario: 相同内容复用物理对象
- **WHEN** 不同合法命令提交完全相同的内容
- **THEN** 系统可以形成各自精确工件清单，但只保留一个经校验的物理对象
- **AND** 每个清单的权限、证据、用途和审计保持独立

#### Scenario: 期望摘要或长度不匹配
- **WHEN** 调用方提供的期望 SHA-256 或期望长度与实际字节流不一致
- **THEN** 写入以不可重试的完整性错误终止且不提交工件清单或引用
- **AND** 临时内容只能作为未引用 staging/孤儿处理

#### Scenario: 已存在对象损坏时拒绝去重
- **WHEN** 规范存储键已存在但对象不是普通文件、长度不符或实际摘要不符
- **THEN** 系统返回终止完整性错误并隔离该对象
- **AND** 不覆盖损坏对象、不提交新引用，也不以新输入静默修复历史损坏

#### Scenario: 并发写入相同摘要保持单一字节事实
- **WHEN** 多个执行者并发写入相同内容
- **THEN** 所有成功调用观察到同一规范摘要和一个不可变物理对象
- **AND** 临时文件竞争、重命名冲突或重试不产生部分对象

### Requirement: 物理耐久先于 PostgreSQL 引用提交

系统 MUST 先使物理对象耐久可读，再使用 C03 单个 PostgreSQL 事务提交工件清单、命令幂等结果和只追加审计。数据库提交失败可以留下未引用孤儿，文件落位或完整性校验失败 MUST 阻止数据库引用；下游领域事实在自己的 C03 事务中引用工件前，MUST 同事务确认精确清单存在、工程与权限范围兼容。C04 不新增 C02 契约外领域事件；工件登记使用零 Outbox 事件，后续领域事实按其既有事件契约发布引用。（RI-S14、RI-S44、RI-S62～RI-S65；RA-S3～RA-S7）

#### Scenario: 工件登记原子提交
- **WHEN** 物理对象已耐久且工件元数据、授权与证据全部合法
- **THEN** 工件清单、命令结果和审计在同一 PostgreSQL 提交后同时可见
- **AND** 提交只公开精确工件引用，不发布未声明的领域事件

#### Scenario: 数据库失败只留下孤儿
- **WHEN** 对象耐久落位后工件清单、审计或命令结果提交失败
- **THEN** 数据库不存在该工件引用或部分清单
- **AND** 物理对象被分类为可在宽限期后处理的未引用孤儿

#### Scenario: 文件失败不留下悬空引用
- **WHEN** staging 写入、刷新、落位或既有对象校验失败
- **THEN** PostgreSQL 中不提交清单、命令结果、审计或领域引用
- **AND** 调用方收到结构化文件/完整性错误

#### Scenario: 下游拒绝未登记引用
- **WHEN** 一个领域事务尝试引用不存在、版本不符或未耐久登记的工件
- **THEN** 工件引用校验和该领域事务一起失败
- **AND** 领域事实、审计与 Outbox 均不留下部分提交

#### Scenario: 工件登记与领域事实保持两步边界
- **WHEN** 工件登记成功而后续领域命令失败或尚未执行
- **THEN** 工件清单保持有效但没有被伪装成领域事实
- **AND** 它可以按未被领域引用的清单执行保留或后续孤儿策略

### Requirement: 命令重放和物理竞争保持幂等

系统 MUST 使用 C03 `(projectId, commandKind, idempotencyKey)` 与包含实际内容摘要的 strict 规范载荷收口工件写入。同键、相同元数据和相同内容的串行或并发重试 MUST 返回首次工件引用，不重复清单或审计；同键但内容摘要或受保护元数据不同 MUST 返回不可重试幂等冲突并保留原结果。（RI-S14、RI-S44、RI-S62～RI-S65；RA-S3～RA-S7）

#### Scenario: 相同写入重试返回原引用
- **WHEN** 调用方以相同命令身份、元数据与内容重试已完成写入
- **THEN** 系统返回首次提交的精确工件引用和清单
- **AND** 清单、审计和物理对象数量不增加

#### Scenario: 同键不同内容冲突
- **WHEN** 调用方复用同一幂等键提交不同内容摘要或不同权限/证据元数据
- **THEN** 系统返回不可重试幂等冲突并指向原命令结果
- **AND** 新落位但未引用的对象仅按孤儿规则处理

#### Scenario: 同内容不同命令保持独立清单
- **WHEN** 两个不同业务命令合法保存相同字节但具有不同父引用、证据或权限范围
- **THEN** 系统复用物理对象并分别保存两个不可变清单
- **AND** 一个清单的授权或生命周期不能改变另一个清单

### Requirement: 权限从授权上下文和父工件只收窄继承

系统 MUST 在工件清单中冻结工程、空间范围、资料访问授权引用和授权策略精确版本。直接工件以当前 C02 授权上下文为权限来源；派生工件 MUST 汇总全部父工件的限制和证据，调用方必须可读取每个父工件，且显式附加范围只能收窄、不能删除父限制或跨工程合并。读取和引用校验 MUST 在暴露任何字节、MIME、长度、摘要、证据或存在性之前完成服务端授权。（RI-S14、RI-S42、RI-S44、RI-S52～RI-S58、RI-S61～RI-S65；RA-S1、RA-S3～RA-S7）

#### Scenario: 直接工件冻结当前权限
- **WHEN** 调用方保存不含父工件的原始输入
- **THEN** 清单复制当前授权上下文的工程、空间、资料授权和策略版本作为不可变权限快照
- **AND** 后续授权策略变化不改写历史清单

#### Scenario: 派生工件继承所有父限制
- **WHEN** 调用方从一个或多个有权读取的父工件生成新内容
- **THEN** 新清单保留全部父工件引用、证据和访问限制的并集，并允许增加更窄限制
- **AND** 不允许省略任一父限制或扩大正文可见性

#### Scenario: 跨工程父工件被拒绝
- **WHEN** 派生请求包含其它工程的父工件或授权上下文工程不一致
- **THEN** 请求以不可重试授权错误终止
- **AND** 不形成文件引用、清单、审计或领域事件

#### Scenario: 无权读取不泄露对象信息
- **WHEN** 调用方缺少清单要求的工程、空间、资料授权或策略能力
- **THEN** 系统在返回任何正文或清单字段前拒绝访问
- **AND** 错误、日志与时序行为不确认目标摘要或对象是否存在

#### Scenario: 已获授权读取成功
- **WHEN** 调用方的冻结授权上下文覆盖清单全部访问限制且目的合法
- **THEN** 系统返回清单和经完整性校验的字节流
- **AND** 授权策略版本与工件引用进入结构化访问记录

### Requirement: 读取必须封闭路径并验证内容完整性

系统 MUST 仅从清单摘要重新派生规范位置，拒绝调用方提供路径、URL 或文件名；打开对象时 MUST 阻止路径穿越、符号链接、目录及非普通文件。读取 MUST 先校验权限和预期长度，并在流结束前计算实际 SHA-256；长度或摘要不符 MUST 返回终止完整性错误，调用方不得基于失败流提交派生事实或工件。（RI-S21～RI-S23、RI-S42、RI-S52～RI-S58、RI-S61～RI-S65；RA-S3、RA-S7）

#### Scenario: 经验证的流式读取
- **WHEN** 获授权调用方读取一个完整对象并消费到流终点
- **THEN** 系统确认实际长度与 SHA-256 等于不可变清单
- **AND** 返回完成态读取收据供后续派生提交引用

#### Scenario: 损坏对象不能被消费为成功
- **WHEN** 对象缺失、被截断或字节发生变化
- **THEN** 读取以终止完整性错误结束并产生受保护诊断引用
- **AND** 不生成成功读取收据、不自动改写清单或用其它同名文件替代

#### Scenario: 非法路径形态被拒绝
- **WHEN** 存储根或规范对象路径包含符号链接、目录、设备文件或逃逸根目录的解析结果
- **THEN** 系统在读取/写入正文前终止
- **AND** 诊断不暴露宿主绝对路径或目录内容

### Requirement: 孤儿维护在宽限期和引用锁下安全收口

系统 MUST 区分未完成 staging、无任何 PostgreSQL 清单引用的物理对象、已登记但尚无领域引用的工件清单以及被一个或多个清单共享的对象。维护操作 MUST 使用冻结宽限期与排他维护边界，只处理超期 staging 或零清单引用对象；删除前后都必须在与写入互斥的边界中复核引用，先隔离再形成维护审计，绝不删除已登记或共享对象。（RI-S14、RI-S44、RI-S62～RI-S65；RA-S3、RA-S7）

#### Scenario: 超期无引用对象被清理
- **WHEN** 物理对象早于宽限期且在维护边界内两次确认没有任何工件清单引用
- **THEN** 系统先把对象移入隔离区并记录维护结果，再安全删除
- **AND** 结果包含摘要、发现时间、处理状态和审计引用但不含正文

#### Scenario: 新近孤儿只报告不删除
- **WHEN** 未引用对象尚未超过冻结宽限期
- **THEN** 系统把它报告为待观察孤儿并保持字节不变
- **AND** 并发写入仍可完成登记

#### Scenario: 共享对象不会因单个清单未使用而删除
- **WHEN** 同一摘要仍被至少一个工件清单引用
- **THEN** 维护操作保留物理对象
- **AND** 未被领域使用的其它清单不会把物理引用计数降为零

#### Scenario: 维护与写入竞争不产生悬空引用
- **WHEN** 孤儿扫描与相同摘要的写入/登记并发
- **THEN** 排他维护边界和登记前复核保证结果只有“保留并成功登记”或“清理后重新耐久落位再登记”
- **AND** 不出现数据库成功引用已删除对象

#### Scenario: 宕机后的隔离对象可恢复收口
- **WHEN** 进程在隔离、维护审计提交或最终删除之间终止
- **THEN** 下次维护根据已提交清单和维护记录恢复、还原或完成删除
- **AND** 不凭临时文件名猜测引用关系

### Requirement: 哈希清单和恢复核对以数据库引用完整为硬门槛

系统 MUST 能从一致的 PostgreSQL 工件清单快照生成确定排序、逐项可校验的 V1 哈希清单；每项至少包含精确工件引用、种类、SHA-256、字节长度、MIME、权限策略版本和证据引用摘要。恢复核对 MUST 比较已恢复数据库、文件快照和给定哈希清单，逐项分类为完整、缺失、损坏、未登记孤儿或清单冲突；任何已提交引用缺失/损坏/冲突 MUST 阻止恢复通过，额外孤儿可以报告后按宽限期处理。系统不得从文件名或哈希清单补造 PostgreSQL 工件或领域事实。（RI-S14、RI-S42、RI-S44、RI-S62～RI-S65；RA-S3～RA-S7）

#### Scenario: 生成确定性哈希清单
- **WHEN** 调用方在冻结数据库快照上生成 V1 哈希清单
- **THEN** 相同清单集合产生相同条目排序与逐项摘要
- **AND** 清单记录 schema 版本、生成时间、备份批次引用和数据库/文件快照引用

#### Scenario: 数据库引用均可验证时恢复通过
- **WHEN** 每个已提交工件清单在文件快照中存在且长度、摘要一致
- **THEN** 恢复核对返回通过及完整计数
- **AND** 报告可单独列出不影响引用完整性的额外孤儿

#### Scenario: 缺失或损坏引用阻止恢复
- **WHEN** 任一已提交工件引用对应文件缺失、长度不符或摘要不符
- **THEN** 恢复核对返回终止失败及受保护诊断引用
- **AND** 应用不得把该恢复点声明为可用或从其它内容静默替代

#### Scenario: 数据库恢复点晚于文件快照被拒绝
- **WHEN** 哈希清单显示文件快照不是数据库引用集合的超集
- **THEN** 恢复核对失败并指出缺失引用集合
- **AND** 不接受“稍后补文件”作为已通过状态

#### Scenario: 孤儿不被补造成清单
- **WHEN** 文件快照包含哈希合法但数据库没有对应工件清单的对象
- **THEN** 系统只把它分类为孤儿
- **AND** 不创建工件引用、证据、权限或领域事实

### Requirement: 错误、审计、敏感数据和可观测性保持闭合

系统 MUST 以闭合工件错误类别表达输入、大小、摘要、引用、授权、继承、文件 I/O、登记、完整性、维护互斥和恢复失败，并标明可重试性、阶段、发生时间、受保护诊断引用及有限上下文引用；上层 MUST 确定性映射到 C02 `ModuleErrorV1`，不得匹配完整文案。成功写入和维护变更 MUST 追加审计；读取成功/拒绝、完整性失败和恢复核对 MUST 形成结构化访问或运维记录。日志、指标、审计和错误不得包含正文、原始文件名、宿主绝对路径、凭据、模型响应或思维链。（RI-S14、RI-S44、RI-S62～RI-S65；RA-S3～RA-S7）

#### Scenario: 临时 I/O 故障可按原身份重试
- **WHEN** 临时磁盘或数据库连接故障被分类为可重试
- **THEN** 错误保留原命令、工件、策略和阶段引用
- **AND** 重试不切换内容、权限、证据、摘要算法或版本

#### Scenario: 完整性与授权失败不可绕过
- **WHEN** 发生摘要冲突、历史对象损坏、权限不足或权限继承扩大
- **THEN** 错误被分类为不可重试终止失败或授权拒绝
- **AND** 不通过重试、换路径、换文件名或省略父引用继续

#### Scenario: 审计失败阻止工件登记
- **WHEN** 工件清单可写但只追加审计无法提交
- **THEN** 工件清单与命令结果一起回滚
- **AND** 已耐久文件仅作为孤儿等待维护

#### Scenario: 可观测数据不泄露正文
- **WHEN** 系统记录写入字节数、耗时、去重结果、校验结果、孤儿数量或恢复状态
- **THEN** 记录只包含稳定身份、摘要后缀/受保护引用、计数、阶段和时间
- **AND** 不包含工件字节、完整路径、凭据或无权证据内容

### Requirement: 大文件与并发操作保持流式和有界

系统 MUST 对写入、读取、哈希清单和恢复核对使用流式、有背压且有界并发的处理方式；不得按工件大小等比例把完整正文载入 JavaScript heap。实现 MUST 允许通过配置限制单工件字节数、并发数、staging 占用和维护批次，并记录冷/热写读吞吐、首字节/完成耗时、峰值 heap、磁盘占用、去重率与核对速率；目标硬件 SLA 由 C37 冻结。（RI-S21～RI-S23、RI-S52～RI-S58；RA-S1、RA-S3、RA-S7）

#### Scenario: 大工件在有界内存中往返
- **WHEN** 调用方以小块异步流写入并完整读取一个显著大于允许 heap 增量的工件
- **THEN** 写入、摘要、耐久落位和读取校验成功
- **AND** 实现不要求调用方或 adapter 构造完整正文缓冲区

#### Scenario: 并发写读受配置约束
- **WHEN** 并发操作达到冻结上限
- **THEN** 系统通过背压或结构化可重试错误控制资源
- **AND** 不突破 staging/文件描述符上限、不丢弃字节或降级跳过哈希校验

#### Scenario: 超过单工件上限被安全拒绝
- **WHEN** 输入流累计字节超过配置的硬上限
- **THEN** 系统终止写入且不提交引用
- **AND** 已写临时内容进入 staging 清理流程

#### Scenario: 性能基线不伪装为生产 SLA
- **WHEN** 定向基准在当前开发/CI 存储上运行
- **THEN** 报告记录样本大小、并发、运行环境和测量值
- **AND** 在 C37 目标硬件基准完成前不宣称生产吞吐、延迟、RPO 或 RTO 已满足
