## Purpose

为规范条文到评估规则提供可追溯、可审核且确定性收口的知识编制与适用性筛选能力，使 RA-S3/S4 只能产出来源合格、无未决冲突并经人工批准的不可变规则依据。

## ADDED Requirements

### Requirement: 合格且冻结的规范条文输入

系统 MUST 只以 C15 已完成且确定性收口的数据清洗结果中的保留资料段作为规范条文输入，并固定工程、来源版本、资料段标识、内容工件、清洗结果、来源授权、适用性上下文和创建时刻。输入来源 MUST 属于已授权的国家规范、行业标准或企业规程等受控标准来源；被隔离、被排除、来源不合格、引用失配、跨工程或未完成清洗的资料段 MUST 在模型调用前拒绝。系统 MUST NOT 从原始 Office 文件、自由文件路径、联网搜索、显示名称或未冻结的“最新版本”补齐条文。

#### Scenario: 真实规范资料段进入知识编制

- **WHEN** 一个来源合格且经 C15 保留的真实规范资料段及其精确证据引用被提交到当前工程
- **THEN** 系统接受冻结输入，并使后续规则持续引用同一资料段、来源版本和内容工件

#### Scenario: 排除或未授权资料段被拒绝

- **WHEN** 输入资料段已被 C15 排除、来源授权不覆盖当前任务或资料段不属于受控标准来源
- **THEN** 系统在调用模型前返回结构化失败且不产生规则候选

### Requirement: C15 清洗结果有界读取

系统 MUST 通过精确工程、actor、请求身份、请求时刻、C06 授权上下文和 C08 任务引用读取 C15 已确定性收口的 `DataCleaningResultV1` 及其精确结果工件引用。读取 MUST 在查询目标和重放历史回执前复验当前 `engineering-data.read` 授权，并同时限定工程和任务引用；成功结果只返回 strict 清洗结果与 `resultArtifactRef`，不得返回原始资料正文、任意 C04 读取句柄、自由路径、列表、搜索或“最新结果”旁路。授权无效、actor/工程不符、跨工程、结果缺失、结果工件不可见或任务—结果绑定不一致 MUST 返回同一种不可重试类型化拒绝，且不泄露目标是否存在或差异化原因。读取审计 MUST 只追加；相同请求身份和规范载荷重放 MUST 返回同一结果且不重复追加审计，同一请求身份携带不同规范载荷 MUST 返回不可重试幂等冲突。

#### Scenario: 当前授权读取清洗结果与工件引用

- **WHEN** 当前获授权调用方以同一工程、actor 和精确已完成 C08 任务引用读取清洗结果
- **THEN** 系统返回 strict `DataCleaningResultV1` 与对应 `resultArtifactRef`，并记录只追加读取审计

#### Scenario: 不可用清洗结果不可枚举

- **WHEN** 授权已撤销、actor 或工程不匹配、任务属于其它工程、结果缺失、结果工件不可见或任务—结果绑定不一致
- **THEN** 系统返回相同 code 与相同公开结构的不可重试拒绝，不返回结果、工件引用、存在性或差异化原因

#### Scenario: 清洗结果读取不提供正文旁路

- **WHEN** C19 取得清洗结果与结果工件引用
- **THEN** 返回值不含原始规范正文、C04 读取句柄、自由路径、列表或搜索能力，后续资料段正文仍须通过既有有界且受权的资料段读取路径取得

#### Scenario: 清洗结果重复读取不重复审计

- **WHEN** 当前授权仍有效的调用方以相同请求身份和规范载荷重复读取同一任务结果
- **THEN** 系统返回同一清洗结果与 `resultArtifactRef`，且不重复追加读取审计；授权撤销后不得重放历史成功，同一请求身份改传其它任务引用时返回幂等冲突

### Requirement: 有界规范知识编制 Agent

系统 SHALL 复用 C08 `knowledge-authoring` 任务契约，将精确模型、提示模板、领域工具、预算、增量 Schema、校验策略和冻结输入绑定到任务。该任务只能读取冻结的合格规范资料段及与之相容的 C18 已发布指标体系，并提交逐项类型化规则增量；不得调用通用数据库、文件系统、Shell、自由联网或知识治理写命令，也不得发布、批准、停用或回滚定义。每项增量 MUST 记录接受、拒绝及原因；字段、格式、引用和增量不完整等可修复错误仅可在原任务剩余预算内修正，来源资格、权限、版本兼容或规则冲突失败不得通过循环绕过。

#### Scenario: Agent 只形成候选修订

- **WHEN** `knowledge-authoring` 任务生成结构化规则候选且所有确定性校验通过
- **THEN** 收口结果仅为 C16 待治理知识修订引用及可选校验引用，发布状态仍由人工流程决定

#### Scenario: 越权动作直接失败

- **WHEN** Agent 尝试发布规则、批准审阅、访问未冻结资料或调用未注册工具
- **THEN** 系统拒绝该动作、保留失败证据与预算消耗且不产生正式规则发布

### Requirement: 结构化评分规则唯一内容契约

结构化评分规则 MUST 使用 C02 `structured-scoring-rule` 定义类型和既有 `StructuredScoringRuleV1` 字段，固定规则身份、三维适用条件、指标项、评分阈值、分级区间、例外条款、证据定位、规则版本与审核状态。Agent 编制候选正文中的 `reviewStatus` MUST 固定为 `pending`，只表示候选工件在编制阶段的自述状态；不得由 Agent 预写 `approved` 或 `rejected`。规则的审核事实 MUST 仅来自 C16 精确发布及其相符的 C07 人工决定；发布不得改写不可变正文，已发布消费方不得以正文 `reviewStatus` 作为准入门禁或未审核证据。三维适用条件 MUST 同时包含 `constructionMethod`、`stratumCondition` 和 `engineeringStage` 的非空规范身份集合；指标 MUST 存在于同一兼容集合的 C18 指标体系；阈值、区间、例外和证据 MUST 可确定性校验。

数值型 `scoringThresholds` 的闭合语义固定为：`lt` 是 `(-∞, value)`，`lte` 是 `(-∞, value]`，`eq` 是闭合单点 `[value, value]`，`gte` 是 `[value, +∞)`，`gt` 是 `(value, +∞)`，`between(value, upperValue)` 是 `[value, upperValue)`；非数值 `eq` 只匹配同类型同值。规范排序后的同一规则数值阈值不得重叠或留下内部空洞，重复的非数值 `eq` 也 MUST 被拒绝。`gradeIntervals` 固定为左闭右开 `[lowerBound, upperBound)`；缺少 `lowerBound` 表示 `(-∞, upperBound)` 且 `upperBound` 仍为开边界，缺少 `upperBound` 表示 `[lowerBound, +∞)` 且 `lowerBound` 仍为闭边界。同一规则的等级区间按下界规范排序后 MUST 首尾相接、互不重叠且无内部空洞；有限最小或最大外边界之外的取值不得猜测等级，必须返回结构化越界失败。C19 的冲突/重叠检测与下游评分 MUST 复用 C19 导出的同一确定性边界归一和求值能力，不得各自解释端点。若未来需要逐规则自定义闭合性，MUST 通过独立公共契约演进 change 增加字段；本 change 不向 contracts 增加闭合性字段。规则正文 MUST 留在内容寻址工件中，治理事实、审计、错误和事件不得复制正文或模型原始响应。

#### Scenario: 完整规则通过内容校验

- **WHEN** 候选规则三维条件完整、指标存在、阈值与区间有效且证据定位指向冻结规范资料段
- **THEN** 系统逐项接受该规则并记录其内容摘要、兼容集合和精确证据引用

#### Scenario: 不完整或悬空规则被拒绝

- **WHEN** 候选缺少任一适用性维度、引用不存在的指标、阈值或区间有空洞/重叠、例外引用悬空或证据不指向冻结资料段
- **THEN** 系统拒绝该项并记录稳定原因码，且该项不得进入送审、发布或适用规则集

#### Scenario: 端点与无穷边界唯一求值

- **WHEN** 数值恰好落在 `between` 或等级区间的共享端点，或落在缺少下界/上界的区间
- **THEN** 系统按左闭右开、负无穷上界开、正无穷下界闭的固定语义得到唯一评分与等级，C19 冲突检测和下游评分结果一致

#### Scenario: 不连续或越界取值被拒绝

- **WHEN** 同一规则的规范化阈值或等级区间发生重叠、内部空洞，或求值落在声明的有限外边界之外
- **THEN** 系统返回结构化失败且不按相邻区间、数组顺序或默认等级补值

### Requirement: 冲突与重叠确定性检测

系统 MUST 在结构化规则修订进入 C16 发布前，按“规则编制与确定性内容校验 → 冲突/重叠检测 → 关系事实与候选 C16 修订原子耐久化 → C07 冲突复核决定 → C16 知识修订审核 → 发布事务内最终门禁 → 发布”的顺序，在同一工程、兼容集合、指标和相交三维适用域内比较候选规则与可适用的既有已发布规则。规则版本身份 MUST 精确为 `ruleId + ruleVersion.entityId + ruleVersion.versionId`；双方按该 tuple 规范排序后才可计算关系。候选集合和比较基线各自出现重复规则版本身份 MUST 整体拒绝；候选继承基线中正文摘要相同的同一规则版本时只跳过该自比较，身份相同但正文不同 MUST 作为版本身份冲突拒绝。检测只生成候选—候选和候选—基线关系，不重复生成基线—基线关系。

系统 MUST 先把阈值相交结果规范化为结论和拟议处置均恒定的极大连通交叠域；每个无序规则版本对在每个该交叠域上至多形成一个事实。相同取值域产生不同评分或等级、例外关系互相矛盾时 MUST 标记为冲突；取值域相交且结论一致时 MUST 标记为重叠。冲突和重叠均 MUST 按版本化闭合优先级策略固定 `retainedRuleVersionRef` 与 `excludedRuleVersionRef`，保留双方证据；适用规则集组装只能消费该拟议处置，不得按数组顺序或 `ruleId` 重算。关系域键 MUST 由策略精确版本、规范排序后的双方规则版本身份和精确交叠域摘要组成；关系语义键 MUST 再加入关系类型与拟保留/拟筛除版本；耐久 `relationId` MUST 再绑定工程与候选 `KnowledgeRevisionRefV1`。因此一个关系事实恰好归属一个候选修订，同一语义关系在新修订中必须获得不同关系引用、C07 任务和决定。同一语义键的贡献 MUST 合并证据并只保留一个规范事实；同一关系域键出现不同关系类型或拟议处置、相同摘要对应不同交叠域载荷、或其它非证据载荷不一致时 MUST 整体失败。持久化不得以静默 `do nothing` 吞掉身份碰撞或把新修订关系留在旧修订名下。

任何关系事实缺失、重复或归属错误，未决冲突，错目标/过期/非批准决定，比较基线漂移，或关系集合摘要不一致 MUST 阻止该结构化规则修订进入 C16 人工审核或发布。系统不得等规则发布后才补做检测，也不得按顺序、置信度或“最新版本”静默选边。

#### Scenario: 冲突规则全部被拦截

- **WHEN** 两条适用域相交的规则对同一指标取值给出不同评分或等级
- **THEN** 系统在候选规则发布前产生绑定该 C16 修订的精确 `rule-conflict` 事实与复核目标，并阻止该修订进入 C16 审核或发布

#### Scenario: 等价重叠被完整记录

- **WHEN** 两条规则的适用域和取值域相交且结论一致
- **THEN** 系统对每个规范化极大交叠域只记录一个重叠事实、双方证据和闭合策略产生的拟保留/拟筛除精确版本，组装直接消费该事实而不重算成员

#### Scenario: 同一语义关系按候选修订隔离归属

- **WHEN** 两个先后候选修订在同一工程、同一策略下产生相同规则版本对和交叠域
- **THEN** 系统为两个候选修订保存不同 `relationId` 且每行只外键归属自己的修订；旧关系的 C07 任务或决定不得解除新修订门禁

#### Scenario: 重复和矛盾的关系贡献确定性收口

- **WHEN** 多个阈值相交路径对同一无序规则版本对产生重复关系贡献，或同一关系域键产生不同关系类型或拟议处置
- **THEN** 完全相同贡献规范化为一个事实；矛盾贡献使整个修订提交失败，修订、关系、审计和回执均不留下部分事实

#### Scenario: 关系检测或补链失败保持未发布

- **WHEN** 关系事实写入、C07 冲突任务创建或任务链接追加在任一步失败
- **THEN** 系统不得创建结构化规则发布；已耐久候选修订继续被门禁，使用原幂等身份重试只补齐缺失事实或链接且不重复检测结论、审阅任务或审计

### Requirement: 规则冲突人工审阅

每个待处置冲突 MUST 在结构化规则进入 C16 `knowledge-revision` 审核前，通过 C07 `rule-conflict` 审阅任务交由有权限的人处理，并绑定候选 C16 修订、精确冲突版本、验证快照、证据快照、等待运行、审阅策略，以及闭合优先级策略产生的拟保留/拟筛除规则版本。只有从 C07 决定事实读取、与目标、工程、版本和审阅类型一致的人工 `approve-publication` 可用于后续审核或放行；该决定只批准精确拟议处置，不得使冲突双方同时进入适用规则集。`reject`、`return-for-revision`、错目标决定、Agent 输出、缓存 link 状态或调用方自造状态均不得视为冲突已解决。冲突审阅决定 MUST NOT 改写已提交或已发布规则；拒绝或退回后必须形成新候选修订并重新检测。

#### Scenario: 人工决定解除精确冲突门禁

- **WHEN** 授权审阅者对当前精确冲突提交相符的 `approve-publication` 决定且后续候选仍通过全部校验
- **THEN** 系统只对该冲突版本及获批拟议处置解除门禁、保留决定链，并在组装时筛除未获保留的规则

#### Scenario: 过期决定不能放行

- **WHEN** 审阅决定指向已被新规则修订替代的冲突版本
- **THEN** 系统拒绝放行并继续保持新冲突版本为未决状态

### Requirement: 结构化规则复用统一定义生命周期

规则集合 MUST 作为 C16 `structured-scoring-rule` 稳定定义的不可变修订和发布治理。提交候选修订时 MUST 将来源、内容、兼容性校验以及基于精确比较基线得到的冲突/重叠事实与该 C16 修订原子绑定；其后必须补齐全部 C07 冲突任务链接并取得精确批准，C16 才可接受 `knowledge-revision` 审核请求。发布调用的真实顺序 MUST 为：C06 验证人工发布者 → C07 验证该修订的 `knowledge-revision` 批准证明 → C16 发布事务内锁定并复验修订、审核链接、当前基线和有效时刻 → C19 最终门禁复验关系归属/唯一性/完整摘要及全部精确 C07 冲突决定 → 插入 C16 release → 原子提交发布审计、回执和适用 Outbox。C19 最终门禁 MUST 在 `business.knowledge_releases` 插入之前执行；门禁失败必须使 release、发布审计、完成回执和 Outbox 均保持零新增，同时保留此前已提交的候选修订、关系和人工决定。Agent 可提交候选修订但不得成为审核者或发布者；已发布规则不得原地更新、删除或被未审核默认规则替代。

#### Scenario: 人工批准后形成不可变规则发布

- **WHEN** 无未决冲突的规则修订获得相符的 `knowledge-revision` 人工批准并由授权用户发布
- **THEN** 系统创建新的精确规则发布且历史修订与决定链保持可重建

#### Scenario: Agent 或未审核修订不能发布

- **WHEN** 发布命令由 Agent 身份发起或目标修订尚无有效人工批准
- **THEN** 系统拒绝发布且不改变当前有效规则版本

#### Scenario: C16 发布前重复校验冲突决定

- **WHEN** 已获知识修订批准的候选在发布时缺少关系事实、仍有未决冲突、冲突决定不再精确匹配或比较基线已经变化
- **THEN** C19 门禁在 C16 release 插入前使发布事务整体失败；该修订的 release 数、`knowledge.publish-approved-release` 审计数、完成回执数和发布 Outbox 数均不增加

#### Scenario: 关系与两级人工决定的审计顺序可观察

- **WHEN** 一个含冲突的候选依次完成修订提交、C07 冲突决定、C16 `knowledge-revision` 审核决定和发布
- **THEN** 修订提交检查点先存在候选修订、完整关系和 `knowledge.submit-revision` 审计但不存在知识审核或发布审计；C07 冲突批准事实先于 C16 `knowledge.request-review` 成功审计；C16 知识审核批准事实先于唯一的 `knowledge.publish-approved-release` 审计，且该发布审计与唯一 release、完成回执和 Outbox 同事务出现

### Requirement: 三维适用性筛选与完整原因

系统 MUST 将精确 C01 `ApplicabilityMetadataSnapshotV1` 与已发布规则的 `constructionMethod`、`stratumCondition`、`engineeringStage` 三个条件逐维匹配。仅当三维均匹配且例外条款不排除当前上下文时规则才可纳入；任一维不匹配、例外命中、来源/版本失效、兼容集合不一致或冲突未决时 MUST 筛除。对候选全集中的每条规则，结果 MUST 恰好记录一次纳入或筛除决定、稳定原因码、适用性快照引用、规则发布/版本与检测证据，不得返回无理由的部分集合。

#### Scenario: 三维匹配规则被纳入

- **WHEN** 规则的三个适用条件均包含快照中的规范身份且没有命中例外
- **THEN** 规则被纳入一次并记录三维匹配证据

#### Scenario: 不适用规则全部筛除

- **WHEN** 规则在任一适用性维度不匹配或命中例外条款
- **THEN** 规则被筛除且原因明确到对应维度或例外，不得进入适用规则集成员

### Requirement: 不可变适用规则集组装与人工发布

系统 MUST 以精确工程修订、适用性元数据快照、规则发布、C18 评估配置发布集合、兼容身份、组装策略版本和业务有效时刻物化适用规则集候选。候选 MUST 包含按规范身份排序的纳入规则引用及对候选全集的完整筛选决定；缺少规则或任一 C18 成员、成员未生效/已停用、跨工程、版本/兼容身份不一致、筛选结果不完整或存在未决冲突时 MUST 整体失败，不得回退、混用或返回部分集合。适用规则集 MUST 复用 C16 `applicable-rule-set` 生命周期，经独立人工审核后创建新的不可变发布；Agent 不得发布或自行审批。

#### Scenario: RA-S3/S4 形成适用规则集

- **WHEN** 至少一条来自真实规范的已发布规则与三维适用性快照和完整 C18 配置集合相容，全部筛选决定完整且无未决冲突
- **THEN** 系统形成 `applicable-rule-set` 候选，并仅在人工批准后创建不可变发布

#### Scenario: 配置或冲突不完整时整体失败

- **WHEN** C18 集合缺失成员、规则与配置兼容身份不一致或任何候选规则仍有未决冲突
- **THEN** 系统返回结构化失败，不发布规则集且不返回可供评分消费的部分结果

### Requirement: 公共评估依据解析

系统 MUST 通过 C02 `KnowledgeModelingPortV1.resolve(assessment-basis)`，以命令中的工程、授权、精确评估准备快照和 `requiredAt` 解析一个不可变 `AssessmentBasisReleaseSetRefV1`。解析结果 MUST 绑定该准备快照所引用的适用性元数据快照、唯一有效的 C19 适用规则集发布和相容的 C18 配置发布集合；解析后下游只能使用该精确引用。尚未组装或未批准、缺失/停用、业务时刻无效、准备快照不匹配、跨工程或兼容身份不一致 MUST 返回结构化等待或失败，不得猜测快照内容、回退历史版本或拼装“最新”成员。

#### Scenario: 精确依据可供后续评估冻结

- **WHEN** 评估准备快照已有匹配且有效的适用规则集和完整 C18 配置集合
- **THEN** 系统返回唯一精确评估依据发布集合引用，不复制规则或配置正文

#### Scenario: 未准备完成时不返回默认依据

- **WHEN** 评估准备快照尚无匹配的已批准规则集或所需成员在 `requiredAt` 不可用
- **THEN** 系统返回结构化等待或失败且不使用默认规则、缓存候选或旧版本冒充正式依据

### Requirement: 评估依据发布集合成员的有界读取

系统 MUST 由 C19 提供一个只接受精确 `AssessmentBasisReleaseSetRefV1`、C06 授权上下文和标准请求幂等身份的狭窄读取入口；请求不得另带调用方可伪造的 `projectId`、`actorId`、名称、列表或 latest 选择器，工程与 actor 只能来自当前 C06 验证结果。入口 MUST 在查询集合或历史回执前按当前事实复验授权上下文及 `knowledge-modeling.read` 能力，只允许读取同一工程中已经物化的不可变评估依据发布集合。成功结果 MUST 是顶层 strict 判别联合，精确为 `{kind: "succeeded", schemaVersion: "1", assessmentBasisReleaseSetRef, memberDigest, applicableRuleSetMember, scoringRuleMembers, configurationMembers}`，不得包装或返回内部 `releaseSet`。`applicableRuleSetMember` MUST 包含精确 `releaseRef`、`revisionRef`、C04 `artifactRef` 与 `contentDigest`；`scoringRuleMembers` 的每项 MUST 包含同样四个字段，按发布引用规范排序，并与适用规则集正文中全部 `included refs` 逐项投影完全一致，输入或快照中的重复、缺失或额外成员均整体失败，不得静默去重；`configurationMembers` MUST 按定义类型规范排序且恰好覆盖 C18 的 11 类，每项包含 `definitionType`、精确 `releaseRef`、`revisionRef`、C04 `artifactRef` 与 `contentDigest`。每个 `contentDigest` MUST 等于对应 strict 正文的规范 JSON SHA-256 摘要，使 C25 在经 C04 当前授权读取正文后可以复算并核对；`memberDigest` MUST 覆盖上述三个成员集合的完整规范投影。入口 MUST NOT 返回内部集合记录中的工程、准备/适用性快照、配置集合、业务/记录时刻，亦不得返回适用规则集、评分规则或配置正文、显示名称、任意元数据或未发布成员；消费方读取正文时 MUST 另行通过 C04 当前授权与留痕。

运行时边界固定如下，且不得把各分支互相伪装：请求 strict Schema 失败返回 `failed/UNSUPPORTED_CONTRACT`，不调用 C06 或 C19 存储；C06 当前事实明确拒绝、过期、撤权、能力或工程不符返回同一 strict `{kind: "unavailable", error: {code: "AUTHORIZATION_DENIED", ...}}`，只保留 C06 安全审计，不查询 C19 目标/历史回执，也不写 C19 领域审计或完成回执；C06 验证自身发生可重试技术故障返回 `failed/TRANSIENT_FAILURE`，同样不查询目标或写 C19 回执。当前授权通过后，集合零行、跨工程、成员快照 strict 失败、规则成员与 `included refs` 不一致或摘要不一致 MUST 返回同一个不可枚举 unavailable；首次该结果与成功结果一样原子写一条 C19 只追加领域审计和 C03 完成回执。

授权复验 MUST 先于历史回执。授权通过后，相同幂等身份与规范载荷重放 MUST 根据既有回执的 audit action 返回原成功或 unavailable 且不重复审计；同键异载荷 MUST 返回 `failed/IDEMPOTENCY_CONFLICT`。历史 success 回执只能在同一不可变成员快照仍存在且 strict 校验通过时重放；success 回执对应行缺失、损坏、摘要漂移或 audit action 缺失/未知属于不可变事实完整性破坏，MUST 返回 `failed/TERMINAL_FAILURE`，不得改写为 unavailable 或创建第二回执。数据库连接、超时、死锁/序列化、C03 或审计提交等可重试故障 MUST 返回 `failed/TRANSIENT_FAILURE`，事务回滚且不完成回执，原幂等身份可重试；其它不可重试技术完整性故障返回 `failed/TERMINAL_FAILURE` 且同样不完成新回执。

reader 只重放已冻结成员，不重新解析“当前发布”：集合形成后成员被停用或出现新发布不得改写该集合；新运行必须通过公共 resolve 形成新集合。reader 也不打开 C04 工件或判断消费方当前是否仍可读取正文；消费方必须使用返回的精确工件引用另行通过 C04 当前授权读取，失败不得由 reader 回退到其它成员。首次在当前授权下得到 completed unavailable 后，即使外部状态后来变化，同一幂等身份仍重放原 unavailable；调用方必须使用新请求身份重新读取。

#### Scenario: 当前授权读取精确集合

- **WHEN** 调用方提交当前仍有效且具备读取能力的 C06 授权上下文和同工程精确评估依据发布集合引用
- **THEN** 系统在授权复验后返回该不可变集合的 strict 成员清单并记录只追加读取审计

#### Scenario: 不可用目标不可枚举

- **WHEN** 集合或必需成员缺失、授权已撤、引用属于其它工程、引用不存在或调用方不可见
- **THEN** 系统返回相同 code 与相同公开结构的不可重试类型化拒绝，不返回成员、存在性或差异化原因

#### Scenario: 成员清单固定精确引用

- **WHEN** 一个有效集合被成功读取
- **THEN** 结果固定集合引用与版本、成员摘要，适用规则集的发布/修订/工件/内容摘要，与其 `included refs` 完全一致且规范排序的评分规则成员，以及 11 类配置各自的定义类型、发布/修订/工件/内容摘要

#### Scenario: 规则成员与内容摘要可复验

- **WHEN** C25 使用成功结果中的工件引用经 C04 当前授权读取适用规则集、评分规则和 11 类配置正文
- **THEN** C25 对 strict 正文复算的每个 `contentDigest` 与结果相等，适用规则集 `included refs` 的规则发布成员规范投影与 `scoringRuleMembers` 完全一致；任一缺失、额外成员或摘要不符均不得作为有效评估依据

#### Scenario: 成员读取不返回正文

- **WHEN** 消费方取得评估依据发布集合成员清单
- **THEN** 结果不包含适用规则集、配置或评分规则正文、显示名称、自由字段或未发布成员，正文只能由消费方使用返回的 C04 工件引用另行受权读取并留痕

#### Scenario: 读取重放保持幂等且不绕过撤权

- **WHEN** 当前授权仍有效的调用方以相同幂等身份和规范载荷重放读取
- **THEN** 系统只在历史 success 回执和不可变成员快照仍一致时返回原成员清单且不重复追加领域审计；若授权已经撤销，则先返回统一拒绝而不查询或重放历史成功结果

#### Scenario: 不可用结果也可幂等重放

- **WHEN** 当前授权有效但精确集合缺失或成员快照不可用，且调用方以相同幂等身份和规范载荷重复读取
- **THEN** 系统两次均返回同一 strict unavailable 结果，只存在一条 `.unavailable` 领域审计和一个完成回执；同键改传其它集合引用时返回幂等冲突

#### Scenario: 瞬时失败不伪装成不可用

- **WHEN** 数据库、审计或 C03 回执提交发生瞬时失败
- **THEN** 系统返回 strict failed 技术结果且不完成读取回执，后续可使用原幂等身份重试

#### Scenario: 历史成功与不可变快照矛盾时失败关闭

- **WHEN** 当前授权有效且历史 success 回执存在，但其集合行、成员快照、成员摘要或对应 audit action 缺失或损坏
- **THEN** 系统返回 `failed/TERMINAL_FAILURE`，不返回成员、不改写原回执、不新增 unavailable 审计或第二回执

#### Scenario: 冻结集合不受后续发布变化追溯改写

- **WHEN** 评估依据集合形成后其成员被停用或同类型发布了新版本，且调用方仍持有当前有效读取授权
- **THEN** reader 仍只返回冻结集合中的精确成员；新评估必须重新 resolve，reader 不选择新成员、旧成员替代或“当前版本”

### Requirement: 授权、事务、幂等与可重放审计

每个 C19 写命令 MUST 在读取目标存在性或产生副作用前校验精确工程和对应 C06 能力；读取和解析 MUST 先限定工程、精确引用、定义类型与时间边界。结构化规则提交时，C16 修订、C19 metadata、完整冲突/重叠事实、C03 命令回执和审计 MUST 在一个事务原子成立；发布时，C19 最终门禁、C16 release、回执、审计和适用 outbox MUST 在一个事务原子成立。C07 task/decision 属于独立事务边界，MUST 采用已耐久发布门禁与稳定幂等身份补偿，任何中断不得产生规则发布。适用规则集 revision/metadata、release/audit/receipt/outbox 以及 basis set/audit/receipt 分别按其命令原子提交。相同幂等身份与规范载荷 MUST 返回原结果，同键不同载荷 MUST 返回不可重试冲突；并发组装/发布必须由预期版本和数据库约束收口。审计链 MUST 能从适用规则集反向重建 C18 配置、三维快照、每条规则、规范资料段、Agent 候选、逐项校验、冲突/人工决定和发布者，但不得保存或展示模型思维链、正文、凭据或内部数据库错误。

#### Scenario: 重放返回同一结果

- **WHEN** 调用方以相同幂等身份和规范载荷重试规则修订、冲突处置或规则集组装命令
- **THEN** 系统返回原精确结果且不新增修订、冲突、审阅任务、规则集或事件

#### Scenario: 任一原子副作用失败即回滚

- **WHEN** 持久化校验事实、筛选决定、治理事实、审计、回执或适用事件中的任一项失败
- **THEN** 当前命令的全部业务副作用回滚并返回脱敏结构化失败
