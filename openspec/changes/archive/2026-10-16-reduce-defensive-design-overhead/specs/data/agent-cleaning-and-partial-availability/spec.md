## MODIFIED Requirements

### Requirement: data-cleaning 任务只使用版本化只读领域工具

清洗工具 MUST 限于任务冻结的资料与监测输入，宿主提供短选项映射真实资料版本和资料段，记录读过的位置并管理分页。每次新资料读取在统一入口检查当前权限，内部工件读取复用决定。工具只观察事实，清洗增量仅能排除已有引用并说明原因。

#### Scenario: 清洗任务经生产组合根以受权能力启动

- **WHEN** 清洗准备已形成冻结清单，且服务端授权来源可为同一发起者、工程、空间和资料范围签发 `agent-task.start-task` 的当前有效授权
- **THEN** 生产组合根通过 C06 取得仅含 `agent-task.start` 能力的授权上下文，并以该上下文调用既有 `AgentTaskPortV1.startTask` 创建 `embedded/data-cleaning` 任务
- **AND** 系统不复用、扩写或伪造原 `engineering-data.freeze` 上下文，不新增公共命令字段或第二套运行时；授权签发或 C08 启动失败时不创建可运行任务，并分别保留 C06 安全审计与 C08/C03 已可靠成立的失败证据

#### Scenario: 读取获准的文档资料段切片

- **WHEN** Agent 请求冻结 JSON-LD 中存在、属于获准资料版本且数量不超过工具策略上限的资料段
- **THEN** 工具返回受保护的不可变观察工件引用，其中仅含所请求的结构、正文片段、定位、置信度和数值保护标记
- **AND** 读取及观察工件继承原资料权限并计入 C08 工具、对象、上下文和墙钟预算

#### Scenario: 读取获准的监测快照切片

- **WHEN** Agent 请求冻结监测快照中存在且数量不超过上限的成员、对齐点或特征
- **THEN** 工具返回受保护观察工件引用，并保持原样本值、规范值、特征值、单位、状态和证据不变
- **AND** 工具不重新对齐、插值、外推或计算新特征

#### Scenario: 越权或越界工具请求被拒绝

- **WHEN** 动作请求冻结集合外对象、其它工程/资料、未列入白名单的工具、超过对象预算，或当前资料授权已撤销
- **THEN** C08 返回稳定的工具、预算或授权错误并记录失败证据
- **AND** 不打开目标正文、不调用其它处理器、不扩大任务输入或工具集合

#### Scenario: 多资料按短选项读取

- **WHEN** 模型依次读取不同资料或同资料多页
- **THEN** 返回正确来源与连续进度，不因同用途读取编号冲突失败

#### Scenario: 模型误选来源

- **WHEN** 模型选项不在任务来源集合
- **THEN** 反馈选项错误供原预算内修正，不读取其它资料

### Requirement: 业务可用性由确定性策略收口

系统 MUST 按资料类型与实际用途选择版式和可用性要求，关键字段、数值保真、来源及排除原因保留。CSV 使用真实表格结构，正常空白页不要求正文，未参与归并的单候选不要求归并依据。清洗可按既有 partial 语义使用合格部分；转换仍完整登记输入的结构和失败情况，不能静默删除失败段冒充转换成功。

#### Scenario: 保留子集达到部分可用门槛

- **WHEN** 一份输入存在被接受的排除项，但保留集合仍达到冻结策略的最低覆盖、必需结构和关键数值要求
- **THEN** 系统将该输入确定为 `partial`，保存精确保留/排除范围及逐项原因
- **AND** 下游只能消费保留引用，同时仍可追溯全部原始输入和排除证据

#### Scenario: 无排除且全部门槛通过

- **WHEN** 输入基线可用、没有被接受的排除项且全部确定性质量门通过
- **THEN** 系统将该输入确定为 `available`
- **AND** 结果引用原输入，不重写或复制其正文和数值

#### Scenario: 低于最低门槛时不可用

- **WHEN** 保留集合低于最低覆盖、必需结构缺失、C14 快照不可计算，或关键数值保护无法满足
- **THEN** 系统将对应输入确定为 `unavailable` 并保存稳定原因与证据
- **AND** 不用零值、空内容、未审核候选或其它输入替代

#### Scenario: 表格与空白页正常处理

- **WHEN** CSV 无章节或 PDF 含确认的正常空白页
- **THEN** 按相应类型策略判断，不因不适用版式条件失败

#### Scenario: 可解释部分使用

- **WHEN** 部分非关键内容被清洗排除而保留内容满足业务要求
- **THEN** 记录排除范围并返回部分可用，不强制全部段100%保留

## ADDED Requirements

### Requirement: 清洗版本保留且读取独立记账

清洗准备、任务、结果与快照 MUST 保存实际输入和策略版本；改变输入创建新结果，重复写命令复用原结果。读取已有准备、结果或工具资料只追加访问记录，不产生业务完成回执或基于授权时间的幂等冲突；权限在读取及结果提交入口应用，历史记录不改写。

#### Scenario: 重复查看准备

- **WHEN** 有权用户重新登录后再次查看已有准备
- **THEN** 取得同一业务快照并记录本次访问，不因新授权拒绝

#### Scenario: 准备冻结防重复

- **WHEN** 同一清洗结果重复冻结识别准备
- **THEN** 只产生原快照和一次就绪事件

## REMOVED Requirements

### Requirement: 版本、幂等与权限支持精确重放

**Reason**: 原要求中的重复防护或跨阶段前置由本次已批准的封闭系统业务设计取代。

**Migration**: 使用“清洗版本保留且读取独立记账”；历史对象、审计和已完成结果继续保留，生产调用在本 change 同步切换。
