## Why

UI 重做 CH-1～CH-4 已归档，下一包 CH-5 需要把识别任务、风险记录、关联图谱和工序模型组织成生产可用的识别工作区。现有追溯入口依赖风险目录首页，图谱重复承载记录列表，页面标题和技术用语也未统一；本包必须在保全真实读取、权限和历史版本的前提下完成切换。

## What Changes

- 保留六条 `/identification` 规范路由，统一识别域标题、四个二级入口、生产设计系统及独立区域七态；技术编号作为辅助可复制信息，不作为主标题或要求用户手输的业务选择。
- 完成识别任务和风险记录的真实有界续页、筛选及精确详情；运行带版本读固定状态快照，无版本才跟踪最新进展，头部启动者/时间取同一最早登记而非恢复者字典序。保留 I0～I9、等待/失败、结果引用、置信度和原证据，不新增识别启动、模型重试或人工决定能力。
- 风险记录详情承载 `tab=trace`，以自身精确风险引用查询原追溯链；正文和追溯各有权限、失败及重试状态，保留原完整有界链读取，不混入评估侧正文或重算事实。
- 永久保留 `/review-audit/trace` 和已知 `/review/trace` 地址：`subject` 只表示风险记录 ID，给定版本保持该版本；缺版本通过识别所属域授权窄解析，不扫描目录首页。无主体到本工程风险列表，无法定位与无权同形拒绝。新承载、解析与生产内部调用方同版切换，删除重复旧追溯页实现。
- 图谱只保留正式关联图与可访问的边/节点浏览，不再嵌第二份风险记录列表；失败提供去风险记录的规范入口，不以裁切图、样例或列表冒充图谱成功。
- 工序模型保留只读业务视图，支持显式发布版本及节点定位，缺省才读当前发布；不搬入原型中未提供读面的工程使用关系或版本历史。治理写操作仍归 CH-8；复核队列/决定/覆盖层和最终六导航仍归 CH-9，本包不撤旧复核入口。
- 同一 change 修正与当前代码和本次切换冲突的旧“八页只读”、图谱内嵌降级列表及独立追溯页面要求，不拆成语义不同的 drift change。

## Capabilities

### New Capabilities

无。不按导航新增识别 capability。

### Modified Capabilities

- `web/identification-and-review-ui`：识别工作区页面组织、真实分页与精确引用、详情内追溯、去重复图谱、工序只读业务视图及本包真实验收；保留原复核所有权。
- `domain/module-interfaces-events-workflows`：在原运行/风险详情分支支持无版本实体身份选择与所选运行头部，复用既有精确引用和错误 Schema，不新增 resolver 分支，保持有界、只读和当前权限。
- `platform/http-command-query-sse-shell`：为上述解析闭合 strict HTTP 输入/结果和正式装配，不开放通用实体解析、任意分支或客户端授权。
