# knowledge/governed-definition-lifecycle Specification

## Purpose
为 RiskFlow 的工序模型、风险机理、评估规则与配置提供统一的受治理定义生命周期，使任何运行都只能消费经人工审核发布的精确不可变版本，并能完整追溯导入、停用和历史版本重新启用决定。

## Requirements

### Requirement: 受治理定义具有稳定身份和不可变修订

系统 MUST 在工程内以 C02 `KnowledgeDefinitionTypeV1` 区分受治理定义，每个定义类型对应一个稳定定义身份；定义正文作为精确 `ContentArtifactRefV1` 引用保存，不复制到治理事实。首次 `submit-revision` MUST 创建该类型的稳定身份和首个不可变修订；已有发布历史的后续提交 MUST 引用同一工程同一类型在命令时刻最近一次已生效的历史发布作为精确 `baseReleaseRef`，形成父修订链，且停用决定不得使该历史发布失去演进基线资格。已有定义但没有任何发布历史时，系统 MUST 将其与“最近历史发布已停用”区分，不得把缺失基线当作停用后的可演进状态。修订一经提交不得原地更新或删除。（RI-S44；RA-S2～RA-S4、RA-S7）

#### Scenario: 首次提交创建稳定定义身份
- **WHEN** 获授权调用方为工程内尚不存在的定义类型提交候选工件和至少一项证据引用
- **THEN** 系统创建该定义类型的稳定定义身份与首个 `KnowledgeRevisionRefV1`
- **AND** 修订固定定义类型、候选工件、证据、工程、操作者和三类时间引用

#### Scenario: 后续修订沿用定义身份
- **WHEN** 调用方基于同工程同类型在命令时刻最近一次已生效的精确历史发布提交新候选
- **THEN** 新修订沿用原稳定定义身份并获得新的修订版本
- **AND** 原修订与原发布内容保持不变

#### Scenario: 唯一发布停用后继续提交修订
- **WHEN** 某定义类型的唯一历史发布已停用，且调用方以该最近历史发布的精确引用提交新候选
- **THEN** 系统接受该发布作为演进基线并创建新的不可变修订
- **AND** 已停用发布仍不可被新运行解析

#### Scenario: 无发布历史不冒充停用状态
- **WHEN** 稳定定义已经存在但从未形成发布，调用方再次提交无基线或不存在的基线引用
- **THEN** 系统返回结构化未找到或陈旧版本错误
- **AND** 不创建第二个无父发布的修订、审计或命令回执

#### Scenario: 停用期间并发提交保持同一演进基线
- **WHEN** 一个发布被停用的同时或之后，多个提交命令均引用该命令时刻最近的同一历史发布，且期间没有新发布成立
- **THEN** 停用决定不使这些精确基线失效，每个有效命令可创建各自的不可变候选修订
- **AND** 若其中任一命令校验前已有更新发布成立，则该命令按陈旧基线拒绝

#### Scenario: 拒绝错误或陈旧基线
- **WHEN** `baseReleaseRef` 属于另一工程、另一类型、不再是命令时刻最近一次已生效的历史发布或不存在
- **THEN** 系统返回结构化授权、未找到或陈旧版本错误
- **AND** 不创建部分修订、审计或发布事实

### Requirement: 精确配置包导入收口到同一修订事实

系统 MUST 将 `submit-revision` 的 `candidateArtifactRef` 视为待治理配置包的精确内容寻址身份，并把命令中的定义类型、基线发布和证据引用作为闭合导入清单。导入 MUST 只登记该精确工件引用，不按文件名、显示名称、自由文本或“最新版”猜测身份；同一工件在同一工程内不得被冲突地登记为不同定义类型或不同稳定定义。C16 MUST NOT 解释 C17/C18/C19 拥有的业务字段，业务内容校验失败由其所属 change 形成新的候选修订，不改写已登记修订。

#### Scenario: 导入甲方已审核配置包
- **WHEN** 获授权调用方以完整 `submit-revision` 命令提交一个已登记的精确内容工件、定义类型和证据引用
- **THEN** 系统按原工件引用创建不可变修订并记录导入来源
- **AND** 不要求 Agent 重新解释内容，也不把导入状态等同于已发布

#### Scenario: 同一导入命令幂等重放
- **WHEN** 调用方以相同工程、命令类型、幂等键和完全相同的精确导入清单重放请求
- **THEN** 系统返回首次创建的修订引用
- **AND** 不重复创建修订、审计或命令回执

#### Scenario: 拒绝工件身份冲突
- **WHEN** 同一工程中的精确候选工件已归属某一受治理定义，却被提交为另一类型或另一稳定定义
- **THEN** 系统整体拒绝导入并返回不可重试冲突
- **AND** 不通过名称匹配、字段补全或部分导入继续处理

### Requirement: 修订必须经显式人工复核后才能发布

系统 MUST 通过 C02 `KnowledgeModelingPortV1.govern` 的 `request-review` 分支和 C07 `ReviewAuditPortV1` 创建 `knowledge-revision` 复核任务。只有仍指向该精确修订且决定为 `approve-publication` 的人工复核决定可用于发布；`reject`、`return-for-revision`、已替代任务、错工程/错类型决定、Agent 结果或调用方自造状态均不得发布。（RI-S44；RA-S3、RA-S4、RA-S7）

#### Scenario: 送审形成精确复核任务
- **WHEN** 获授权调用方对一个尚未发布且可决定的修订请求复核
- **THEN** 系统返回只引用该修订、验证/证据快照和复核策略的 `ReviewTaskRefV1`
- **AND** 复核任务、审计、命令回执和 `review.review-requested.v1` 原子提交

#### Scenario: 获批修订可以发布
- **WHEN** 发布命令提交与目标修订和工程完全匹配的 `approve-publication` 决定
- **THEN** 系统允许创建新的不可变发布版本
- **AND** 发布事实引用该修订与人工决定

#### Scenario: Agent 或失败决定不能发布
- **WHEN** Agent、系统调用或人工提交拒绝、退回、陈旧或目标错配的决定尝试发布
- **THEN** 系统在写入前拒绝请求
- **AND** 不产生发布、活动集变化或已发布事件

### Requirement: 发布版本按生效时间组成不可变发布集合

每次 `publish-approved-release` MUST 为目标定义创建一个新的不可变 `KnowledgeReleaseRefV1`，固定获批修订、复核决定、`effectiveFrom`、工程、定义类型、操作者、授权、命令和审计引用。后续修订发布时，其 `baseReleaseRef` MUST 在发布事务校验时仍是最近一次已生效的历史发布；当该历史发布已停用且不存在其它 active 发布时，不得因 active current 为空而拒绝。若期间已有更新发布成立、存在不匹配的 active 发布或发布时间线重叠，系统 MUST 拒绝陈旧发布。同一工程同一定义类型在任一业务有效时刻最多有一个有效发布；并发或重叠发布 MUST 由数据库约束和预期版本检查收口。已发布内容不得原地修改，未来生效发布也不得在生效前被另一命令静默覆盖。同一发布命令的幂等重放 MUST 返回原发布，不同命令不得为同一修订重复创建发布。

#### Scenario: 发布进入工程发布集合
- **WHEN** 获授权调用方发布一个获批修订且其生效时间不与同类型既有有效区间冲突
- **THEN** 系统创建新的精确发布引用并使其从 `effectiveFrom` 起属于该工程的有效发布集合
- **AND** 修订、发布、审计和命令回执在一个事务中提交

#### Scenario: 停用后发布后续修订
- **WHEN** 获批修订基于最近一次已生效但已停用的历史发布，当前没有其它 active 发布，且期间没有更新发布成立
- **THEN** 系统允许创建引用该修订的新发布
- **AND** 新发布、历史发布与停用决定均保持不可变且可审计

#### Scenario: 停用期间的并发发布仍只有一个成立
- **WHEN** 当前没有 active 发布，两个获批修订基于同一最近历史发布并发发布
- **THEN** 至多一个命令创建新发布
- **AND** 另一命令在定义级串行校验中因基线陈旧而失败，不覆盖获胜发布

#### Scenario: 并发发布只有一个决定生效
- **WHEN** 两个命令基于同一当前发布并发发布同类型的不同修订
- **THEN** 至多一个命令创建新发布
- **AND** 另一命令返回陈旧版本或业务冲突且不覆盖获胜发布

#### Scenario: 同一修订不被重复发布
- **WHEN** 调用方幂等重放已成功的发布命令，或以不同命令再次发布同一修订
- **THEN** 幂等重放返回原发布引用，不同命令返回陈旧版本或业务冲突
- **AND** 两种情形都不创建第二个发布、审计、命令回执或领域事件

#### Scenario: 未来发布保持可预期
- **WHEN** 已存在同类型的未来生效发布后再次提交会造成重叠的发布
- **THEN** 系统拒绝新命令并保留既有时间线
- **AND** 不通过移动既有 `effectiveFrom` 解决冲突

### Requirement: 停用和历史版本重新启用只追加新决定

`deactivate-release` MUST 对精确发布追加停用决定和原因，使其在决定记录时间之后不可被新运行解析；不得删除或改写发布、修订及历史运行引用。`rollback-by-new-release` MUST 以历史发布中的原精确修订创建一个新的发布决定和新的 `KnowledgeReleaseRefV1`，保留历史发布、原停用决定和新的复核决定；不得把“当前”指针移回旧行。（RI-S44；RA-S4、RA-S7）

#### Scenario: 停用阻止新运行解析
- **WHEN** 获授权调用方停用一个当前有效发布
- **THEN** 系统追加停用事实并返回该发布的精确引用
- **AND** 停用之后开始的新运行不能再解析该发布

#### Scenario: 已冻结运行不被追溯改写
- **WHEN** 某发布在运行冻结后被停用
- **THEN** 已形成的运行与业务记录仍保留原发布引用并可重放
- **AND** 系统不把历史引用替换为其它发布

#### Scenario: 重新启用历史内容形成新发布
- **WHEN** 获授权调用方以历史发布和匹配的人工批准决定执行 `rollback-by-new-release`
- **THEN** 系统创建引用历史修订的新发布版本并记录回滚原因
- **AND** 历史发布、停用事实与新发布均保持可审计

### Requirement: 运行只解析精确且当时有效的发布版本

治理模块 MUST 依据调用方提供的工程、用途、要求时刻和已冻结输入，返回 C02 声明的精确发布引用或结构化等待/失败；不得返回裸“当前版本”别名，也不得在缺失、未生效、停用、未批准、类型不兼容或跨工程时自动选择其它版本。下游运行冻结后 MUST 持续使用返回的精确引用，版本变化只能触发新运行。（RI-S44、RI-S55～RI-S56；RA-S4、RA-S5、RA-S7）

#### Scenario: 精确解析成功
- **WHEN** 调用方在要求时刻解析工程内用途所需的发布，且每个必需类型均存在唯一有效且兼容的获批版本
- **THEN** 系统返回只包含精确发布引用的解析结果
- **AND** 下游无需读取治理内部表或推断最新版

#### Scenario: 缺失或停用版本不降级
- **WHEN** 任一必需发布缺失、尚未生效、已停用或类型不兼容
- **THEN** 系统返回知识准备等待或结构化失败
- **AND** 不使用历史版本、基线结果、未审核修订或其它工程版本继续运行

#### Scenario: 冻结后发布变化创建新运行
- **WHEN** 运行已经冻结精确发布引用，随后同类型发布新版本
- **THEN** 原运行仍使用原引用完成或终止
- **AND** 需要新版本时由调用方创建新的运行而非改写原运行

### Requirement: 治理命令遵守授权、幂等、原子审计与最小披露

每个治理命令 MUST 在读取目标存在性或产生副作用前通过 C06 校验精确工程和 `knowledge-modeling.govern` 能力；下游调用只能保持或收窄授权。修订、发布/停用事实、C03 命令回执、只追加审计和适用的 C02 领域事件 MUST 原子提交。相同幂等身份与载荷返回原结果，同键不同载荷返回不可重试冲突。日志、错误、审计、事件和查询结果不得复制配置正文、资料正文、模型响应、凭据或内部数据库错误。

#### Scenario: 无权调用不泄露目标
- **WHEN** 授权上下文过期、工程不匹配、能力不足或资料范围越界
- **THEN** 系统在目标读取和写入前返回与目标不存在不可区分的授权拒绝
- **AND** 不产生修订、复核、发布、停用、审计成功或事件事实

#### Scenario: 原子提交失败整体回滚
- **WHEN** 治理事实、审计、命令回执或 Outbox 任一步写入失败
- **THEN** 同一命令的全部写入均不可见
- **AND** 调用方可沿用原命令身份安全重试

#### Scenario: 同键不同载荷冲突
- **WHEN** 调用方复用已完成命令的幂等键但改变修订、决定、有效时间、原因或工件引用
- **THEN** 系统返回 `IDEMPOTENCY_CONFLICT`
- **AND** 原治理事实和原审计保持不变

#### Scenario: Agent 无治理发布权
- **WHEN** Agent 授权上下文尝试提交发布、停用或历史版本重新启用命令
- **THEN** 系统确定性拒绝该命令
- **AND** Agent 只能产生候选修订或命令提案，不能成为发布决定主体

### Requirement: 治理查询按工程和时间有界

治理模块的内部解析与验收查询 MUST 先约束工程、定义类型和精确时间或引用，再访问修订/发布时间线；不得扫描其它工程、其它类型或全部历史。修订、发布、停用与导入历史 MUST 保留 `occurredAt`、`recordedAt`、`persistedAt`，支持按精确引用和记录时间重建决定链。

#### Scenario: 按精确引用重建生命周期
- **WHEN** 获授权调用方追溯一个修订或发布引用
- **THEN** 系统可关联候选工件、证据、父发布、复核任务/决定、发布或停用决定、操作者、授权、命令和三类时间
- **AND** 所有内容引用仍指向当时使用的不可变版本

#### Scenario: 工程隔离查询
- **WHEN** 调用方解析或追溯一个属于其它工程的定义引用
- **THEN** 系统拒绝请求且不泄露该引用是否存在
- **AND** 查询计划不通过跨工程全表扫描寻找候选
