## Why

C21 已能为冻结的识别工作项形成 RI-S56 五项上下文，但系统尚不能把该上下文转化为经确定性校验、全运行合并和验收路由的标准化风险记录。C22 闭合 RI-S57～RI-S65 的候选到正式识别事实链路，为后续 C24 识别图和 C25 风险评估提供可重放输入。

## What Changes

- 使用冻结的五项上下文、模型部署和提示模板执行 RI-S57 专用 LLM 推理，输出严格六字段风险候选；模型原始响应与输入引用可重建，候选直接进入确定性校验，不增加同一 Agent 的形式化复审。
- 对候选执行结构、字段、引用、规则一致性及可选仿真约束校验；仅字段、格式和引用类可修复错误可在原冻结版本与预算内修正，权限、来源、版本和规则冲突失败关闭并保留证据。
- 按工序一致性、风险事件表达和证据定位的版本化策略，在一次识别运行内形成合并组；无重复时显式记录跳过，不覆盖原候选或来源。
- 依据模型置信度、规则一致性、可选仿真约束和多来源合并结果计算可解释的综合置信度，并按冻结阈值与强制复核策略把每组路由到自动验收或 C07 人工复核。
- 只接受与验收路由逐组对应的自动决定或已成立人工决定；原子保存不可变标准化风险记录、审计及既有 `identification.risk-record-accepted.v1` 事件，拒绝部分验收、陈旧决定和跨工程引用。

## Capabilities

### New Capabilities

- `identification/risk-candidate-validation-merge-and-acceptance`：覆盖 RI-S57～RI-S65 的专用模型候选、确定性校验、全运行合并、综合置信度、验收路由及标准化风险记录入库。

### Modified Capabilities

无。

## Impact

- **依赖与契约**：复用已归档 C01/C05/C07/C21 以及 C02 的 `RiskIdentificationPortV1`、共享记录 Schema、复核契约、权限分支和领域事件；不修改公共契约、权限矩阵或第三方依赖。
- **代码所有权**：新增 C22 自有的 core 识别候选领域模块、PostgreSQL 适配与迁移、Worker 专用模型运行/组合及对应测试；中间正文复用 C04 工件，事务、审计与 Outbox 复用 C03，人工复核复用 C07。
- **范围**：C24 负责 I0～I9 图、生产冻结输入和阶段接线；C23 负责人工作台/交互闭环。本 change 不实现图、API/Web 页面、P/C 计算、风险矩阵、预警或处置。
- **追踪与样本**：覆盖 RI-S57～RI-S65，并保持资料段 → 工序 → 机理 → 候选/合并 → 标准化风险记录的精确引用链。甲方脱敏样例未提供时，验收样本标记为“合成样本、待甲方复核”。
