## ADDED Requirements

### Requirement: 校准公开治理入口必须使用单分支授权和精确决定

系统 MUST 提供校准复核结果收口与未发布草案创建两个独立公开命令。结果收口只接受精确建议、真实复核决定及 reject/return-for-revision，草案创建只接受精确建议、真实 approve-draft-creation 决定。命令入口 MUST 按自身分支复验单能力授权，下游复核证明、知识读取和修订提交 MUST 分别取得当前主体、工程、空间和来源范围内的用途授权，不要求调用方伪造多能力上下文。全部操作 MUST 复用既有 C29/C07/C16 用例、幂等身份和事务语义，不直接发布配置。（RA-S7）

结果收口的公开成功 outcome MUST 仅为 rejected 或 returned；草案结果 MUST 使用独立草案形状。请求与结果均按各自命令分支校验，不能因内部用例支持批准而放宽公开收口结果。

#### Scenario: 单能力上下文下形成未发布草案
- **WHEN** 经理以真实会话确认精确批准决定，且复核证明、知识读取和治理分支均获准
- **THEN** 系统返回原用例形成的草案工件、知识修订和公共偏差版本
- **AND** 当前配置保持不变，重试返回同一修订

#### Scenario: 拒绝退回与错误决定分离
- **WHEN** 用户提交真实拒绝/退回决定，或者把批准决定声明为拒绝/退回
- **THEN** 前者只收口对应精确建议，后者被拒绝
- **AND** 不转移决定、不创建占位后继或绕过独立复核

#### Scenario: 收口成功不能返回草案批准
- **WHEN** 结果收口分支返回批准 outcome 或草案创建结果形状
- **THEN** 公共结果边界拒绝该响应
- **AND** 不将其呈现为合法拒绝或退回成功

#### Scenario: 下游撤权或尾事务失败
- **WHEN** 下游治理/证明授权被撤销，或知识修订成功后校准尾事务失败
- **THEN** 撤权在读取/副作用前失败，尾事务可沿原命令身份重试收敛到单一草案
- **AND** 不扩大原授权、不重复修订、不将部分成功标为完工
