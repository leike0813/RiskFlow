# data/agent-cleaning-and-partial-availability Specification

## Purpose
为 RiskFlow 提供受统一 Agent 运行时约束的数据清洗与业务可用性收口，使结构化/OCR 文档和监测快照在不改写原始事实与关键数值的前提下形成可追溯、可部分使用且可由识别流程冻结消费的输入。（RI-S13、RI-S14、RI-S21～RI-S23；RA-S1）

## Requirements
### Requirement: 清洗准备冻结精确文档与监测输入

系统 MUST 为一次数据清洗准备固定工程修订、空间范围、资料版本、每份资料对应的成功转换记录、JSON-LD 工件和资料段集合、可选监测快照、数据处理策略、父运行、授权上下文与业务幂等身份。文档输入 MUST 接受 DOCX、文本型 PDF、XLSX、CSV 以及通过同一转换契约形成的 OCR 版面结果；监测输入 MUST 只引用 C14 已冻结的精确快照，不得读取持续变化的“最新值”。同一准备中的资料版本与资料段集合 MUST 一一对应。（RI-S13、RI-S14、RI-S21；RA-S1）

#### Scenario: 四类结构化文档与地表沉降快照进入同一准备

- **WHEN** 获授权调用方提交四个分别具有成功 DOCX、文本型 PDF、XLSX、CSV 转换结果的精确资料版本，并按冻结数据处理策略提供地表沉降监测截止点
- **THEN** 系统形成只含精确转换、JSON-LD、资料段集合和监测快照引用的不可变清洗准备
- **AND** 不把资料正文、完整 JSON-LD 或监测样本值复制进任务信封

#### Scenario: OCR 结果复用同一清洗契约

- **WHEN** C13 通过统一转换接口形成成功 OCR 版面结果、JSON-LD 工件和资料段集合
- **THEN** 系统按与其它文档相同的清洗输入处理该结果，并保留页码、版面、置信度和表格定位证据
- **AND** 不读取 PaddleX 私有响应来建立第二套文档事实

#### Scenario: 输入版本不完整或不一致时拒绝准备

- **WHEN** 任一资料没有成功且版本匹配的转换与资料段集合、资料与集合不能一一对应、监测快照不属于请求工程/空间/截止点，或数据处理策略版本不匹配
- **THEN** 系统在创建 Agent 任务前返回结构化业务阻断、版本或授权失败
- **AND** 不猜测“最新版”、不省略失败输入、不创建可运行任务

### Requirement: data-cleaning 任务只使用版本化只读领域工具

清洗工具 MUST 限于任务冻结的资料与监测输入，宿主提供短选项映射真实资料版本和资料段，记录读过的位置并管理分页。每次新资料读取在统一入口检查当前权限，内部工件读取复用决定。工具只观察事实，清洗增量仅能排除已有引用并说明原因。

#### Scenario: 清洗任务经生产组合根以受权能力启动

- **WHEN** 清洗准备已形成冻结清单，且服务端授权来源可为同一发起者、工程、空间和资料范围签发 `agent-task.start-task` 的当前有效授权
- **THEN** 生产组合根通过 C06 取得仅含 `agent-task.start` 能力的授权上下文，并以该上下文调用既有 `AgentTaskPortV1.startTask` 创建 `embedded/data-cleaning` 任务
- **AND** 系统不复用、扩写或伪造原 `engineering-data.freeze` 上下文，不新增公共命令字段或第二套运行时；授权签发或 C08 启动失败时不创建可运行任务，并分别保留 C06 安全审计与 C08/C03 已可靠成立的失败证据

#### Scenario: 读取获准的文档资料段切片

- **WHEN** Agent 请求冻结 JSON-LD 中存在、属于获准资料版本且数量不超过工具策略上限的资料段
- **THEN** 工具返回受保护的不可变观察工件引用，其中仅含所请求的结构、正文片段、定位、置信度和数值保护标记
- **AND** 读取及观察工件继承原资料权限并计入 C08 工具、对象、上下文和墙钟预算

#### Scenario: 读取获准的监测快照切片

- **WHEN** Agent 请求冻结监测快照中存在且数量不超过上限的成员、对齐点或特征
- **THEN** 工具返回受保护观察工件引用，并保持原样本值、规范值、特征值、单位、状态和证据不变
- **AND** 工具不重新对齐、插值、外推或计算新特征

#### Scenario: 越权或越界工具请求被拒绝

- **WHEN** 动作请求冻结集合外对象、其它工程/资料、未列入白名单的工具、超过对象预算，或当前资料授权已撤销
- **THEN** C08 返回稳定的工具、预算或授权错误并记录失败证据
- **AND** 不打开目标正文、不调用其它处理器、不扩大任务输入或工具集合

#### Scenario: 多资料按短选项读取

- **WHEN** 模型依次读取不同资料或同资料多页
- **THEN** 返回正确来源与连续进度，不因同用途读取编号冲突失败

#### Scenario: 模型误选来源

- **WHEN** 模型选项不在任务来源集合
- **THEN** 反馈选项错误供原预算内修正，不读取其它资料

### Requirement: Agent 增量只能排除既有引用

系统 MUST 将清洗候选表示为任务类型化增量，且每项操作只能按精确资料段标识或监测样本版本引用提出排除，并携带策略允许的原因码和现有证据引用。增量不得包含正文替换、通用 JSON Patch、整对象覆盖、数值、单位、时间戳、公式缓存值、坐标、置信度、C14 特征或已发布事实的新值。原始转换工件、资料段集合、监测批次、样本和快照始终不变。（RI-S21～RI-S23；RA-S1）

#### Scenario: 合法引用级排除进入确定性校验

- **WHEN** Agent 对冻结集合内的重复/噪声资料段或异常监测样本提交允许原因码、目标引用和证据
- **THEN** 系统逐项校验并记录 `accepted | rejected`、稳定原因码及证据引用
- **AND** Agent 输出本身不修改任何资料段、样本、快照或下游事实

#### Scenario: 正文或数值修改整体拒绝

- **WHEN** 候选包含替换文字、修正数值/单位/时间、重算公式/特征、路径式补丁、未知字段或整对象内容
- **THEN** strict Schema 或确定性校验拒绝该候选
- **AND** 不把非法内容转换为排除操作或正式清洗结果

#### Scenario: 受保护关键数值不能通过排除消失

- **WHEN** 候选试图排除数据处理策略或冻结输入标记为关键数值证据的资料段，或试图把受保护监测样本从可用集合移除
- **THEN** 确定性校验以不可修正规则拒绝记录该项及证据
- **AND** 不允许通过改写原因码、拆分操作或修正循环绕过保护

### Requirement: 业务可用性由确定性策略收口

系统 MUST 按资料类型与实际用途选择版式和可用性要求，关键字段、数值保真、来源及排除原因保留。CSV 使用真实表格结构，正常空白页不要求正文，未参与归并的单候选不要求归并依据。清洗可按既有 partial 语义使用合格部分；转换仍完整登记输入的结构和失败情况，不能静默删除失败段冒充转换成功。

#### Scenario: 保留子集达到部分可用门槛

- **WHEN** 一份输入存在被接受的排除项，但保留集合仍达到冻结策略的最低覆盖、必需结构和关键数值要求
- **THEN** 系统将该输入确定为 `partial`，保存精确保留/排除范围及逐项原因
- **AND** 下游只能消费保留引用，同时仍可追溯全部原始输入和排除证据

#### Scenario: 无排除且全部门槛通过

- **WHEN** 输入基线可用、没有被接受的排除项且全部确定性质量门通过
- **THEN** 系统将该输入确定为 `available`
- **AND** 结果引用原输入，不重写或复制其正文和数值

#### Scenario: 低于最低门槛时不可用

- **WHEN** 保留集合低于最低覆盖、必需结构缺失、C14 快照不可计算，或关键数值保护无法满足
- **THEN** 系统将对应输入确定为 `unavailable` 并保存稳定原因与证据
- **AND** 不用零值、空内容、未审核候选或其它输入替代

#### Scenario: 表格与空白页正常处理

- **WHEN** CSV 无章节或 PDF 含确认的正常空白页
- **THEN** 按相应类型策略判断，不因不适用版式条件失败

#### Scenario: 可解释部分使用

- **WHEN** 部分非关键内容被清洗排除而保留内容满足业务要求
- **THEN** 记录排除范围并返回部分可用，不强制全部段100%保留

### Requirement: 清洗结果经确定性收口自动生效并完整留痕

系统 MUST 在候选通过确定性校验后形成不可变清洗结果工件，并以工程数据模块的正式清洗事实记录任务、冻结输入、策略、模型、提示、工具、预算、候选、逐项校验、保留/排除范围、可用性、证据、权限和审计引用。清洗结果不需要人工发布或确认；只有 C08 任务达到 `completed` 且其正式结果引用与清洗事实一致时，结果才可被识别准备消费。系统不得保存或展示模型内部思维链。（RI-S14、RI-S21～RI-S23）

#### Scenario: 合格候选自动形成正式清洗结果

- **WHEN** `data-cleaning` 候选全部通过确定性校验且结果工件、正式清洗事实和审计均成功保存
- **THEN** C08 任务完成后该结果自动成为对应冻结输入和策略的可消费结果
- **AND** 不创建人工发布、批准或二次 Agent 自审前置

#### Scenario: 工件或业务收口失败不成立结果

- **WHEN** 结果工件、正式清洗事实、逐项决定、命令收据或审计任一步失败
- **THEN** 系统返回结构化工件、持久化或任务失败并保留已可靠成立的诊断证据
- **AND** 下游不得把内存候选、孤儿工件或未完成任务当作正式结果

### Requirement: 必经 Agent 失败不得静默跳过

系统 MUST 把模型不可用、工具失败、预算耗尽、租约恢复失败、确定性拒绝和任务终止分别保存为可审计失败。识别准备 MUST 验证对应 `data-cleaning` 任务已完成并消费其精确结果；任务未运行、运行中、失败、取消或结果版本不匹配时 MUST 阻断，不得直接使用 C12/C13 转换结果、C14 快照、缓存候选、默认可用结论或替代模型继续。（RI-S21～RI-S23）

#### Scenario: 预算耗尽阻断准备

- **WHEN** 必经清洗任务耗尽模型、工具、上下文、候选、对象、修正、并发或墙钟预算且没有合格结果
- **THEN** 任务进入显式失败终态，识别准备返回对应失败/阻断引用
- **AND** 不扩容、换模型、减少审计或把未清洗输入标记为可用

#### Scenario: 任务仍在运行时不冻结输入

- **WHEN** 调用方在清洗任务完成前请求识别准备快照
- **THEN** 系统返回结构化业务阻断并指向同一任务
- **AND** 不创建准备快照、输入就绪事件或下游运行

#### Scenario: 失败重试沿用冻结任务

- **WHEN** 可安全重试的技术故障在 C08 冻结重试预算内恢复
- **THEN** 系统沿用原任务、输入、策略、模型、工具、动作幂等键和累计预算
- **AND** 不重复工具副作用、正式清洗事实、排除决定或审计

### Requirement: 识别准备只冻结已收口的可用输入

系统 MUST 实现既有 `identification-preparation` 冻结语义，消费前置契约演进后的复数 `includedSourceSegmentSetRefs[]`：每个 `sourceVersionRef` 按相同顺序对应一个精确资料段集合，排除决定 MUST 指向集合内资料段。`coverageDecisionRef` 与每个 `excludedSegmentDecisionRefs[]` 成员 MUST 是 strict `RouteDecisionRefV1`，其精确版本身份绑定对应确定性决定内容与正式清洗结果来源，不得以 `ContentArtifactRefV1` 冒充。至少一份文档为 `available` 或 `partial` 且整体策略门通过时，系统 MUST 保存可由公共 `IdentificationPreparationSnapshotV1` Schema 完整解析的不可变快照；不可用文档全部段显式排除，部分可用文档只排除已接受范围。（RI-S1、RI-S2、RI-S13、RI-S21～RI-S23）

#### Scenario: 监测结果可用性决定覆盖决定中的监测快照引用

- **WHEN** 监测结果为 `available` 或 `partial`，或为不可用
- **THEN** 可用或部分可用时保存精确监测快照引用
- **AND** 不可用时在覆盖决定中保留原因，不把监测快照作为可消费输入

#### Scenario: 多资料部分可用准备成功

- **WHEN** 四份资料的清洗任务完成，其中至少一份为部分可用，所有资料版本与资料段集合一一对应且整体覆盖达到策略门槛
- **THEN** 系统返回一个可由公共 strict Schema 解析的识别准备快照，保留全部资料版本/集合引用、精确 `route-decision` 排除决定、`route-decision` 整体覆盖决定和清洗版本引用
- **AND** 下游可以仅从未排除资料段继续，同时重放每项排除和质量结论

#### Scenario: 内容工件引用不能冒充路由决定

- **WHEN** 覆盖决定或任一排除决定仍是 `content-artifact`、未知引用类型或无法绑定对应决定内容与正式清洗结果来源
- **THEN** 系统在识别准备快照成立前拒绝该 payload
- **AND** 不保存无法通过 `IdentificationPreparationSnapshotV1` strict Schema 的准备快照或发布输入就绪事件

#### Scenario: 全部文档不可用时阻断

- **WHEN** 所有请求文档的清洗结论均为 `unavailable`，或整体覆盖低于冻结策略下限
- **THEN** 系统返回业务阻断并保留清洗结果与原因引用
- **AND** 不创建空准备快照或发布输入就绪事件

#### Scenario: 前置复数契约未就绪时禁止实现

- **WHEN** `evolve-identification-preparation-segment-set-refs` 尚未归档，或运行时仍只接受单数资料段集合字段
- **THEN** C15 实现/启动检查失败并报告契约版本不兼容
- **AND** 不在 C15 内修改公共 Schema、压缩多资料为一个集合或只取第一份资料

### Requirement: 准备快照、审计和输入就绪事件原子提交

系统 MUST 在一个 C03 事务中提交识别准备快照、覆盖决定、排除决定引用、命令收据、一条事实审计和 `engineering.inputs-ready.v1` Outbox 事件。事件 MUST 只携带精确识别准备快照引用，不得复制资料正文、清洗候选、监测值或 Agent 响应。任何事务步骤失败 MUST 整体回滚；C12、C13、C14 或单项清洗结果完成时不得提前发布该事件。（RI-S14、RI-S23）

#### Scenario: 完整准备可靠发布输入就绪事件

- **WHEN** 全部必经清洗任务完成、确定性收口通过且准备快照事务提交成功
- **THEN** 系统原子保存准备、审计、回执和一条引用该准备的输入就绪事件
- **AND** 至少一次事件投递由消费者按事件身份和业务幂等键去重

#### Scenario: 审计或 Outbox 失败整体回滚

- **WHEN** 准备快照、覆盖决定、命令收据、审计或 Outbox 任一步写入失败
- **THEN** 整个准备提交失败且不返回业务成功
- **AND** 已完成清洗结果保持不变，可用原命令身份安全重试准备收口

### Requirement: 清洗版本保留且读取独立记账

清洗准备、任务、结果与快照 MUST 保存实际输入和策略版本；改变输入创建新结果，重复写命令复用原结果。读取已有准备、结果或工具资料只追加访问记录，不产生业务完成回执或基于授权时间的幂等冲突；权限在读取及结果提交入口应用，历史记录不改写。

#### Scenario: 重复查看准备

- **WHEN** 有权用户重新登录后再次查看已有准备
- **THEN** 取得同一业务快照并记录本次访问，不因新授权拒绝

#### Scenario: 准备冻结防重复

- **WHEN** 同一清洗结果重复冻结识别准备
- **THEN** 只产生原快照和一次就绪事件

### Requirement: 已完成清洗任务支持当前授权下独立完成准备

C15 MUST 提供complete-identification-preparation冻结分支，仅接收精确完整agentTaskRef，并使用新命令当前engineering-data.freeze授权。系统 MUST 验证原发起人/工程一致、真实completed任务、冻结清单/策略及正式结果匹配，当前空间/资料权限、C04消费完成和原覆盖校验通过后复用原摘要形成唯一准备快照；不得重新发起清洗或以过期原授权执行。已有快照在当前复验后返回，新的完成命令单独审计；并发与重投 MUST 不重复快照或inputs-ready。事件继续保留真实完成命令及可验证原父运行因果，不新增任意父运行输入。

#### Scenario: 启动授权到期后完成准备

- **WHEN** 原清洗任务completed而原命令授权已到期，原发起人以当前有效会话提交精确完成命令
- **THEN** 原任务/输入/结果和当前权限通过验证后返回正式准备，模型/工具用量不变，旧命令仍按原期限拒绝
- **AND** 当前复验按实际资料与空间范围返回授权增量，完成准备不要求其与入口的完整授权快照逐字段相等；脱敏或当前拒权仍阻止收口

#### Scenario: 完成资格不足或并发重投

- **WHEN** 任务未完成/失败/取消、主体/工程/引用/策略不符、当前撤权、C04损坏/超限或原因果未证明，或者完成命令并发/重投
- **THEN** 前述失败不生成准备或就绪事件；合法并发/重投只引用首次正式快照并保留各命令审计，同键异载荷冲突

### Requirement: 清洗必须观察未识别表格图片及其冻结变化

冻结文档可包含unrecognizedTableImageCount，MUST 从受权JSON-LD真实引用计算并在初始模型定位消息显示。受选表格切片 MUST 包含同表纯图单元格的逻辑位置和未识别引用；不得因缺少textBlock丢弃。读取严格限于当前选择关联表格并计入原对象/字节预算，超限拒绝。相关段parsedFingerprint MUST 纳入同表图片引用，无图片沿原含义；完整JSON-LD指纹继续冻结全部结构。不得新增通用读取工具或推断图形值。

#### Scenario: 读取带纯图单元格的表格

- **WHEN** 清洗Agent在原预算内选择含未识别图片的表格段
- **THEN** 源级数量及切片行列和图片引用可观察，纯图单元格不混同于空值，原权限和工件验证生效

#### Scenario: 图片变化或资源不足

- **WHEN** 同表图片引用改变，或关联观察超过原对象/字节预算
- **THEN** 前者改变相关冻结指纹，后者明确失败，不截断观察或扩容；没有图片的历史输入保持原语义

### Requirement: 清洗定位按冻结资料有界分页

系统 MUST 在版本化工具白名单声明定位工具时，提供read-cleaning-preparation-catalog-slice动作，以精确冻结sourceVersionRef及offset读取最多maxSegmentsPerRead个真实段标识/种类，并返回明确nextOffset。读取 MUST 复验当前授权及冻结清单，保留C04消费完成与访问记录；初始消息保留全部资料身份和规模，完整清单留在冻结输入，不截断或拆分任务绕过预算。

#### Scenario: 读取冻结资料定位下一页

- **WHEN** Agent使用登记的定位工具及合法offset
- **THEN** 返回该资料有界页及下一页位置，行动计入原调用/字节/对象预算，重放不改变冻结集合

#### Scenario: 定位超范围或工具未登记

- **WHEN** 资料不在冻结集合、offset越界、当前撤权，或策略未声明该工具
- **THEN** 读取被结构化拒绝，不返回其它资料定位或扩大范围

### Requirement: 清洗模型获得真实有界定位与观察

系统 MUST 在可信组合根经原冻结输入与当前受权读取提供清洗模型选择原领域工具所需的真实资料版本、资料段或监测样本定位。上一轮观察 MUST 经同任务冻结清单绑定、精确C04用途和读取完成后进入模型消息；消息继续受原字节、token与上下文预算约束，超限不得截断或扩大预算。任务信封 MUST 继续只保存引用，不增加模型通用工件、数据库或文件工具。

#### Scenario: 模型选择真实资料段

- **WHEN** 模型请求清洗工具前需要资料段身份
- **THEN** 宿主提供当前冻结集合内的真实定位，工具继续复验版本、授权及上限
- **AND** 不把清单工件当作资料版本，不伪造资料段标识

#### Scenario: 观察越界或消息超预算

- **WHEN** 观察来自其它冻结清单、读取被拒绝或损坏，或渲染消息超过原预算
- **THEN** 请求以原错误类别失败并留证，不发起模型推理、扩大输入范围或跳过读取校验

#### Scenario: 多次读取后仍保留已完成定位

- **WHEN** 清洗任务完成多个有界目录、资料段或监测读取，并继续或从原行动账本恢复
- **THEN** 模型获得同任务已成功调用的结构化读取进度与原观察引用，目录定位按冻结集合重建，最近观察仍经原C04完整读取
- **AND** 失败/未完成调用不作为已读事实，错源/错段/错工具或超预算拒绝；不增加通用存储工具、模型思考或第二套任务记忆

#### Scenario: 生成工具行动时只允许冻结资料身份

- **WHEN** 清洗模型生成目录或资料段读取行动
- **THEN** 生成Schema绑定本任务实际资料版本及原单次上限、目录offset绑定冻结段数，监测行动只在存在实际冻结快照时提供
- **AND** 原注册动作Schema与工具来源/成员/权限复验继续执行，不允许清单工件冒充资料版本，也不把未分页的全量段定位写入Schema
