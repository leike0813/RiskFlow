## ADDED Requirements

### Requirement: 配置包评分规则使用真实来源与正式治理

系统 MUST 支持 C04 登记的严格评分配置包导入，以包工件及逐条来源证据形成独立于 Agent 编制的互斥正文来源分支。包 MUST 固定工程、工程修订、配置集合、兼容和评分策略版本，可选精确比较基线，并有界携带受控来源、证据段及规则成员。包分支不得携带或创建虚假的 Agent/清洗任务引用，也不得混入 Agent 来源成员。未结构化规范的 Agent 编制仍使用原 C15/C08 冻结输入契约。

#### Scenario: 配置包无需评分 Agent 即进入人工治理

- **WHEN** 有权调用方提交来源完整、版本匹配且规则校验通过的真实 C04 包候选
- **THEN** 系统形成待治理修订与关系事实，无评分 Agent 任务；经真实人工审核及发布后才能进入适用规则集及评估依据

### Requirement: 配置包来源及版本确定性校验

提交前 MUST 完整消费受权 C04 包工件并等待 verified，核对候选与包内容、命令比较基线、当前 C06 来源权限及真实 C18 发布集合，核对指标正文摘要。来源段与证据版本、规则指标、适用性、阈值、区间和例外 MUST 经确定性校验；冲突/重叠检测及基线读取复用原 C19 算法。所有来源、成员及正文读取 MUST 有固定上界，基础设施错误不得伪装成缺资料或成功。

#### Scenario: 包或来源漂移时拒绝提交

- **WHEN** 包工件缺失、未验证、跨工程，来源权限不足，正文与包不符，证据悬空，指标不存在或配置/策略/基线版本漂移
- **THEN** 系统拒绝候选，不新增规则修订、关系或发布，不以伪造任务、其它版本或静态样例补足

#### Scenario: 两种来源不能混用

- **WHEN** 候选同时携带配置包和 Agent/清洗字段，或包来源正文混入 Agent 来源成员
- **THEN** 唯一正文 Schema 拒绝该候选，保留原 Agent 分支的任务和来源校验

### Requirement: 配置包沿用人工审核及原子发布门禁

审核事实 MUST 来自本实例真实 C07 决定及 C16 发布，包内自述审核状态不替代该事实。候选规则审核状态 MUST 为 pending，提交仍原子绑定 C16 修订与 C19 关系；原冲突审核和发布前最终门禁 MUST 同时适用于包来源。静态合成身份必须由正式预置回执绑定，不视为已登记事实。

#### Scenario: 配置包保留原发布门禁

- **WHEN** 包候选未经知识审核，存在未决规则关系或比较基线发生漂移
- **THEN** 原 C07/C16/C19 门禁阻止发布；发布、发布审计、回执及 Outbox 保持零新增
