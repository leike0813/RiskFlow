## ADDED Requirements

### Requirement: PJ-D-R1 工程工作区只能公开所属类型化修订和精确读取

系统 MUST 为工程工作区提供工程/空间业务上下文的类型化修订与精确读取，复用已有不可变修订和本地事务，不开放任意对象覆盖、补丁或通用 repository。当前身份、工程、空间及能力由服务端确定；请求只携带业务字段、明确目标和预期版本。业务修订不创建授权 scope identity，不修改授权树；空间新身份及访问修订仍由原授权所有者管理。首修订、陈旧版本、生命周期、里程、父子关系、幂等收据、审计与事件沿原领域规则，历史读取不自动换当前版本。（RI-S14；RA-S1）

#### Scenario: PJ-D-S01 既有工程和空间修订经正式接缝往返
- **WHEN** 有权用户提交已开通工程或同工程已登记空间的合法业务修订
- **THEN** 返回所属领域创建的精确不可变修订，按该引用刷新仍可直接读取，不产生另一套上下文事实

#### Scenario: PJ-D-S02 无权陈旧和原子失败
- **WHEN** 主体/工程/空间越界、预期版本陈旧、上下文非法或审计/事件提交失败
- **THEN** 沿原领域安全错误拒绝，业务事实、指针、收据及必要审计/事件不发生部分成功；网络重试保持原命令身份

### Requirement: PJ-D-R2 接入读取必须从登记来源解析真实处理关系

系统 MUST 以当前工程的来源资料精确版本或监测序列精确版本为接入记录身份，有界提供所属登记的转换结果、资料段、清洗准备与正式结果以及批次/快照引用和安全状态，不建立独立接入任务身份、状态表或后台编排。列表每页至多 50 项，详情按精确引用直接读取，禁止扫描目录首页、全历史或客户端传入工件路径反查。所有来源/空间由服务端登记解析后按当前权限读取；可选 Agent 关联在披露前独立检查 Agent 权，无权不返回引用、标记或存在性。缺席、失败、处理中与正式可用分别表达，未取得的预算/校验不编造。（RI-S1～RI-S2、RI-S14）

#### Scenario: PJ-D-S03 接入目录分页及历史精确详情
- **WHEN** 记录超过一页或用户直接打开旧来源版本
- **THEN** 页规模固定有界，详情精确对应所选来源和处理关系，另一版本或当前目录首页不影响该详情

#### Scenario: PJ-D-S04 领域结果与Agent关联独立授权
- **WHEN** 来源可读但 Agent 关联无权，或某处理阶段尚未登记/正式收口
- **THEN** 已获准领域结果仍可读，无权 Agent 关联被完全裁剪，未发生阶段显示缺席而非假零或成功

#### Scenario: PJ-D-S05 当前撤权与读取故障
- **WHEN** 来源/空间权限已撤销、目标跨工程，或登记处理结果读取发生技术故障
- **THEN** 前者按现有安全边界拒绝而不泄露目标，后者返回类型化技术失败而非空记录；历史事实及原审计不改写
