# platform/mineru-service-integration Specification

## Purpose

通过受权限和资源约束的 MinerU 文档服务接入，使官网功能验收与本地 GPU 交付能复用同一资料规范化与耐久证据链，真实反映不同协议、输出粒度和模型身份的差异，防止第三方响应或临时任务被误当作已成立的业务事实。

## Requirements

### Requirement: 服务协议显式选择且网络边界受限

系统 MUST 显式选择官网精准 v4 上传批次协议或自托管 4.0.12 V1 tasks 协议，禁止自动降级、跨协议猜测或换模型。官网 MUST 用专用 token 创建单文件上传批次，上传受权字节后有界轮询并下载 ZIP；自托管 MUST 使用上传字节的异步 tasks，PDF/图片使用 Standard、DOCX 使用 Flash。源资料不得公开 URL、回调或在业务输入中指定远端服务。下载和签名上传地址 MUST 落在冻结 allowlist，Bearer 不得发送给签名地址，重定向 MUST 拒绝。

#### Scenario: 官网受控上传
- **WHEN** 获授权命令使用官网服务
- **THEN** 系统只上传该精确资料工件，验证单文件批次和响应关联身份
- **AND** 上传与下载仅使用批准地址，不泄露服务 token

#### Scenario: 自托管异步任务
- **WHEN** 获授权命令使用本地服务
- **THEN** 系统提交单文件任务，验证完成状态和真实 2.0 Middle 协议
- **AND** partial、未知结果格式或丢失任务不能成功

### Requirement: 远端任务在原预算内耐久收口

系统 MUST 在既有 deadline、输入/输出字节、页数、ZIP 展开、轮询次数和独立并发预算内处理。远端原始结果 MUST 在业务成功前存为受资料权限保护的 C04 工件；规范化只消费已耐久并完整性复验的字节。失败诊断 MUST 区分输入、协议、结构、质量、超时、限流、取消、任务丢失与工件失败。自托管取消 MUST 尝试 DELETE 当前任务；官网停止本请求等待，不能声称未确认的远端取消成功。

#### Scenario: 取消与预算耗尽
- **WHEN** 调用者取消、deadline 到达或轮询预算耗尽
- **THEN** 请求终止且不登记资料段，自托管只取消当前任务
- **AND** 官网诊断表明远端取消未确认，其它请求与模型预算不受影响

#### Scenario: 结果耐久失败
- **WHEN** 原始响应无法完成 C04 写入或受权复验
- **THEN** 转换失败并保留可成立的诊断引用
- **AND** 不采纳内存响应形成业务成功

### Requirement: 新转换版本与分层验收保留历史证据

新转换部署或策略 MUST 通过 C11 正式新资料版本形成新资料段集合，并重建对应清洗、知识和检索输入，不得仅换 conversionId 覆写原版本。官网真实样例 MUST 验证实际产物字段后冻结消费结构，未知结构严格拒绝。默认测试 MUST 仅用测试目录协议替身验证确定性契约；真实服务证据与替身分开报告。本 change MUST 以 MinerU 转换器真实功能与受影响回归收口，并单列本机 CPU/GPU 补充基准；C37 负责完整业务和浏览器流程，C38 负责目标交付机专用模型质量、双 GPU 并发资源、离线制品/许可与最终交付。

#### Scenario: 历史版本不覆写
- **WHEN** 运维以新 MinerU 部署或策略重新转换资料
- **THEN** 使用正式新资料版本并生成新的下游输入引用
- **AND** 原始响应、资料段与历史评估引用保持可重放

#### Scenario: 外部证据缺失
- **WHEN** 缺少官网 token、真实产物或本地 GPU 服务
- **THEN** 实际服务和硬件验收明确记录 BLOCKED
- **AND** 配置校验与替身 PASS 不替代真实证据

### Requirement: 本机固定服务与性能基准可复用

本机部署 MUST 使用版本固定的独立服务与专属持久化目录，保留模型、配置、启停/重启及健康检查入口，默认仅发布到回环地址。CPU/GPU 基准 MUST 使用同一镜像、Standard 档位、ONNX 小模型与同一专用 VLM GGUF 权重，单文件并发1；DOCX 使用原生 Flash。CPU轮 MUST 显式禁用 GPU，GPU轮 MUST 显式选择 Vulkan 并记录实际设备与 offload，初始化失败不得计为 GPU 成功。报告 MUST 区分模型准备、冷启动与至少3次暖请求，保存质量、逐次耗时、中位数、吞吐和资源峰值，不推定 GPU 必然更快。

#### Scenario: 服务在验收后继续可用
- **WHEN** 本机固定服务完成验收或容器重新启动
- **THEN** 服务仍使用相同本地模型、配置和受控端点，可被后续客户端复用
- **AND** 任务索引重启后的丢失边界保持明确，客户端耐久结果不依赖远端旧任务存活

#### Scenario: CPU与GPU记录同一质量口径
- **WHEN** 同一合成清单在CPU和GPU实例分别转换
- **THEN** 每轮按源字段、记录关联、源页和JSON-LD校验，再记录性能
- **AND** GPU报告注明小模型仍在CPU及VLM的实际Vulkan设备，不以CPU回退或缓存命中冒充GPU推理速度
