# RiskFlow 完整产品目标与 MVP 完成标准

## 1. 产品定义

RiskFlow 是面向变径盾构站隧一体化施工的、有人监督的风险决策与闭环管理系统。系统将工程资料、监测数据、施工工序知识、风险机理、规范规则和历史案例组织为可追溯的业务事实，贯通：

> 资料接入 → 知识建模 → 风险识别 → 风险评估 → 动态预警 → 处置建议 → 人工复核 → 现场反馈 → 偏差分析与规则校准

完整产品必须保留风险识别 RI-S1～RI-S6、风险评估 RA-S1～RA-S7 的可追踪对应物。LangGraph 负责业务图编排，确定性领域服务负责规则、评分、矩阵、阈值、Schema 与版本判断；LLM 提供受证据约束的抽取、识别、解释与建议能力，不拥有最终风险事实。

### 1.1 产品责任边界

- 系统可以自动完成资料处理、风险识别、风险评估和预警判定。
- 校验失败、证据不足、置信度不足及重大风险必须进入人工复核。
- 预警发布策略可配置；处置方案发布、规则校准和版本生效必须由授权人员审批。
- 系统提供风险判断、处置建议和可审计依据，不直接控制施工设备，不替代现场责任人作出最终安全决策。

### 1.2 外部系统边界

RiskFlow 不重复建设文档管理、监测采集、CAD/BIM、施工进度管理或设备控制平台。完整产品通过文件导入、数据库连接、API 或专用适配器使用这些系统的数据，并保留外部来源、版本和调用记录。

### 1.3 用户范围

完整产品服务以下用户群，具体角色名称、权限矩阵与职责分离由后续用户角色票据确定：

- 查看总体风险态势并作管理决策的项目管理人员；
- 执行识别、评估、预警、处置和现场反馈的风险业务人员；
- 维护工序、机理、规则、指标和校准版本的工程与领域专家；
- 处理异常、复核重大风险并审查证据链的复核与审计人员；
- 管理数据接入、模型服务、运行状态和私有部署的系统运维人员。

## 2. 完整产品能力范围

| 能力域 | 完整产品目标 | 双专利主线 |
|---|---|---|
| 工程与项目上下文 | 管理多项目、区段、里程、工序阶段、参与单位和访问范围 | RI-S1、RA-S1 |
| 工程数据接入 | 接入文件、数据库、API 与监测来源，完成元数据、版本、权限、资料段和结构保留转换 | RI-S1～RI-S2 |
| 知识与规则治理 | 管理站隧一体化施工工序模型、风险机理库、规范标准库、类比案例库、指标体系、量化标准、风险矩阵和措施库 | RI-S3～RI-S4、RA-S2～RA-S4 |
| 风险识别 | 运行混合检索、关系检索、机理驱动 LLM 推理、结构化校验、多来源合并和综合置信度计算 | RI-S5～RI-S6 |
| 风险评估 | 冻结适用性元数据和版本，提取并验证指标值，确定性计算 P/C，映射风险矩阵并生成风险评估记录 | RA-S1～RA-S5 |
| 预警与处置 | 执行风险等级、监测阈值、趋势和联合规则判断，生成预警和受措施库约束的处置建议 | RA-S6～RA-S7 |
| 反馈与校准 | 记录处置执行和效果，计算偏差，生成校准建议，经审批发布新规则版本 | RA-S7 |
| 人工复核与审计 | 处理异常、低置信度和重大风险，保存审批、版本、运行、模型、证据和变更日志 | RI-S2～RI-S6、RA-S3～RA-S7 |
| 智能 Agent | 统一承接内嵌与交互 Agent 任务，以任务类型化工具和增量参与有语义判断的环节，返回结构化结果与证据引用，不维护第二套业务事实 | 横跨 RI/RA，但不替代领域服务 |
| 集成与私有部署 | 提供受控外部接口、身份权限、模型网关、运行监控、备份恢复和内网部署能力 | 系统交付约束 |

## 3. MVP 范围原则

MVP 采用“全链路覆盖、受限深度”。它缩小输入广度、知识规模、运行规模和集成数量，但不删除风险闭环中的必经步骤。

### 3.1 MVP 必须真实具备的能力

- 在一个经甲方确认的工程样例中，运行 RI-S1～RI-S6 和 RA-S1～RA-S7 的全部强制路径。
- 支持后续接入范围票据选定的有限资料格式、监测数据来源和一套正式风险规则或风险矩阵。
- 形成版本化的资料段、工序模型、风险机理条目、标准化风险记录、适用规则集、风险评估记录、预警信息、处置建议、反馈记录、偏差记录与校准建议。
- 使用 BM25 与向量检索的双索引，执行机理驱动的 LangGraph 风险识别，并对 LLM 输出进行结构化和规则校验。
- 使用确定性逻辑完成指标值验证、P/C 计算、风险矩阵映射和预警阈值判断。
- 至少完成一次“记录反馈 → 计算偏差 → 生成校准建议 → 人工审批 → 发布新版本”的 RA-S7 闭环。
- 通过业务界面完成资料接入、识别、评估、预警、处置、复核、反馈和追溯；日常流程不得依赖命令行、数据库直改或开发人员手工串联。
- 提供智能 Agent 工作台；Agent 必须引用正式业务对象与证据，并调用同一套 LangGraph 业务图。
- 共用一个 Agent 任务运行模块，真实跑通数据清洗、非结构化知识编制、识别检索审阅、处置建议组合和校准建议候选五类必经内嵌任务；每类至少有一套受限策略和一个固定验收样例。
- Agent 任务必须冻结工具白名单和硬资源预算，以领域操作记录相对基线的增量；必经任务失败时不得静默跳过、换模型或以确定性基线冒充正式结果。
- 具备权限、人工复核、版本和审计机制，以及单机、离线、完全私有的部署方式。

### 3.2 MVP 允许限制的维度

- 单个工程项目及有限区段；
- 有限资料格式、监测指标和数据来源；
- 有限工序、机理、规范、案例、指标、规则和措施规模，但不得删减专利规定的最小领域枚举；
- 单套经批准的指标体系、量化标准和风险矩阵；
- 单机部署、受控并发和有限上下文长度；
- 系统内预警与一种可工作的数据接入或对外适配路径。

这些限制必须在后续范围与验收票据中给出明确清单，不得在实现阶段临时缩减。

### 3.3 MVP 后续能力

- CAD 深度解析；
- 生产级实时 MCP 数据通路；
- 多渠道自动通知；
- 高可用、横向扩展和多项目规模化运行；
- 更大规模的知识、规则、案例与监测接入；
- LoRA 微调，仅在基线模型评测表明有必要时进入实施；
- 更高配置模型或 `Qwen3.8-Flash-Next` 的升级适配。

后续能力不影响完整产品设计：领域、接口和界面应预留清晰扩展边界，但 MVP 不实现空入口、占位服务或伪回退。

## 4. MVP 验收数据基准

- 最终验收使用至少一套由甲方提供或书面认可的脱敏工程样例。
- 样例应包含工程资料、风险规则或风险矩阵，以及完成评估所需的监测数据。
- 工程样例、规则、输入版本、适用配置和预期核查要点组成固定验收包，可在私有部署环境中重复执行并保留版本。
- 合成数据可以用于开发、自动化测试和故障场景验证，但只能证明技术就绪；未经甲方认可的工程样例验证，不得判定 MVP 完成。

## 5. MVP 完成门槛

以下五个门槛必须同时通过，且由后续验收票据补充量化指标与证据模板。

### 5.1 端到端业务门槛

固定工程样例能够从资料接入运行到反馈校准。每个阶段具有明确输入、输出、状态、版本和失败处理；异常路径能够进入复核并从原运行恢复。

### 5.2 追溯与审计门槛

每项识别、评估、预警和处置结果均可追溯至资料段、工序节点、风险机理条目、规则版本、模型调用和审批记录。审计日志不可静默丢弃。

五类必经 Agent 任务还必须保留可重建输入、原始模型响应、工具行动、预算消耗、候选版本、Agent 增量、确定性接受/拒绝结果与正式产物引用；不保存模型内部思维链。

### 5.3 可重复与确定性门槛

- 相同输入与版本下，Schema 校验、指标换算、P/C 计算、风险矩阵映射、阈值判断和版本选择必须得到一致结果。
- LLM 输出无需逐字一致，但每次运行必须保存模型与量化版本、调用参数、提示模板版本、检索证据、结构化输出和校验结果，以支持审计重放和差异比较。
- Agent 任务在相同冻结基线和策略下不要求逐字复现，但必须能够重建当次输入、解释每项增量及其是否被系统接受；确定性校验和正式写入仍须精确重放。

### 5.4 产品可操作门槛

授权业务用户能够从界面完成全部日常流程；Agent、权限、复核、审批、版本、审计和错误恢复均实际生效。部署、模型装载和底层运维可以使用配置文件与管理命令。

内嵌 Agent 子任务可从对应业务运行查看；Agent 任务详情能够显示任务类型、状态、冻结策略、已用/剩余预算、工具步骤、增量、校验、失败和正式结果引用。

### 5.5 私有部署与质量门槛

系统能够在最低目标硬件——单张 RTX 4090 24GB 显存、128GB 主机内存——完成离线私有部署，并通过后续票据确定的功能、模型、检索、规则、性能、恢复和工程样例验收指标。

任何一个门槛未通过，都不得宣称 MVP 完成。

## 6. 状态判定

| 状态 | 判定条件 |
|---|---|
| 开发中 | 仍有强制业务路径、界面操作、审计链路或部署能力未完成 |
| 技术就绪 | 技术门槛已通过，但尚未取得甲方认可的固定工程样例验收结果 |
| MVP 完成 | 五项完成门槛全部通过，并以甲方认可的固定工程样例形成可复查的验收证据包 |

以下情况均不构成 MVP 完成：只有界面或截图；只有 API、脚本或项目骨架；使用预先写死的样例结果；依赖 Mock 后端；仅用合成数据验证；LLM 输出无法定位证据或还原调用版本；必须由开发人员直接改库才能完成流程。
