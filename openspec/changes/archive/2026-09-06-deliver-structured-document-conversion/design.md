## Context

见 [proposal.md](./proposal.md#why)。C11 已建立工程资料、不可变资料版本、`资料ID-章节ID-资料段ID`、三类资料段定位及权限登记，但目前只接受调用方给出的完整资料段集合；它没有在读取正文前解析精确资料版本的窄接口。C04 可保存不可变工件与诊断，C03 提供幂等事务收口，C07 只追加审计；这些基础能力已经足够，C12 无需再建内容仓库或通用解析框架。

C12、C13 和 C14 从同一基线并行实现。协调决策固定：C12 拥有共享转换 Schema 与端口且可使用迁移 `000009`，C13、C14 分别使用 `000010`、`000011`；既有 `EngineeringDataPortV1` 签名保持不变。C12 只实现 DOCX、文本型 PDF、XLSX 和 UTF-8 CSV，C13 后续实现同一输入联合中的 OCR 版面结果。

## Goals / Non-Goals

**Goals:**

- 用一个闭合端口固定转换输入、结构化块、坐标、JSON-LD、资料段和诊断引用，落实 RI-S21～RI-S23。
- 让文件格式差异停留在适配器，规范化、分块、合规与持久化收口保持确定性、可测试、可重放。
- 复用 C11、C04、C03、C07 的事实与基础设施，不复制资料、权限、工件、错误或审计 DTO。

**Non-Goals:**

- 不实现 OCR、CAD、监测预处理、数据清洗 Agent、知识抽取、风险推理、API/Worker/UI 或交付投影。
- 不推断缺失页码、文档语义或风险知识，不重新计算电子表格公式，不承诺任意 CSV 编码。
- 不新增人工复核类型；C07 当前没有文档转换复核契约，C12 以结构化失败与诊断收口。

## Decisions

### 1. 独立转换端口与闭合引用契约

在 `packages/contracts` 新增 `StructuredDocumentConversionPortV1`，只含 `convert` 与 `read` 两个用例；`convert` 的输入是 `docx | text-pdf | xlsx | csv | ocr-layout` 可辨识联合，固定 `SourceVersionRefV1`、输入 `ContentArtifactRefV1`、转换策略引用、授权与命令信封。成功结果返回转换记录、JSON-LD 工件和资料段集合引用，失败返回既有 `ModuleErrorV1` 及诊断工件引用；`read` 返回转换元数据和引用，不返回正文。

新增 `StructuredDocumentConversionRefV1` 并纳入 `ContractReferenceV1`。结构块、坐标、资料段草稿、合规结果和转换统计均由 strict Zod Schema 定义并派生类型；格式特有字段留在可辨识联合的对应分支，不使用开放元数据袋。C13 只增加 OCR 适配器，不再定义第二套 DTO。

备选是扩展 `EngineeringDataPortV1`。这会让 C11 的资料登记接口同时承担解析器生命周期，并扩大并行分支冲突面，因此舍弃。另一个备选是让每个格式各有端口；它会复制下游收口和失败语义，也舍弃。

### 2. C11 只增加受权资料版本解析用例

C11 的 `EngineeringContextSourceRegistryV1` 增加一个窄查询：依据精确资料版本和授权上下文返回处理所需的资料、版本、内容工件与元数据引用。C12 必须在调用 C04 `open` 前完成该查询，且只能使用返回的精确引用；跨工程、陈旧版本或无正文处理权限均在内容读取前失败。

这项查询仍由资料事实所有者实现，不向转换模块暴露仓储或通用查询能力。备选是在 C12 直接读取 C11 表，违反模块边界；在命令中信任调用方重复提交资料元数据则会形成第二事实源，均舍弃。

### 3. 一个最小规范化模型承接四类解析器

适配器只把文件转换为有序的规范化块：标题、段落、图注、表格、分页、工作表/单元格和对应源坐标。核心模块对该模型统一完成资料段构造、文本分块、JSON-LD 和合规验证；不引入可插拔解析器注册表或通用 AST。

- DOCX：以 `fflate` 读取 OOXML 包，以 `fast-xml-parser` 解析必要 XML，按正文顺序处理段落、样式、表格、图注和显式 `lastRenderedPageBreak`/分页符；拒绝 DTD、外部实体、损坏关系和超限压缩包。
- 文本型 PDF：以 `pdfjs-dist` 读取文本层，保存页码、文本变换得到的坐标和稳定阅读顺序；缺少可靠文本层时返回 C13 路由诊断，不返回空成功。
- XLSX：以 `exceljs` 读取工作表、单元格坐标、合并区域、公式及缓存值，不执行宏或重新计算公式。
- CSV：以 `csv-parse` 解析 UTF-8、BOM、引用和多行字段，保存行列坐标；其他编码显式失败。

备选 `mammoth` 的当前许可证不在仓库允许列表，`officeparser` 会把 OCR 依赖带入 C12，手写 PDF/XLSX 解析则风险和维护量过高，因此不采用。

### 4. 确定性分块和受控 JSON-LD

文本长度按 Unicode 码点计算。分块先沿规范化结构边界，再选择稳定的句末/空白边界，只有单一片段仍超限时按码点硬切；每块最多 512 个码点。块标识由资料版本、结构位置、分块序号与策略版本的稳定摘要导出，前后指针只连接同一资料版本中的相邻块；规范化文本拼接必须无丢失、无重复。

JSON-LD 使用随代码版本化的本地 `@context`，不解析远程上下文。根对象包含资料元数据、结构实体/关系、文本块、证据片段，并按输入存在性附加表格或工法步骤；资料段标识与定位完全复用 C11 Schema。结构实体和关系只表达源文档可证明的结构，风险机理与知识语义留给后续知识编制。

备选按 JavaScript UTF-16 `length` 计数会把代理对重复计数，舍弃。备选把整个 JSON-LD 写入数据库会复制 C04 内容事实并放大事务，舍弃。

### 5. 原子收口与可恢复幂等顺序

执行顺序固定为：

1. 校验 strict 命令、授权和精确资料版本；
2. 通过 C04 打开并校验输入工件，在冻结资源预算内解析；
3. 纯函数完成规范化、分块、JSON-LD 和字段/实体/关系/资料段合规校验；
4. 幂等写入 JSON-LD 或诊断工件；
5. 仅在全部合规时调用 C11 原子登记完整资料段集合；
6. 在 C03 本地事务中以转换幂等键保存不可变转换记录、事务回执和 C07 审计。

转换主键和输出工件键由工程、资料版本、输入工件摘要、解析器集合版本与转换策略版本稳定导出。若第五步已完成而第六步暂时失败，重试通过相同资料段集合幂等恢复；同键不同载荷直接冲突。失败转换也保存诊断引用和终态审计，但不登记资料段。C12 不发布 `engineering.inputs-ready.v1`，因为 C15 尚未完成清洗与部分可用判断。

备选在解析器回调中逐段登记会留下部分成功，舍弃。备选用分布式事务绑定 C04、C11 与 PostgreSQL 会显著增加复杂度，稳定键加幂等重放已经覆盖当前一致性要求。

### 6. 数据模型、迁移和查询

迁移 `packages/adapters/src/postgres/migrations/engineering-data/deliver-structured-document-conversion/000009_structured_document_conversion.ts` 新增只追加 `structured_document_conversions` 表，保存转换标识/版本、工程与资料版本、输入/输出/诊断工件引用、资料段集合引用、输入种类、状态、解析器集合/策略/授权策略版本、命令/幂等/因果运行、统计、操作者和时间戳。唯一约束覆盖工程、命令类型与幂等键；状态和输入种类使用检查约束。正文、JSON-LD 和诊断详情只存 C04。

`read` 只按精确转换引用返回该行映射的 strict DTO，并重新应用授权。不存在、跨工程或不可见结果使用既有稳定错误类别。

### 7. 版本化资源边界和可观测性

转换策略固定输入字节数、ZIP 条目/解压总量/压缩比、单 XML 大小、PDF 页数/文本项、工作表/单元格、CSV 记录/字段、单块码点和总块数。适配器不得联网、执行宏/脚本/公式或加载远程 JSON-LD 上下文。超限、加密、损坏、格式伪装和不支持编码都快速失败，诊断详情留在受权工件中，日志仅记录稳定代码、阶段、资料/转换引用和统计。

成功与失败均记录计数、字节、耗时和命中限制类型，不记录正文。指标沿用既有可观测性适配器；不新增高基数正文标签。

### 8. 依赖由主调度独立检查点写入

实现需要精确版本 `fflate@0.8.3`、`fast-xml-parser@5.11.1`、`pdfjs-dist@6.3.289`、`exceljs@4.4.0`、`csv-parse@7.0.2`。它们分别为 MIT 或 Apache-2.0，均在当前许可证允许列表内；`pdfjs-dist` 的 Node 要求与本项目 Node 24 基线相容。主调度在生产实现前独立完成依赖安装、lockfile、`config/dependency-policy.json`、安全与许可证检查，使生产 Agent 不并发修改依赖事实源。

离线构建使用内网 npm 镜像或预热 `pnpm fetch` store。若安全审计失败、Node 24 不兼容、关键结构/数值无法保持或平台能力已等价覆盖，检查点退出并由主调度选择替代，不让实现代码携带兼容分支。

## Risks / Trade-offs

- [DOCX 页码只在源包显式记录分页时可靠] → 只保留可证明页码；没有分页标记时使用标题路径等现有合法定位，不推测版面。
- [PDF 文本顺序和坐标依赖生成器质量] → 保存页与原始文本变换，使用真实样例校验关键结构；无可靠文本层时明确转 C13。
- [结构边界处硬限制可能切开长词或编号] → 先选结构和文本边界，仅超长不可分片段硬切，并保证可逆拼接。
- [C04、C11、C12 跨模块写入不在单个数据库事务内] → 使用稳定输出键、资料段集合和命令幂等键按固定顺序重放，不尝试分布式事务。
- [解析器可能出现高危漏洞或资源耗尽] → 精确锁版、依赖检查点、无网络解析与分层资源上限；解析失败不产出部分结果。
- [迁移号与并行 change 冲突] → 已由协调者固定 C12=`000009`、C13=`000010`、C14=`000011`，合并前再次核对迁移注册表。

## Migration Plan

1. 主调度完成依赖检查点，更新 adapters manifest、lockfile 和依赖治理策略并运行许可证/安全检查。
2. 发布 contracts 与 C11 窄查询，再发布 core 规范化/合规逻辑和四类 adapters。
3. 应用 `000009` 后运行真实 DOCX、文本 PDF、XLSX、CSV 样例验收及权限、幂等、失败和资源上限测试。
4. 先以调用方显式提交转换命令启用，不回填历史资料；已有资料保持未转换状态，按需幂等转换。
5. 回滚应用代码时停止新转换并保留已写 C04 工件、资料段、转换记录和审计；数据库迁移保持前向兼容，不删除历史事实。需要重新转换时使用新解析器或策略版本创建新记录，不覆盖旧结果。
