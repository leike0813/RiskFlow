# platform/unified-bounded-agent-runtime Specification

## Purpose

定义 RiskFlow 内嵌与交互 Agent 共用的有界执行运行时，确保五类 MVP Agent 任务只能在冻结输入、最小授权、版本化领域工具、硬预算、类型化增量、确定性校验和可恢复审计边界内运行。

## Requirements
### Requirement: 统一版本化 Agent 任务信封

系统 SHALL 以严格 Zod DTO 保存统一的 `AgentTaskEnvelopeV1`。该信封 SHALL 复用 C02 `StartAgentTaskCommandV1`、`AgentTaskRefV1` 和策略引用，固定任务标识、发起者、工程、父运行、冻结输入、触发模式、模型部署、提示模板、工具策略、预算策略、增量 Schema、校验策略、授权范围、幂等信息和创建时间；后续恢复 SHALL 不得替换这些引用。

系统 SHALL 仅接受 `embedded` 与 `interactive` 两种触发模式，以及 `data-cleaning`、`knowledge-authoring`、`retrieval-review`、`response-recommendation`、`calibration-suggestion` 五类任务。内嵌与交互任务 SHALL 使用同一状态机、预算、持久化和审计规则。

#### Scenario: 创建内嵌任务

- **WHEN** 已授权调用方以完整冻结输入和精确策略引用创建五类任务之一
- **THEN** 系统通过 C03 事务原子创建唯一任务引用、初始预算台账、可领取执行记录和命令审计
- **AND** 重复的相同幂等命令返回同一 `AgentTaskRefV1`

#### Scenario: 创建交互任务

- **WHEN** 已授权用户创建 `interactive` 任务
- **THEN** 系统保存与内嵌任务相同的信封和约束
- **AND** 仅在生成写命令提案时进入用户确认状态

#### Scenario: 拒绝未知任务或策略版本

- **WHEN** 请求包含未知任务类型、触发模式、契约版本或未注册策略引用
- **THEN** 系统在模型或工具调用前返回结构化输入、策略或版本错误
- **AND** 不创建可运行任务或隐式选择近似策略

### Requirement: 类型化任务定义与领域工具白名单

Agent MUST 使用已登记任务类型和领域工具；宿主将任务内资料映射为短选项，解析为真实版本后执行，不让模型填写操作者、授权和长技术身份。分页及已读进度由宿主管理，字段与选项在工具入口检查；通用数据库、Shell、任意文件或联网工具不作为业务能力开放。

#### Scenario: 调用允许的领域工具

- **WHEN** Agent 从任务提供的短选项中选择已登记只读工具和资料
- **THEN** 宿主解析真实版本并在新读取入口检查当前权限及剩余预算后执行

#### Scenario: 拒绝越权或未列入白名单的工具

- **WHEN** 任务请求没有登记的工具或真实来源权限已经撤销
- **THEN** 拒绝工具行动；任务内短选项的普通格式错误可在原预算内反馈修正

#### Scenario: 拒绝通用修改格式

- **WHEN** 模型返回 JSON Patch、整对象覆盖或不匹配任务类型化增量 Schema 的写入内容
- **THEN** 运行时拒绝该动作
- **AND** 不将其转换为领域命令或业务事实

#### Scenario: 模型使用短资料选项

- **WHEN** 助手读取任务内一份资料
- **THEN** 宿主解析真实引用并返回该资料片段及读取进度

#### Scenario: 普通选项错误可修正

- **WHEN** 模型漏填字段或选项不属于任务候选
- **THEN** 返回可理解的结构化纠错，不执行错误工具行动

### Requirement: 版本化硬预算与原子预留

系统 SHALL 以 `AgentTaskBudgetPolicyV1` 固定精确模型部署、提示模板和工具策略，并至少限制模型调用次数、各工具及工具总调用次数、输入/输出/上下文规模、候选数、对象数、有界补搜轮数、修正次数、瞬态重试次数、并发数和墙钟时间。系统 SHALL 以 `AgentBudgetLedgerV1` 累计已预留和已使用资源，恢复、重试、修正、租约转移或暂停 SHALL 不得重置台账。

每次模型或工具动作前，系统 SHALL 在 C03 事务中原子预留相应预算并检查并发上限；完成后记录实际消耗，并将该动作的实际墙钟时长累计到耐久台账。任何超限 SHALL 在调用外部端口前失败，不得自动提高预算、减少审计、替换模型/提示/工具策略或改用其它候选来源。

#### Scenario: 并发动作竞争最后预算

- **WHEN** 两个 Worker 同时尝试消费同一任务剩余的最后一份调用预算
- **THEN** 数据库原子状态转换最多允许一个预留成功
- **AND** 另一动作返回预算或并发上限错误且不调用外部端口

#### Scenario: 恢复后继续累计预算

- **WHEN** 任务在租约失效、暂停或可重试失败后恢复
- **THEN** 运行时从耐久台账继续计数
- **AND** 不重新获得已使用或已预留的模型、工具、候选、修正、重试或墙钟额度

#### Scenario: 尝试换模型或扩预算

- **WHEN** 执行过程请求替换信封中的模型部署、提示模板、工具策略或预算策略
- **THEN** 运行时返回 `AGENT_POLICY_MISMATCH` 或 `AGENT_BUDGET_EXHAUSTED`
- **AND** 不调用 C05 或创建替代正式结果

### Requirement: 工件先耐久化且不保存思维链

系统 SHALL 使用 C04 保存可重建任务所需的渲染输入、C05 原始响应工件引用、工具动作与观察、候选版本、类型化增量、确定性校验结果、资源消耗、失败证据、命令提案和正式结果引用。受保护内容 SHALL 继承任务的工程与资料授权，不得以数据库大字段、文件路径或下载 URL 代替工件引用。

对每个模型或工具步骤，相关 C04 工件 SHALL 先达到耐久状态，C03 事务才可写入引用、任务转换和一条事实审计。系统 SHALL 不要求、保存或展示模型内部思维链；模型解释只有在任务 Schema 将其定义为可审计的简短结论或证据引用时才可保存。

#### Scenario: 模型响应完成

- **WHEN** C05 返回严格结构化响应及其原始响应工件引用
- **THEN** C08 先保存渲染输入、候选/动作和校验工件
- **AND** 随后通过 C03 事务提交引用、资源消耗、状态和审计

#### Scenario: 工件写入失败

- **WHEN** 任一必需工件未能耐久保存
- **THEN** 系统返回 `AGENT_ARTIFACT_FAILURE`
- **AND** 不提交引用该缺失工件的任务状态或业务效果

#### Scenario: 模型输出包含未契约化推理文本

- **WHEN** 响应包含任务 Schema 之外的思维链或自由推理字段
- **THEN** 严格 Schema 校验拒绝或丢弃整个非法候选而不持久化该文本
- **AND** 审计仅保留错误类别、可公开证据引用及 C05 受保护原始响应引用

### Requirement: 类型化增量与确定性校验收口

模型输出 MUST 在统一运行时经原 Schema 和领域规则校验。格式、缺字段、数量及冻结选项错误可在原任务剩余修正次数、token 与时间预算内反馈；网关提供已保存原响应及可修正原因，不自行重试。权限、真实来源资格、专业规则冲突及处置三项约束不由模型反复尝试改变。

#### Scenario: 可修复格式错误

- **WHEN** 候选只因字段、格式、引用或增量完整性不满足 Schema
- **THEN** 运行时记录被拒候选和确定性原因
- **AND** 仅在同一策略与剩余修正预算内请求新候选版本

#### Scenario: 候选越过冻结集合

- **WHEN** 模型填写了冻结候选之外的选择编号
- **THEN** 不执行该增量，反馈可修正的选项错误；真实来源资格与业务冲突不由循环改变

#### Scenario: 不可修正约束失败

- **WHEN** 候选违反权限、来源资格、版本兼容、规则冲突或处置三项约束之一
- **THEN** 运行时记录终止性拒绝和证据引用
- **AND** 不将失败反馈为可循环规避的修正请求

#### Scenario: 结构错误在原任务修正

- **WHEN** 原响应正常结束但缺字段且修正预算有余
- **THEN** 记录本次失败与消耗，反馈错误并生成新候选，原响应保留

#### Scenario: 预算不足停止

- **WHEN** 模型尚未形成合格输出且剩余预算不足
- **THEN** 显示明确终态及已用资源，不以空结果继续

### Requirement: 状态机、租约、取消和幂等恢复

系统 SHALL 以耐久内部状态区分 `pending`、`running`、`waiting-user-confirmation`、`retryable-failure`、`completed`、`terminal-failure` 和 `cancelled`，并映射到 C02 公共任务状态。状态转换 SHALL 使用任务版本、稳定动作标识和 compare-and-set；终态不可逆，取消为协作式且 SHALL 保留已经提交的工件、事实和审计。

Worker SHALL 使用 PostgreSQL 有界批量 claim、租约令牌和 `FOR UPDATE SKIP LOCKED` 领取任务。租约过期后其它 Worker MAY 恢复未完成任务，但 SHALL 复用已完成动作结果。外部动作前 SHALL 耐久记录动作意图；仅在明确未产生效果，或目标端口以相同幂等键可安全重放时，才可自动重试。无法确认效果的动作 SHALL 进入显式可重试失败或人工处置，不得盲目重发。

#### Scenario: Worker 在工具效果提交后崩溃

- **WHEN** 领域工具已以稳定幂等键提交效果，但 Worker 在更新任务状态前崩溃
- **THEN** 恢复 Worker 查询或重放相同幂等命令并获得同一结果引用
- **AND** 不产生重复业务效果或重复正式候选

#### Scenario: 外部动作效果不确定

- **WHEN** Worker 丢失连接且无法证明模型或外部工具动作未执行，也无法按稳定标识核对结果
- **THEN** 运行时记录 `AGENT_ACTION_UNCERTAIN`
- **AND** 不自动重新发起该动作

#### Scenario: 恢复端口未返回结果

- **WHEN** 已开始动作只能通过注册的稳定幂等键恢复，恢复端口未返回可验证的结果引用
- **THEN** 运行时记录 `AGENT_ACTION_UNCERTAIN`
- **AND** 不提交候选、结果或重复动作

#### Scenario: 长动作续租与数据库取消

- **WHEN** 模型或领域工具动作持续时间超过一次租约心跳周期，或数据库中的任务出现取消请求
- **THEN** Worker 在动作期间持续续租并检查耐久任务状态，将数据库取消或续租失败传播为当前动作的 cooperative `AbortSignal`
- **AND** 续租失败、租约失效或取消确认后以 fail-closed 方式停止动作，不再提交新的预算、候选、结果或终态事实

#### Scenario: 取消运行中任务

- **WHEN** 已授权调用方取消非终态任务
- **THEN** 运行时耐久记录取消请求并向当前 C05/工具调用传播取消信号
- **AND** 任务最终进入 `cancelled`，保留已存在的审计和工件，不再启动新动作

#### Scenario: 重复完成消息

- **WHEN** 同一动作或 Worker 完成消息被重复提交
- **THEN** 稳定动作标识和任务版本使后续提交返回已有结果或幂等冲突
- **AND** 预算、候选、审计和业务效果不重复累计

### Requirement: C03 事务、Outbox、审计与 checkpoint 边界

系统 SHALL 使用 `TransactionUnitV1` 原子提交每条 Agent 任务事实、一条命令审计、命令收据以及零个或多个 C02 已声明领域事件。C08 SHALL 不为 Worker 队列伪造新的领域事件或建立平行审计表；没有已声明事件时使用零 Outbox 事件，由 Worker 轮询 C08 任务事实。

LangGraph checkpoint SHALL 只保存任务引用、输入/输出版本和运行结果引用。任务信封、预算台账、动作、候选、确认和终态的事实源 SHALL 是 C08 业务表及 C04 工件；checkpoint 丢失、恢复或回滚 SHALL 不得创建、覆盖或推断 Agent 任务事实。

#### Scenario: 审计写入失败

- **WHEN** C03 事务无法写入对应命令审计
- **THEN** 任务状态、预算预留、动作或结果引用一并回滚
- **AND** 不出现有事实无审计的提交

#### Scenario: 工件先于预算与动作意图

- **WHEN** Worker 准备启动模型或领域工具动作
- **THEN** 动作意图工件先经 C04 持久化，再由同一个 `TransactionUnitV1` 原子写入预算预留、动作意图、命令收据和审计
- **AND** 工件持久化失败时不产生预算或动作事实，C03 收据或审计失败时预算与动作事实一并回滚

#### Scenario: 没有对应领域事件

- **WHEN** Agent 状态转换不产生 C02 已声明的业务领域事件
- **THEN** 事务提交零个 Outbox 事件
- **AND** Worker 仍从 C08 耐久任务队列领取工作

#### Scenario: 只有 checkpoint 引用

- **WHEN** 父 LangGraph 从 checkpoint 恢复并持有 `AgentTaskRefV1`
- **THEN** 它从 C08 公共端口查询或恢复对应任务
- **AND** checkpoint 本身不能重建不存在的任务、预算或候选

### Requirement: 交互写命令必须由用户确认

交互 Agent SHALL 只能生成类型化、版本化的 `AgentCommandProposalV1`，其中包含工程、目标对象、目标版本、预期效果和外部副作用。提案 SHALL 先以 C04 工件保存并使任务进入 `waiting-user-confirmation`；确认前不得执行原领域写命令。

用户确认 SHALL 绑定提案版本、确认者和新鲜 C06 授权，并通过原领域端口重新执行授权、Schema、版本和业务规则校验。拒绝、过期、目标版本变化或授权范围扩大 SHALL 不执行命令；Agent 身份不得代替用户确认。

#### Scenario: 用户确认有效提案

- **WHEN** 用户确认当前提案版本，目标实体版本未变且新鲜授权不超出冻结范围
- **THEN** 运行时通过原领域接口提交类型化命令
- **AND** 保存确认、领域结果引用、任务终态和审计

#### Scenario: 未确认提案

- **WHEN** 交互 Agent 生成了带写效果的命令提案但尚无用户确认
- **THEN** 任务保持等待确认
- **AND** Worker 不执行该命令或将提案标记为正式业务结果

#### Scenario: 提案过期或被拒绝

- **WHEN** 用户拒绝提案，或目标版本、授权、策略版本已变化
- **THEN** 系统记录拒绝或 `AGENT_CONFIRMATION_STALE`
- **AND** 不执行旧提案，不以 Agent 生成新提案绕过确认

### Requirement: 必经 Agent 失败不得静默降级

五类必经内嵌 Agent 任务在预算耗尽、C05 不可用、工具失败、确定性拒绝或恢复失败时 SHALL 形成显式失败结果和可审计原因。系统 SHALL 不得跳过必经任务、把基线/缓存/未审核候选冒充正式结果、切换模型、扩大预算或自动解除人工确认。

甲方已审核配置包原样导入 SHALL 不强制 Agent 重新解释。RI-S57 风险候选生成 SHALL 继续由 RI-S56 上下文约束的专用 LLM 节点执行并直接进入确定性校验，不得包装为同一 Agent 的形式化复审。P/C 计算、矩阵映射、阈值判定、Schema 校验、业务入库、版本发布与回滚 SHALL 独立于 Agent 可用性。

#### Scenario: 必经任务预算耗尽

- **WHEN** 五类必经任务之一耗尽硬预算且未产生合格结果
- **THEN** 任务进入 `terminal-failure` 并返回结构化失败引用
- **AND** 下游流程暂停、失败或转人工复核，不得使用替代正式结果继续

#### Scenario: 已审核配置包原样导入

- **WHEN** 下游导入甲方已审核且版本有效的配置包而不需要语义编制
- **THEN** 领域模块按自身确定性导入流程处理
- **AND** C08 不创建形式化 Agent 任务作为前置条件

#### Scenario: 确定性评分不依赖 Agent

- **WHEN** assessmentGraph 执行指标取值、P/C、风险矩阵或预警阈值判定
- **THEN** 确定性领域模块可在没有 Agent 运行时的情况下执行
- **AND** C08 不提供覆盖最终分值、等级或阈值结果的接口

### Requirement: 下游只通过稳定公共引用接入

C15、C17、C19、C21、C27、C29 SHALL 通过 C02 `AgentTaskPortV1`、`AgentTaskRefV1` 和 `AgentTaskResultRefV1` 创建、恢复、取消、确认和消费任务，并为各自任务注册严格领域定义。下游 SHALL 不自行实现第二套模型循环、预算、工具授权、持久化或恢复协议。

任务结果 SHALL 只使用 C02 为对应任务类型允许的主输出引用族及可选校验引用。需要人工审阅的候选 SHALL 由下游领域模块创建 C07 审阅任务；C08 只提供候选、校验和审计证据引用，不自行发布知识、采纳措施或应用校准。

#### Scenario: 下游消费对应结果族

- **WHEN** 五类任务完成
- **THEN** `data-cleaning` 返回内容工件引用，`knowledge-authoring` 返回内容工件或知识修订引用，`retrieval-review` 返回检索工件集引用，`response-recommendation` 返回建议候选或处置建议引用，`calibration-suggestion` 返回校准建议引用
- **AND** 不返回其它任务类型的主输出族

#### Scenario: 候选需要人工审阅

- **WHEN** 知识或校准候选满足 C07 人工审阅条件
- **THEN** 下游领域模块使用候选与校验引用创建 C07 审阅任务
- **AND** C08 任务完成不等于候选已发布或人工决定已作出

### Requirement: C35 Agent 任务只读投影必须有界并保留冻结契约

系统 MUST 提供工程内有界任务目录与精确详情，复验当前 `agent-task.read` 权限并限制到原任务的获准空间/来源范围。详情 MUST 只返回任务、发起者、父运行、冻结输入/策略引用、公共状态、真实预算台账及上限、安全动作、候选/增量/校验引用与逐项决定、结果和当前提案摘要。系统 MUST NOT 暴露完整授权信封、Worker 租约、数据库行、任意工件正文、模型响应或思维链；不改变现有私有完成结果读与终态失败证据读语义。

#### Scenario: 当前任务有界读取
- **WHEN** 获权用户按类型/状态翻页或读取一个精确任务
- **THEN** 返回当前工程内实际可披露的任务及原冻结策略，动作/候选使用独立分页，不因页切换重置预算

#### Scenario: 无权或引用错配
- **WHEN** 查询跨工程、越界来源、伪造游标、错任务版本或已撤权
- **THEN** 在披露对象前安全失败，不返回名称、计数、提案或正文

### Requirement: C35 交互提案摘要必须可确认且不得扩展工具权

系统 MUST 只为真实注册且支持交互模式的定义提供可启动上下文；上下文绑定精确父运行、冻结输入、模型/提示/工具/预算及校验策略。等待确认详情 MUST 从已耐久的当前提案返回精确任务/提案/目标版本、效果和外部副作用，而非从消息文本构造命令。所有启动/恢复/取消/确认 MUST 继续调用原端口并在执行时复验当前授权、版本与剩余预算。

#### Scenario: 可启动上下文由所属事实证明
- **WHEN** 用户请求一个已登记任务输入的交互启动上下文
- **THEN** 仅在定义支持、输入真实且当前授权足够时返回完整启动载荷，不推测缺失策略或把 embedded 改为 interactive

#### Scenario: 精确提案确认
- **WHEN** 用户确认或拒绝当前提案
- **THEN** 原确认端口处理该版本；提案陈旧或拒绝零领域效果，重放不重复效果或预算

### Requirement: 任务范围冻结且权限按业务动作检查

任务 MUST 固定发起者、工程和输入范围，统一业务动作入口在每次新资料读取及正式结果提交前应用当前权限。Worker 不依赖旧会话或过期启动授权；内部模块不逐层签发行动凭据。新授权不能扩大已冻结任务来源，账号停用或撤权在下一动作拒绝。

#### Scenario: 任务跨网页登录期限

- **WHEN** 会话到期而原账号仍有权限、预算和有效执行资格
- **THEN** 继续原任务，不更换模型或重置预算

#### Scenario: 撤权后阻止新动作

- **WHEN** 任务发起者失去目标资料权限
- **THEN** 下一读取或结果提交拒绝，保留已完成动作记录

### Requirement: 失败任务证据按当前权限直接读取

系统 MUST 允许有权用户按任务精确引用读取任务类型、终态、安全错误、取消原因、预算与动作候选校验引用；不返回模型正文、思维链或任意工件正文。普通重复读取仅记录访问，不使用写命令去重。入口区分无权、获准范围内不存在及读取故障。

#### Scenario: 旧任务证据重复查看

- **WHEN** 有权用户多次打开同一失败任务
- **THEN** 得到原安全证据，各次访问互不冲突

#### Scenario: 系统异常明确反馈

- **WHEN** 精确证据读取遇到内部技术错误
- **THEN** 返回读取失败与定位引用，不伪装为任务无权
