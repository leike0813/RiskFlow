# RiskFlow 完整产品功能规格与用例契约

> 状态：本票已确认的规划基线；本文不是 OpenSpec 正式规格。
>
> 本文只定义业务能力及其可观察行为。页面布局留给“设计完整产品界面与交互规格”，接口字段、Schema 与实现任务留给后续 OpenSpec changes。

## 1. 规格目标

本规格把 RiskFlow 定义为一组可由界面、智能 Agent 或受控外部适配器调用的业务用例。三种入口必须调用同一领域命令、读取同一查询投影，不能各自维护风险、评估、预警或处置事实。

每个用例至少说明：

- 谁在什么条件下发起；
- 发起时冻结哪些输入、对象版本和工程上下文；
- 正常完成后产生什么业务事实或过程任务；
- 哪些失败允许重试，哪些情况必须暂停并进入复核；
- 如何处理并发、重复请求、作废、版本发布和历史重放；
- 哪些操作者、决定、证据与运行信息进入审计；
- 完整产品与 MVP 的能力深度有何不同。

规格以用例作为模块的公开接口。OCR、分块、BM25、向量检索、P/C 聚合、矩阵映射和 LangGraph 节点属于实现，不直接变成面向用户的零散功能。

## 2. 全局行为约束

### 2.1 工程上下文与权限

- 所有业务命令必须在一个明确的工程及操作者身份下执行；跨工程批量查询、系统运维命令除外。
- 用户可在不同工程拥有不同预设角色。系统管理员身份不自动取得工程业务权限。
- 无权命令在产生任何业务事实之前拒绝；拒绝事件进入安全审计，但不得泄露目标工程或资料内容。
- 资料证据读取继续受资料自身权限约束。能查看风险结论不等于能读取原始资料。

### 2.2 版本、时间与幂等

- 业务运行引用精确对象版本、发布集合和输入快照，不读取含义不清的“最新版”。
- 不可变业务事实只追加。修正通过新版本、新记录、取代关系或作废决定表达。
- 受治理定义发布后不可原地修改；回滚通过重新启用历史版本或发布新集合完成。
- 每个有外部副作用的命令都带业务幂等键。重复提交返回既有结果，不重复生成风险记录、预警、任务、通知或审计业务事件。
- 每项事实同时记录业务发生时间和系统记录时间；补录历史数据必须标明历史补算，不能伪装为当前实时结果。

### 2.3 运行、失败与人工复核

- LangGraph 运行是有明确起止的过程任务。检查点用于暂停、恢复和重试，不是业务事实源。
- 可重试技术失败保留已完成步骤，从稳定检查点恢复；重试不得重复业务入库。
- 字段或证据不完整、低置信度、重大风险、工序模型连续校验失败、规则冲突、规则无法可靠结构化、处置建议约束失败、校准建议待发布等情况创建统一复核任务。
- 复核任务只指向确定对象版本。复核过程中不得直接修改被审对象；“退回修改”结束当前任务，由提交方创建新版本再送审。
- 审计写入失败时，相关业务命令不得静默成功。外部通知失败不得回滚已可靠入库的预警事实。

### 2.4 查询与命令分离

- 查询投影可组合风险全链路，但不拥有业务事实，也不能直接回写领域对象。
- 界面中的编辑、确认、发布、作废、重新评估和恢复运行都必须转换为显式领域命令。
- 智能 Agent 只能代当前用户准备和提交正式命令。高影响命令执行前必须展示工程、对象、输入版本和预计结果并取得确认。

### 2.5 Agent 任务

- 内嵌与交互 Agent 共用统一、有界的 Agent 任务契约；任务冻结发起者、工程、输入版本、模型/提示模板、工具策略、资源预算和 Agent 增量 Schema。
- 只有数据清洗、非结构化知识编制、识别检索审阅、处置建议组合和偏差超限后的校准建议候选为必经内嵌任务；常规评估与预警不创建 Agent 任务。
- Agent 只能调用任务类型化领域工具，并以受限领域操作表达相对基线的增量。确定性模块逐项接受或拒绝，Agent 不直接写领域存储。
- 必经 Agent 失败或预算耗尽时不得静默跳过、换模型或用基线冒充结果；可修复结构错误只能在原预算内有限修正。

## 3. 角色与权限基线

| 角色 | 核心权限 | 明确限制 |
|---|---|---|
| 工程风险管理员 | 配置工程业务上下文；接入资料；启动识别评估；处理复核；发布受治理定义；确认预警和处置；登记反馈；导出报告 | 只能在获授权工程内行动，不能绕过资料权限 |
| 系统管理员 | 开通工程；管理账号、连接、备份、模型服务和系统配置 | 不因系统角色自动获得工程业务数据访问权 |
| 复核人 | 领取并决定被授权类型的复核任务 | 不能在复核过程中直接改写目标对象 |
| 现场处置人员 | 查看分配的处置任务；登记实际执行与现场反馈 | 不拥有规则发布、风险作废或工程配置权限 |
| 业务查看者 | 查看获授权工程的风险闭环；按权限导出 | 不得修改、确认、发布或通过 Agent 间接执行写命令 |

同一账号可叠加角色。MVP 不强制提交人与审核人分离，但每次关键确认必须留下独立决定和审计记录。

## 4. 工程与访问管理

### F-PJ-01 开通并启用工程

| 契约项 | 规定 |
|---|---|
| 触发与权限 | 系统管理员开通工程；工程风险管理员补充并确认业务上下文 |
| 冻结输入 | 工程身份、参与单位、施工工法数据、地层条件数据、工程阶段数据、初始空间区段、初始发布集合选择 |
| 正常结果 | 工程从“筹备”进入“生效”，形成业务上下文修订和首个适用性元数据基线 |
| 异常与复核 | 三个最小适用性维度缺失时不得生效；发布集合不兼容时给出逐项原因，不自动换用其它版本 |
| 版本与审计 | 记录创建人、业务确认人、精确配置版本、生效时间和差异 |
| MVP 深度 | 可预置唯一验收工程，但工程风险管理员必须能在界面核对并确认业务配置 |

### F-PJ-02 维护空间区段与工程上下文修订

工程风险管理员可以新增或修订空间区段层级、里程范围、施工工法、地层条件和工程阶段。关键变化创建新修订，并提示受影响的资料关联、项目工序模型、适用规则集和待重新评估风险。历史事实继续引用原修订或当时快照。

区段里程冲突、父子区段越界或已被事实引用的区段删除请求必须拒绝；需要撤销时使用停用或新修订。变更只形成“待识别/待重新评估”原因，MVP 不自动启动运行。

### F-PJ-03 管理工程成员与资料访问

系统管理员维护账号，工程风险管理员或获授权管理员维护工程成员、预设角色和资料访问范围。授权变化即时影响新请求，不追溯改写既有审计主体。移除成员后保留其历史操作身份。

完整产品可按工程开启多人审批策略；MVP 使用简单预设角色，不提供任意权限设计器。

## 5. 工程资料与监测接入

### F-DA-01 登记工程资料版本（RI-S1，RA-S1）

| 契约项 | 规定 |
|---|---|
| 触发与权限 | 工程风险管理员上传文件或确认来自数据库/API 的资料；系统管理员只能配置技术连接 |
| 冻结输入 | 工程资料项、原始内容或外部来源引用、资料类型、形成时间、位置/里程、来源单位、权限、接入方式和解析配置版本 |
| 正常结果 | 创建不可变工程资料版本及新资料ID，记录提供方、系统录入人、时间戳和变更日志 |
| 异常与复核 | 重复内容提示关联既有资料版本；来源不可读、权限不完整或元数据校验失败时不启动解析 |
| 版本与审计 | 原始内容、来源摘要、权限、配置和操作者冻结；新上传或重新解析不覆盖旧版本 |
| MVP 深度 | 支持票据“确定工程资料与监测数据接入范围”选定的有限格式和一种可工作的导入路径 |

### F-DA-02 解析、分段并校验资料（RI-S2）

接入任务按文件类型执行结构保留转换，生成章节、页码、表格、图注、监测字段或工法步骤等 JSON-LD 内容。语义块不超过 512 字符，相邻块保留前后指针；资料段标识固定为 `资料ID-章节ID-资料段ID`。

字段、实体、关系或资料段校验失败时，任务记录结构化失败原因并定位到资料段。合格资料段进入统一清洗 Agent 任务，Agent 以清洗增量判断剩余覆盖和排除范围；结构、权限、资料段标识与审计硬约束通过后，结果自动成为业务可用输入。工程风险管理员可修正元数据、选择新解析/Agent 策略或仅重处理失败资料段；每次重处理创建新的工程资料版本和资料ID，旧版本保留。

### F-DA-03 接入监测序列并冻结监测快照（RI-S2，RA-S1）

系统按监测序列接收不可变批次。数据清洗由统一 Agent 任务主导，时间对齐、异常与缺失检测、单位换算及短期斜率、加速度、频域主峰和异常评分算法作为任务白名单工具；算法失败或效果不佳时，Agent 可以在冻结 raw 范围内继续处理。Agent 以类型化领域操作提交清洗增量和质量判断，系统保存工具、预算、候选、前后差异、模型/提示模板版本和依据证据。一次识别、评估或处置效果比较必须显式冻结监测快照，引用确定批次、清洗结果和时间窗口。

迟到数据形成历史补录批次，可触发“历史补算”提示；同一采样时间的更正值形成带更正关系的新批次。任何新数据均不改写既有批次或快照。结构、权限和审计完整性继续由确定性硬约束校验，P/C 只读取已经冻结的版本化清洗结果。

## 6. 知识、规则与版本治理

### F-KM-01 编制并发布项目站隧一体化施工工序模型（RI-S3）

工程风险管理员从已发布基线初始化项目模型，或从合格工程资料生成候选节点、装备、构件、状态参数和关系。从非结构化资料生成或修订候选时必须经过知识编制 Agent 任务；原样导入甲方已审核配置包时不要求 Agent 重新解释。系统执行结构与关系一致性校验，并确保五个必含工序节点覆盖。通过校验后提交复核；发布集合固定所有成员精确版本。

一致性校验再次失败时必须创建复核任务。共享基线更新只生成项目差异提示，不自动改变已发布项目模型。识别运行只引用已发布项目模型版本。

### F-KM-02 治理风险机理库与检索证据库（RI-S4、RI-S52）

受权用户可以导入、编制、修订和送审风险机理条目、规范条文和类比工程案例。从非结构化工程资料、规范或案例编制、修订候选时必须经过知识编制 Agent 任务；甲方已审核配置包原样导入只执行确定性契约校验。风险机理条目必须关联适用工序、状态参数/监测指标、证据需求和证据定位；发布前校验触发条件可解析、证据可定位和关键工序覆盖。

风险机理库、规范标准库与类比工程案例库各自保留条目来源、审核状态和修订历史，并通过精确成员版本组成发布集合。检索索引是可重建派生物；索引重建失败不得改变发布集合事实。

### F-KM-03 治理指标、量化标准与风险矩阵（RA-S2）

完整产品支持导入、有限编辑、差异比较、送审、发布、停用和回滚指标体系、量化标准、权重、风险矩阵、风险可接受阈值和监测预警阈值。每个指标项必须保存类型、适用条件、字段映射、权重、分级区间、分值和阈值来源。

风险可接受阈值与监测预警阈值分别管理。权重和矩阵发布后不可原地覆盖。MVP 以导入甲方确认的版本化配置包为主，只提供核对、有限参数调整、发布和回滚，不建设通用规则设计器。

### F-KM-04 结构化规范条文并形成适用规则集（RA-S3、RA-S4）

规范条文结构化通过知识编制 Agent 任务生成结构化评分规则草案。草案必须含规则适用条件、指标项、评分阈值、分级区间、例外条款、证据定位、规则版本和审核状态；无法可靠映射的定性表述进入复核。Agent 无权发布、停用或回滚规则。

系统先执行规则一致性校验，冲突或重叠输出结构化说明并暂停发布；再把工程适用性元数据快照与规则适用条件严格匹配，保留筛除原因。经审核发布的适用规则集冻结生成时间、项目元数据快照、规则成员版本和审核状态。常规评估只读取已发布适用规则集，不在评分时临时让 LLM 选择规则。

MVP 日常路径以原样导入甲方确认的版本化规则配置包为主，同时必须选取至少一条真实或甲方认可的非结构化规范条文，真实跑通“知识编制 Agent 结构化增量 → 确定性校验与冲突检测 → 人工审核 → 适用规则集发布 → 风险评估精确引用”。两种入口形成同一领域事实和审计链，不建设两套规则模型，也不建设通用批量规则设计器。

### F-KM-05 治理措施库

措施项以风险事件、施工工法、地层条件、工程阶段、资源和工序约束为适用条件，采用与其它受治理定义相同的修订和集合发布机制。非结构化来源编制或修订措施项候选时使用知识编制 Agent 任务；甲方已审核措施包可原样导入。处置建议只能从已发布措施库的候选集中组合；候选为空时进入人工处置编制流程，不能让模型自由生成无来源措施。

## 7. 风险识别

### F-RI-01 启动并运行风险识别（RI-S1～RI-S5）

| 契约项 | 规定 |
|---|---|
| 触发与权限 | 工程风险管理员从界面或 Agent 显式启动；完整产品可按工程开启事件驱动策略 |
| 冻结输入 | 工程/区段修订、合格资料版本、监测快照、项目工序模型、风险机理库、规范标准库、类比工程案例库、检索融合配置、模型和提示模板版本 |
| 正常流程 | 展示待用版本并确认；执行确定性基线检索、必经 Agent 审阅与有界补搜、确定性上下文选择，再运行专用 LLM 启发式推理；保存 Agent 增量、模型输出候选及证据 |
| 正常结果 | 产生与工序节点绑定的模型输出候选，不直接产生正式风险事实 |
| 异常与复核 | 输入缺失不启动；模型/检索技术失败按策略重试；证据不足、输出越过字段契约或低置信度进入复核 |
| 版本与审计 | 保存运行/图/节点、输入实体、模型、提示模板、检索配置、Agent 任务/工具/预算/增量、原始结构化输出、证据和路由决定版本 |
| MVP 深度 | 必须真实调用私有模型和 BM25/向量双索引，不接受预写结果或 Mock 回退 |

### F-RI-02 验证、合并并验收标准化风险记录（RI-S58～RI-S65）

系统对候选执行 Schema、必填字段、证据定位、规则一致性和完整性检查。多工序节点或多资料来源重复识别时，按配置执行工序节点一致性、事件表达相似性和证据定位相似性合并；不存在重复时显式记录跳过。

合格候选形成标准化风险记录的新版本和验收决定，固定工序节点、风险机理条目、资料来源、综合置信度及其形成依据。人工通过采用同一入库接口。任何路径都不得改变七项专利内容字段或绕过 RI-S61 完整性检查。

### F-RI-03 查看和作废识别事实

授权用户可查看工序风险关联图谱及“资料段 → 工序节点 → 风险机理条目 → 标准化风险记录”的证据链。补充证据或人工修正创建新记录版本并指向旧版本；误判通过作废决定取消当前效力。作废不会删除历史评估、预警或处置事实，并应产生是否需要后续风险重新判断的提示。

## 8. 风险评估与重新评估

### F-RA-01 启动评估并冻结评估依据（RA-S1～RA-S4）

工程风险管理员显式选择一个标准化风险记录精确版本或一个外部风险事件，两者必须二选一。系统冻结适用性元数据、监测快照、适用规则集、指标字段映射、权重、风险矩阵和两类阈值版本；缺少必需输入时不给出临时分值。

适用规则集不存在或与当前元数据不匹配时，评估进入“等待规则准备”，不得由 LLM 临时选规则。外部风险事件保持独立来源和证据链，不复制成标准化风险记录。

### F-RA-02 确定性计算 P/C 与风险等级（RA-S5）

系统按显式字段映射提取指标实际值，经已发布规则映射单指标基础分，结合版本化权重分别计算 P 与 C，再按风险矩阵确定风险等级。随后使用冻结的风险可接受阈值、监测预警阈值和联合触发策略确定性生成触发类型与触发指标集合，最后原子写入完整、不可变的风险评估记录。所有输入、单指标明细、聚合函数、矩阵格、舍入规则、触发判定和策略版本均进入该记录；未命中预警时触发指标集合为空。

常规评估与预警阶段不创建内嵌 Agent 任务。交互 Agent 可以解释已入库评分依据、诊断缺失输入或准备重新评估命令，但不能插入计算链或成为评估可用性依赖。

P/C 聚合由风险评估模块内受控、版本化的评分策略类型执行。MVP 只实现甲方确认的一种策略；权重、区间、舍入和矩阵均来自不可变配置，不建设任意公式或 JavaScript DSL。出现新的真实规则族时再通过 OpenSpec 增加策略类型，不扩张调用方接口。

无法映射、单位不兼容、数据过期或规则冲突时不生成部分有效的最终等级；系统给出受影响指标和处理入口，必要时创建复核任务。相同输入和版本必须得到一致结果。

### F-RA-03 管理重新评估

监测快照、适用性元数据、适用规则集或风险矩阵出现新版本时，系统创建带原因的“待重新评估”提示。MVP 由工程风险管理员检查版本后显式启动；完整产品可按工程策略自动创建独立重评估运行。

每次重评估新增风险评估记录，引用上次评估和触发原因。当前风险等级由查询投影按有效输入和业务时点选择，不写回标准化风险记录。

## 9. 预警、处置与反馈

### F-WR-01 判定并记录预警（RA-S6）

风险评估记录可靠入库后，预警处置模块读取其中已经冻结的触发判定。任一条件命中即生成不可变预警信息，保存预警等级、触发类型、触发指标、证据、建议处置方向、通知状态和审计信息；风险评估记录不再回写。外部通知仍须等待预警信息可靠入库。

每个风险评估记录按命中的触发类型分别生成预警信息，同一类型可以包含多个触发指标。同一“工程 + 风险稳定身份 + 处置空间范围”存在尚未关闭的预警处置任务时，新预警关联该任务；风险升级追加升级事件，不依赖固定时间窗口。任务关闭后再次越限创建新任务；不同处置空间范围分别建任务。

### F-WR-02 确认预警并执行通知

预警事实与通知任务分离。工程风险管理员查看触发指标和证据后，可以确认、质疑或登记线下通知结果；外部通知必须在预警入库后创建任务，并按配置选择责任人和渠道。通知失败进入重试/人工补发，不回滚预警。

“确认”只记录责任人已读并接管，不控制预警事实成立、对外通知或现场处置。质疑、作废、通知和处置分别使用独立命令。

### F-RS-01 生成并校验处置建议（RA-S7）

系统从已发布措施库按风险事件和适用性元数据形成冻结候选措施集，必经处置建议 Agent 任务只在候选集内选择、组合、排序并补全资源需求和目标指标。Agent 输出在依次通过触发指标一致性、规范合规性、现场资源与工序约束可执行性校验前只是处置建议候选工件。

任一校验失败时保留候选工件并创建复核任务，不生成处置建议。复核人可以修正候选或退回上游治理，但必须重新执行全部校验；任何角色都不能覆盖失败结果并强行通过。通过校验的处置建议仍不是施工指令，工程风险管理员可以采纳或不采纳；另行组合措施时形成新候选并重新校验。

### F-RS-02 管理预警处置任务与现场执行

系统以“工程 + 风险稳定身份 + 处置空间范围”归集尚未关闭期间的预警、建议、实际采用方案、责任人、执行进度和通知结果；任务关闭后再次越限创建新任务。任一时点至多有一个获批准执行版本。建议、实际采用方案和实际执行结果分别保存。

每次实际行动形成现场处置执行记录，来源可以是采纳的处置建议或现场独立决定。现场处置人员可自行登记；工程风险管理员可以代录，但必须分别记录实际执行人、决定来源和系统录入人。紧急独立行动不被包装成系统建议，也不自动进入措施库；取消、未采纳、延期和偏离建议均需理由，不删除原建议。

### F-RS-03 记录反馈、偏差与校准建议（RA-S7）

处置执行前，系统针对确定处置建议版本生成独立、不可变的处置效果预测，冻结处置前监测快照、预测时间范围、目标指标、评分依据、预测策略和证据。MVP 使用一种经样例验证的确定性监测趋势策略，LLM 不直接预测数值、P/C 或风险等级。

完成处置后，系统冻结处置后监测快照并登记现场反馈，使用预测时冻结的同一评分依据计算实际风险变化，再与预测变化比较，生成不可变偏差记录。新规则下的当前风险重新评估可以并行产生，但不参与该偏差。预测不可用、目标时间范围未到或缺少执行前预测时不编造偏差或校准建议。

偏差记录可靠入库且超过冻结阈值后，系统启动必经校准建议 Agent 任务。Agent 只读取预测、反馈、偏差、所用规则/权重/阈值版本和证据，提出偏差原因与建议调整对象；结构与引用校验通过后形成校准建议候选并进入人工复核。工程风险管理员可以从校准建议创建权重、评分阈值或分级区间的新草稿；新草稿仍须校验、复核和发布。系统不得自动覆盖当前版本。MVP 至少真实完成一次“反馈 → 偏差 → Agent 校准建议 → 人工确认 → 新版本发布”的闭环。

## 10. 复核与审计

### F-RV-01 领取并解决复核任务

复核人或具备相应权限的工程风险管理员领取待复核任务，查看目标精确版本、触发原因、证据、运行和历史决定，然后作出类型化决定：通过、退回修改、作废或取消。外部专家意见可代录，必须保存专家身份、意见来源和录入人。

决定形成正式领域事实后，系统恢复对应 LangGraph 线程或结束相关流程。重复恢复必须幂等；目标版本已被取代时禁止基于陈旧版本作决定，并提示重新领取最新任务。

### F-AU-01 查询端到端证据链与审计

授权用户可以从任一标准化风险记录、风险评估记录、预警信息或处置任务沿标识和精确版本回溯：

> 资料段标识 → 工序节点 → 风险机理条目 → 标准化风险记录 → 风险评估记录 → 预警信息 → 处置建议 → 偏差记录 / 校准建议

查询同时展示运行、模型/提示模板、检索证据、规则/权重/矩阵、操作者、复核和作废信息。无资料读取权限时只显示允许披露的定位摘要，不泄露原文。

### F-AU-02 导出业务报告与审计证据包

工程风险管理员和获授权的业务查看者可以导出工程报告，系统记录导出事件。默认报告包含风险结论、P/C、等级、触发指标、处置结果和主要版本标识。

“附带审计证据”默认关闭；开启后加入获准导出的证据定位、审计事件、运行记录、模型/提示模板版本、规则计算明细和证据片段。原始工程资料由独立选项和资料权限控制，不自动打包。

## 11. 智能 Agent

### F-AG-01 查询、解释与导航

Agent 在当前用户和工程权限内检索查询投影，回答风险态势、单项风险依据、规则版本、运行状态和待办问题。回答必须引用正式业务对象或证据；无法取得资料权限时不得通过生成内容泄露原文。Agent 可返回页面深链，但不维护独立会话事实替代业务记录。

### F-AG-02 准备并提交业务命令

Agent 可以帮助选择输入、解释影响并准备识别、评估、复核、预警确认、反馈或导出命令。执行前展示工程、目标对象、精确输入版本、预计生成的事实和是否会触发外部副作用；用户确认后调用同一领域接口。

只读用户不能通过 Agent 执行写命令。Agent 不得代替复核人、绕过发布、自动选择未发布规则、修改 P/C 或把模型回答写成业务事实。

### F-AG-03 运行并审计统一 Agent 任务

内嵌与交互 Agent 共用同一过程任务。任务状态为待运行、运行中、等待用户确认、可重试失败、终止失败、已完成或已取消；会话可以持续存在，但任务必须有界。系统展示并保存冻结基线、模型/提示模板、工具策略、硬预算、工具步骤、候选版本、Agent 增量、确定性接受/拒绝结果、错误和正式结果引用。原始渲染输入与模型响应作为受权限保护的不可变工件保存，不记录模型内部思维链。

## 12. 系统运维与外部集成

### F-OP-01 配置数据源、通知与外部系统适配器

系统管理员配置文件、数据库、API、监测、通知和风险管理系统适配器的技术连接；工程风险管理员确认它们可作用的工程、数据类别和业务用途。密钥不进入业务记录或导出包，连接测试只返回最少必要诊断。

MCP 只用于“实时多源监测数据 → 指标实际取值”的外部接入通路，不能执行 P/C、矩阵映射或规则选择。连接中断保留最后成功快照及其时效，禁止把陈旧值伪装为实时值。

### F-OP-02 运行监控、模型版本与备份恢复

系统管理员可以查看 API、Worker、LangGraph 队列、模型网关、索引和存储健康状态，管理经验证的模型/量化/提示模板发布版本，并执行备份与恢复。运维动作不直接改写领域事实。

恢复演练必须验证业务记录、检查点、对象文件、发布集合、索引重建和审计链的对应关系。检查点缺失不能伪造业务事实；可重建索引不作为唯一备份。

## 14. 已确认的预警语义

### 预警确认仅表示已读并接管

评估结果越限后，系统先可靠保存不可变预警信息，该预警随即在工程内生效。工程风险管理员执行“确认预警”时，只记录责任人已读并接管；确认不控制预警事实成立，也不延迟处置入口出现。

外部通知、现场处置和施工措施批准分别使用独立策略与命令。误报通过质疑、复核和作废决定处理，原预警及处理过程继续保留用于审计。
