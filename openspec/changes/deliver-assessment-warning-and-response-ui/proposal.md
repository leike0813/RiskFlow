## Why

C25–C31 已交付评估、预警、处置反馈与校准领域能力，C32/C33 已在 `demo/` 接通真实工程、知识、识别与复核界面，但评估和预警仍是静态样例。C34 复用 `demo/v2` 的 16 页设计，把评估结果解释与人工处置闭环接到真实接口。

## What Changes

- 在既有 `demo/` 应用落地 P-OV-01 与 P-RA-01～07、P-WR-01～04、P-RS-01～05 共 17 页：风险态势，评估候选/启动/运行/记录/矩阵/重评历史，预警与任务列表/详情，建议/执行登记/预测/反馈偏差/校准详情。
- 复用 v2 页面分区、版本化 SVG 矩阵和交互；数据、权限、确认、证据、会话与路由复用 C32/C33 已接线设施。移除被替换页面的静态事实和假操作。
- 新增两个闭合、有界的领域只读接口及对应 HTTP 查询分支，展示实际保存的评估解释、预警确认/通知、正式建议、预测、执行、反馈、偏差和校准关联。复用现有记录 Schema，不建立第二套业务记录。
- 经既有公开命令启动初评和重评，确认预警、采纳或拒绝建议、登记执行和反馈；所有写入先确认并保持精确版本与原幂等身份。历史回填记录可读，本轮不增加回填写入口。
- 在 C30 既有运行工件中原样保存重评前驱、显式原因和变化引用，供父子运行、恢复与历史解释共用；冻结输入集合不代替变化集合，缺失历史入口事实时安全失败。
- 将 C29 已有复核结果收口与未发布草案创建接入两个窄 HTTP 命令，以单分支授权和逐用途下游授权保持当前权限模型。
- 扩展已有真实 Chromium + PostgreSQL 验收，覆盖权限、版本、响应丢失重试、历史解释与跨页追溯。

## Capabilities

### New Capabilities

- `web/assessment-warning-and-response-ui`：上述 17 页的真实读取、解释、人工写入、状态、证据与浏览器验收。

### Modified Capabilities

- `domain/module-interfaces-events-workflows`：新增风险评估、预警处置的独立只读端口、strict 查询/结果与模块所有权接缝，闭合重评入口事实的保存、恢复和原因码映射。
- `platform/http-command-query-sse-shell`：登记两个查询及两个校准治理命令分支，沿用当前会话授权、失败信封与 OpenAPI 派生。
- `domain/calibration-suggestion-and-governance-loop`：公开精确复核结果收口与草案创建入口，明确单分支授权接缝。
- `domain/engineering-context-source-registry`：增加已登记适用性快照与外部风险事件的有界只读接缝，供评估启动预览使用。

## Impact

- 路线节点 C34；固定基线 `d1ad73a005b08cd8fb2718c597ba0ae1af2b7019`。基线已有公共契约、角色授予和 HTTP 目录接线；继续补正与复验这些实现，不将其当作完整交付。执行图直接依赖 C10/C25/C26/C27/C28/C29/C30/C31 均已归档；同时复用已归档 C32/C33 的 demo 接入和 C41 人工命令接线。
- 文件所有权涉及 contracts 公共读取契约、core 角色授予与 C30 运行元数据、Worker 重评入口传递/恢复、各领域 adapter 内部只读实现、API 路由、demo 页面/接入层/验收。详见 design 与 implementation-plan 的闭合文件清单。
- 追踪 RA-S1～RA-S7；风险输入与证据保持 RI-S6 引用，评估界面不改识别事实。校准决定经既有复核页作出，校准页消费精确决定收口或创建草案；后续发布仍经知识治理。
- 无新增第三方依赖、锁文件变化、表或迁移；不更改 P/C、矩阵、阈值、Agent 预算、工作流状态机和人工决定语义。v2 审阅工具、fixtures、契约镜像与 gap 覆盖层不进入交付应用。
