# RiskFlow 完整产品界面与交互规格

> 状态：Wayfinder 已确认的规划基线；本文不替代后续 OpenSpec 正式规格。
>
> 输入基线：信息架构（04）、功能规格（13）、识别工作流契约（15）、评估预警处置引擎（16）。本文只派生页面、交互与界面状态，不新增业务事实、命令或字段。

## 1. 规格目标

把七项业务导航与全局 Agent 停靠栏展开为可直接实施和验收的完整界面规格：每个页面的骨架类型、数据与操作、空/加载/异常/权限状态、跨页面跳转、Agent 交互、证据抽屉与角色差异，并逐页标注 MVP 与完整产品差异。

本文不定义视觉细节（沿用 04 号票视觉系统）、不复制字段契约（引用 AGENTS.md §2.6/§2.7 与功能规格的 SSOT）、不展开五张汇报截图的逐像素设计（由“设计汇报截图”票在本规格完成后重新校准）。

## 2. 全局应用框架

继承 04 号票框架并细化如下（Agent 形态对 04 号票的修订见 §5）：

- **顶栏**：产品标识、当前工程切换器、空间区段选择器、工序阶段选择器、通知中心入口、Agent 停靠栏入口、当前用户与角色。工程/区段/工序切换只改变查询与命令的上下文，不跨页面搬运对象状态；切换后停留在当前页面并重新加载。
- **左侧导航**：七项业务导航（风险态势、工程项目、风险识别、风险评估、预警处置、知识与规则、复核与审计）。智能 Agent 不是导航项，而是全局停靠栏（§5）。系统管理区见 §15，不进业务导航。
- **主工作区**：承载当前页面骨架。
- **右侧停靠区**：按需展开，包含两个可切换面板——“上下文”（证据抽屉 §4、版本与审计摘要、关联对象）与“Agent”（§5）；不使用跨页面悬浮对话框拼接信息。
- **待办入口**：复核与审计导航项显示当前用户可领取复核任务数；通知中心显示应用内通知（预警、任务分配、运行结果）。

## 3. 全局页面骨架

全部页面归入五类骨架。骨架统一交互，页面规格只写业务差异。

### 骨架 A：列表页

- 结构：页面标题与上下文说明 → 主操作区（如“启动识别”“登记资料”）→ 筛选区（状态、类型、时间、关键字）→ 表格区 → 分页。
- 表格行点击进入对应详情页；行内不放会跳转的嵌套链接以外的操作按钮，危险操作只放详情页。
- 空状态：说明当前筛选下无数据，并给出最可能的下一步操作入口（如“还没有风险评估记录，先去待评估风险启动评估”）。
- 加载：骨架屏占位，不闪烁切换空状态。
- 异常：加载失败显示结构化错误摘要与“重试”，不显示技术堆栈。

### 骨架 B：对象详情页

- 结构：头部（对象身份、业务状态徽章、版本徽章、主操作）→ 主区内容分节 → 右侧停靠区“上下文”面板（证据、版本与审计、关联对象）→ 底部时间线（业务事件流）。
- 头部主操作不超过三个，其余收入“更多操作”。无权限的操作置灰并提示所需权限；因业务状态暂不可用的操作置灰并提示原因。
- 不可变对象不提供“编辑”；修正入口以“创建新修订/新版本/作废决定”等类型化命令呈现。

### 骨架 C：运行监控页

- 用于识别运行（I0–I9）、评估运行（A0–A9）、接入任务等 LangGraph 过程任务。
- 结构：运行头部（运行标识、状态、阶段、触发原因、操作者、启动时间、幂等键）→ 阶段进度条（当前阶段高亮，暂停/失败阶段标注）→ 子任务表（工序工作项/合并组/批次，各自状态）→ 错误与重试面板 → 结果汇总区。
- 运行状态沿用统一过程任务语义：待运行、运行中、等待复核、可重试失败、终止失败、已完成、已取消；`stage` 以阶段进度条表达，不扩张状态枚举。
- 页面自动刷新有界：运行中按固定间隔轮询，终态后停止；离开页面不丢失任务。
- 技术失败显示错误码、阶段、可重试性与重试策略摘要，并提供“恢复运行”（有权限时）；业务阻断显示阻断原因与上游入口（如知识准备任务链接）。

### 骨架 D：治理与版本页

- 用于知识与规则下全部受治理定义（工序模型、机理库、规范库、案例库、指标体系、评分规则、适用规则集、矩阵、阈值、措施库）。
- 结构：对象列表（审核状态筛选：草稿/待审核/已发布/已停用）→ 条目详情（当前修订、证据定位、关联对象）→ 修订表单 → 差异对比视图（两个版本并排，字段级差异高亮）→ 送审/发布/停用/回滚操作。
- 发布后不可原地修改：发布版本的表单全部只读，修改只能“创建新修订”。
- 回滚表达为“重新启用历史版本”或“发布新集合”，界面措辞不使用“撤销发布”。

### 骨架 E：复核工作台

- 结构：复核队列（类型、工程、触发原因、提交时间筛选；支持多选批量“原样通过/拒绝”）→ 复核详情（目标对象精确版本快照、触发原因、校验结果、证据、历史决定、类型化决定表单）。
- 复核详情内不直接编辑被审对象本体；识别复核的“修正并通过”在候选工件上编辑（见 §14 P-RV-03）。
- 批量提交前展示确认摘要：工程、任务数量、触发原因分布、涉及工序与风险事件、将产生的业务结果；后台逐项执行，响应按任务返回逐项结果，界面只要求继续处理失败项。

## 4. 证据抽屉

证据抽屉是右侧停靠区“上下文”面板内的统一组件，从任何“证据定位信息”入口打开：

- 内容：资料段标识（`资料ID-章节ID-资料段ID`）、所属资料与版本、章节路径与页码、证据片段原文或监测摘要、该证据被引用的全部业务对象。
- 无资料读取权限时只显示定位摘要（资料名称、章节路径、资料段标识），不显示原文；界面对此脱敏状态有固定提示，不留“加载失败”歧义。
- 抽屉内可继续打开资料详情页（携带资料段锚点）查看完整上下文。
- 每个分值、结论、预警原因、触发指标旁就地提供证据入口，不设置统一“更多详情”。

## 5. Agent 交互规格

**本节修订 04 号票“智能 Agent 是独立一级工作台”的决策**：Agent 改为“全局停靠栏 + 全屏工作台模式”的混合形态，一级导航相应从八项调整为七项业务导航。

- **全局 Agent 停靠栏**：右侧停靠区的“Agent”面板，可从顶栏入口或任何业务页展开/收起；跨页面导航时保持会话与任务状态不丢失；自动携带当前页面对象上下文（工程、区段、工序节点、风险记录、评估记录、预警信息），无需用户手动选择上下文。承担日常问答、轻量命令确认与证据引用查看。
- **全屏工作台模式**：停靠栏可弹出为全屏（也可从运行记录、任务详情进入），采用“对话 + 任务执行 + 结构化结果 + 证据引用”四区布局，承载多步骤任务执行监控、结构化结果审阅与复杂命令确认。两种模式共享同一会话与任务状态，不维护两套数据。
- **统一任务形态**：接入清洗、非结构化知识编制、检索审阅、处置建议、校准建议和交互式 Agent 共用一个 Agent 任务详情结构。内嵌任务在用户已经确认的业务运行内自动执行，不逐阶段追加确认；交互式 Agent 准备正式写命令时进入“等待用户确认”。
- **任务步骤**：只展示可审计的步骤，包括任务类型与状态、冻结输入、策略/模型/提示模板版本、允许的工具、硬预算与消耗、工具调用、原始输出引用、类型化增量、确定性校验和增量应用结果；不展示模型内部思维链。
- **命令确认**：交互式 Agent 准备写命令（启动识别、启动评估、复核决定、预警确认、反馈登记、导出）时展示确认卡片——工程、目标对象、精确输入版本、预计生成的事实、是否有外部副作用；用户确认后才提交。无权限用户的确认按钮置灰并提示所需权限。重命令（涉及多步骤或批量副作用）在全屏工作台确认。正式领域命令提交时仍执行该命令自身的常规权限校验。
- **结果引用**：Agent 输出不形成独立结果格式；识别、评估、处置结果分别引用领域 SSOT 对象，点击即跳到对应详情页；Agent 返回的页面深链可跳回业务页。
- **边界提示**：界面不把确定性 P/C、矩阵映射、阈值判定或 Schema 校验包装成 Agent 结论，也不展示“Agent 审阅自己刚生成的结果”等虚构多角色步骤。必须的 Agent 失败时显示重试预算与失败状态，不提供“跳过并使用基线结果”。

## 6. 全局交互原语

- **命令确认对话框**：一切会产生业务事实的命令（启动运行、送审、发布、回滚、验收、作废、确认预警、采纳建议、登记执行、导出）执行前展示工程、对象、精确版本、预计结果与外部副作用；高影响命令（发布、回滚、作废、批量复核）必须显式确认。
- **异步运行**：启动命令提交后立即跳到运行监控页，不在表单页阻塞等待；重复提交由业务幂等键保证返回同一运行，界面显示“已存在相同请求的运行”并跳转。
- **版本徽章与版本入口**：所有版本化对象显示版本徽章；点击展开版本时间线（历史版本、发布人、生效时间、差异对比入口）。
- **审计入口**：对象详情页“上下文”面板固定“版本与审计”节，展示创建、修订、审核、发布、作废及操作者；完整审计流跳转 P-RV-06。
- **风险色**：只表达风险等级与预警状态（甲方风险分级映射的红/橙/黄）；运行状态、操作状态使用工程蓝、绿或中性色。
- **权限降级**：无权限的命令与入口置灰并以提示说明所需权限；因业务状态暂不可用的操作置灰并说明原因；无资料读取权限的证据按 §4 脱敏；跨工程数据不出现任何泄露目标内容的提示。
- **表单校验**：必填、格式与单位在提交前就地提示；服务端确定性校验失败返回字段级错误就地显示；业务校验失败（如规则冲突、证据不可用）以结构化原因面板展示并给出处理入口，不转化为技术报错页。

## 9. 智能 Agent

Agent 不是业务导航项，由全局停靠栏与全屏工作台组成（§5）；下表为其两个界面形态与任务详情页。

| 页面 | 骨架 | 核心内容与操作 | 主要状态与异常 | MVP 差异 |
|---|---|---|---|---|
| P-AG-01 Agent 停靠栏 | 专用（§5） | 对话、冻结上下文摘要、轻量命令确认卡片、证据引用；跨页面保持状态 | 模型服务不可用时显示技术阻断与冻结预算内重试，不生成降级回答冒充结果 | 一致 |
| P-AG-02 Agent 全屏工作台 | 专用（§5） | 四区布局：对话流、任务执行面板、类型化增量与领域结果面板、证据引用；六类 Agent 任务统一检索与监控、复杂命令确认 | 空状态展示可发起的交互式任务；内嵌任务从所属业务运行进入 | 一致 |
| P-AG-03 Agent 任务详情 | C | 任务类型、所属运行、状态、输入/策略/模型/提示模板/工具/预算/增量/校验器版本、工具调用、原始输出引用、增量差异、领域结果或命令状态 | 状态支持待运行/运行中/等待用户确认/可重试失败/终止失败/已完成/已取消；失败时不提供跳过或扩预算操作 | 一致 |

## 20. 验收要点（供 MVP 验收票引用）

1. 七项业务导航、Agent 停靠栏与系统管理区下每个页面可定位到本规格的骨架、数据、操作与状态约定；无规格外页面。
2. 五类骨架的空/加载/异常/权限降级行为在各页面一致。
3. 证据抽屉在分值、结论、预警原因旁就地可达，无权限时脱敏表现一致。
4. 高影响命令确认对话框完整展示工程、对象、版本、预计结果与副作用。
5. 识别复核“修正并通过”为一次操作；`modelConfidence` 只读且与人工修正并列展示。
6. 处置建议校验失败不存在任何“强行通过”入口；现场独立行动如实标注。
7. 校准建议无“立即生效”入口，必须经新草稿、审核与发布。
8. 预警“确认”界面语义为已读并接管，无“消除预警”操作。
9. 角色矩阵逐项可验证：无权命令置灰并提示所需权限，只读用户写命令确认按钮置灰。
10. 五类内嵌 Agent 任务和交互式 Agent 共用 P-AG-03；内嵌任务自动运行，交互式写命令等待用户确认。
11. 普通 P/C、矩阵和预警页面不显示 Agent 参与；RI-S57 后不显示同模型 Agent 自我审阅。
12. 必须的 Agent 失败时无跳过、静默降级、换模型或扩预算入口，可重建输入、原始输出引用、工具、预算、增量和校验结果可追溯。
13. 五张汇报截图可直接从 §18 所列正式页面派生。
